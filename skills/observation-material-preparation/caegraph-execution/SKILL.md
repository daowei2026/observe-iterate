# E｜CAEGraph 执行／运行

## 定位

E 同时包含：

1. **专业判断**：由 E Agent／executor 完成，负责判断候选运行结果、返回 B／C／D、核对最终图、决定正式取哪些数据并核对结果；
2. **真实操作**：由 Worker 执行，W1 运行图，W2 导出已接受图中明确需要的数据。

```text
E 判断“什么结果可接受”
Worker 执行“已经明确授权的实际操作”
```

## 执行优先

本阶段默认追求快速取得真实反馈：

- W1 收到任务后先运行，优先返回 HTML 或首个阻断错误；
- W2 收到任务后先导出指定数据，不先建设通用框架；
- E1 基准和 E4 取数准入是简短引用集合，不要求另写长报告；
- 日志、Git diff 和现有提交优先承载事实；
- 完整环境快照、文件哈希、全量血缘、详细缺失说明只在实际需要时补充。

## 为什么仍分 W1／W2

- [W1 短执行卡](RUN_REPAIR_ORDER_TEMPLATE.md)：运行 D 定义并做权限内机械修复；
- [W2 短执行卡](DATA_EXPORT_ORDER_TEMPLATE.md)：最终图被 E 接受后，只导出明确列出的正式数据。

两张卡分开，是为了不在图尚未被接受时提前授权正式取数；不是为了制作两套审计材料。

通用身份、权限、工作区和 Return 使用 [WORKER_ORDER](../../../longrun/templates/WORKER_ORDER.md)，阶段卡不重复填写。

## 输入概览

- D 完整 CAEGraph 定义；
- C2 当前展示预期和当前预期 HTML；
- 外层特征实例与 B 位置；
- 实际工作区、运行入口和输出目录；
- 当前操作授权。

字段级合同见 [IO_SPEC.md](IO_SPEC.md)。

## E 自己的专业 Workflow

见 [WORKFLOW.md](WORKFLOW.md)：

```text
建立最小运行基准
→ 消费 W1 真实结果并分类问题
→ 核对最终脚本和最终图
→ 明确本次正式需要导出的数据
→ 消费 W2 数据并做必要一致性核对
→ 交付
```

## Worker 派单

见 [WORKER_DELEGATION.md](WORKER_DELEGATION.md)。它只说明 W1／W2 的触发、边界和回流，不重复通用长程工单规范。

## 最终输出概览

- E 接受的最终脚本和 HTML；
- W1 的最小运行事实：状态、日志、diff、阻断；
- 最终图与 D／C 的核对结果；
- 简短正式取数准入及 W2 明确导出的数据文件；
- 图层／对象到文件、数据阶段和行数的最小映射；
- 本轮实际需要的一致性核对、限制和未决问题。

## 完成条件

- 候选图已在真实环境运行，或阻断已准确暴露；
- E 已核对最终脚本与 D、最终图与 C；
- 只有图被接受后才启动 W2；
- W2 只导出本次明确需要的数据；
- 最终脚本、HTML 和正式数据能相互追溯；
- 本轮会影响下游判断的差异、缺失和转换已经说明。

## 不允许做的事

- 不把 E 的专业判断交给 Worker；
- 不让 Worker 先写大量说明再开始运行／导出；
- 不在 W1 中提前授权正式取数；
- 不让 W2 默认导出所有数据阶段或建设通用血缘系统；
- 不因脚本跑通就宣称最终图通过；
- 不把调试数据、少量预览或未核对文件冒充 `DATA_READY`。
