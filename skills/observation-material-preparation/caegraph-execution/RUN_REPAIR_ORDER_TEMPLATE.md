- **E1 签发 W1 的目标就是运行 D 并做权限内确定性机械修复**。实际 W 正文由本短执行卡加上通用 W 的必需身份／授权和已知精确入口实例化，不得额外扩成独立的运行环境调研、构建、部署、来源审计或通用验收工程；不得用“更严格”替代必要性判断。
- **真实运行优先**：已有可执行 D、工作区及获准入口且没有已证实的危险写入／破坏性操作时，先真实启动 D。若此前默认入口已实际失败，可让 Worker 在现有工作区有界定位并使用已存在的正常入口，继而尝试 D；不要只反复派环境探测工单。记录真实运行异常后，再按下文“可以直接修”在同一 W 内有限修复、重跑。
- **不得由 E1 自行创造额外的运行前一票否决条件**。例如“所有 `mquant*` 模块必须在同一个物理目录内”“所有 symlink 均不得出目录”“未列出全部模块哈希／完整 provenance 就不能运行”，均不是本 Skill 的通用前置。已有运行入口主动设置 `sys.path`、使用符号链接或复用工作区平台模块，不能仅凭这一事实认定版本冲突／不可运行。来源差异可以记录，但不得自动升级为 STOP 或 Owner 运行环境请求。
- 只有**实际确认**必要输入缺失、锁定的目标业务实现不匹配、入口无法执行、可能发生未经授权／破坏性写入，或者真实错误的合法修法不唯一时，才停止或请 E 判断；否则先运行，交付 HTML 或实际 traceback。不能因为未证明“全部环境同根纯净”就推断运行不可能。

## 可以直接修

仅限不改变业务含义的确定性问题：

- Python 语法、import、模块或文件路径；
- 锁定版本中已经核实的 API 名称／参数差异；
- 明确的类型转换、输出目录、文件名或日志接线；
- 本工单另行明确授权的机械问题。

有修改时优先直接提交 `git diff`；不要求把每项修改再手工抄成一套审计表。

## 必须停止并回 E

- 需要改变品种、时间、多尺度位置或特征实例；
- 需要删除、增加、替换业务字段或另算近似值；
- 需要改变主图／附图、图元、时间表达、标准化、交互或其他展示含义；
- 正确修法不唯一，或无法判断是否影响业务语义；
- 动作存在未授权写入、明显破坏性或超出预算的风险。
