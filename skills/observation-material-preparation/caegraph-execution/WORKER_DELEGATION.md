# E｜Worker 派单合同

> 本文件只说明 E 何时派 W1／W2、Worker 的操作边界以及结果回到哪里。身份、授权、工作区、预算和 Return 由通用 [WORKER_ORDER](../../../longrun/templates/WORKER_ORDER.md) 与长程协议负责；两张阶段卡不重复这些字段。

## 1. 基本原则

```text
通用工单：管身份、权限、工作区和回交
W1／W2 短执行卡：只管本次实际要做什么
E 专业 Workflow：判断结果是否可接受、下一步去哪里
```

默认采用“**最少填写、先做实事、异常再展开**”：

- W1 先真实运行一次，优先返回 HTML 或首个阻断错误；
- W2 先导出明确列出的数据，不先建设通用导出框架；
- 日志和 `git diff` 优先承载事实，不要求 Worker 手工重复抄写；
- 环境快照、哈希、完整血缘、详细缺失说明只在本轮确实需要时补充。

### W1 工单不得增设环境验收工程

E1 将 W1 短执行卡实例化为真实工单时，除通用 V2 必需的操作身份、授权、工作区、回交外，专业内容只需：**D 完整脚本／已知运行入口、输出目录、有限机械修复边界、必须回 E 的条件、最小回报**。E1 可以根据实际首错给 Worker 明确的机械修复线索，但不把自己无法在现场验证的推断升级为 Worker 执行前硬门槛。

- 首选现有正常运行入口。若默认入口已失败而工作区存在可用候选入口，由 Worker 有界核实、按既有入口真实运行 D；不要求整个 `mquant*` import closure 的物理路径必须收敛到单一目录。符号链接或正常的多目录包布局本身不证明版本冲突。
- 只有已确认目标业务源码版本错误、输入缺失、授权越界、可能产生破坏性写入或真正不可运行时才能阻止尝试 D。来源信息不全／普通平台模块来自工作区其他目录应记录为证据限制，不能无技术因果地判定 E 阶段缺 Owner 环境授权。
- Worker 按短执行卡在**同一 W 内**处理修法唯一且不改变业务语义的机械错误、留下日志和 diff 后重跑；E1 不得因“需要谨慎”取消这一授权，也不需要预先给 Worker 一份详尽的环境构造算法。
- 任何新 W1 revision 都应回答：**这张工单将实际运行什么？若不运行，哪条原 Owner／Skill 必要条件或哪条已确认的真实风险使运行不合法？** 不得以新造的全环境检查项目代替真实业务工作。

## 2. 与 E 专业 Workflow 的对应

| E 专业产物 | 实际操作 | 执行卡 | 回到 E 的位置 |
|---|---|---|---|
| E1 `执行与核图基准` | 运行 D 定义，做权限内机械修复 | [W1 短执行卡](RUN_REPAIR_ORDER_TEMPLATE.md) | E2 消费候选运行事实 |
| E2 判断只剩机械问题，且基准未变 | 继续运行／修复 | 新 W1 revision | E2 |
| E4 `正式取数准入` | 导出已接受图中明确需要的数据 | [W2 短执行卡](DATA_EXPORT_ORDER_TEMPLATE.md) | E5 核对图与数据 |
| E5 判断只是导出动作错误，且准入未变 | 重做导出 | 新 W2 revision | E5 |

Worker 只生产事实和实物，不替代 E2／E3／E4／E5 的专业判断。

## 3. 为什么仍保留 W1 与 W2

```text
W1 运行出候选图
→ E 判断脚本和图是否正确
→ E 接受最终图并明确需要哪些数据
→ W2 只导出这些数据
```

保留两张卡，是为了不在图尚未被接受时提前授权“正式数据”。这不意味着要制作两套庞大的审计材料。

## 4. W1 的边界

### Worker 先做

- 在真实环境运行 D 的完整脚本；
- 生成候选 HTML，或返回首个阻断错误；
- 修复短执行卡允许的语法、import、路径、已确认 API 差异、明确类型和输出接线问题；
- 用 `git diff` 和日志记录实际变化。

### Worker 不决定

- 是否更换品种、时间、多尺度位置或实例；
- 是否改变字段、主附图、图元、时间表达、标准化或交互；
- 是否用近似值代替特征输出；
- 最终图是否通过；
- 是否已经 `DATA_READY`。

回报只需脚本、HTML、日志、diff 和当前阻断。额外说明按短执行卡中的触发条件补充。

## 5. W2 的边界

### Worker 先做

- 使用 E 已接受的脚本／HTML／运行；
- 只导出短执行卡表格中列出的图层和数据阶段；
- 返回数据文件及最小映射：`图层／对象 → 文件 → 数据阶段 → 行数`。

### Worker 不决定

- 不修改已接受的图、脚本、位置、字段和展示语义；
- 不自行扩大到所有数据阶段；
- 不默认生成全量血缘、哈希和审计包；
- 不判断数据是否在专业上可接受。

需要修改图或脚本时，停止并回 E；旧取数准入失效。

## 6. 重跑与快速反馈

- 第一次 W1 回报优先给结果或首个阻断，不等待长报告；
- W1／W2 效果未知时先对账，不盲目重跑；
- D、C、实例、位置或环境基准变化后，旧 W1 不能无痕续用；
- 最终脚本、HTML、运行或取数清单变化后，旧 W2 不能无痕续用；
- 只是导出动作错误且准入未变时，可定向重试 W2，不重做 A～D。
