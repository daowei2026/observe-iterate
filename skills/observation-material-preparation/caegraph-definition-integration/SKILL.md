# D｜CAEGraph 定义集成

## 定位

D 当前只有一个专业动作，不设置内部 Workflow：

> **根据外层 Workflow 的特征名称、代码版本和特征实例，以及 A 的事件／字段、B 的真实位置、C1／C2／C3 的输出，形成完整 CAEGraph 定义。**

这个动作内部包含理解仓库、注入实例、绑定位置和字段、处理确定性上游缺项以及形成脚本，但它们不是需要分别管理的多个业务步骤。

D 不重新设计 C2 的展示预期，不重新选择 B 的位置，不派 Worker，不运行最终图，也不正式取图数据。

## C 与 D 对特征实例的边界

C 可以只读检查外层特征实例，或临时用它生成 C2 预期 HTML；但 C3 的正式展示代码必须保留实例注入接口，不得把外层真实实例固化为不可替换内容。

D 负责真正完成：

```text
外层真实特征实例
+ A 的真实事件和字段
+ B 的真实品种／时间／多尺度位置
+ C1 待展示信息
+ C2 当前展示预期／预期 HTML
+ C3 可注入代码和注入合同
→ 完整 CAEGraph 定义
```

## CAEGraph 仓库理解要求

D 不能只读类名摘要，也不能凭旧脚本猜测 API。必须先按 [CAEGraph 仓库结构与定义集成参考](../references/CAEGraph仓库结构与定义集成参考.md) 理解锁定版本仓库中与本次定义相关的：

- 正式导出；
- `CAEGraph / PlotSet` 配置；
- 布局类和绘图类；
- Feature／特征实例怎样进入绘图器；
- `PlotCtx` 怎样处理 SOF、日历、品种、时间和数据；
- DataFrame 怎样转换为 Bokeh CDS；
- `PlotDataFolder / PlotDataNode` 怎样暴露构图数据；
- 本次涉及的动态标准化、控件、多尺度、前端回调或 server 路径。

“理解仓库”必须落实到本次使用的真实源码链和版本引用；不要求抄录无关文件，但不能把实际使用的类、参数或数据路径留成猜测。

## 输入概览

- 外层输入：特征名称、特征代码版本、特征实例；
- A 阶段事件、发生位置、业务角色、真实字段和处理关系；
- B 阶段普通位置或高频多尺度位置；
- C1 待展示信息；
- C2 当前展示预期、当前预期 HTML、复杂点处理记录和能力缺口；
- C3 位置与实例可注入的 CAEGraph 代码及注入合同；
- 锁定版本 CAEGraph／uplot 仓库及其运行依赖。

字段级格式见 [IO_SPEC.md](IO_SPEC.md)。

## 单一集成动作

D 一次性完成：

1. 核对外层输入和 A／B／C 产物属于同一当前任务及兼容版本；
2. 按仓库源码理解 C3 代码使用的 CAEGraph 类、参数和数据链；
3. 把外层真实特征实例和正式 Feature／数据入口注入 C3 的实例接口；
4. 把 B 的普通位置或多尺度位置写入真实 SOF、日历、对象和 `timespans`／相应配置；
5. 把 A 的真实事件、时间、身份和数值字段绑定到 C3 图元；
6. 处理拿得准的 B／C 确定性缺项或错误，或把拿不准的问题退回原阶段；
7. 形成完整 Python CAEGraph 定义／脚本初稿，并保留仓库理解、上游纠正、C→D 集成差异和定义级检查。

这些只是同一个集成动作的内容，不另立 D1～D7，也不要求分别派单或验收。

## B／C 缺项或错误怎样处理

D 不需要因为任何小缺项都机械返回 B 或 C，但也不能借“集成”名义自行改业务选择。

### D 可以直接纠正

只有同时满足以下条件时，D 才可直接修正并继续：

1. **结果唯一**：依据 B／C 既有规则、外层输入或锁定 CAEGraph 仓库，只有一个合理修法；
2. **不引入新业务选择**：不重新选择品种、时间、多尺度路径，也不改变 C2 已接受的页面、信息、图元和业务语义；
3. **证据清楚**：能够指出原缺项／错误、修正依据和修改前后；
4. **完整留痕**：写入 `上游确定性纠正记录`，不能只在最终代码中无痕改掉。

典型情况：

- B 漏填一个已经由 B 当前默认唯一确定的字段，例如沿用特征实例 SOF、默认钢铁板块或默认时间范围；
- C3 的注入参数名、占位替换或 CAEGraph API 用法与锁定仓库明显不符，但 C2 预期和正确修法都没有歧义；
- C3 代码遗漏了 C2 已明确要求、且实现方式唯一的机械接线。

### 必须返回 B

- 需要换品种、换时间或重新选择多尺度路径；
- B 的当前位置存在两个以上合理选择；
- 是否使用默认位置本身需要业务判断；
- 修正会改变“最终看哪里”。

### 必须返回 C

- 需要改变 C1 待展示信息；
- 需要改变 C2 当前预期 HTML、面板结构、图元含义、转换、交互或业务阅读方式；
- C3 代码有多种可能修法，无法从 C2 预期唯一确定；
- 修正会改变“应该怎样展示”。

### A 事实不清时

若 D 发现 A 的事件、字段、位置或引用关系本身不清楚，返回 A；不能让 D 或 C 从字段名猜业务语义。

## 最终输出概览

- 已绑定真实特征实例、真实数据入口、品种、时间、字段和按需多尺度位置的完整 CAEGraph Python 定义／脚本初稿；
- CAEGraph 仓库理解记录；
- B／C 上游确定性纠正记录，或返回 B／C／A 的具名问题；
- C3 代码到完整定义的集成记录和差异；
- 定义级检查结果；
- 只有 E 真实运行才能确认的事项。

## 完成条件

- 已按锁定版本真实仓库解释本次使用的 CAEGraph 类、参数和数据路径；
- 外层真实特征实例在 D 中完成正式绑定，C 的预览绑定没有被误当成最终实例；
- B 的位置和 A 的字段均已进入真实代码，而不是只写在说明中；
- C2 的展示预期没有被无痕改变；
- B／C 缺项若由 D 直接修正，已经证明修法唯一、未改变业务选择并完整留痕；
- 拿不准的 B／C／A 问题已经返回原阶段，而不是在 D 中猜测；
- 产物是可以直接交 E 尝试运行的完整定义／脚本初稿，不是文字方案、伪码或片段；
- 已区分定义级检查和 E 的真实运行验证。

## 不允许做的事

- 不在存在多个合理选项时自行替 B 选择位置；
- 不无痕改变 C2 的展示预期；
- 不把 C 的临时预览实例直接当作最终实例绑定；
- 不绕开 C3 代码另写一套业务语义不同的图；
- 不以近似新计算代替 A 的真实特征字段；
- 不凭记忆或旧示例猜 CAEGraph API；
- 不把“我觉得这样也行”当成拿得准的确定性纠正；
- 不派 Worker；
- 不把生成脚本初稿当作 E 已完成。
