# D｜CAEGraph 定义集成

## 定位

D 当前只有一个专业动作，不再设置内部 Workflow：

> **根据外层 Workflow 的特征名称、代码版本和特征实例，以及 A 的事件／字段、B 的真实位置、C 的展示预期与可注入展示代码，形成完整 CAEGraph 定义。**

这个动作内部当然包含理解仓库、绑定实例、位置和字段以及形成脚本，但它们不是需要分别管理的多个业务步骤。

D 不重新设计 C 的展示预期，不重新选择 B 的位置，不派 Worker，不运行最终图，也不正式取图数据。

## C 与 D 对特征实例的边界

C 可以只读检查外层特征实例，或临时用它生成预期 HTML；但 C 的正式展示代码必须保留实例注入接口，不得把外层真实实例固化为不可替换内容。

D 负责真正完成：

```text
外层真实特征实例
+ A 的真实事件和字段
+ B 的真实品种／时间／多尺度位置
+ C 的展示预期、可注入代码和实例注入合同
→ 完整 CAEGraph 定义
```

## CAEGraph 仓库理解要求

D 不能只读一份类名速查，也不能凭旧脚本猜测 API。必须先按 [CAEGraph 仓库结构与定义集成参考](../references/CAEGraph仓库结构与定义集成参考.md) 理解锁定版本仓库中与本次定义相关的：

- 正式导出；
- `CAEGraph / PlotSet` 配置；
- 布局类和绘图类；
- Feature／特征实例怎样进入绘图器；
- `PlotCtx` 怎样处理 SOF、日历、品种、时间和数据；
- DataFrame 怎样转换为 Bokeh CDS；
- `PlotDataFolder / PlotDataNode` 怎样暴露构图数据；
- 本次涉及的动态标准化、控件、多尺度、前端回调或 server 路径。

“理解仓库”必须落实到本次使用的真实源码链和版本引用；不要求抄录无关文件，但不能把任何实际使用的类、参数或数据路径留成猜测。

## 输入概览

- 外层输入：特征名称、特征代码版本、特征实例；
- A 阶段事件、发生位置、业务角色、真实字段和处理关系；
- B 阶段普通位置或高频多尺度位置；
- C 阶段展示预期、复杂点处理记录、实例注入合同、位置与实例可注入的 CAEGraph 代码和预期 HTML；
- 锁定版本 CAEGraph／uplot 仓库及其运行依赖。

字段级格式见 [IO_SPEC.md](IO_SPEC.md)。

## 单一集成动作

D 应一次性完成：

1. 核对外层输入和 A／B／C 产物属于同一当前任务及兼容版本；
2. 按仓库源码理解 C 代码所用 CAEGraph 类、参数和数据链；
3. 把外层真实特征实例和正式 Feature／数据入口注入 C 的实例接口；
4. 把 B 的普通位置或多尺度位置写入真实 SOF、日历、对象和 `timespans`／相应配置；
5. 把 A 的真实事件、时间、身份和数值字段绑定到 C 的图元；
6. 形成完整 Python CAEGraph 定义／脚本初稿，并保留 C→D 集成差异和当前可做的定义级检查。

这六项只是同一个集成动作的内容，不另立 D1～D6，也不要求分别派单或验收。

## 最终输出概览

- 已绑定真实特征实例、真实数据入口、品种、时间、字段和按需多尺度位置的完整 CAEGraph Python 定义／脚本初稿；
- CAEGraph 仓库理解记录；
- C 代码到完整定义的集成记录和差异；
- 定义级检查结果；
- 只有 E 真实运行才能确认的事项。

## 完成条件

- 已按锁定版本真实仓库解释本次所有 CAEGraph 类、参数和数据路径；
- 外层真实特征实例在 D 中完成正式绑定，C 的预览绑定没有被误当成最终实例；
- B 的位置和 A 的字段均已进入真实代码，而不是只写在说明中；
- C 的展示预期没有被无痕改变；
- 产物是可以直接交 E 尝试运行的完整定义／脚本初稿，不是文字方案、伪码或片段；
- 已区分定义级检查和 E 的真实运行验证。

## 不允许做的事

- 不重新选择 B 的位置；
- 不重新发明或自行改变 C 的展示预期；
- 不把 C 的临时预览实例直接当作最终实例绑定；
- 不绕开 C 的展示代码另写一套业务语义不同的图；
- 不以近似新计算代替 A 的真实特征字段；
- 不凭记忆或旧示例猜 CAEGraph API；
- 不派 Worker；
- 不把生成脚本初稿当作 E 已完成。
