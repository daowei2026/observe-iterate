# C｜展示方式准备

## 定位

本阶段回答：特征输入、业务主输出和必要中间处理结果应怎样在 CAEGraph 中展示，才能沿时间过程方便核对。

C 分成三部分：

1. **C1：列出待展示信息**；
2. **形成展示预期**：先理解 CAEGraph，再使用已有展示知识；复杂点循环求解；
3. **实现展示预期**：给出不绑定 B 最终真实位置、也不固化外层真实特征实例的 CAEGraph 展示代码和预期展示 HTML。

本阶段不选择最终真实品种和时间，不关心 B 最终有多少位置，也不运行 D 绑定后的最终图。

## 特征实例在 C 与 D 之间怎样处理

外层特征实例可以在 C 中**只读使用**，用途只有两类：

- 理解真实数据形状、字段和 occurrence 结构，避免用假想数据结构设计展示；
- 必要时作为生成预期 HTML 的临时预览绑定。

但 C 的正式展示代码不得把这个实例固化为最终运行实例。C 必须保留明确的实例／Feature 注入接口；真正把外层特征实例、真实数据入口和 B 的真实位置绑定进完整定义，是 D 的职责。

因此：

```text
C：理解实例，形成展示预期和可注入实例的展示代码
D：把外层真实实例、A 的真实字段和 B 的真实位置注入 C 代码
```

若 C 为生成预期 HTML 临时使用了真实实例，必须记录“预览实例绑定”，并确保该绑定可被 D 替换，不能把预览运行冒充最终集成。

## 输入概览

- A 阶段的事件级 occurrence、事件发生位置和处理关系；
- 外层特征实例（只读、条件使用）；
- [CAEGraph 展示能力与构建速查](../references/CAEGraph展示能力与构建速查.md)及其锁定版本原手册；
- 本 Skill 中关于主图、附图、时序阅读、事件身份和困难点处理的展示知识。

字段级格式见 [IO_SPEC.md](IO_SPEC.md)。

## 最终输出概览

1. **待展示信息清单**；
2. **展示预期**：页面结构、主附图、信息位置、事件时间与身份、图元和阅读方式；
3. **复杂展示点及处理记录**：每轮想法、能力核实、修正和剩余缺口；
4. **位置与实例可注入的 CAEGraph 展示定义代码**：不绑定 B 的最终真实位置，不固化外层真实特征实例；
5. **实例注入合同**：D 应怎样传入外层特征实例、Feature／数据入口和字段映射；
6. **预期展示 HTML**：用于 E 阶段核对最终实际图；
7. **真实 CAEGraph 能力缺口**。

## 内部 Workflow

见 [WORKFLOW.md](WORKFLOW.md)。

## 完成条件

- C1 已明确输入、业务主输出和本轮必要中间结果；
- 已阅读并使用锁定版本的 CAEGraph 术语、构建链路、布局类和绘图类资料；
- 已形成可供人阅读的展示预期，而不是直接从字段跳到代码；
- 复杂展示点已经经过至少一轮“展示想法—能力核实—调整或缺口”的处理；
- 已形成位置与实例可注入的 CAEGraph 定义代码和可打开的预期展示 HTML；
- 若使用真实实例生成预期 HTML，已明确记录预览绑定且没有把它固化为最终实例；
- HTML 与展示预期一致，且没有冒充最终真实运行结果。

## 不允许做的事

- 不选择或删改 B 的最终真实观察位置；
- 不跳过 CAEGraph 理解，直接凭记忆猜类名和能力；
- 不把主图／附图经验机械应用，而不检查时序阅读是否方便；
- 不在发现复杂点后直接提出新功能，必须先核实现有用法和替代表达；
- 不用复杂交互替代本可由主附图和共享时间轴表达的内容；
- 不从显示值反推业务原值；
- 不把外层真实特征实例硬编码为 C 展示代码不可替换的一部分；
- 不把 C 的样例代码和预期 HTML 冒充 D 的完整定义或 E 的最终结果。
