# C｜展示方式准备

## 定位

本阶段回答：特征输入、业务主输出和必要中间处理结果应怎样在 CAEGraph 中展示，才能沿时间过程方便核对。

C 固定分成三部分：

1. **C1｜列出待展示信息**；
2. **C2｜形成并迭代展示预期**：先理解 CAEGraph，再直接给出第一版展示预期 HTML；发现复杂点后循环核实现有能力，并同步更新展示预期和 HTML；
3. **C3｜整理可注入的 CAEGraph 展示代码**：把 C2 当前被接受的展示实现整理成不绑定 B 最终位置、也不固化外层真实特征实例的代码。

本阶段不选择最终真实品种和时间，不关心 B 最终有多少位置，也不运行 D 绑定后的最终图。

## 特征实例在 C 与 D 之间怎样处理

外层特征实例可以在 C 中**只读使用**，用途只有两类：

- 理解真实数据形状、字段和 occurrence 结构，避免用假想数据结构设计展示；
- 必要时作为生成 C2 预期 HTML 的临时预览绑定。

但 C3 的正式展示代码不得把这个实例固化为最终运行实例。C 必须保留明确的实例／Feature 注入接口；真正把外层特征实例、真实数据入口和 B 的真实位置绑定进完整定义，是 D 的职责。

```text
C：理解实例；形成、迭代展示预期和预期 HTML；整理可注入代码
D：把外层真实实例、A 的真实字段和 B 的真实位置正式注入 C3 代码
```

若 C2 为生成预期 HTML 临时使用真实实例，必须记录“预览实例绑定”，并确保该绑定可由 D 替换，不能把预览运行冒充最终集成。

## 输入概览

- A 阶段的事件级 occurrence、事件发生位置和处理关系；
- 外层特征实例（只读、条件使用）；
- 锁定版本 [`daowei2026/uplot@e6.2/CAEGraph使用手册.md`](https://github.com/daowei2026/uplot/blob/e6.2/CAEGraph使用手册.md)，以及复杂点所需的对应源码；
- 本 Skill 中已经确认的主图、附图、时序阅读和困难点处理知识。

字段级格式见 [IO_SPEC.md](IO_SPEC.md)。

## 最终输出概览

1. **C1 待展示信息清单**；
2. **C2 当前展示预期**：页面结构、主附图、信息位置、图元、阅读方式和当前预期 HTML；
3. **C2 复杂展示点处理记录**：每轮想法、能力核实、HTML 更新和剩余缺口；
4. **C3 位置与实例可注入的 CAEGraph 展示代码**：不绑定 B 的最终真实位置，不固化外层真实特征实例；
5. **实例、位置和字段注入合同**：D 应怎样传入真实实例、Feature／数据入口、B 位置和 A 字段；
6. **真实 CAEGraph 能力缺口**。

## 内部 Workflow

见 [WORKFLOW.md](WORKFLOW.md)。

## 完成条件

- C1 已明确输入、业务主输出和本轮必要中间结果；
- C2A 已直接阅读锁定版本的 CAEGraph 使用手册相关章节，并在需要时查源码；
- C2B 已直接形成第一版展示预期和可打开的第一版预期 HTML，而不是只写文字构想；
- C2C／C2D 已识别并循环处理复杂展示点，每次决定都同步更新展示预期和 HTML；
- C2 当前 HTML 已能表达当前被接受的展示预期，或已如实标明无法解决的能力缺口；
- C3 已把当前展示实现整理为位置与实例可注入的 CAEGraph 代码；
- 若使用真实实例生成预期 HTML，已记录预览绑定，且没有把它固化成最终实例；
- 没有把 C 的预期 HTML 冒充 D 的完整定义或 E 的最终结果。

## 不允许做的事

- 不选择或删改 B 的最终真实观察位置；
- 不用本地二手摘要替代锁定版本原使用手册；
- 不跳过 CAEGraph 理解，直接凭记忆猜类名和能力；
- 不把未经 Owner 确认的推断写成所有特征都必须遵守的通用展示规则；
- 不把主图／附图经验机械应用，而不检查最终 HTML 是否方便阅读；
- 不在发现复杂点后直接提出新功能，必须先核实现有用法和替代表达；
- 不用复杂交互替代本可由主附图和共享时间轴表达的内容；
- 不从显示值反推业务原值；
- 不把外层真实特征实例硬编码为 C3 代码不可替换的一部分；
- 不在 C3 另造一份与 C2 当前 HTML 不同的展示语义。
