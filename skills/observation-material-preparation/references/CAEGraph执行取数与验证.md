# CAEGraph：执行、核图后正式取数的技术参考

> 状态：技术接线参考（候选）。本文件服务 [E｜CAEGraph 执行／运行](../caegraph-execution/SKILL.md)，不替代 E 的专业 Workflow，也不替代 [CAEGraph 使用手册](https://github.com/daowei2026/uplot/blob/e6.2/CAEGraph使用手册.md)。所有结论以本次真实运行版本为准。
>
> **使用原则**：本文件说明“需要时怎样查深”，不是要求每次运行都建设完整导出和审计体系。默认先取得本轮明确需要的图和数据，只有实际问题或下游用途要求时才展开。

## 1. E 的顺序

```text
D 完整定义
→ W1 快速运行／权限内机械修复
→ E 与 D/C 核对并接受最终图
→ E 列出本轮真正需要的数据
→ W2 定向导出
→ E 作本轮必要的一致性核对
```

调试过程中可以临时查看数据，但只有最终图被接受后、按 W2 清单导出的数据，才进入正式观察材料。

## 2. 三类数据阶段不能混同

| 数据阶段 | 可以取得什么 | 不能据此宣称什么 |
|---|---|---|
| 业务特征源／公开输出 | 原始业务记录、主输出和已公开中间结果、真实时间字段 | 不代表已进入最终图 |
| CAEGraph 构图数据树、图对象和 Bokeh CDS | 图元实际使用的字段数组及 Figure／Renderer／data source 关系 | 不自动等于业务原值，也不自动等于浏览器最终显示状态 |
| 指定可见窗口和前端回调后的显示数据 | 当前基准、动态处理和视窗下的最终显示数组 | 未验证回调完成时不能称稳定 `viewport_final` |

`__prestd_*` 只表示动态标准化之前，不保证是业务最原始字段；被裁剪或标准化的显示值不能反推缺失原值。

W2 只导出 E 明确列出的阶段，不默认三类全部导出。

## 3. 已核对的构图入口

[utlv2.py · CAEGraph.layout](https://github.com/daowei2026/uplot/blob/e6.2/utlv2.py) 支持 `plot_roots`、`all_figs` 等参数；`produce_widgets()` 建立数据树，`PlotSet.plot()` 维护图对象。

```python
plot_roots = []
figure_groups = []
layout = graph.layout(
    ncols=1,
    plot_roots=plot_roots,
    all_figs=figure_groups,
)
```

[源码 pdt.py](https://github.com/daowei2026/uplot/blob/e6.2/pdt.py) 中 `PlotDataFolder.children` 与 `PlotDataNode.cds.data` 可用于取得构图数据。注意：不调用 `show()` 也可能触发取数、上游计算或显著内存占用。

### 默认最小导出

对 W2 清单中的每一项，先保存：

```text
图层／对象
→ 数据文件
→ 数据阶段
→ 行数
```

并保存实际导出日志。

### 仅在需要时继续追深

- 图与数据不一致，或下游明确需要时，再追 Figure／Renderer／CDS／源表；
- 需要业务原值时，回源特征读取，不能从显示值逆推；
- 需要 `viewport_final` 时，再核实浏览器回调和视窗状态；
- 不为未来可能有用而默认递归导出全部数据树。

当前不声称存在“任意视窗一键完整导出”的通用 API。

## 4. 加载范围、可见范围与前端状态

只有本轮涉及动态视窗或前端处理时，才需要进一步区分：

- **加载范围**：构图时已经载入或计算的历史；
- **可见范围**：当前 `x_range.start/end`；
- **参数状态**：控件值是否已经通过更新或回调生效；
- **处理方式**：动态 JavaScript、静态 Python 或未标准化；
- **完成状态**：窗口回调是否完成、能否取得固定快照。

手册、[pfw.py](https://github.com/daowei2026/uplot/blob/e6.2/pfw.py) 与 [dynstd.js](https://github.com/daowei2026/uplot/blob/e6.2/dynstd.js) 可用于核对动态标准化路径。只能导出构图阶段值时，标记 `construction_snapshot`，不能写成 `viewport_final`。

## 5. 与 C2 当前预期 HTML 的核对

默认核对：

- 面板数量、顺序和主附图关系；
- 图元类型及其业务语义；
- A 已确认的事件位置、成员或引用关系；
- 多品种布局、图例、hover 和必要中间结果。

允许因真实数据变化：曲线形状、点数量、坐标范围和局部缩放。无需追求像素级一致。

## 6. W2 默认交付与按需扩展

### 默认交付

```text
数据文件列表
最小映射：图层／对象 → 文件 → 数据阶段 → 行数
未取得项及原因
导出日志
```

### 只有触发时才扩展

| 扩展内容 | 触发条件 |
|---|---|
| Renderer／CDS／源表完整映射 | 图与数据不一致，或下游明确需要血缘 |
| 原值／显示值详细关系 | 标准化、裁剪或显示派生影响本轮判断 |
| 完整缺失语义 | 空值、无 occurrence、缺数据等影响本轮判断 |
| `viewport_final` | 本轮明确需要前端回调后的最终值 |
| 文件哈希 | 任务明确要求、文件不受版本库管理或身份有争议 |
| 完整环境快照／manifest | 正式归档、复现争议或下游明确要求 |

不强制把所有内容合并为一个超级 DataFrame，也不强制每次生成 `observation_manifest`。

## 7. 本轮必要的一致性检查

至少检查：

1. 文件是否对应被接受的脚本、HTML 和运行；
2. 图层／对象与文件是否对应；
3. 数据阶段是否标对；
4. 品种、时间和行数是否合理；
5. 是否存在会影响本轮判断的缺失、截断或转换。

只有在本轮确实涉及时，才进一步检查同一业务记录多图元计数、图例与稳定身份、动态回调、完整缺失分类等。

只导出预览时必须标记 `preview`，不能形成 `DATA_READY`。

## 8. Worker 权限边界

W1 可在派单授权内修复语法、import、路径、确定 API 差异和不改变业务语义的机械错误；优先用 `git diff` 留痕。

以下情况必须返回：

- 更换品种、时间、多层位置或实例；
- 删除、增加、替换业务字段；
- 改变主附图职责、事件位置表达、标准化或交互；
- 新算一个值替代真实特征输出；
- 正确修法不唯一或无法判断语义影响。

W2 不修改已接受的脚本和图，只执行 E 明确列出的数据导出。必须修改图或脚本时停止并回 E。

## 9. 现有功能不够时

只形成当前阻断所需的最小缺口：受影响图层／字段、实际错误、已试过的现有入口、最低替代方案及其语义损失。区分：

- 源特征已有但未公开：补读取或临时 trace；
- 后处理不足：使用确定性处理组件或纯函数；
- 图元／布局不足：返回 C；
- 视窗最终值无法读取：只在本轮确实需要时提出导出接口；
- 业务证据本身不存在：回 A 或源特征，不能靠绘图技术臆造。
