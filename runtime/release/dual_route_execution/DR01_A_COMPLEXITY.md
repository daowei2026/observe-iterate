# Mission A：判断业务需要的表达与实现复杂度

执行修订：`2026-09-12`。本方法服务完整业务合同，不替代 A 的建图、局部细化和 MapRevision 专业正文。

## 1. 先说清这里的复杂度在区分什么

当前体系实际比较的是：**既有滤波器体系＋普通 Reflex 能充分表达的工作**，与**涉及 CEPS 等复杂表达的工作**。前者对应同事 `feature-production-agent` 的能力，后者对应我方 Mission C。A 从业务需要说明表达理由，B 再核实际平台与接收方，形成两类完整工程任务。

这不是“纯函数对有状态”“单次计算对持续过程”的二分。普通 Reflex 本来可以用 Event、Dynamic、Behavior、采样和状态更新；出现这些东西并不自动要求 CEPS 或 Mission C。反之，不应为把工作交给普通实现者而把确实需要的复杂表达藏进一个大函数。滤波器体系指 task source 和实际实现方法，不能在这里随手选滤波算法或参数。

## 2. 从真实业务链识别承重点

恢复 source／measurement／fact／Feature及上层解释，说明每部分的输入、当前方法程序、输出和消费者。问清楚什么材料到达会改变判断，读的是哪个时点的状态，哪些结果需要修订、结束或保留历史，未知和合法空分别意味着什么。现有对象、Book、DSU、controller名称只是候选，不是必须照着建立的答案。

关键判断应给正常或边界场景，展示两种表达的差别和代价。没有真实分歧时不编三套备选；无法据来源判断的地方具名保留，不能借复杂度标签回避业务未细化。

## 3. 四种粒度分别看

业务步骤是能独立说明、做错或调整的动作；运行表达是函数、滤波器、普通 Reflex 或 CEPS 的组织；委派任务是接收者能完整交回的结果；一轮聊天是控制上下文的工作批次。四者没有一一对应关系。

一个 Feature 可含多个方法与状态步骤；一个复杂 Mission C 任务内部仍有普通函数；不要求把每个 helper 公开或分出去，也不能为了 Agent 接收条件把整个复杂用例塞成一个总 Fao。业务工作地图可以按实际结果分层，但不按聊天轮次切业务。

## 4. 用三个分析角度支持表达选择，不把它们变成固定路由器

**方法内部。**实际程序是否只是确定性计算或有限分支；递归的参数／可换方法是否清楚；局部模糊判断是否回答了正确业务问题。方法长、参数尚待校准、返回Double或Bool，都不是 CEPS 的充分理由。不能只留下版本名或方法槽，把“怎样得到结果”推到 B。

**事件和状态关系。**多个发生怎样协调、何时采样、何处读旧状态、谁单写、相互依赖怎样形成。如果普通 Reflex 已能清楚完整表达，应说明怎样表达；确需 CEPS 组合时指出实际带来的分工和组合价值，而不只是说“有生命周期所以复杂”。仍须保护发生含义、current/history和修订法律。

**数据规模与持续运行。**每次回看什么、活跃状态多少、结束后的索引怎样清退、正式历史怎样恢复、重算成本怎样增长。业务回看问题先在 A 明确，B 决定物理结构。运行历史应保真，不代表全部历史常驻内存。规模问题不自动成为表达层或新平台理由。

## 5. 形成最低充分的当前候选

比较现有滤波器／普通 Reflex 与必要复杂表达，选择一个当前可执行、理由明确的方案；可替换处保留方法程序、参数来源、版本和不变量。可以在授权下用可逆暂定首版，不等 Owner再给一个手工分好的样本；暂定不能掩盖核心程序空缺。

CEPS按真实业务关系递归组合，不能强制Local/Global两层或固定线性步骤。一个局部适合模糊控制器，并不意味着 scope、knownness、candidate、历史和生命周期都塞进同一RulePack。业务函数能具名就具名，是否成为独立 Feature、状态 owner 或公共API另行论证。

## 6. 未知量分开，缺口由正确责任者处理

业务未知需要继续 A 分析或真实 Owner 取舍；平台未知交 B exact RepoFact；配置或校准未知保留明确不执行／Pending分支；接收 Agent 不支持交 B 适配或重划交付。不能统称“复杂”，也不能为了进入 B 把自己尚未写出的程序包装为 Source blocker。

来源足够支持的程序写出来；来源不足的数值不胡填。方法具有可执行首版与 production参数已激活是不同事实。真实数据后可按证据回修，不能用现代码倒定义业务。

## 7. 在建图、局部细化和交接时反复使用

首次建图时给完整业务图景及表达理由；局部深入时用具体方法、事件和规模修订这些理由；交 B 时给完整当前合同和受影响边界。发现根因更深，可以有依据地回 MapRevision并保留不受影响部分，不因复核重新从零。

A 执行者写回**业务工作地图和业务合同**，保留原有专业方法要求。长程进度图、共同 Owner 说明、全局投入与下一任务由管理／审查端根据实物接收更新，不额外要求普通 A 聊天重述整个 campaign。
