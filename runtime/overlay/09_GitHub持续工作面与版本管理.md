# GitHub 持续工作面：完整地图、管理接收与版本管理

执行修订：`2026-09-12`。适用于A/B/C跨用例长程；不定义用例对象、算法、固定里程碑数量或轮数。既有业务与代码授权不因本文件扩大。

## 1. 正文、业务地图与推进地图的职责

任务正文在获授权GitHub目录原位维护，Git保存历史；ZIP只用于明确离线、冻结或外部移交。**业务工作地图**描述市场对象、特征、动作、方法和关系，是Mission A实质产物，仍由A按任务修订。**长程推进地图**解释完整工作、当前结论和实物、使用资格、剩余问题、条件性投入预期及下一责任，由管理／审查端维护。它不裁新业务，不另造缩写任务包，也不能退化成打勾表。

公共Owner意图、用语定义、阶段关系和跨线说明优先放已有父入口一次；子图展开各自工作线，父入口链接子图而不重复手工维护全部细节。主说明要使人知道发生了什么，再允许沿exact引用下钻，不能把理解全部推给链接。

## 2. 写前核真实输入、分支与权限

新建或接续需要完整任务目标、来源、目标repo和授权分支／工作面、现有地图与当前任务。能从已连接入口读取的不重新问Owner。核构包锁和live head差异，选exact commit读取承重正文；缺原件具名报告用途、受影响结论和可继续工作，不拿旧摘要或现代码补业务。

授权某仓不等于永久直写main。遵守本轮Owner和仓库写权，不改保护、不force、不代推他人内容；写前再核活动head，漂移时检查相关路径、授权和输入，正常重基线或暂停受影响写面。Git工具授权、当前实际动作和远端写成功分开证明。

## 3. 从真实成果恢复完整图，不从临时模式重建

已有地图先与完整目标、当前任务、正文、最近review和Owner纠正对账，检验状态是否有证据。旧图仍可用就原位保持路径；退化成状态页时恢复丢失的完整结果说明，不在坏壳上无限只改最新局部。没有地图时从实际材料恢复少量可交付结果及依赖，同轮可开始实质工作，不先建若干轮管理基础设施。

保留有效决定、正文、历史投入和已经取得的资格。未知历史独立循环写未知，不造次数、不清零。任务过大可按业务理由拆结果范围，并保留未完事项和原投入，不能换编号消账。阶段切换／材料补齐／review不是更换地图管理对象的理由。

导入ZIP先锁Owner指定parent及hash，保留有效完整正文；不能按最大版本或mtime选真源。已有Git正本就按exact repo/commit/path使用，不强求ZIP。原始字节确有证据意义但未取得时继续缺失，不从清单复造。材料补齐按11执行，不自动放行业务或运行门。

## 4. 最小工作面与写者

沿用现有等价结构，通常为父README、子任务目录中的 `00_长程推进地图.md`、`01_当前任务.md`、完整 `artifacts/`、`reviews/` 和本轮 `provenance/turns/`。内容足量才按主题拆文件，不复制新版本目录充当current。

普通执行者提交本轮实际提示、完整回答、实质正文／代码和证据，不维护父README／推进图、全局投入或签发卡。管理／审查端顺序单写共享入口、子图、资格和下一任务，依据真实执行者交付而非其自评。专业review若不兼管理角色，就提交review让管理者接收，不同时多写总图。

管理与审查可以一聊天；如果其参与候选形成，不能由切换称号制造fresh。运行端只机械接收、核验和投递，不补业务路线。一个完整任务跨A/B/C仍使用同一图；独立并行子任务可以子图，共享依赖在父入口可见，不强制所有用例先造三张图。

## 5. 地图应让人实际理解哪些东西

开头用业务语言交代完整目标、Owner重要用词、当前所在层和最关键未解决问题。首次出现的“复杂度”“两路”“可用”“完成”等词说明真实含义及来源，不能用状态码或身份表开篇。

按**实质结果**组织工作线。每区说明它在市场／工程中解决什么，已有具体结论和实物，当前候选／已审／已实施／已运行／已接受分别到哪，最重要剩余问题及后果，直接依赖／消费者，下一结果和责任，以及exact证据。非焦点区域不能只写“其余scope保持”，要有可继续比较优先级的信息。代码被要求返修，不抹去已写代码；资格降低单独说明原因和影响。

保留完整审查循环的候选／review／修订／复核对应，历史不明写未知；阶段离站必须有实质条件。记录关键路线转折：原来做到什么、什么新证据改变判断、什么保留、为何回到哪层、何时接回主线。Git保存所有历史，不替代当前路线所需的这段解释。

保留少量最高损失风险、真实Owner问题、可并行未阻断工作、下游正在使用的冻结版本，以及最新有证据的路线。路线理由比较错误解释和返工风险，不以文件更多为理由。篇幅大就按真实区域分层；不靠删除未知和未完范围、复制全部规范正文或机械多表控制篇幅。

## 6. 条件性工作量及事实分账

Owner或执行AI的预期要有来源、条件和起止范围；明确是顺利情形估计、滚动预测还是已发生事实。具体任务拆分和审查次数由负责AI现场判断，本方法不预分几轮。后续事实推翻顺利条件时，保留原预期，说明新增工作与调整，不悄悄改目标。

实际投入来自问答／执行记录，区分主体、独立审查、返修、材料／工具工作。失败有成本但不增加完成量，重复收取不双计，换聊天／任务编号不清零。Pro回合、Codex执行、构建次数、机器时间和routine批次不混算；未知不造小时或人日，共享工作不双计。

剩余量根据剩余实物重估，不只是原预算相减；不要求每轮强写数字。明显偏离时实际调整工作安排、范围划分或执行方式，不能靠无限后移预测维持忙碌。预期不是验收条件，更不能删业务scope或强制PASS。

## 7. 每次增量怎样写回完整图

执行者交成果后，管理者核对上次接收后的新正文、代码、审查、运行反馈，连同Owner／规则变化。先判断本轮改变了哪个区域的结论、方法、资格、依赖或路线，再更新该区与受影响共享说明，保留其余区域。必要时说明对某区无影响的依据，不能把最新报告整体覆盖进去。

`01_当前任务.md`是已签发问题，不是Builder建议池。普通执行者在自己的交付中说明完成或中断，管理端在核实后更新卡。Builder NEXT_ACTION始终只是提案；新里程碑／路线由有权管理／独立判断形成，不能通过初始化地图绕过离站挑战。

新规则或Owner纠正本身也触发对活动图和已接结果的检查，不能因为没有新业务文件就skip。旧判断失效时只更新受影响关系，不能复活旧pending、旧分支或旧NEXT_ACTION。

## 8. 真实引用、唯一正本与消费版本

稳定路径原位写，文件头语义版本和Git字节版本分开。一个活动目录不代表所有下游都读moving main；消费固定 `(repo, commit, path/section, 使用资格)`。不兼容修订明确影响哪个下游并重新交接，不要求全任务重跑。

需求／工程成果链接完整正文和具体修订；代码进度链接实现仓提交、文件和符号；构建／数据链接实际版本、配置、输入范围、命令、日志、结果和未执行项；review链接被审版本、finding、裁定、修复和复核。旧代码测试不自动证明新版，发布回执不替代业务输出。相对链接在同提交解析，历史／外仓用exact，不写latest。

提交前不能预写包含自身的commit；同批正文用相对链接，提交后机械回执给输出SHA即可，不产生递归提交。Git历史不代替语义连续性：KEEP、修改、完整移动、明确删除都有依据；冲突改旧正文，不只追加“新版优先”。不以治理之名清理档案或整体改名。并行／破坏性试验用授权分支，不用多套current目录冒充隔离。

## 9. 发布与管理接收是两个可恢复的事务

普通执行者提交自己的实物和完整问答，按11远端回读。管理者随后将对应review／地图／任务和接收记录一致发布；管理本人同时做实质审查时可同批交这些管理产物。**不再要求普通Builder把全局图和业务正文一起改。**

跨实现仓和材料仓不能假装原子提交：先确认实际代码ref，再在材料工作面引用该版本。中间失败只补缺失发布／记录，不重新实现。没有新事实不造空commit。发送前核对所给输入是否仍对应当前卡，已交／在途状态未知时先查现场，不盲目重发。

用可检测并发方式提交，非force更新ref；提交后fresh读取确切远端入口、完整问答、本轮必要正文和引用，不只确认commit存在。失败报告实际停点、未发布改动和恢复点；不把ZIP同等宣称为已发布事实。

## 10. 验收地图和后续派发

机械核对：exact引用、非空完整内容、受保护工作区未静默消失、已知投入未归零、证据版本对应、管理接收与任务一致。重要结构恢复／意图变化／阶段切换用10的新读者检验判断解释忠实，不能靠字数、关键词和机器PASS替代。

可执行入口及输入合同见 [12](12_管理接收与地图校验.md)。接收失败时实物继续保存，只挡依赖错误地图的新派发，并向具名管理角色给确切输入和实际修复任务，不重做业务或冻结无关线。已有授权任务是否已在途先查实际运行端。

检查器只有被真实接收／发送入口调用、失败转管理修复时才构成执行约束。它不等于已经部署routine或Git保护，也不能判市场语义／实际审查独立性。首次采用要记录真实执行端版本和一次接续结果；不足时明确边界，不能仅因规则提交就报告维护自治成功。
