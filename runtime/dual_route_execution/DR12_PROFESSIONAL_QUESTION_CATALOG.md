# BI-01：具体特征专业工作与来源索引（候选）

## 1. 专业主轴

新专业任务以具名已实现、能够取得实际数据的特征为观察对象，围绕**初始合理参数、特征展示方式、aidata 实际制图、特征正确性和普通投资者正常解读的检查分析**开展工作。四项可返回迭代，**不是 S1→S2→S3 或四个固定签收阶段**。

- [基本输出表达](../../professional/feature_observation/01_OUTPUT_BASE_FORMAT.md)
- [初步实施细节](../../professional/feature_observation/02_WORK_DETAILS.md)

U2/U3 原设计和历史输入只是当前具名特征需要时采用的上下文，不再作为完整观察目标。

## 2. 专业 mode 与工作内容

当前协调配置使用统一候选 mode：**FEATURE_OBSERVATION**。这不是四项工作各一轮/一关的意思。

| 工作 | 核心内容 | 初始成果 |
| --- | --- | --- |
| 初始参数 | 了解含义、输入输出及参数层次，考虑第一轮参数 | 具体采用的配置和初步理由 |
| 展示方式 | 明确画哪些必要信息，文字解释图形，考虑单/多品种 | 初步展示方案 |
| aidata 制图 | 判断长期概览/大中小是否合适，再实际配置绘图 | 真实图与对应数据、读图说明或具体缺件 |
| 观察分析 | 检查正确性及普通投资者对真实市场的正常解读 | 观察认识、疑问、反例和需要返回之处 |

结果格式用于表达已做实质，不要求每轮四项全部完成。重要的格式外分析应保留。

## 3. 管理、审查与局部研究

- M-START：只在新 Owner GO 和合法 BOOTSTRAP 后签发真实地图、任务、Binding。
- M-REASSESS：根据实际成果、未完和重要变化安排后续。
- M-CLOSE：判断是否有据接收、继续或待决；不用图/字数代替完成。
- INDEPENDENT_REVIEW：只在具名授权和真实审查能力具备时开展，不自动通过。
- 局部 Case：可按真实问题开展，不能未经授权缩掉完整未完范围。

## 4. 读取与交付

source_reads 按有权版本指定准确 commit/path/selector，专业者真实取得本次特征实现、结果与参数。历史 V2 04/05/06 可按需引用，但不能自动引入旧 S1–S3、固定 ZIP 和 U3 四束的硬要求。

Worker 按真实工单使用 aidata，确需修改其工具时在 aidata 自身独立分支处理。管理、执行、Worker、操作端的通用协议继续适用。**新任务当前没有 Owner GO、正式 run、Binding 或已采用 Workmap，不得派发。**
