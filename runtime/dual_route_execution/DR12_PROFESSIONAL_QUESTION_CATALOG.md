# BI-01 V2 专业问题与来源索引

## 1. 本轮业务主轴

当前专业工作只用 **S1 确定观察对象 → S2 使用 aidata 形成图及同源数据 → S3 给观察想法**，S3 需要继续观察时可回到 S2。题号只用于有权任务和接续，不代表新增角色、写权、手机派发授权或新 Gate。

**完整目标：**先核 rb、i、hc 中 U2 共同机会簇位置是否合理，再核这些位置上 U3 四方面能否辨别品种是否好做。具体算法、字段和数据来源必须以真实 Source/Method 绑定为准，不凭本题库猜测。

## 3. 管理、审查和局部问题

- M-START：从实际 Owner GO 形成真实管理地图、任务和签发；没有现行地图可合法先 BOOTSTRAP。
- M-REASSESS：重要图与数据结果、设计反证、Owner 反馈或到期投入复看时，对完整目标作新安排。
- M-CLOSE：检查完整目标与所有未完成处，决定真实接收、继续或有据等待。
- AUDIT / INDEPENDENT_REVIEW：仅凭明确审查权限和真正覆盖的专业方法评价，不以管理认可冒充独立检查。
- CASE-...：有真实业务必要时的具名局部研究问题。必须保留 S1–S3 总目标和任务的全部剩余，不能因为局部 Case 完成而主动收工。

## 4. 源读取和真实交付

管理/专业任务须锁实际来源 commit、path、selector，`source_reads` 选择本轮必须读的完整专业方法和业务 Source/Method，不以本题库或名字替代原文。完整业务目标和相邻依赖保留，实际事实、图、数据、反证、回交、继续/停止条件均以本 run 真结果为准。

默认情况下不用 AI 小范围验算；它只是在特征没有正式实现、且真实输入/方法合法可得时的特殊参考措施。Worker 必须用 aidata，不在 observe-iterate 另造 CSV 制图库。图形生成成功不是观察结论完成，只有文字报告但没有 Owner 可核验图也不算可审阅交付。
