## 2. 专业 mode 与工作内容

当前协调配置使用统一候选 mode：**FEATURE_OBSERVATION**。这不是四项工作各一轮/一关的意思。

| 工作 | 核心内容 | 初始成果 |
| --- | --- | --- |
| 初始参数 | 了解含义、输入输出及参数层次，考虑第一轮参数 | 具体采用的配置和初步理由 |
| 展示方式 | 选择必要信息、K线主/附图和时间状态表达，以正常Uplot/CAEGraph真实重新画通、测交互并修订 | 实际可交互Notebook和配置、专业判断，交管理Pro接收 |
| aidata 观察交付 | 消费管理Pro已认可的工作2适用画法，以aidata实际组织观察节点、平台图和正式数据 | 同run平台可打开的report_url、board正式切片/索引/delivery，交管理Pro接收 |
| 观察分析 | 在管理Pro认可工作3相应交付后，基于同节点正式数据和必要图形检查正确性及投资者正常解读 | 有来源的业务认识、疑问、反例及必要返回修订 |

结果格式用于表达已做实质，不要求每轮四项全部完成。**无依赖可并行，有依赖须先交付并经管理Pro认可才派发下游**；这不是四个固定阶段Gate。重要的格式外分析应保留。

## 3. 管理、审查与局部研究

- M-START：只在新 Owner GO 和合法 BOOTSTRAP 后签发真实地图、任务、Binding。
- M-REASSESS：根据实际成果、未完和重要变化安排后续；涉及工作依赖时明确上游接收及下游放行范围。
- M-CLOSE：判断是否有据接收、继续或待决；不用图/字数代替完成。
- INDEPENDENT_REVIEW：只在具名授权和真实审查能力具备时开展，不自动通过。
- 局部 Case：可按真实问题开展，不能未经授权缩掉完整未完范围。

## 4. 读取与交付

source_reads 按有权版本指定准确 commit/path/selector，专业者真实取得本次特征实现、结果与参数。历史 V2 04/05/06 可按需引用，但不能自动引入旧 S1–S3、固定 ZIP 和 U3 四束的硬要求。

Worker 按真实工单使用 aidata，确需修改其工具时在 aidata 自身独立分支处理；管理Pro按受限工单委派接收核验时，Worker只交实际现场证据，不能作业务认可。管理、执行、Worker、操作端通用协议继续适用。**没有真实Owner GO、run、Binding或Workmap采用的新任务不得派发；已启动的BI-01-FO-01按其真实运行记录接续。**
