# Mission A：判断业务需要的表达与实现复杂度

执行修订：`2026-10-09-input-boundary-and-expression`。本方法服务完整业务合同，不替代 A 建图、局部细化和 MapRevision 正文。协调者传递既定要求，不替 A 判断业务。

## 1. 输入起点与三项联动分析

本平台的跨用例完整约束见[输入与分工参考07](../../platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/cross_language/07_cross_language_product_handoff.md)。A首次建图/局部合同及审查应实际读取其业务相关内容。

**从 K 线起步的特征不需要涉及 Numba，直接在 FRP 中形成和组合。**从完整半秒 tick 起步时，Numba 完成必要的密集计算、基础检测和充分稀疏化，能够消费这些材料的后续工作尽量放在 FRP。混合输入只让确需 tick 的支路使用 Numba。模糊控制器在 FRP 表达。

A分别回答并联动修订：输入及计算分工；FRP内普通滤波器/函数/基本Reflex与必要CEPS表达；业务单元与DSU资格。三者不构成 Numba→Reflex→CEPS→DSU 的升级阶梯。业务复杂度不按输入频率判断，K线可以形成复杂过程，tick稀疏结果也可以形成普通完整Feature。

## 2. 比较的实际路线

比较既有滤波器体系＋普通 Reflex 能充分清楚表达的工作，与需要 CEPS 等正常复杂表达的工作；分别对应同事 feature-production-agent 能力和本体系 Mission C 的适用方法。A给业务表达理由，B核真实平台和接收能力，方法路线与执笔者/仓库/任务粒度分开。

普通 Reflex 有 Event/Dynamic/Behavior、采样和状态，可以形成完整 Feature、正式结果、历史与消费者。复杂任务内部普通函数保持普通，普通 Feature 也可供上层 CEPS 消费。不得因有状态、方法长、返回类型、保存需求或控制器就自动增加 CEPS/DSU。

需要真实过程协作、独立推进/结束、局部替换和递归组合时，认真采用能清楚保留这些关系的表达；不能把复杂关系藏进总函数后声称普通足够。无需证明普通代码在计算能力上绝对无法实现，也不为展示复杂度凑处理器。滤波器体系指实际任务和方法，不随意挑一个滤波算法顶替业务。

## 3. 从完整业务形成链识别需要

恢复 source/measurement/fact/Feature 及上层解释，说明合法输入、当前方法程序、输出和消费者；什么材料改变判断，读取哪个时点状态，何时修订/结束，未知和合法空分别意味着什么。现有 Book、DSU、controller 只是候选，名称不要求原样建设。

对连续材料参与的承重过程，说明为何必须连续观察、测量/检测怎样形成必要事实与变化，以及后续哪些方法能据此独立继续。核单品种稀疏结果是否足够表达联合关系；不足时指出需保留的联合材料，不把完整密集矩阵交 FRP。

进行中判断所需信息必须按时出现，不能只交最终结果。若不同原始过程被压成相同稀疏输入，却按合同应产生不同后续结果，需补材料或调整当前方法，不允许靠删分支、改频率或让消费者猜来取得充分性。展开后续方法可能反过来改变所需材料，允许受控往返，不先永久固定物理切口。

关键判断给正常或边界情境，说明实际区别和表达价值。没有分歧不编备选；来源不足具名保留；方法欠账不能用复杂度标签掩盖。

## 4. 方法、事件与回看

**方法内部。**展开计算、分支、递归参数和可换子步骤。模糊控制器使用既有业务方法细化要求并在FRP表达；其存在不决定外围采用普通Reflex、CEPS或DSU。方法只剩名称或槽位继续A，不能推B；数值待校准与程序未形成分开。

**事件和状态。**说明多发生的使用、旧状态采样、单写责任、并行/顺序及相互依赖。能独立说明、做错或调整的步骤具名，是否是公共API、独立Feature、CEPS或DSU另判。正常简单状态更新可以直接用基本Reflex；多过程不能压成总WholeState再包事件外壳。

**规模与回看。**说明当前问题要回看哪些事实、起止锚、仍有效和未决义务、结束后只供历史解释的材料。不得为性能删掉有效材料，也不要求全历史常驻内存。多参数实例、同时间多发生、chunk与业务时间、缺席/零/缺失、安静期间的业务计时均按07及合同保留。

B选择具体容器、缓存、索引、活跃摘要、物理清退/恢复、模块和跨语言表示。A可定向查代码或作小见证以澄清表达，不扩成完整工程优化或第二运行模型。

## 5. 业务单元、表达和委派分别判断

业务步骤粒度不等于聊天或任务粒度。一个Feature可以包含多方法多状态；普通完整Feature可独立委派，复杂父任务中的普通helper不为分路公开。

DSU依据业务身份、运行记忆、process、product及实例和组合需要判断；可采用独立/嵌套单元、所属过程的实体状态、普通Feature、局部动作或事件产物。不因进入FRP、记录可寻址或结果要保存就新增DSU。已经由合同采用的DSU须真实落实，但其内部仍可使用普通函数或基本Reflex。

基础结构的价值看其市场含义、形成方法及向上使用能力，不按DSU数、表数或模块数评价。CEPS按真实关系递归组合，不强制只有Local/Global两层；root负责构造连接，不吞具名业务步骤。

## 6. 首版、未知与后续责任

给出当前基本合理、可修改且有理由的版本，保留实际程序、参数语义、来源、不变量、限制和重开条件。普通可逆细节由Pro判断，不要求Owner先分好样本；暂定不能掩盖核心方法空缺。

业务未定继续A；平台事实由B exact RepoFact调查；配置未激活与方法未形成分开。真缺来源只影响依赖处，不用永久Pending替代可完成主体。实施和市场效果由适用后续任务取得，不冒称已验证。

接收方法不匹配由B明确适配，不能统称复杂。代码证明实现事实，不能反定业务。反馈确需改变业务时修原合同和实际受影响部分，不扩成全面历史审计。

## 7. 写回、交接和收拢

首次建图保完整业务，局部细化联动方法、材料、事件、规模与单元。沿现有 task packet/handoff 的 guards、events/materials、major processes、method、engineering freedom 交出适用架构、连续/稀疏关系、不可丢信息、表达及单元理由、具体未决。不得只填Numba/FRP或简单/复杂标签。

A维护业务图与合同；长程安排、预算和后继归管理。有效部分保留，不因复核从零重做。审查既核不必要下沉/密集流进入FRP，也核普通Feature被强制复杂化、真实复杂关系被藏入总函数。复做一个承重形成关系即可发现实质差异，不建设形式化配额。

参考程序与测试是业务见证：先指出待澄清区别，结果回装方法/时间/消费者，已清即停止同构模型扩展。缓存命中、存储恢复、代码覆盖或关键词出现均不能替代投资需求完成。
