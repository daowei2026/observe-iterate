# 固定问题怎样组成连续工作：安排、上下文与管理

修订：2026-10-27-bound-professional-methods。与 [DR12专业取源](DR12_PROFESSIONAL_QUESTION_CATALOG.md)、[DR14输入回交合同](DR14_QUESTION_WORK_CONTRACT.md)共同使用。这里预先规定跨用例重复的组织办法；具体业务答案、边界、排序、权力和投入由有权Pro根据当前用例决定。不得照搬某个例子的分包、固定轮次或CYF专业工程结构。

## 1. 名词与不可相互替代的边界

完整阶段责任、当前集中深入的关联问题和一次实际消息分别处理。完整责任始终保持；深入范围围绕相互影响的方法、材料和消费者组织，一次调用尽力连续推进，不预设完成其中一项即停。减少同时深读的无关问题不等于删业务范围；中间提交可小，但不能长期只交内部零件并推迟主要责任。

**完整目标**：Owner当前授权最终要求交付的全部结果。**工作批**：完整工作中实际形成并交回的连贯业务/工程/实施增量，可以跨多个调用，不能据此设立缩小的实质推进目标。**固定问题**：本次采用的专业义务和本文件的管理题，由DR12定位。**本轮重点**：当前优先处理的位置，只决定顺序，不改变全部阶段责任。**小里程碑**：可观察的实质进展；只在预先指定时触发审查/管理，不天然是一轮聊天或完成停点。**专业mode**：由本任务有权Router与Binding确定具体角色、方法和写权，不由题号代替。

**每次实质推进均以完整做完所属用例当前阶段全部约定工作为目标。禁止预设单个Case、一组局部观察、一个接口/文件或最近修复清单完成即停。**Owner明确的批次与反馈边界依原要求执行，主控不另加逐Case等待批准。实际执行有依赖和写面边界，不能以这些边界取消其他已明确工作；容量不足如实交已成实物，接续仍承担完整未完。

不把问题、业务步骤、表达形态、任务、文件和聊天一一对应。通用机制不自行固定Case、图、Worker工单或管理角色的数量；Owner明确的批次数量由实际任务执行。固定题可组合、拆出具名重问题、定向返回、核适用后复用；不能删适用义务。题库未覆盖的真实必要问题，由有权Pro在原目标内具名补入当前工作，后续维护通用材料，不强塞进某题也不因此开新体系。

## 2. 开始一项任务时，谁确定什么

管理先确定当前采用、已撤要求、已知问题裁定、保全边界、完整顺序和合法写面；推进者完成实际业务／工程，不重做管理已完成的历史裁定。主控只按决定装配和传送，不补业务。缺重型判断时管理定向委派具体问题，不把全部未判事项匿名塞给实施者；已明确且获授权的工作不等全仓审计。

Owner只需完整目标、当前来源、实际权限及未入库的新纠正，不填业务地图和所有方法答案。管理者先实际读来源并独立判断：目标相对旧成果要求改变什么、重要遗漏和错误方向、有效复用及全部重要剩余。现有计划经过核适用仍可用时直接续接，不因采用题库再开启动会。

管理者在整体上看全，当前安排具体到可执行。未有明确观察问题和数据依据时先核本次业务目标及必要输入缺项，不凭空冻结全部未来Case和工单。重大新要求进入M-START；普通检查点不触发M-START。

首段计划至少明确：完整阶段结果、当前顺序、问题及被授权mode、已有结果/全部未完、必要原文和相邻依赖、实际写面/执行者、正常续作/交接/回压、语义完成要求、具体回看条件及条件性预算。结构定位按DR14，专业判断在原正文，不能只填ID。管理从全目标决定工作，不以Builder最新remaining、当前报错或已有投入决定优先级。

管理者可以按真实任务调整下述默认组合，但必须指出影响的输入、结果和仍被保留的义务；不要求为每个正常选择写多方案比较。未经授权不降低完成标准、取消独立审查、放开阶段或改平台边界。

## 3. 本次专业工作怎样进入运行

本段不重复定义专业工作的实质。专业目标取配置的 goal_ref，工作对象、产出、方法和完成含义取本次真实任务及 source_reads 指定的完整专业正文；[professional](../../professional/README.md)只是导航。

专业者按实际问题安排内部探索和返回，保留仍有效的结果。通用运行层不固定专业项数，不要求某个已实现特征或某套完整上游设计成为所有任务的主体，也不把业务产出一一对应为聊天轮次。

没有依赖的工作可并行；真实任务明确要求上游接收的跨工作依赖，须先取得适用实物和管理认可范围。已签完整任务内部的普通步骤不因此逐步增加管理Gate。返修影响已采用产物或下游资格时具名处理，当前重点只决定顺序，不以单图、单Case或填完格式代替完整目标。

## 6. 上下文与读取合同

### 6.1 四层输入与实际读取周期

管理明确当前执行用途，旧任务的历史事实与已撤行动要求分开。历史正文保留，但不每轮作为另一份完整当前任务重载。减少无关携带须使用准确正文和必要相邻关系，不能用管理概述、字段目录或摘要代替正确详细方法。

|层|首次进入|续作|重开条件|
|---|---|---|---|
|完整目标/Owner纠正/授权|直接来源与当前版本必须取得|保留有效内容及定位，不用Builder摘要代替|新纠正/权限改变/原理解可疑|
|当前专业mode完整方法|按原profile完整必读取得，含有效补充/否定/例外|仅在同一上下文已读、内容未变且仍可使用时复用|新上下文/方法版本变/读取不全/无法恢复关键规则|
|当前重点和相邻合同|实际使用前读完整必要正文与版本|定向读diff和受影响正文，保留完整必要前提|对象/方法/时间/产品/消费者变化|
|历史/原始聊天/无关阶段|正常不默认灌入|有明确来源冲突/Owner原话/回修触发才读|按实际source profile触发，记录具体用途|

本修订把profile中的“每次完整读取”解释为每个新的专业运行上下文及材料失效/未取得触发；同任务同上下文满足以上条件不重复全文重载。完整必读集合未减少。切重点不表示可忘记已适用规则；新聊天只有旧阅读回执不等于已取得内容。真实读取、输入提供、自报、未读/截断分别登记；不将主控下载当专业者阅读。

需要重组长reference时由获授权材料维护者处理，**当前正确业务/工程正文禁止任何压缩、摘要替换或仅留历史引用**；补易读地图和阅读位置不能删原细节。普通执行者不得自由删减。读取周期与重点变化不缩完整必读义务。任务方法与案例来源分别锁，出现方法漂移先明确影响，不静默追latest。

### 6.2 按本轮问题限定深入范围

管理深读影响完整判断的原文和产物；需求工作深读业务方法、时间、状态与消费；工程工作深读承重合同、平台事实与工程关系；实现工作深读实际工程、代码、平台调用及消费者；工程师取得同一已定语义并深读现场相关工程；审查者从原依据恢复预期，不仅跟随作者概述。只有实际任务包含相应工作时才采用，不默认加载所有工程阶段。

BI-01专业首次进入时，须读取本次采用的完整目标、方法、产出说明和承重实际输入；需要特征实现、参数或历史背景时定向取得。旧运行Gate/聊天不作为新任务活动结果。Worker 按有权任务定向取所需工具和现场数据，不由本文件预置业务输入。

管理者保持全目标与各工作线真实位置，深入本次影响安排的专业结果、相邻承诺和原文；不能只读执行者待办，也不默认复做全部专业分析。已有结论要交适用范围/证据版本/限制/失效条件。需要重型专业判断且输入尚不存在时具名委派原专业角色，管理责任仍未完。

有实际实现工作时，各方先取得同一正常主线与自身／相邻责任：施工深读相关业务／既有特征／平台，编译深读小修范围和实际错误，实跑读配置／资源／正式链，分析读真实结果和方法／状态，接收回全范围。重点改变不表示可忘记仍适用约束，新上下文按原完整读取规则恢复。

### 6.3 可操作的过载处理

容量、实际截断与材料冲突分别判断；无记录不得宣称硬容量超载，也不设统一文件、题目或 token 上限。冲突先由有权责任者收拢；相关业务过多时调整同时深入范围，完整目标不缩。换上下文按原规则保留身份、成果、完整未完与正确来源，不清零投入或自动取得独立资格。

方法/合同被截断：取得缺失部分，回查受影响判断；不靠先前记忆宣布已读。多项承重未知同时相互影响：按依赖先处理相关重点，保存真实结论和完整未完，继续同一完整任务；不得设为本轮只做这一组。集中任务每次都必须改无关部分：请管理调整执行关系和共享前提，不缩全目标。长期上下文混入多种职责或可靠性下降：按原恢复程序换上下文，保留工作身份和完整实物，不清零、不自动取得独立资格。

没有任务级实测就不设统一token、文件或题数上限。测量只辅助判断，不降低scope/深度。相邻问题适合合并的条件是同合法mode、相同主体/材料、高度需要互相修订、同一交付；独立审查、不同写权、多组无关承重未知不硬合并。

## 7. 管理问题：引用专业结果，按真实决定调用

通用必读：[DR06](DR06_SUBSTANTIVE_MANAGEMENT.md)、[DR08](DR08_START_CONTINUE_AND_RETURN.md)、[管理Harness](MANAGEMENT_METHOD_HARNESS.md)，加DR12所指当前专业方法/原文和实际成果。三题不新增三类Agent，不要求每个小里程碑轮流问全。兼任审查要分别交齐且符合原独立性。

<a id="m-start"></a>
### M-START｜启动、重大要求变化或确有必要的总体重判

直接交已经完成的当前来源采用和旧要求处置；未定问题具名返回，不交推进者重做全部历史裁定。

**直接题面：**从Owner完整目标及本次相对旧成果的改变出发，独立核已有目标解释、结构、方法选择、进度和全部重要剩余。必须预期它们可能局部、不完整甚至方向全错，不能先承认大方向再修细节。依据本次采用的专业义务选择适用问题及工作对象；说明真实复用/不适用/待做，题库外必要问题具名进入当前计划。

整体看全，近期具体。依完整业务地图确定当前处理顺序，说明真实专业 mode、完整来源、相邻依赖、业务/技术写权、交付、审查、管理与预算条件；未来依真实结果才能决定的事项不预制逐轮排程。本次对象及输入由有权任务和实际来源锁定，不继续把旧任务的固定输入或阶段作为默认前置。

**交付：**目标与实际改变、全范围差距、重要前提独立判断、当前计划与签发工作、Owner必要事项、地图/工作量更新、未完管理责任。用DR14定位；仅发下一题不算完成。存在可安全继续的已授权独立工作时，不因管理未完停全部线；依赖未完判断的新路线不能先派。

<a id="m-reassess"></a>
### M-REASSESS｜执行中一项重要取舍

检查已有安排实际改变了什么。若局部循环仍在，当前工作中改变真实后继，而非再发同义的继续提示。

**直接题面：**引用具名专业问题、结果、支撑/反例与相邻承诺，同时对照完整目标和全部重要剩余。判断继续这块会消除什么高后果不确定性，哪些已有足够首版，哪些仍缺核心形成/时间/工程，哪些需要真实材料。不能只证明finding正确就把它排到最高层。明确继续、停止当前深挖、转向整合/接收、改变安排或需要Owner的具体决定与依据。

BI-01依据本次真实研究对象、实际产出和未完安排后继。旧专业阶段不继承；发现具体数据或方法疑问时定向检查并反馈，不擅自重置整个任务。

**交付：**已消除的重要问题、保留/改变的具体安排、当前投入收益、完整剩余受影响位置、新工作/原工作续作、条件性预算更新、相应地图及Owner事项。无变化可引用现有有效内容并说明依据，不造新的问题数量或比较表。

对本次专业产出和后续任务，管理者明确哪些判断还需深化、哪些结果已可信、哪些需补方法、数据/图或技术核查；对实际要求接收的上游成果须明确接收或返修、准确引用、可消费范围及下游是否可派；不能因工具或来源辅助循环丢失业务观察目的。

<a id="m-close"></a>
### M-CLOSE｜实际成果收拢与完整终点检查

已否技术任务退出剩余，不列未来必做；原业务未完保留。部分改动和局部源码通过不得扩张成全包保真或完整阶段通过。

**直接题面：**对照完整目标、原scope和计划，说明哪些已形成实质结果、哪些仅candidate/局部证据、哪些重要义务从未被提起。核对应题目的形成、运行/工程、整合、接收及独立审查是否真正发生，按完整链检查不隐藏上游/下游。分类剩余为真实业务判断、主要工程、明确实施/整合、必要来源/权限、验证/接收，并结合这些事实给条件性追加投入与下一安排。

依据当前有权完整任务收拢：真实专业认识、规定的交付实物、必要技术结果、真实依据、争议与 Owner 事项及后继。局部结果不冒充全项完成。

**交付：**可读业务进展/真实Git实物、完整未完、资格与限制、原预期/新预测/已知投入/偏差原因、收拢决定和直接后继。只给未来待办或“不保证几轮”不满足预测责任。历史投入未知保留未知，当前剩余仍尽量预测，不把今天再需十多轮当新起点。

对已签阶段进行原目标、真实产物、已核事实、专业解释与阶段接收的全面核对；技术完成、执行自查、独立审查、管理Gate及Owner决定不能相互冒充。

### 专业审查与管理的组合条件

审查固定问：确切成果是否回答被委派专业问题，原义务/方法是否落实，核心判断复做及反例怎样，finding实际影响何处。探针、独立审查和管理资格分别保留。相同材料高度复用、判断负担可控、权限/独立性相容时，可同轮审查并作必要管理接收；重型审查和重型全局重判不强合。完成局部审查不关闭尚欠管理。

## 8. 何时介入：三种触发，主控不裁业务

管理者签发完整工作时定义具名触发，绑定原题、实际成果条件、接收者、消息正文和是否影响继续。详见DR14。

1. 实质里程碑：例如具名完整产品形成链或代表性接收反馈。实际任务要求接收的跨工作依赖，须经管理 Pro 核实完成、认可范围后才能签发下游；普通内部步骤不据此另设Gate。专业者报告事实和证据；小测试/单commit无自动管理资格。
2. 重要变化：Owner纠正、核心前提被否、跨任务影响、真实方法遗漏或任务形状错误。专业者/审查者按原权力识别，管理可主动抽查完整目标；不完全依赖Builder自报。
3. 本批投入复看位置：在计划中给有条件的有效调用计数或实际时间界限及从何处起算；触发复看，不强制完成/停工/缩范围。达到前一直未形成里程碑也能唤起管理。没有可信计数时报告缺口，不伪造数字。明确采用`WHILE_WORK_ACTIVE`时，这个已定间隔在完整工作ACTIVE期间持续承接下一段复看；一次管理只结算当前段，不能因RETURNED/CONSUMED让看管消失。管理者可按实际成果调整间隔或结束关系，主控不得自行改数值。

同一里程碑+投入信号落到同一决定合并一次；已完成/在途按当前段去重。当前专业主动作、已签独立接收和到期非阻塞管理是不同责任，可并存；主控可顺序投递给不同聊天，不承诺后台异步能力。持续EFFORT沿原起点按间隔倍数形成下一段责任，累计投入不清零；普通commit不触发，PAUSED、合法交接或完整接收时不继续。管理未完成由同一管理work接着做，旧路线不因返回CONTINUE永久免责。

## 9. 新 run、真实成果与反馈怎样接续

新 run：真实 Owner GO → M-START 依据本次完整目标签发任务、地图与 Binding → 专业执行在已满足依赖的范围推进，按实际工单使用 Worker → 原签发 Pro 消费 Worker 结果，管理按任务接收适用专业成果并安排后继 → 迭代研究、返修及完整收拢。专业产出不是固定消息轮次或自动增加的Gate。

新任务的身份、Owner GO、Binding/Intake及现场状态取本次真实记录，不能由方法文件预填。另一运行的 R/GO、Workmap、Gate、专业成果与在途不自动取得新任务权限；历史资料按需带准确来源使用，不成为默认固定输入。准备与真实启动分开。

### 已发现错误设计、结果或工具时的定向修订

本节只有在**这次 BI-01 真正观察到具体问题**时才适用；不继承 CYF 曾撤销的哈希、私有发布或 Host 设施作为新任务。

1. 先指明原 Case/Source/Method/As-Of 与哪个实际结论、资格或消费者受到影响，区分业务设计问题、数据身份/时间、计算错误、缺失和真实市场现象。
2. 由有权角色对具体方法/任务作保留、返修、撤销或待证决定；可信未变的专业正文保留，不用一次错误全线清零，也不替 Owner 扩权。
3. 确有 Worker 工单才由工程师连续修直接依赖、正常入口、计算与图；执行 Pro 消费真实结果并判断能否形成观察增量，管理 Pro 接受阶段及下一责任。
4. 必要相同 Case 复核及反例检查完成后，按实际影响更新业务观察与下游使用资格；技术修复或代码 commit 不能代替相应专业/管理接收，也不自动开新阶段。
5. 临时定向修复结束后返回原业务目的，已有历史按需追溯，不把失败治理留成永久运行前置。

## 10. 防遗漏与维护

原义务→固定问题→实际成果的对应放现有覆盖图，真实复杂度如共享方法/产品须有承办者和变更消费，不能按ID数宣告全。并行写面及共同定义明确谁改谁消费，不增加运行owner。模型/探针有具名证明问题和结束位置，不能无限追加证明代替正式交付。

原件/权限/材料缺失要有取得/裁定责任和恢复条件；不影响工作继续，终点资格仍未满足。Owner沉默不批准，已给过内容先恢复，不因敏感名词强迫逐项Owner回答。

迁移时保留活动work、在途调用、已做/已审、原任务和原预算；由有权管理接收本版，不单为迁移做一轮业务重审。不覆盖旧有效回交，不批量提高资格。规范正文和实际入口共同更新；投影只引用规范源，同一规则不多头修改。发布不证明本机采用或性能改善。

已否辅助任务必须从当前正文、工作单、前置、验收、后继及只服务它的代码/检查删除，不列暂缓/未来必做；正确内容保持完整原深度，禁止压缩。不能仅在顶部追加强规则而继续执行相反旧文，也不能为消除冲突整章删掉正确细节。维护沿现有文件原位进行，不新建管理/地图/阅读证明平台。
