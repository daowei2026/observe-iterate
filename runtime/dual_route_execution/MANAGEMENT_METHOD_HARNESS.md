# 管理职责与专业材料遵循检查

BI-01 管理方法适配：通用管理职责沿 DR06，专业阶段和 Gate 从 P00—P07 及真实有权任务读取；旧 CYF A/B/C 审查与 Host 施工不在本 Harness 的生效范围。主控使用 Overlay08，不裁业务；机械检查不证明专业正确、实际读取、独立或部署。Owner 已停止旧 I4 试跑，下次新 run 不倒填旧业务成果和投入。

## 1. 完整目标与投入

从Owner完整目的判断全部必要工作，不能只审最近候选。旧路线未独立核适用、阶段/名单替代目标、持续局部漏主体、只交下一步、结果正确却做错原问题，均须修实际判断和任务；不能只补“已考虑全局”。独立不要求故意反对，已有安排合理要放行。

检查管理是否真正改变了任务与后继，还是只重复完整 remaining；最近 finding 若持续支配全部安排而主体不动，须当轮改变实际工作。已知问题裁定、撤销与保全由管理完成，不再打包交专业者重新调查。

对同一仍有效 run，预算按完整终点承接，原预期、预测、实际投入分账，换轮/聊天不清零；Owner 已取消旧 I4 试跑，下一次为独立新运行，不承接旧预算、聊天、Gate 和业务结果，旧记录只留审计。局部成果增长但完整交付没有推进时，检查哪些已有首版、哪些停止深化、哪些必要主体未交。不能靠删scope/审查或隐藏失败提速，也不为控制新增每轮审批/评分。

## 2. BI-01 阶段与角色是否真正适用

根据现行真实来源、阶段合同和有权任务检查实质成果，不把 I1— I6 当作 CYF A/B/C 工程阶段，也不把一次 Pro 回复或技术测试等同完整 Gate。

- I1/G1：观察问题有明确业务价值和所需证据，纯计算节点不能取代业务问题。
- I2/G2：本次 Case 所用 Source、Method、数据、配置、输入范围和实际/确认/As-Of 时点有合法依据；参考方法与正式方法分开。必要原件缺失需具名限制，不能猜参数。
- I3/G3：真实领域结果可读、可追溯与必要复算，输入身份、时间、算法和状态达到具体下游观察所需的资格；只批准可靠的结果范围。局部参考条件满足不等于正式 Cluster/H1 或全链 G3。
- I4/G4：执行 Pro 形成有业务实质的事实观察、增量或无增量、支持反证、合法替代解释和下一问；不能仅复述数值。管理 Pro 根据必要挑战和真实证据接收 G4。
- I5/G5：Owner Pack 能直接解释真实过程、图、支持反证、争议与行动选项；可制图和能审阅不等于 Owner 已批准。
- I6/G6：真实 AI/Owner 反馈被转成具名的下一轮任务、输入输出、Gate、责任或合法等待/停止；一句建议继续不算安排完成。

I4 发现 G3 限制时按实际影响定向回 I2/I3；无关有效工作不全线冻结。执行自查、独立审查、管理 Gate 和 Owner 重大决定保持各自资格。新 run 不得以旧四段 I4 试跑结论作为已通过的当前输入。

## 3. BI-01 专业方法与技术结果

专业方法只从 P00—P07、实际 Case/Source/Method/As-Of、本轮专业来源读取计划和真实 Binding 中取得；路径存在、自报已读或结构 PASS 均不证明方法真的应用。新上下文重新取得承重原文，已读未变且实际可用时允许复用。

管理 Pro 按完整目标负责当前阶段及重要剩余、授权、预算、Gate 和后继；执行 Pro 负责业务观察、挑战、结果解释、自查与合法同工作续作。执行Pro可签有权Worker实施工单；管理Pro在接收时确需Notebook或平台图的实际操作核验，可签有权、限定范围的Worker技术核验工单，技术结果回管理。Worker不签业务认可或下游放行，技术结果、执行Pro专业判断及管理Pro实际接收分别记录。不默认创建CYF编译/Host五段或两个工程路线。

BI-01依赖交接须检查：工作2真实Notebook/配置是否完成并经管理认可，才可正式派工作3消费；工作3平台图与同节点board数据是否完成并经管理认可，才可正式派工作4。接收决定须引用准确成果、版本、范围和限制；Worker现场技术证据不自动替代管理判断，管理/执行角色没有实际打开图不得声称自己看过。

管理复看实际 Case 时应检查：输入身份、方法与时间是否成立；新结果相对原业务基线有独立增量还是仅改善可追溯性；无增量是否如实报告；数据缺失、计算故障、市场现象是否混同。证据必须真的支持结论，不能只凭字段齐全或图好看。专业 Router / 独立审查 Harness 仍为 MISSING/PARTIAL 时不得借旧 CYF 审查方法自签 PASS。

## 4. 回交与实际接续

核原委派、binding、两份RETURN、真实出处和continuation/remaining同源。局部提交不关全目标，兼任职责分别完成；缺字段只补字段，缺实质实际续作。独立按真实参与，旧适用结果复用，新证据定向审查。

核管理已完成已知判断，专业者不代写全局安排；被撤任务不再列为当前执行来源。管理欠判断回管理，专业欠实物回专业，运输缺件仅补运输，不一概退给 Pro。

原主CONTINUE、已签独立接收与到期非阻塞管理分别保留，不能因主续作存在而丢接收；工作/obligation/cycle按段去重，无新回交仍核EFFORT。完整工作ACTIVE且本段复看已消费时，应存在明确的下一段持续复看或等价已承接管理／交接；没有则报告“持续管理安排缺失”，定点补安排，不冻结无关合法工作。采用`WHILE_WORK_ACTIVE`时沿原起点和间隔计算，普通commit不触发，累计投入不清零。管理说停止但后继还要求同样深化，决定未消费；不依赖它的正常工作继续。格式修复不重新派业务。

BI-01 必要专业审查复核真实 Case、来源方法、结果解释与反例，不只看字段、文件或执行者自测。需要补验证时指出当前判断和实际影响，不能由一个问题扩成整类测试工程。测试/proof/抽象/文档/控制材料持续增长而主体和真实链不前进时，管理停止非必要部分并改变实际后继；不能只登记注意轻重缓急。修订和复验须发生，有据不采可选复杂方案。每次正常实施/管理/审查提示有正确分工和主体优先定位；收到、执行、采用分别报告。

检查新 run 当前任务、实际 Binding/continuation 是否准确送达，原回复、附件和返回是否取得，管理复看有无被真正消费。技术补算的成果应由执行 Pro 解释并回归原观察目的；技术修复不等于 G4 或完整 Goal 已完。

## 5. BI-01 成对判断情形（必须由实际有权 Pro 检验）

- 当前候选输入与自身 manifest 一致，但与指定真实原件的等价尚无证据：只能说明内部一致，不得提升数据资格。旧 I4 中同类情况仅可作风险启发，新 run 必须重新取得/核验真实数据。
- 本次参考方法有局部资格，但正式产品的历史条件或发布责任未成立：保留局部事实，不把参考结果伪装正式 Cluster/H1；组外域合法空也不自动证明组外优势。
- 结果仅改进 Case 关联、组织或可追溯性，尚未证明独立投资知识增量：承认组织价值，但需以真实挑战检验 G4 的增量或无增量。
- 当前执行 Pro 有合法 CONTINUE、并存重要 G3/G4 管理触发：继续尚获授权的同工作，但管理判断按已签路由实际回交；不能因 CONTINUE 遗漏管理复看或由操作端编新专业任务。
- Worker 已交真实图/代码但尚无人核结果：只算技术交付，不能升为专业结论；不存在真正 Worker 工单时也不强制创建。
- 地图文件变更 SHA 而管理决定没有实际更新任务/预算/接收：管理义务仍未消费；Owner 速览更新不等于 Gate。
- 真实业务可用首版已具条件就尽早取得反馈与反例；长时间只维护工具/报告却无实际认识，管理须调整实际安排但不删已授权阶段义务。

这是实际专业审查需作出判断的情形，而非关键字检查、每轮打分或虚构的自动测试。未进行专业审查保持 NOT_RUN。

## 6. 失败处理

字段/引用缺失定向补，方法没用/主体未成续作，任务前提错回正确角色，固定材料冲突交材料维护。管理交付缺件必须回原管理责任者，不能套同名repair路线发给专业执行者；业务finding返修仍回实际工程／业务职责。独立receiver必须收到只读接收正文，不能同时要求其编制或修改候选。重复同根因要改变实际安排，不无限同句重发；不让Owner成为普通细节下一步按钮。固定控制材料不由长程聊天每轮重编。无现场发送/模型接收证据不宣称自动化已部署。
