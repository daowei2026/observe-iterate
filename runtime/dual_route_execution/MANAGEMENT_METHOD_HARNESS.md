# 管理职责与专业材料遵循检查

执行修订：`2026-09-29-pro-code-real-data-first`。用于现有管理/审查，职责仍DR06，专业方法仍A/B/C。协调者使用Overlay08，不承担业务语义裁判；结构检查不证明专业正确、实际读取、真实独立或部署。

## 1. 完整目标与投入

从Owner完整目的判断全部必要工作，不能只审最近候选。旧路线未独立核适用、阶段/名单替代目标、持续局部漏主体、只交下一步、结果正确却做错原问题，均须修实际判断和任务；不能只补“已考虑全局”。独立不要求故意反对，已有安排合理要放行。

检查管理是否真正改变了任务与后继，还是只重复完整 remaining；最近 finding 若持续支配全部安排而主体不动，须当轮改变实际工作。已知问题裁定、撤销与保全由管理完成，不再打包交专业者重新调查。

预算对同一完整终点；原预期、预测、实际投入分账，换周期/聊天不清零。局部成果增长但完整交付没有推进时，检查哪些已有首版、哪些停止深化、哪些必要主体未交。不能靠删scope/审查或隐藏失败提速，也不为控制新增每轮审批/评分。

## 2. 任务阶段是否真正适用

查看本轮新增的主体结果回答了什么。A必须增加投资业务含义、形成方法、观察/回看、时序状态或产品/消费者的清楚度；代码/小实验允许，但须说明消除了哪个具体业务未知并写回合同。正确实现下业务等价的缓存、容器、索引、物理恢复不作为A完成前置或主要完成量。不得以关键词禁止状态、事件、函数或必要技术观察。

B必须交主要工程决定、实际方法调用/结果消费、状态/正式产品/两路任务/父组合；设计欠账实际补，不能推给C。计划上游还没代码、尚未build/DBA/真实数据，不自动阻止完整设计接收；必要关键验证与全面未来实现证明分开。

有真实跨层反馈就定向回相应问题，不自动重开全部阶段。发现混写必须改实际任务/完成条件/后继，光换术语或加更高优先级段落不足。保留当前必需义务、有效成果和未来真实验证责任，不能把已知不适用检查暗改成PASS。

管理先分流 A 业务含义、B 承重工程、C 实现和现场工程问题；一次推进不重做全部阶段。原正确方法深度与 A／B 专业地图保留，普通工程选择随已有授权处理。

C 核实际业务源码、两路连接和当前目标的真实结果；B接受不替代C实证。首批实物可早审，合法真实路径尽早运行；不将全场景测试/proof前置，不让局部待审冻结无关施工。必要编译、运行保护、正式读回和结果解释保留；源码、测试程序、现场执行与专业接收分别报告。

C五段主线按业务链作用，不作为新增机器阶段或固定审查轮。B接收不以未发生的C实跑阻断，C则不能以B已接受代替实际结果。

## 3. 专业方法与结果

A原递归Action、函数参数/方法、S1–S3、模糊控制、事件状态、回看、产品/消费者、真实Case、停止和探针继续按原方法；足够首版不无限证明，空方法不能叫校准。B方法构造/调用/参数/结果、状态回看/历史/恢复和消费联动，两路按实际能力，不以有状态或重要内核预分给复杂路线。C按受指派完整主体和四前沿真实施工，诚实最短路径后早运行。

读取看实际用途和产物：路径存在/已打开/自报已读都不证明使用。新上下文不继承阅读布尔值，必读来自mode与任务，已读未变可用者复用。来源不可得与可读未读分开。

C 源码主体和结果分析尽量由 Pro 完成；Codex 在当前完整任务已授自主修通权与合法写面内处理依赖、普通实现、类型状态、生成、存读、接线和实际兼容，无须逐项证明为何委派。真正未定业务、保护面和共享平台公共行为按原责任处理。纯执行单没有源码提交仍可如实交付，不能为满足流程制造改动。当前不默认同时补齐测试程序。

涉及已有Feature核业务含义和实际输出形态及消费；import／配置存在不证明接通。Pro分析真实对象／关系与参数作用，工程师现场对照和复验，各自责任均需实做。

## 4. 回交与实际接续

核原委派、binding、两份RETURN、真实出处和continuation/remaining同源。局部提交不关全目标，兼任职责分别完成；缺字段只补字段，缺实质实际续作。独立按真实参与，旧适用结果复用，新证据定向审查。

核管理已完成已知判断，专业者不代写全局安排；被撤任务不再列为当前执行来源。管理欠判断回管理，专业欠实物回专业，运输缺件仅补运输，不一概退给 Pro。

原主CONTINUE、已签独立接收与到期非阻塞管理分别保留，不能因主续作存在而丢接收；工作/obligation/cycle按段去重，无新回交仍核EFFORT。完整工作ACTIVE且本段复看已消费时，应存在明确的下一段持续复看或等价已承接管理／交接；没有则报告“持续管理安排缺失”，定点补安排，不冻结无关合法工作。采用`WHILE_WORK_ACTIVE`时沿原起点和间隔计算，普通commit不触发，累计投入不清零。管理说停止但后继还要求同样深化，决定未消费；不依赖它的正常工作继续。格式修复不重新派业务。

C 审查复核具体方法及结果，不只看字段、文件和Builder自测。需要补验证时指出当前判断和实际影响，不能由一个问题扩成整类测试工程。测试/proof/抽象/文档/控制材料持续增长而主体和真实链不前进时，管理停止非必要部分并改变实际后继；不能只登记注意轻重缓急。修订和复验须发生，有据不采可选复杂方案。每次正常实施/管理/审查提示有正确分工和主体优先定位；收到、执行、采用分别报告。

检查CURRENT_C_WORK／原续作是否准确送达，普通小修复编是否连续、结果是否有人分析、技术问题解决后是否回原业务目的。局部接收不关完整Goal。

## 5. 成对语义验证（需要实际Pro，不能正则自证）

A小程序区分两种历史解释，应保留并回装；A要求先建设业务等价缓存，应修任务。B缺主要工程决定，应继续设计；B设计清楚仅缺未来源码/运行，应允许按原流程接收。普通Reflex充分时采用同事完整Feature方法，源码仍可由Pro完成；真实复杂协调不可因求快压扁。

C 主体未完却扩写全场景测试，应回到实际业务与接通；已发生具体错误的定向复验应完成，不借后移测试忽略错误。Pro交代码而Codex执行尚未发生，可交源码但不能报运行通过。纯执行任务不强制改源码；合法现场小修按明确授权。局部疑点待测，无关施工继续。平台正常保证的环境不加默认巡查，有具体故障才查。差别用实际判断验证，不增统一评分、固定轮数或测试治理系统。

以上为场景标准，未实际调用时保持NOT_RUN。本地机械测试只证明来源、角色、阶段配置与载荷处理，不证明这些语义判断已执行。原question_work_cases/longrun_handoff_cases及各阶段Harness继续适用；不新建监督平台。

既定业务下的列表类型、Event／状态表示和直接消费者问题，由已授权工程师集中修通并复编；真正改变业务含义或承重设计才交相应责任者。有可信结果即分析，不先无限优化。全空／非空仅支持有限结论，核心对象形成演化与关键参数作用需实际依据。新增要求仅作原Harness场景，未观察不报通过。

新增判断反例：新函数去掉一次存读转换却继续计算摘要身份，职责并未退出；工程包保留名称却混淆两类关系端点，业务未保全；旧理解题改名后仍作开工门，前置未退出；内部新路径正确但公共入口仍走旧机制，正常调用未切换；管理只把最新 finding 加进下一轮并附完整范围声明，仍须改变安排。文件少不自动偷懒，文件多不自动完整，以实际职责和消费者变化判断。上述只是既有审查的判断标准，不新增逐题填写或测试系统。

## 6. 失败处理

字段/引用缺失定向补，方法没用/主体未成续作，任务前提错回正确角色，固定材料冲突交材料维护。管理交付缺件必须回原管理责任者，不能套同名repair路线发给专业执行者；业务finding返修仍回实际工程／业务职责。独立receiver必须收到只读接收正文，不能同时要求其编制或修改候选。重复同根因要改变实际安排，不无限同句重发；不让Owner成为普通细节下一步按钮。固定控制材料不由长程聊天每轮重编。无现场发送/模型接收证据不宣称自动化已部署。
