# 正式委派 Agent、明确接入版与方法借用

执行修订：`2026-09-29-pro-code-real-data-first`。适用 B分派、长程负责人和接收实施角色。同事Agent指同事开发的软件角色，不是同事本人；任务不以同事个人解释、修改、审批或提供机器为正常前置。

## 1. 正式委派实际交出什么责任

确定可以独立交回的连贯结果，指定接收角色、完整输入、实际使用规则、调用范围和交回成果。范围不能只写“实现简单部分”；明确是完整Feature、包装、接线、只读接收检查或已经定义的其他角色任务，以及到源码、编译、包装、运行或集成的哪一步结束。

接收者交回实际文件／代码提交、输入版本、完成证据和未完成工作，不只聊天结论。负责人跟到结果进入整条链，分派本身不等于完成。方法借用时父任务保持交付和验收责任，只使用适用方法，不能声称完整外部Agent已运行或伪造原版PASS。

## 2. 分路和交付粒度

以 DR01 的业务分析为依据：滤波器体系／普通 Reflex 能充分表达的完整特征，可以进入同事现成完整Feature路径；涉及CEPS等复杂表达的工作进入我方Mission C。是否有状态不是分界。业务本来有独立输入输出、消费者和完整交付价值才适合正式委派，不为调用Agent新造公开Feature。

复杂任务内部普通函数由父任务承担，可以借用方法，不因归属C升级CEPS。确有独立委派收益时，另形成明确受限任务，规定模块、调用、测试、父过程接线和发布责任；不能临场要求原版Haskell Agent忽略顶层Fao条件。

两路是能力选择，不是配额。没有适合某一路的单元时说明原因，不人为凑两个包。业务表达、接收支持程度和未细化欠账分别记录，不能把所有不兼容都丢给C。

## 3. 三种实际使用身份

原版委派：冻结档案、输入、权限和条件真实满足原版，按实际角色完成要求判断。

明确接入版：保留适用完整方法，显式调整输入接纳、读取、调度或受限职责，给自身版本和完成条件。使用 [DR07](DR07_FEATURE_PRODUCTION_ADAPTER.md)，不冒充原版team已验收；原runner不支持时不能期待它自动兼容。

方法借用：没有转移独立交付责任，报告借用了哪段及实际作用，不能仅列链接。

每项任务选明一种身份，锁 exact Agent ref、沿用／调整段落、执行者和交付边界。采用的任务必须可读完整A/B，不复制一份可以各自修改的第二业务真源。

## 4. 从哪一步接入

已有完整 A/B→接收投影及核对→指定实施角色→按授权继续包装、验证或交回。不要另让一套需求Agent从粗叙事重做。ImplementationPreparationAgent只从档案与唯一事实准备输入，不替代B的新模块、方法、状态和连接设计。已核实事实、B新设计和真实待决分别交接，不能把to-be伪装成现代码。

完整team涉及分支准备、Haskell、Python、验收、提交和集成，调用范围逐项明确，不让两个调度者控制同一分支及完成状态。只调用Haskell不表示整个Feature已验收；只有源码不满足编译完成。

## 5. 实际执行者与代码指令

方法路线、Pro/Codex执行者、代码仓库／分支和接受权分别指定。两路源码都尽量由Pro编写，包括类型、调用、注册、手写包装和修复；编译、测试执行、真实运行及现场调查由Codex承担。采用同事普通Feature方法不自动把完整Feature交Codex编码，也不改变其完整业务边界。

只有Pro确实做不了或有具体理由不适合的编码才明确委派Codex。已签发完整B任务可直接作指令，不逐函数重问；但简单、工程明确或包已存在均不单独构成委派理由。当前先完整实现业务和正式连接，尽早真实反馈，不默认同步扩写测试矩阵；后续确需测试程序时按源码与现场条件分工。

Pro如何形成完整指令见[DR10](DR10_PRO_IMPLEMENTATION_AND_CODEX_ORDERS.md)，Codex如何加载确切路线、实施、运行及回传见[DR11](DR11_CODEX_TWO_ROUTE_EXECUTION_AND_FEEDBACK.md)。

Codex不能自己从地图选新任务、换路线或以“工程等价”新增源码修改。编译、运行、调查可在既有授权内主动进行；发现需要改代码时回Pro形成指令，不能自行扩展为存储转换、编码解码、阈值或平台修改。使用哪套方法不决定把代码写到Agent材料仓；按B锁定的真正实现仓落地。纯执行任务无需源码提交，Pro写补丁、Codex应用/生成/提交及执行分别说明。

机械导入、归档和版本登记不制造内容接受。原版Owner归档要求与接入版任务授权分别满足，不假造历史handoff，也不把同事本人当必经审批者。

## 6. 接收反馈必须回到实物

接收者指出应交什么、哪个位置不能实施、两种解释的结果差异、哪些已可用和具体需补什么。Pro裁定接受／部分接受／有反证拒绝，不默认下游或Auditor永远正确。

业务／方法缺口回A，平台事实／主要工程／错误分派回B，路径／格式／档案由适配交付修，环境由执行端处理。修订进入正文，重发受影响输入，再次被消费，才算处理。普通执行者保存完整分析与实物；全局地图、接收状态和下一任务归管理／审查端，采用外部方法也不改变这一分工。
