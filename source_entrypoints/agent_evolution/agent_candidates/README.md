## 连续工作与完整目标

固定问题提前说明，具体用例的业务答案、表达与任务组合由Pro依事实判断；题号不等于轮次、mode或Feature。既有工作可能局部甚至方向错误，管理者独立确定必要工作、轻重缓急、首版和收拢，不能只接收最近候选。计划支持一段连续工作，小检查点不自动开管理。

首次无计划使用DR14 BOOTSTRAP，计划/覆盖/预算是管理输出，不要求Owner先分好。旧任务恢复保留parent、成果、已审、未完、预算和在途；不能冒充新建。专业CONTINUE不吞到期管理；责任按work/obligation/cycle去重，无新回交仍核投入。普通专业者有原任务内续作责任，不维护公共长程图；A业务图是专业产物。

## 输入分工、表达和业务单元

共同完整规则见[输入分工07](../platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/cross_language/07_cross_language_product_handoff.md)。**K线起步的特征不需要涉及Numba，直接在FRP形成和组合；完整半秒tick由Numba完成必要密集计算、基础检测及充分稀疏化，后续尽量在FRP继续。模糊控制器在FRP表达。**这些约束跨用例适用，不绑定来源用例拓扑。

分别联动判断输入/计算分工、FRP内普通滤波器/基本Reflex或必要CEPS、业务单元与DSU资格。普通完整Feature可以有状态和正式结果，进入FRP不自动DSU化；复杂内部也保留普通函数。不能以局部tick依赖下沉整个上层过程，再只评价FRP剩余外壳；也不能为修正下沉而把所有普通步骤CEPS化。

A从完整形成方法分析所需材料、进行中变化、联合关系与表达，B核真实平台并落实caller/方法/状态/产品和实际切口，C使用同一合同与锁。三项判断在细化中可相互反馈，无需先永久冻结分界。

## 两路、阶段和工程尺度

滤波器/普通Reflex与必要CEPS表达按业务理由和真实平台判断，不按状态/频率/类型/名词分流。B核同事方法能力，普通完整Feature可整体委派，不预设我方内核与同事外围，不凑路线或实体。内部helper不自动公开。方法、执行者、代码仓和父组合分别说明。

A给业务所需回看、时间、方法和消费者，技术观察服务这些问题；业务等价缓存/容器/索引由B决定。B交可施工设计，缺核心设计继续B，未来实现证据不应反过来阻止设计交接。首版可改，不空方法、不假输入或验证，诚实正式路径存在后尽早真实反馈。

共享资料从[参考入口](../platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/README.md)按问题读，B锁reference/字节与live事实，实施消费同一锁；不另建平台真源。Pro/Codex施工按DR10/DR11，同事接入按DR03/DR07。
