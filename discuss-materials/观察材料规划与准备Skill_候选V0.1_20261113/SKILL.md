# 观察材料规划与准备（候选 Skill V0.1）

**成熟度**：候选、可试用；尚未证明跨多真实用例稳定复用或由 Owner 正式采纳。该 Skill 是专业方法合同，不等于一个 Agent、数据处理特征或独立运行平台。

## 任务与成功标准

目标：**把具体观察意图变成实际可用、可追溯的观察数据材料**，必要时附图；交给后续合理性分析判断，而不越权直接宣称业务合理性结论。

完成“材料准备”至少要求：（1）本次关键材料能实际取得；（2）所需身份、时间、来源、处理口径与观察范围可解释；（3）重要缺项被记录并说明对本次判断的影响。**只完成图定义、给出转换代码或贴一张截图，不等于完成取数。**

## 输入（获取而非无条件向 Owner 索要）

- 观察问题及预期要判断的业务现象；明确哪些是 Owner 直接给定，哪些只是 AI 推导的候选关注点。
- 被观察的特征/策略：业务叙事、预期输入与业务输出、实际处理源码、实现中的输出/状态类型；相关数据与代码版本。
- 现有 CAEGraph Notebook/定义及运行环境、日历、品种/对象、参数实例、数据范围和取数权限。
- 约束：历史真实可得时间、预算、现有可靠性分析的推进目标以及尚未解决的信息。

若某输入可由仓库和实例调查取得，应主动调查；不允许以猜测填充业务字段、实质阶段、已知时间或缺失状态。

## 执行步骤

### 0. 识别任务入口及当前可用资产

- **已有完整 CAEGraph**：优先调查原完整图、源特征、现有数据接口；不把图拆成各 Skill 再重做。
- **需新建图/材料**：按下述方法规划，再复用已有局部绘图定义、函数和处理器。
- **只需纯数据**：可直接使用原特征及确定性后处理，不必为 AI 先生成浏览器图；仍必须交代与观察方法的对应关系。
- **混合页面**：明确哪些内容由 CAEGraph 提供、哪些来自独立 Bokeh/AI Data/其他工具，不能称所有数据都由 CAEGraph 输出。

### 1. 还原业务处理骨架，并双向核对输出

沿真实业务逻辑列出：
1. **业务输入**：参与处理的对象与参照；不是所有细碎技术输入都必画。
2. **实质处理阶段**：阶段输入→判断/更新→形成什么中间结果，及其作用于下一阶段的关系。
3. **业务预期输出**：期望提供什么业务信息、为了判断什么而存在。
4. **实现中真实存在的输出/状态**：正式业务输出、子输出、working-state、调试/绘图用输出及根本未提供的中间信息。

将业务预期与实际实现逐项对照：一致、实现另有中间结果、业务需要但未提供、语义/时间不一致。不要以类型或显示字段相似替代输出角色的判断。

**不以代码中函数个数决定画几层。**优先识别会改变业务候选、资格、时间、对象身份或输出解释的**实质阶段**；极小转换不必单独呈现。为每段记录“为什么看这一层、缺它会阻碍什么”。

### 2. 对每项观察材料作出取舍

逐项标记：
- **必需**：缺少将阻止本次核心问题的可靠判断；
- **有条件需要**：先开展可支持的观察，只有发现某种现象、追问某个原因时再补；
- **可选建议**：有观察价值，但不提升本轮决策或成本过高；
- **暂不准备**：仅为低价值技术细节或与本轮问题无关。

常见默认：重要的输入参照、最终业务输出要考虑；多步实质处理的中间结果应评估观察价值，但**不是每一步都必须画或都必须导出**。为了回答“为什么没有到达最终结果”，通常需向上游补查足以区别不同失败原因的中间证据。

如果重要中间信息尚不存在：先看现有源数据、内部 trace、可读状态、低成本临时导出；需要长期承诺稳定产物时才讨论改变正式特征输出合同。将“建议改进”与“本轮阻塞”分开，参照 [判断与证据表](templates/观察材料准备任务单.md)。

### 3. 对每项数据说明要看什么，再选择处理方法

区分原业务数据和用于直接观察的视图。为每项指定：观察问题、对象身份、来源、字段、时间角色、原值/显示值、是否需要比较/聚合/裁剪/局部基准/几何关系，转换造成的损失。

优先查 [候选方法索引](references/候选观察方法索引与选用规则.md)：
- 多组同类事件 → 高频 S1；
- 历史评价、已知、应用 → S2；
- 同一对象多时间位置 → S3（EAW E2 为第二实例）；
- 局部价格共同基准 → S4（EAW E4 有静态/动态边界）；
- 同一判断的竞争语义支持度 → EAW E1；
- 事件与多分辨率行情共时比较 → EAW E3（独立方法身份仍待验证）。

**不适用时允许不使用任何候选方法。**按手册自拟处理方案，注明新的专业判断是基于本次用例提出，尚不是已有 Skill；不得把“参数换一下”误写成已验证的新通用方法。

### 4. 落地设计：优先既有图和代码，再按最小增量扩展

按优先顺序：
1. 原 Notebook/现成完整 CAEGraph 是否已有对应图层或取数；直接复用。
2. 是否只需修改既有类参数：数据字段、`df_key`、`timespans`、标签、主/附布局、`dynstd` 等。
3. 是否已有特征后数据处理组件或小函数：`FeatDFProcessor`、`FeatADTProcessor`、字段映射、过滤和裁剪等。**这不是重算业务特征**。
4. 是否可以使用 CAEGraph 手册中的已有绘图类、布局类、特征雷达、控件进行组合。
5. 若仍不够：提出具体临时处理/导出方案；确实缺必要能力才提出 uplot/CAEGraph 支持需求或源特征输出改进建议。须说明已有能力不足的证据、受影响观察问题、最低替代方案及成本。

见 [技术使用与执行取数](references/CAEGraph执行取数与验证.md)，不要在 Skill 里复制整份手册。

### 5. **必须实际取得材料：运行、指定观察状态、导出**

依据本次选定的完整图定义和实际数据上下文：
1. 记录代码提交、数据源版本、对象、日历、参数及**加载范围**；运行/复用 CAEGraph。先检查是否会触发昂贵的特征计算、重放或大规模载入。
2. 利用已存在的 `graph.layout(..., plot_roots=..., all_figs=...)` 收集**构图阶段**的数据树和图对象；将数据源、图元、面板、标题、图例及源特征一一关联，不仅记录前几行预览。
3. 若分析需要局部放大/平移之后的值：明确**可见范围**、动态/静态处理方式、实际生效的参数及回调完成状态，取得**对应窗口的显示数据**，并验证其与浏览器行为一致。构建时 `cds.data` 不自动等于浏览器 JS 更新后的数据。
4. 需要原始强度、业务 ADT、成员 trace 等而图已经压缩/丢弃时，**另从源特征或中间输出来补取**。不能从图的像素或显示值逆向猜原值。
5. 如果图未生成、数据没加载或接口不能提供所需状态，报告真实失败和可继续的范围；不得用静态图定义当成“实际取得数据”。

输出数据还应带一份元信息：面板/图层和真实对象的对应、原值与显示值阶段、图例、数据量、实际窗口、基准、取数来源及缺失情况。**图例不等于参数身份**，同一数据源/事件出现在多图元不能重复计为多个事件。

### 6. 质量检查，区分“准备完”与“分析完”

最低检查：
- 必要阶段各自有数据或明确缺口；无事件、有效空、缺数据、历史不足、未确认不混同。
- 关键身份（参数、品种、业务事件）可追溯；多时间标记保持共同身份；不同观测粒度时点与区间的语义不混同。
- 真实源值、后处理值、构图 CDS 与视窗处理后的显示值**标明阶段**，不重做处理，不把截断后的数当原值。
- 时间轴、日历、实际点/确认点/判断已知时刻及数据有效区间符合本次用途；不能把历史评价区间当成应用生效区间。
- 价格基准只作用于声明的关联价格字段；加载范围和可见范围分开；需要时核对 Bokeh 真实模型数据。
- 不遗漏图外必要的业务输入/中间信息，不将截图/标题/图例作为唯一证据。
- 记录真实执行/验收情况，区分合成测试、源码核对、真实取数和业务观察。

### 7. 交接与边界

最终交付：
1. **观察材料计划与阶段清单**：每项为何准备、如何得到、是否必要。
2. **实际取得的数据包/引用**：原值/处理值/图形数据、时间窗、图层对应、验证记录。
3. **缺口及处置**：不妨碍当前分析、限制某个判断、阻塞某个核心判断三类；明确建议、成本和后继动作。
4. **可供后续业务合理性分析的问题**：列出已有证据足以判断什么、目前不能判断什么；**不在准备阶段宣布特征合理或不合理**。

完成状态只能择实填写：
- `PLAN_READY`：方案和来源已清楚，尚未真实取得完整数据；
- `DATA_READY`：本轮必需数据真实取得、核对通过；
- `PARTIAL_WITH_LIMITS`：取得部分材料，明确可分析范围与不能越过的边界；
- `BLOCKED`：本轮核心问题需要的证据缺失或取数不能完成，并记录原因。

这些是**本 Skill 的交付标签**，不是已有 CAEGraph 或业务特征中的正式状态类型。不得用 `PLAN_READY` 伪装 `DATA_READY`。

## 使用注意

- 本 Skill 首要任务是**数据准备**，合理性分析由后续专业判断承担。
- 四个高频候选及两个 EAW 新候选是检索和启发资源，**不是必须调用的固定流水线**。
- 已有图不强制重做；已处理的数据不二次处理；只缺当前不影响判断的中间状态不强制开发新输出。
- 若从新用例发现可复用方法，记录触发问题、输入语义、稳定方法、实现选项、正/反例与迁移边界；未经跨例验证不宣布成熟。
