当前 N 特征的业务目的与观察锚点分析
这次我进一步查了 U2NormalNodeBehaviorFrp 的原始讨论、实际业务方法、输入输出、U2 依赖关系，以及 BI-01 当前已经形成的观察成果。

先给一个关键判断：

当前 N 特征的设计内容已经比较明确，但它希望为投资业务提供的认识，还没有被充分转化为一个能够直接指导看图和迭代的核心问题。

这正是我们现在要补的东西。

一、先还原 N 在业务上究竟是什么
从现有来源看，N 不是为了直接判断多品种谁强谁弱，也不是为了独立识别大拐头或机会簇。

它是 U2 的一个较上游、偏描述性的特征，位于这样的关系中：

价格、尺度转折及转折后的实际运动过程

N：近期价格过程 Behavior

单品种、单尺度、近期已完成过程与当前未完成过程

按需要使用这些描述的下游业务判断

关系解释、运动背景比较、后续业务叙事等

这里有一个需要特别说明的事实：N 是描述性支线，并非所有 U2 关系和机会判断都要先消费 N。当前独立转折关系特征也有不选择 N 方法的正常路径。因此，上图表示可能的使用关系，不是强制流水线。

这在 CYF 2026 年 10 月 15 日的原始交付讨论 和 U2 业务地图 中都有明确依据。

而 N 自身实际做了三件主要事情：

对最近一组已完成运动过程，描述其推进、持续、行程、效率、逆向运动等表现。

将这组近期过程与此前一组过程比较，描述近期表现发生了什么变化。

独立维护当前尚未完成过程的表现，使读者可以把当前正在发生的运动与近期已完成运动放在一起理解。

当前采用的是最近六个与此前六个完成过程，并保留各指标的统计离散程度及 LOO 敏感性。

这说明 N 的核心并非简单地“计算几个运动指标”，因为那些指标在上游单个过程中已经存在。

N 真正额外做的是把多个先后发生的运动过程组织成一个持续更新的近期行为描述，并把当前尚未完成的过程放进这个背景之中。

这是它区别于上游单段过程量测的关键所在。

但还需要继续区分：能够形成这样一份描述，并不自动意味着这份描述在业务上已经足够有意义。

二、追查原始意图后，一个很重要的发现
我认为这里需要区分两种“为什么存在”。

第一种是工程上的存在理由：为什么要把 N 单独做成一个特征？

CYF 10 月 15 日的讨论很明确：完整 U2/U3 很大，需要从已经具备可靠输入的上游部分开始，逐项形成可以运行、可以读取、可以观察的具体特征。

N 适合沿着既有价格过程继续实现，而且能够作为具有历史状态的特征独立交付。

这是合理的实施理由，但不能替代投资业务上的存在理由。

第二种是业务上的存在理由：为什么需要这种近期行为描述？

这里的材料要弱一些。

在 10 月 21 日的讨论中，CYF 自己也明确担心：N 过于上游和平凡，交给投资业务人员观察，到底能产生什么有价值的认识？

当时形成的建议是，观察它能否有效表达单品种近期过程，以及哪些重要信息被统计压缩掉了，而非承诺它已经具有独立投资解释力。

我目前没有从核查材料中找到一项已经明确确立的、专属于 N 的投资场景，例如“为了判断某种明确的拐头风险，所以必须采用这两组六段统计”。

因此不能倒过来，凭 N 已有的六项指标和两组窗口，给它编造一个已经被确定的业务目标。

这意味着，现在的观察迭代其实还承担着一项更上游的研究任务：弄清楚这种近期过程 Behavior 是否值得独立成为一项业务表达，以及它应当承担哪些业务责任。

这与先假定 N 的设计目的完全正确，然后逐项找它实现得是否合理，是有本质区别的。

三、我建议暂时采用的核心业务锚点
结合现有设计，我认为可以先形成这样的候选业务目的：

对于一个品种在某一尺度上的价格运动，利用最近已经完成的一组运动过程，形成对近期运动表现及其变化的概括，并结合当前尚未完成的过程，帮助理解这个品种目前的运动与近期背景之间的关系。

重点检验这种概括能否保留值得认识的市场差异，而不是把关键差异压缩掉，或者把没有业务意义的统计变化误认为市场变化。

这里我刻意没有使用“预测拐头”“识别强势品种”这样的下游目标。

也没有把“趋势状态”作为唯一目的，因为 N 当前的六项指标并不完整表达趋势方向、发生顺序或不同品种之间的关系。

这个锚点目前应该是待业务观察验证的目的假设，而不是已经成立的 N 正式定义。

如果后面的观察发现它确实能够形成有用的近期运动画像，就可以进一步明确其独立业务用途。如果它主要只是方便下游取得一组统计事实，那么应当把它定位成描述性输入，不强求其独立解释力。

这种变化是真实的统计量变化。

但它是否等于我们关心的市场运动状态变化，需要单独观察。

例如，最近六段包含了三个比较顺畅的上涨过程和三个比较顺畅的下跌过程，中位数效率可能很高。

这和连续六段主要向同一方向推进，不是同一种市场运动。

N 的聚合统计未必能区分它们。

那么真正要判断的是：

近期 Behavior 的业务目的，是概括各段运动的典型表现，还是进一步表达这些运动如何在方向和时间上组织起来？

如果只是前者，当前设计可能合理。

如果需要后者，仅修改六段这个参数，未必能解决问题。可能需要保留或另行处理方向、顺序、过程之间的关系。

因此，这是一个目的和设计结构的问题，不是先去判断六段应该改成四段还是八段。

2. 当前未完成过程为什么要和已完成窗口放在一起？
这也是关键设计。

已完成窗口描述的是一批完整过程的统计表现；当前 Working 描述的则是一个仍在发展、其长度和内部路径会不断变化的过程。

现有实现并没有直接计算统一的“Working 相对完成窗口偏离程度”，而是把它们作为不同部分保留在同一 Behavior 中。

所以观察时不能默认两者已经可直接比较。

从业务角度真正值得研究的是：

已完成的历史过程为当前运动提供了什么参照？当前过程表现出来的不同，是有意义的变化，还是因为它还没有走完而产生的自然差别？

如果这个问题能够回答好，N 可能形成很有价值的持续过程描述。

如果很难回答，Working 与两个完成窗口放在同一个特征里，也许主要体现了数据组织上的方便，而不是已经形成了完整的业务解释。

另一个细节也很说明问题：六成员中位数的 LOO 绝对影响，在成员全部有效时会全部并列。这是偶数样本中位数的数学性质，不是一个能够直接指出哪个过程最重要的分析方法。此前 R33 已确认这个边界。它提示我们，某个字段即使计算正确，也不一定具有原本期待的区分能力。

我认为可以先围绕下面几种真实情况展开。这里使用 CYF 之前已经计算并核对过的 N 结果，而不是凭空构造市场结论。

它们目前只能作为候选业务观察位置；正式工作4仍需相应平台交付获管理认可。

如果实际 K 线显示近期完成过程确实比更早的过程顺畅，而当前运动突然开始频繁折返，那么 N 就可能提供一种有意义的认识：近期历史运动表现与当前正在发生的运动已经出现明显差异。

场景 B：历史很差，但当前 Working 很顺畅
螺纹钢 rb 在 2016 年 5 月 30 日的一个真实样本中，最近完成窗口效率约为 0.0105，此前约为 0.190，而 Working 效率约为 0.842。

它与场景 A 恰好形成相反的结构。

我们需要观察，这是否表示市场运动正从反复折返转向相对顺畅，还是由于新的未完成过程很短、尚未暴露逆向运动。

如果后面有持续发展的市场过程可以对照，还可以进一步区分：N 当时提供的是有用的变化线索，还是一个大量发生但不具持续解释意义的瞬时差异。

这里不需要要求 N 具有收益预测能力，但需要检验它表达的东西在市场过程中是否真的有可理解的意义。

场景 C：统计很漂亮，但市场过程未必漂亮
铁矿石 i 在 2021 年 10 月 21 日有一个已核对样本，六段效率分别为：

1、1、0.1628、0.6723、1、1

中位数为 1，MAD 为 0。

这是不是说明最近的运动过程总体非常顺畅？

从统计定义看，中位数确实为 1。但其中四个单向短段足以形成这个结果，不能据此证明近期市场具有很好的单边可做性。

这种情况值得用实际价格图核对，因为它能够直接检验：

一组过程的统计概括，与投资者对近期市场运动的整体感受之间，究竟可能有多大差别？

如果差异明显，后续再判断是 N 的设计要修改，还是需要明确限制它能表达的内容。

这三个样本来自 R33 基本合理性接收的第 5.3 节。原来的样本选择主要服务于实现和数值边界检查，不应把它们当作已经完成了独立的投资业务观察。

六、这轮观察最终应该产生什么有价值的业务成果？
结合前面的分析，我现在认为，N 的观察结果最值得争取的并不是某一组最终参数，而是对下面这个问题形成有依据的答案：

这套近期过程描述，在市场认识中到底能够承担什么业务职责？

可能形成三种不同的结果：

观察后的认识

业务上的产出

N 确实能有效表现某些近期运动性质及其变化

明确这些业务概念、适用场景、使用方式以及相关参数

N 只适合表达基础统计事实，不足以独立形成重要市场解释

明确它作为描述性上游信息的职责，区分哪些进一步认识应交给下游

N 的部分统计组织无法保留其本应表达的重要差异

提出具体的结构或方法修改，而不仅是调整参数

这里还有一项很重要的判断：即使 N 不能独立产生有价值的投资认识，也不必立即认定它没有价值。

如果下游实际需要一种标准化的近期过程描述，那么它仍可能具有复用价值。但这种价值要通过具体消费者及其业务问题来证明。

反过来，如果下游既不需要这份概括，投资者看图也没有因为它获得更清楚的认识，那么就应该考虑减少 N 的业务责任，甚至简化这部分设计，而不是继续调出一组看起来更漂亮的参数。

我认为这才真正回答了你最初担心的“最后会不会白做”。

观察迭代不仅应该改进特征，还应该有能力发现：某项既有设计是否值得继续存在，以及应该以什么形式存在。

七、对当前 BI-01，我建议接下来怎样实际应用
我也核对了当前最新的 BI-01 管理 R0043。

截至这份 10 月 25 日的报告，N 的参数来源、图形设计、指定知识时点的回看与正式资料关联已经推进得比较多，但正常共享平台还没有完成实际接入和页面核验，所以正式工作4尚未签发。

已有的 rb 确认前后以及 i 缺价恢复等场景，主要解决的是时间、Life、数据可用性和展示正确性问题。它们很有必要，但还不能代替上述以业务目的为中心的市场观察。

因此，当前最好把两种工作区分开：

正在进行的专业任务继续处理已经确定的平台交付与真实依赖，不需要为了这次讨论推翻或重做已完成内容。

后续业务观察的核心方向则应明确为：先通过市场上重要且具有区分力的过程变化，检验 N 对近期运动背景及当前运动的表达价值，再决定具体要修改什么，以及哪些问题应由下游继续处理。

尤其值得在观察中同时保留一个对照：如果不使用 N，只看原始 K 线、尺度转折与单个过程的已有指标，我们已经能认识什么？加入 N 后，又让哪些认识更清楚、更稳定或更方便后续处理？

因为 N 本来就是对既有过程信息的再组织，它不必产生新的原始市场信息，但需要证明这种组织本身有什么业务用途。

八、这次分析后的阶段结论
我认为现在已经可以把 N 的讨论推进到一个比较清楚的位置：

可以确认的： N 的实际职责是描述单品种、单尺度的近期完成过程、近期相对变化及当前未完成过程。它属于 U2 的上游描述能力，不是独立的机会簇或重点品种判断。

目前最合理的目的假设： 为投资者和确有需要的下游提供一个持续更新的近期运动背景，让当前运动可以在这一背景下得到理解。

尚未得到证明的： 这种背景是否保留了投资者真正关心的市场差异、是否优于直接使用原有过程信息，以及哪些下游判断实际需要它。

下一轮观察最值得获得的结果： 不是笼统的“N 基本合理”，而是弄清楚“N 在什么样的市场情形下能够形成有用的运动认识，在什么情形下会造成误解，以及哪些认识根本不应由 N 负责”。

我认为这已经初步形成了你之前说的那个“大锚点”。

不过，当前最需要进一步深入的，不是全部六项指标的计算细节，而是“两组已完成过程如何代表市场近期背景”以及“这个背景与当前 Working 的关系”这两个关键设计。 它们决定了 N 作为一个整体，究竟是不是有意义的业务表达，而不仅仅是一些分别计算正确的统计量。

二、从下游业务问题出发，N 可能究竟增加了什么？
我们可以先从 U2 比较明确的业务问题开始：

几个品种在相近时间发生转折，并且随后都产生一定运动，它们之间究竟形成了什么关系？是否存在共同的机会组织？

现有转折关系与两过程比较主要能告诉我们：转折是否接近、方向是否相容，以及转折后的推进、效率、逆向运动等是否具有某种关系。

但我们可以进一步提出一个问题：

这几个品种虽然这一次的运动表现比较接近，但它们此前一段时间的运动背景是否相同？这种不同是否值得成为理解当前关系的依据？

例如，假设有两个品种 A 和 B，都在相近时间向上转折。

A 在此前一段时间的运动普遍比较顺畅，近期变化也不大；B 此前的运动经常折返，但最近几段明显改善。

这时，仅看当前转折和转折后的短期运动，可能觉得 A、B 很接近。

如果使用 N，理论上可以进一步表达：

A 当前的运动接近其近期既有表现，而 B 当前的运动发生在一个近期表现正在变化的背景之中。

这个差异是否具有投资业务意义？ 这才是我们应该研究的下游问题。

如果这种背景差异有助于解释两个品种为什么在后续组织中表现不同，N 就可能提供有价值的补充信息。

如果最终发现，当前转折及其后过程已经能够充分解释这种差别，N 所提供的背景并没有帮助，那就说明至少在这个业务用途下，不需要 N。

这里我并不预设“背景改善就意味着未来更强”。我们只是先明确下游需要辨识什么，再检验 N 是否提供有意义的材料。

三、这样反推以后，N 的设计问题会变得具体
例如，假设下游真的希望比较多个品种的近期运动背景，那么原本看起来很普通的“最近六段”参数，就会变成一个值得重视的设计问题。

因为两个品种即使都取最近六段，实际覆盖的市场时间也可能相差很大。

品种 A 的六段可能只覆盖几个交易日，品种 B 的六段可能覆盖很长一段市场历史。

如果下游希望比较的是它们在同一近期市场环境中的表现，就需要检验这两个背景是否真的可以相互比较。

但如果下游希望比较的是各品种最近六次独立运动的典型表现，那么这种时间跨度不一致可能本来就是合理的。

到底是否合理，要由下游需要怎样的业务比较来决定。

同样，当前部分指标还没有进行跨品种可比的归一化。如果下游只是看一个品种相对自身的变化，这和直接比较两个品种的绝对运动幅度，对归一化的要求并不一样。

因此，这种倒查会直接改变我们对 N 的观察重点：

不是先找一个最合理的六段参数，而是先确定下游希望使用怎样的“近期背景”，再检验现有选窗、统计和归一化是否能够提供它。

### 回答：

我认为你现在提出的，其实是当前 BI-01 长程任务中一个比较根本的问题：我们已经有了“怎样持续观察和迭代”的工作方法，但还没有充分明确“观察迭代最终要使这个特征达到什么业务状态，以及达到什么程度就可以把主要精力转向下游”。

这个问题如果不解决，确实可能出现你担心的情况：四项专业工作都做了很多，参数调过、图画过、问题也发现过，但最后无法回答这个特征究竟怎么样了、为什么值得继续投入、下一步究竟该做什么。

我重新看了当前仓库的专业主干，发现这里确实存在一个值得补足的层次。

一、先区分三个层次的意图
我认为当前需要把三件事分开：

最终业务意图

使一组特征能够合理表达原本希望认识的市场现象，并能被下游特征可靠使用

当前单个特征的阶段目标

通过真实市场观察，明确它是否合理、在哪些条件下合理、怎样配置和使用，以及剩余局限

四项专业工作的作用

参数探索 → 展示与画通 → aidata 组织 → 观察分析 → 定向返回修改

你现在已经相对明确了第三层的工作内容，但第二层的终点比较模糊，因此第一层也就显得遥远。

目前仓库里的 00_PURPOSE_AND_FOUR_WORKS.md 把目标表述为：了解具体特征的含义、输入、输出与参数，在实际市场数据上探索如何展示和理解，检查正确性及其结果是否符合普通投资者对市场过程的正常解读。

这个定义作为观察工作的目的是成立的，但还不足以构成一个明确的阶段性业务完成目标。

尤其是它没有充分回答：

什么情况意味着特征已经基本合理？

参数合理和设计合理分别要证明什么？

发现问题后，哪些必须修改，哪些可以保留为已知局限？

观察到什么程度，值得停止当前特征的主要探索，转向下游？

哪些是必须先完成的前置条件，哪些可以伴随后续使用继续迭代？

这些不是继续把四项工作细化，就能自然得到答案的问题。

二、我建议把单个特征的最终产出定义为一种“有依据的可用状态”
单个特征观察迭代的最终产出，不应仅仅是合理参数、修改后的实现或一份观察报告。

更完整的产出应当是：

一个经过实际市场观察、适用范围和局限已经比较清楚，能够支持明确下游用途的特征版本，以及支撑这个判断的证据和使用知识。

这里至少包含三个方面。

方面

最终要知道什么

可能的实际产出

特征本身

它是否正确、合理地表达了想表达的市场现象

保留或修改后的特征设计与实现

使用方式

哪些参数、条件、品种、尺度下可以合理使用

推荐配置、适用范围、局限和反例

下游衔接

下游能够可靠地从它取得什么信息，哪些不能推断

明确的输出语义、时间边界和下游使用约束

这样，你提到的两种结果就不是两个互不相干的终点。

一种情况是：参数探索发现某一组参数比较合理，既有设计不用修改。

另一种情况是：发现原设计存在问题，提出并落实修改，再重新观察。

两者最终都应当走向同一个方向：使这个特征成为一个边界清楚、可被继续使用的业务能力。

还有第三种同样有价值的结果：观察后发现原设计思路不成立，或者其业务价值不足，决定暂缓、替代甚至放弃该特征。只要有足够的证据，这也不是白做。

关键并不是每个特征最终都必须通过，而是每个特征都要形成一个能够支持后续决策的结论。

三、“基本合理”到底应该怎么确定？
这里最重要的是：基本合理不是说观察了大部分历史情况都成立，也不是说特征已经没有明显问题，而是相对于它承担的业务职责，重要的正确性、合理性和使用边界已经获得足够支持。

我建议分成四个判断维度。

1. 计算正确
首先确认实际实现没有把预期处理逻辑做错。

例如目前观察的 U2NormalNodeBehaviorFrp，需要保证：

已完成过程、当前未完成过程没有混淆。

最近六段与此前六段的范围正确。

当前可知的信息没有使用后来才确认的信息。

关键统计、归一化和参数逻辑符合设计。

这一层主要验证特征有没有按照它宣称的方式工作，并不直接证明业务设计正确。

2. 业务表达合理
这一层更重要，也更难。

需要从这个特征原本想表达的市场现象出发，判断它的输出与实际行情能否形成合理对应。

例如，当前 N 特征大致在表达单品种、单尺度上的近期已完成过程和当前未完成过程的 Behavior。

那么观察时就应关心：在明显推进、推进减弱、反复折返、当前过程尚未走完等不同情况下，特征能不能把相关事实合理表达出来？

不能因为计算没有 Bug，就认为特征合理。

同时也不能因为特征没有提供完整的 U2/U3 市场认识，就说它不合理。它是一个上游特征，职责本来就有限。

3. 参数和适用边界合理
这里正好对应你提到的“一组合理参数”。

我认为最终不一定要得到一组放之四海皆准的参数，更可能得到下面几种情况：

观察结果

对参数的认识

一组参数在多种典型场景中均合理

可以形成优先采用的配置

不同品种或尺度明显需要不同参数

形成分类配置规则

一段范围内多组参数结果接近

存在相对稳健的参数区域，不必追求某个精确最优值

参数怎么调整都解决不了关键反例

很可能属于设计问题，而非参数问题

其中第三种很重要。

假设参数取 4、5、6 都能合理表达某个市场现象，那么往往不值得为了证明 5 比 4.8 更好，投入大量后续观察成本。

反过来，若从 5 改成 5.1，特征就产生完全不同的市场解释，这是需要关注的敏感性。

所以参数探索的终点更接近：

已明确可采用的参数配置或配置规则，并了解合理变化范围及重要敏感性。

并非找到数学意义上的全局最优。

4. 剩余问题不妨碍当前下游用途
这是我认为最适合确定阶段完成的标准。

例如 N 特征经过一轮观察之后：

计算正确性得到支持；

已完成过程的推进、幅度、效率等表达总体合理；

当前未完成过程的部分输出还存在较大波动；

但下游当前只需要已完成过程的统计信息。

那么就可能作出这样的结论：

N 特征的已完成过程相关输出，在明确的参数与适用范围内，可以供下游开始使用；当前未完成过程的某些输出仍需继续观察，不授权下游据此形成强业务判断。

这意味着，同一个特征完全可以部分达到可用状态，不必所有设计和所有市场情况全部研究透彻才允许继续。

这与你之前要求四项工作可以按实际依赖分批接收的思路也是一致的，不过这里进一步涉及业务层面的成熟度和下游资格，而不只是工作交付的管理接收。

四、我建议把最终阶段结论分为四种，而不是只有完成／未完成
A. 当前范围基本合理，可以继续下游

重要正确性及业务合理性获得支持，参数与使用边界清楚，没有阻断当前下游用途的问题。后续仍可根据新反馈迭代。

B. 部分合理，允许限定范围继续下游

哪些输出、参数和场景已经足够可靠，哪些还存在问题能够明确区分，下游只能消费有依据的部分。

C. 存在实质性问题，需要继续修改和验证

问题影响核心业务表达，尚不能安全地交给相关下游。需明确修复对象和再观察范围。

D. 现有思路不值得继续投入或暂时无法判断

可能是设计假设不成立、与已有能力重复、业务价值不足，或关键证据暂时无法获得。需要重新考虑特征的必要性或研究优先级。

这样的结论，比笼统说“工作4又发现一些问题，继续循环”更容易让你判断整体进度。

特别需要注意，A 或 B 也并不代表永久验收、生产就绪或者投资收益已经得到证明。它只代表在声明的业务范围内，具备进入下一层研究的依据。

五、那么是不是 N 基本合理以后，就继续观察它的下游特征？
我认为总体方向是的，但最好理解成沿特征依赖关系逐步形成可用的业务能力，而不是机械地把所有特征从上游到下游依次验收一遍。

当前 N 特征所在的位置，可以这样理解：

真实行情与上游过程数据

基础运动过程、已完成／未完成信息
当前 N 特征：U2NormalNodeBehaviorFrp

单品种、单尺度的近期过程 Behavior
后续 U2 组织与多品种关系能力

不同对象、不同尺度之间的关系与组织
U3 及进一步业务叙事

特征组合、角色、重点品种等更完整的业务判断
这是业务依赖的概念示意，不等于当前源码的完整依赖图，也不表示所有下游必须串行。
现在有一个容易混淆的问题：

你可能希望通过观察 N 特征，确定它能不能很好地解释“哪些品种会更强、哪些更弱”。

但 N 特征本身主要表达单品种的过程 Behavior，真正的强弱对比可能要到下游多个品种之间的关系和组织中才形成。

所以不能把下游应承担的业务能力提前变成 N 的验收标准，否则当前特征可能永远无法完成。

另一方面也不能只因为 N 自身描述得合理，就认为它必然对下游有用。

因此，这里实际存在两种不同判断：

第一种：特征自身的合理性。

它是否正确、合理地表达了自己应该表达的市场现象。

第二种：特征在下游的实际信息价值。

下游使用它以后，是否能产生有意义的新认识，是否存在冗余、缺失或错误解释。

这两种判断有联系，但不能混为一谈。

我的建议是：N 达到当前用途的基本合理之后，就让下游开始消费，并通过下游实际使用继续检验 N。没有必要等 N 的所有可能用途都研究完。

这样整体工作将从“一个特征内部反复循环”，发展为“多个特征之间沿真实业务依赖不断迭代”。

六、时间预期应该怎么形成？
这是目前最值得改进的另一个问题。

如果把目标定义为“直到观察不出问题”，那么确实几乎无法预估时间。因为市场情况太多，后面永远可能发现新的反例。

我建议不要按“要观察多少天历史、多少个 Case”直接推算，而是按认识逐步收敛的过程来估计。

一个合理的推进过程
形成第一版可观察对象

理解特征、参数、输出，并让真实数据与图能够正确对应。这一步解决的是能不能开展有效观察，不要求已经证明特征合理。

通过典型场景形成第一轮业务认识

优先观察最能暴露特征作用和问题的典型场景，包括正例、反例及边界情况。识别正常表现、明显问题和参数敏感性。

处理影响主要业务用途的问题

把发现的问题区分为实现错误、参数问题、表达问题、原设计问题。定向修改，并检查原问题是否解决、有无引入新的重要问题。

验证主要认识能否跨场景成立

在不同历史阶段、市场状态、必要的品种或尺度中核对，而不是只在最初发现问题的位置反复调参。使用未参与调整的案例检验，尤其需要保留反例。

形成阶段性使用结论，转向下游

明确能使用什么、不能使用什么、剩余问题是否阻断下游。把适用范围内的特征版本、参数及使用知识交给下游，后续再根据反馈迭代。

这里的第二、三、四步可能反复往返，但不应该无限循环。

下面只是用于项目规划的粗略量级，不是已经由当前 BI-01 实际运行数据验证的工期。

对于当前 N 特征，我不会直接给出“还需三天”这样的结论，因为还缺少本轮真正完成的观察、关键反例数量、有效图形及下游依赖等证据。

更有用的是在第一轮典型案例之后，形成一个初步判断：

当前究竟主要是参数探索问题、几个可定位的局部错误，还是更根本的设计问题？

一旦性质明确，时间预期才可能明显收敛。

七、怎样避免最后发现前面工作都白做了？
我认为真正的风险不是发现特征设计错了，而是研究了很久，却没有留下可以继续使用的业务认识。

例如 N 最后发现“当前未完成过程的某种归一化设计不合理”，这本身不意味着之前的观察白做。

只要前面已经弄清楚了它在什么情况下失真、失真来自哪里、什么替代方案可以解决，研究就是有产出的。

相反，如果只是不断调参数、画图、生成报告，而没有形成明确的业务判断，即使最后找到了一组好参数，未来换一个品种或场景，也可能要重新做一遍。

因此，我建议每次实质观察，都要求推动下面三个问题中的至少一个：

对这个特征的业务含义或适用边界，获得了什么新认识？

某个具体问题是否已经被解决、反证或者缩小范围？

对这个特征是否能够进入下游使用，判断是否发生了变化？

不要求每轮都有正面成果，但要能够识别哪种探索方式已经没有明显信息增量，及时换方法或停止。

还有一个很重要的成本控制原则
不用为了证明一个上游特征“全面合理”，把所有可能的市场场景都观察一遍。

应该根据它当前承担的业务职责、可能造成的错误后果，以及下游实际依赖，决定需要投入多大观察成本。

如果某个细节只影响暂时不会被使用的输出，可能应当保留问题而继续其他工作；如果某个细节会造成严重的未来信息泄漏，即使只观察到一个反例，也必须先解决。

这里的优先级应该主要来自问题的业务影响，而不是反例出现的数量。

八、我认为当前 BI-01 真正应该补上的，是一层“特征成熟度与下游接续决策”
现在的四项专业工作不用推翻。

我重新核对的 01_OUTPUT_BASE_FORMAT.md 已经明确提出：不能因为四个栏目都填完，就认为专业观察完成；应由具体特征值得研究的问题、已得认识和接续方向决定。

这个方向是正确的，但我认为目前还缺少将这句话落实为明确业务判断的方法。

建议最终让管理 Pro 在适当时点，依据专业 Pro 的真实成果，能够回答下面五个问题：

管理需要回答的问题

对 Owner 的价值

当前特征主要希望解决什么市场认识问题？

确认工作有没有偏离原目的

当前哪些认识已经获得支持，哪些仍然不清楚？

明确实际业务进展

主要问题是什么，是否阻断当前用途？

决定继续迭代的必要性

当前是否已经具备某种范围内的下游可用性？

决定能否开始下一层研究

继续投入最值得解决什么问题，预期取得什么新证据？

控制投入和时间预期

这不是建议立刻新增第五项专业工作或再建一套固定 Gate，而是让原有管理职责能够在适当时点作出业务上的收敛与接续判断。

我也不建议现在直接让主控修改仓库，或者让当前长程任务突然改变执行目标。应该先把这一层业务意图讨论清楚，再判断现有专业方法和管理职责需要补多少内容。

九、最终我建议采用的整体定位
把当前及后续特征的研究理解为以下过程：

从一个已经实现、但业务合理性和使用方式尚不充分清楚的特征出发，通过真实市场观察，逐步形成可靠的使用认识；在有依据的范围内让下游开始使用，再通过下游反馈继续完善上游。

这样整个任务就不再只有“循环”，而有一个实际推进方向：

特征实现或候选设计

观察、发现问题、定向迭代

形成有边界的合理性与使用结论

可用部分进入下游特征与叙事

下游使用产生新的证据和反馈

必要时再返回修改上游

这会形成两个同时成立的目标：

对单个特征： 尽早形成有证据、有边界、可以支持当前下游用途的成熟版本，而不是追求一次性完美。

对整个 U2/U3 业务能力： 逐步让越来越多的上游信息能够被下游合理消费，最终支撑原本希望形成的多品种市场过程认识和投资业务叙事。

而且每次推进都应该留下三种可继承资产：稳定的特征能力、已形成的业务认识、可以复用的观察与验证方法。

这样，即使某个特征最后被推翻，前面的研究也不一定白做。

我认为下一步最值得进一步讨论的，不是先制定一个统一的“基本合理”验收表，而是以当前 N 特征为例，具体推导它的职责边界、典型市场场景、必须排除的关键错误，以及最早满足什么条件就值得转向哪个下游。

通过这个具体例子，才能判断我们提出的成熟度标准是否合适，也更容易估出第一轮观察究竟需要投入多大成本。这比现在直接给全部特征规定一个统一的观察周期和验收比例更可靠。

### 回答：

这次我理解到你的核心问题了。前面我的分析确实有些偏向了“怎样判定特征达到基本合理、何时停止”，但你现在真正想确定的是：

我们究竟是为了认识什么市场现象，才要做当前这个具体特征？如果这个目的没有讲清楚，那么后面看图时发现的各种合理、不合理，都可能只是零散的局部判断，无法构成有方向的业务观察。

所以现在值得做的不是先制定成熟度标准，而是先回到 U2NormalNodeBehaviorFrp 本身。

一、先说查到的一个关键事实
根据当前 U2 的业务依赖图和 N 特征的具体方法，N 并不是直接用于识别多品种强弱、机会簇或重点品种的特征。

它直接处理的是：

一个品种、一个尺度上，最近已经完成的价格运动过程呈现什么行为特征；这些行为与更早的一段过程相比发生了什么变化；当前还没有完成的运动过程又正在怎样发展。

这是它目前能够明确定位的业务职责。

U2 完整业务依赖地图 也把近期行为 N 单独放在“过程历史 → 近期行为 → 关系／机会判断中的描述信息”这个位置，并特别说明它不构成所有关系和机会判断的前置条件。

这很重要，因为它意味着我们不能简单把“能否判断哪个品种更强、哪一个机会更好”当作 N 自身的观察锚点。

但这里还有一个更深的问题：

为什么需要把近期的过程组织成这样的 Behavior？单独看这个 Behavior，究竟能让投资者获得什么原本不容易获得的认识？

我认为这才是你现在应该深入分析的地方。

二、结合 N 的具体设计，我认为可以提出一个更准确的业务目的
N 当前的主要结构是：

组成

实际提供的信息

可能承担的业务作用

最近六个已完成过程

推进、幅度、持续时间、行程、效率、逆向运动的中位数及离散情况

描述近期已经形成的运动背景

此前六个已完成过程

同一组指标的历史参照

判断近期运动背景发生了什么变化

当前未完成过程（Working）

当前推进、路径效率、逆向运动、极值更新节律等

描述正在发生的运动与已完成背景的差异

LOO（逐段剔除）

单独剔除一个过程后统计结果的变化

说明部分统计结论对样本的敏感程度

这套结构实际上隐含着一种业务设想：

不是孤立地描述一个转折、一个运动过程，而是让人能够持续认识“这个品种最近的运动表现是什么样的，以及现在正在怎样变化”。

这是我根据实际方法推导出的候选目的，还不能说原需求已经明确确立了这句话。

我认为可以进一步把它表达成一个待验证的核心业务问题：

当我们观察某个品种某个尺度上的价格运动时，N 能不能在原始 K 线和转折过程的基础上，提供一个合理的近期运动背景，使我们更容易理解当前正在发生的运动？

这个背景是否抓住了重要的市场差异？有没有因为统计方式而丢失那些实际上很重要的信息？

这里包含两个性质不同的问题：

一是它表达出来的东西有没有业务意义。

二是它采用的表达方式，能不能充分表达这种意义。

例如 N 的六个完成过程是分别统计再取中位数，而没有完整保留各段的发生顺序。因此它能表达某种近期总体水平，却未必能表达“运动正在逐次加快或减弱”。

这未必是 N 的设计错误。

如果 N 本来只是想提供近期总体背景，这种压缩可能是合理的；如果 N 本来希望让下游据此判断运动正在发展还是衰退，那就可能丢失了关键信息。

所以必须先说清楚希望 N 承担哪一种业务认识，才能判断这个设计是否合理。

三、真正看图时，应该围绕哪几种核心问题？
我认为可以用一个已经存在的真实例子说明。

在 CYF 10 月 21 日的原始讨论 中，提到了铁矿石 2019 年 2 月 19 日的一组数据：

此前完成窗口的路径效率约为 0.095。

最近完成窗口的路径效率约为 0.418。

当前未完成过程的路径效率约为 0.043。

这些数值在当前业务上可以解释为：最近已完成过程的净位移相对行程改善了，但当前正在发生的过程却呈现出很低的路径效率。

假设把它画在 K 线上，我们会看到实际走势与这三组信息的对应关系。

此时最重要的观察问题，不应是“0.043 看起来是不是太低了”，而是：

这套近期完成过程与当前未完成过程的对照，究竟能否帮助我们认识市场正在发生的一种重要变化？

这里可能有几种完全不同的答案。

情况 A：确实表达出了有意义的运动变化。

例如近期完成过程相对顺畅，而当前运动在明显折返。N 把这种差异表达出来，帮助人更清楚地认识当前过程与近期背景的不同。

那么我们就得到了一条支持 N 业务价值的证据。

情况 B：数值差异很大，但盘面上并没有相应的业务变化。

比如当前过程刚开始，尚未经历足够长的运动，当前效率与完整历史过程缺乏可比性。

这时问题可能不是计算错误，而是“如何比较不同成熟程度的过程”这一设计问题。

情况 C：盘面上存在重要变化，但 N 没能表达。

例如最近六段的表现是先越来越顺畅、后来又持续恶化。但另一段历史中的六段只是顺序相反，两者的中位数和离散程度却可能完全一样。

这时就需要判断：这种先后变化本来是不是 N 应承担的？

如果是，N 的现有统计可能不足。

如果不是，这个发现更可能提示下游需要一个表达过程演化顺序的特征。

注意，三种情况都不是单纯的“这儿不合理、那儿不合理”。

它们都是在回答同一个问题：N 所提供的近期运动背景，能不能承担我们希望它承担的市场认识？

而且可以据此判断发现的问题应该在哪里解决。

四、但还存在一个必须澄清的问题：N 自己究竟需要有多大的独立业务价值？
这是我认为你现在特别值得关注的地方。

你提到它“是不是只是为下游提供信息”。这个可能性不但存在，而且从当前 U2 的依赖图来看，确实不能排除 N 主要是一种上游描述性能力。

我认为需要区分两种定位。

定位一：N 本身就是一个有投资业务观察价值的特征。

那么我们期待投资者在看 K 线和 N 时，能获得某种有价值的认识，比如近期运动背景变化、当前运动与历史背景的差异。

此时应该检验它比原始价格、转折与单段指标增加了什么，以及有没有明显误导。

定位二：N 主要是一个供下游消费的过程描述特征。

例如，下游在研究多个品种转折之间的关系时，可能需要知道每个品种此前过程的推进、效率和逆向运动背景。

这种情况下，N 不一定要单独产生完整的投资判断。只要它提供了下游确实需要、含义正确而且适合使用的信息，就可能具有价值。

不过也不能仅凭“将来下游可能用到”就认为有价值。至少要能够说清楚某个真实下游业务问题需要它提供什么信息。

目前从已查到的材料来看，N 的描述性职责比较明确，但它究竟在哪些具体下游业务判断中不可替代，还没有得到同样充分的证明。

CYF 当时甚至明确表示，第一项的观察目的是检验这套单品种过程描述是否有观察价值，而不是认为它已经具备完整的 U2 投资解释能力。

因此，我暂时不会替你把 N 的最终业务目的定死为“识别运动状态转变”，更不会定为“提前判断拐头”或“帮助选择强势品种”。

这些是可能的后续用途，但是否属于 N 自身职责，还需要从原始设计和下游消费需求进一步确认。

五、那么现在究竟该不该深入特征细节？
我认为应该，而且这是目前确定观察锚点所必需的一步。

但不是去做全面的源码审计，也不是要把 N 的每个字段和计算分支都研究透。

应该从业务目的出发，有针对性地深入这些设计：

需要深入的内容

真正要弄清楚的业务问题

上游怎样划分一个过程

N 所描述的“运动过程”到底对应什么市场现象

为什么选最近六段和此前六段

希望用怎样的市场历史来代表“近期背景”

为什么使用这些运动指标

希望区分市场运动的哪些重要性质

为什么使用中位数、MAD、LOO

哪些信息希望保留，哪些差异允许被压缩

当前未完成过程怎样参与

希望怎样认识正在发生的过程及其变化

下游实际怎样消费 N

N 是独立业务认识，还是其他特征的基础信息

这些问题有可能让我们发现，原本觉得已经确定的特征目的，其实还有重要的模糊之处。

甚至可能进一步发现：原来将若干信息组合成 N 这个特征的方式，本身还有必要重新考虑。

这不是坏事，而是把观察从无方向的局部挑错，转变为真正针对业务意图的分析。

还有一个需要避免的混淆
CYF 的 R33 管理接收 已经认为 N 在当时合同和真实历史使用范围内达到了基本合理性。

但阅读其具体内容会发现，主要检查的是原始价格与数值的对应、统计结果、时间语义、缺失状态以及有限样本的可解释性。

这些成果有价值，但它们与我们现在想做的、针对 N 业务表征价值的观察不是同一个问题。

因此，不能因为 CYF 已经接受了 N，就认为你现在的观察任务已经没有实质内容；也不能要求重新证明那些已经完成的计算正确性。

六、我建议下一步先解决的真正问题
我现在认为，先不要急着定义 N 观察迭代的最终完成标准，也不要急着去安排大量看图工作。

更合适的顺序是：

先结合 N 的原始业务设计、真实处理逻辑、现有结果及其下游关系，搞清楚三个层次：

第一层：为什么需要 N？

原始价格和转折过程已经有了，为什么还需要把多个过程形成近期 Behavior？希望额外认识什么？

第二层：N 具体打算怎样实现这个目的？

两组六段、统计指标、当前未完成过程和敏感性等设计各自承担什么作用，又有哪些信息明确不由 N 表达？

第三层：怎样通过真实行情观察这个目的是否达到？

应该优先看哪些具有代表性的市场变化，观察哪些关键差异，而不是漫无目的地逐项检查所有字段。

如果这三层建立起来了，你之前的问题才有一个真正的判断基础：

观察最终应该产生什么业务认识；

什么问题值得修改 N；

什么问题应该交给下游；

哪些参数研究有价值；

继续观察到什么程度就没有必要再把主要精力留在 N 上。

所以我目前的判断是：你缺的不是更严格的验收门槛，而是当前 N 特征从“它为什么存在”到“它怎样产生有价值的业务认识”的完整目的关系。

现有材料已经给出了一个可信的初步方向：N 是对近期单品种运动过程及其变化的描述。但这个定位还需要结合具体设计和下游需求继续追问，才能成为真正指导业务观察的锚点。

这一步值得先做扎实。否则，即使后续图画得很好、观察了很多市场历史，也可能始终只是不断产生零散的合理性意见，而没有回答最重要的业务问题。
