这份 README 介绍的是：把较长时期的行情组织成可以逐层深入的图，并让 AI 取得与图中同一段行情对应的数据。
我读取了 GitHub main 的正文和相关引用。下面按使用者的角度解释。
1．它希望怎样帮助你分析行情
从长时间范围开始，先看整体走势，找值得深入的位置；然后放大这些位置，观察更细的行情和特征；需要 AI 分析时，导出对应范围的数据。
它提供的几个层次是：
层次	展示内容	用途
长期概览	日线走势、大尺度定位标记与窗口	看整体背景，选择深入的日期
大尺度图	30 分钟行情及特征	看局部较完整的运动过程
中尺度图	1 分钟行情及特征	查看内部变化
小尺度图	5 秒行情及特征	查看更细的过程
tick 图	半秒盘口	按需研究更细的盘口变化


这里的“大、中、小”是观察层次，不直接代表投资机会或运动质量。能否深入到某一层，还取决于实际数据是否可用。平台操作说明
2．文档里的“节点”是什么意思
“节点”可以理解为：被工具确定并保存下来的一段行情时间窗口。
例如，大窗口中包含几个中窗口，中窗口中再包含小窗口，形成 big → mid → small → tick 的关系。每个窗口保留定位来源，后续画图和导出数据都据此进行。
节点有两种主要确定方式：
- 人工指定时间段。
- 用已有特征定位：先找到转折等事件，再根据前后余量、合并规则等生成窗口。
README 列出的默认组合是：
要定位的节点	默认依据
big	30 分钟收盘价的 Zig 转折，回撤阈值 10%
mid	30 分钟行情的 L 尺度贴近转折
small	1 分钟行情的 M 尺度贴近转折
tick	1 分钟行情的 Zig 转折，回撤阈值 0.4%


这里容易混淆：**特征自身的 L/M 名称，与节点的 big/mid/small 名称不是同一套分类。**例如 L 转折用于定位 mid。
这些是默认配置，可以通过参数替换；人工窗口也属于已有能力。输入字段合同
3．“定位特征”与“观察特征”是两种职责
- 定位特征决定在哪里划出窗口。
- 观察特征叠加在这些窗口中，帮助解释行情，并提供对应数据。
因此，在同一批已确定的节点上，更换观察特征、刷新图，不应该顺带重新划分时间窗口。改变搜索范围或定位规则时，才需要重新生成节点。
README 中的 Thick 是观察特征的例子；正文没有解释它的具体算法和业务含义，不能仅凭名称推断它代表什么。
4．实际使用时，你需要做什么
README 的主要用法是：你用自然语言说明板块、时间范围、想看的特征和关注的问题，由 AI 配置并调用工具，返回图链接。
AI 填写的 run_brief，就是本次运行的参数单，包含数据环境、品种范围、定位方式、窗口参数和观察特征。
几个函数的区别，可以理解为：
入口	做什么
build_chart_run	建立看图需要的节点、窗口和来源记录
build_run_overview_chart_page	生成长期概览图入口
build_big_world_chart_pages	生成各节点的详情图入口
build_board_run	在节点基础上生成特征切片和交付数据包


只想看图时，可以先生成图；之后需要 AI 分析，再沿用已确定的窗口补数据，不必一开始就导出所有细节。开发参考
5．引用文档中，有几处需要特别说明
第一，Python 调用与 /aidata 网页有不同的配置范围。
README 主推 AI 根据需求配置 run_brief。而 /aidata 网页使用固定的标准配置，只开放板块、日期和已登记特征等有限选项。
所以，网页里不能改某个参数，不等于 Python API 也不能改。网页当前固定的历史范围，也不代表整个工具只能处理这个范围。平台详细参考
第二，从概览进入详情，目前存在明确的衔接限制。
概览与 focused 详情会分别生成 run。当前 focused 根据选中的日期重新搜索节点，尚不能直接沿用概览中那个 big 节点的身份。
所以，两个结果都出现 big_000001，不能认为它们就是同一个窗口，需要核对 run 和时间范围。reuse_core=True 只能复用当前 run 的节点，不能解决这种跨 run 衔接。TODO 第 16 节
第三，图上可见范围与数据切片范围可能不同。
图可以多显示窗口前后的行情，帮助理解上下文；导出的切片仍按已保存的节点范围。因此不能直接拿图的最左、最右边界当作数据包范围。开发参考
第四，特征切片与“图层数据导出”也不同。
feature_slices 是从真实特征数据按窗口切出的主证据；plot_view_data 用来对齐图中实际展示的内容。开发文档明确将两者分开，图层导出不能自动代替完整特征证据。开发参考
