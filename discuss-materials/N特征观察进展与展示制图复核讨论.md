这张示意图只是为了说明它的组织方式。真实实现是 Bokeh 交互图，带多个图层和表格。
2. B3.2：图、表、文字分别怎么展示？
A. 价格与过程图
这是展示的主要部分。

底图使用真实 5 分钟行情；不同运动过程使用不同颜色标注。Worker 最终采用的规则如下：
图形元素	具体展示	想表达什么
灰色实线	此前六个完成过程的真实 close 路径	旧的市场运动情况
蓝色实线	最近六个完成过程的真实 close 路径	较新的已完成运动情况
红色实线	当前 Working 的真实 close 路径	当前尚未完成的运动
对应颜色的虚线	每个过程的起止端点连线	过程边界，不是实际行程
三角形标记	完成过程的确认／known-from 位置	何时获得相应信息
OHLC 底图	原始 5m 行情	市场价格背景

这样展示，投资者可以直接把价格走势和特征划分的过程对应起来。

比如，一段实际价格路径反复折返，但从起点到终点的净位移很小。通过同时展示实线路径和端点连线，就可以直观看到它们的区别，而不把端点位移误认为整段行程。

这里有一项比较重要的设计：实际转折的位置与后来确认该转折的位置要分开标注。 否则可能让人误以为转折发生时，系统就已经知道了结果。
B. 完成窗统计表
专业 Pro 没有要求把六个指标全部叠加在价格走势图上，而是计划用表格展示。

实际六项指标是：
指标	业务上主要描述
BusinessDuration	过程持续多久
CanonicalPathLength	价格实际走过多少行程
DirectionalProgress	沿既定过程方向净推进多少
PathEfficiency	端点位移相对于实际路径行程的效率
RawAmplitude	起止端点绝对价格差
RawCounterMove	过程中最大逆向运动负担

每项指标都显示此前与最近两个完成窗的统计，例如：
真实 rb 样本：路径效率
统计内容	数值
最近六段中位数 current	0.151417
此前六段中位数 previous	0.084543
差值 change	+0.066874
最近六段 MAD	0.025989
LOO 最大绝对移位	0.002945

数据取自本轮 Worker 对 2024-02-29 14:55 的 rb 正式读取和展示投影。
你可以理解为：走势图告诉你这些运动过程长什么样，统计表告诉你这些过程被 N 特征总结成了什么数字。

LOO 的六个明细另放表格，不会画成六个完成过程的贡献排名。
C. Working 与节律展示
这部分与完成窗统计分开，因为 Working 尚未完成，不能直接把它当作第七个已完成过程。

这里计划展示两组信息：

一组是当前 Working 的运动状况，比如持续时间、净推进、路径效率、逆向量。

另一组是当前 Working 内部的极值更新节律，比如最近六个极值更新间隔、此前三个和最近三个间隔的中位数、距上一次更新的等待时长以及 waiting_ratio。

实际 rb Case 中：
Working 数据	数值
方向净推进	50
路径效率	0.037764
最大逆向量	80
Waiting	123600
Waiting ratio	15.846154

专业 Pro 想让投资者能够同时看出：历史完成过程的统计有某种变化，但当前尚未完成的过程可能表现出另一种情况。
D. 文字说明
这里的文字不是要重复表格中的数字，而是解释它们为什么不能被直接理解为某种市场结论。

例如，路径效率提高并不等于投资收益提高；近期六个完成过程不代表最近六天；Working 的 Pending 状态不等于它没有可用的当前数值。

所以 B3.2 的实质就是：行情图展示事实过程，统计表展示特征计算，Working 表展示当前状态，解释文字负责连接它们的业务含义。

需要注意，实际 run_summary.json 里记录的是：
data_mode = fixed_input
feature_executions = 0
source_count = 8
view_count = 3


feature_executions=0 的含义是：这一次 aidata 本身没有重新执行 N 特征。 N 的数据是前面通过正常 OnlyRead 读取、关联和投影完成后，再交给 aidata 绘制的。

这与让 aidata 根据 run_brief 自己实例化和执行某个 Feature，是不同的使用方式。

三、这两项专业工作之间目前是什么关系？
根据实际成果，可以还原为：
环节	主要责任	当前成果

当前最值得你确认的一点是：

专业 Pro 的展示方案实际上是一种“特定 As-Of 下，行情过程＋统计截面＋Working 当前状态”的呈现方式。

这已经有助于观察和解释 N 特征，但它与“观察这个特征在市场历史中怎样持续变化”并不完全相同。

例如当前的三张图虽然覆盖不同历史时间范围，但 N 的统计结果仍取自同一个 As-Of，不是把不同历史时点的 N 结果连续绘制出来。

这未必是错误，因为第一轮完全可以先观察单次结果与真实行情是否对应。不过，之后应该根据实际业务观察目的判断：仅看固定截面是否足够，还是需要增加 N 在多个 As-Of 下的输出变化和对应行情过程。

这也是我认为现在对专业工作 2 最值得进一步审视的设计问题，而不仅是配色、表格或图形布局是否好看。
