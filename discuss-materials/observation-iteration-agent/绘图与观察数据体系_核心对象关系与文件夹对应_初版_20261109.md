# 绘图与观察数据体系：核心对象及对象关系（V0.2，讨论稿）

> **性质**：为 T03 合理性观察迭代 Agent 建设整理的系统对象认识，不是已经通过审查的 Agent 工作流、工具开发需求或运行合同。
>
> **本轮范围**：只整理主要对象的性质、对象之间的关系及需要区别的身份。对象与仓库、类、文件夹和运行目录的对应，待对象关系确认后再修订。本轮暂时沿用原文件路径，避免使已有 GitHub 引用失效；路径中的“文件夹对应”不代表本版已完成这项工作。
>
> **依据**：此前读取的 UPlot、AI Data、frame、m3sof 源码及项目说明，feature-production-agent 的特征运行实例及 ReqConform 材料，以及 observe-iterate 的实际 AI Data 使用记录。将代码中直接存在的对象和为理解系统所作的概念归纳明确区分；不声称完整调查了 Trier 平台内部实现。

## 一、整个体系的结构

先区分五个性质不同的部分：

| 部分 | 主要性质 | 包含的主要对象 |
|---|---|---|
| 特征计算环境 | 提供数据及特征执行条件 | 特征运行工作区、Sof 数据源、实际数据集、运行上下文、特征实例、特征运行结果 |
| UPlot 绘图系统 | 将行情和特征数据表达为图形 | CAEGraph、PlotSet、图表布局、绘图类、PlotCtx 及绘图数据 |
| 平台 CAE 系统 | 登记并打开 CAE 图 | CAE 业务／图形对象、平台 CAE 节点、图页面及显示服务 |
| AI Data 系统 | 组织观察时间窗、图、相应数据和用户操作 | Run Brief、AI Data Run、观察时间节点、Evidence、图引用、切片、交付包、User Operation 等 |
| 特征全链路取数 | 取得具体特征从输入到输出的运行结果 | 上游输入特征结果、责任块中间结果、目标输出及运行记录 |

它们并非五套相互平行的绘图工具。UPlot 提供绘图表达，平台承担图的登记和展示，AI Data 可以调用两者，负责观察运行的组织以及图与对应数据的关联；完整特征运行取数则是另一种用途的实际计算结果获取方式。

### 总体关系图

    特征运行工作区 ─── 提供实际可执行环境
         │
         ├── 可访问 Sof 数据源 ─── 定位实际数据集
         └── 可执行具体 Feature 实例
                            ▲
    运行上下文 ── 选择 Sof、品种／板块、日历、时间范围
                            │
                            ▼
                   Feature 的实际计算
                            │
               ┌────────────┴─────────────┐
               ▼                          ▼
         结果可供图形展示           特征全链路取数
               │                  （输入、中间、输出）
               ▼
         UPlot／CAEGraph
               │
               ├── 可被直接用于图形显示或平台注册
               │
               └── 可由 AI Data 组织和使用
                              │
                         AI Data Run
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
       观察时间节点        图形对象／引用     对应特征数据
             │                │                │
             └── 共享时间窗 ───┴── 关联切片 ────┘
                              │
                       数据与图的交付
                              │
                  平台 CAE 节点／图页面

这张图表达的是关系，不是规定必须依次执行的步骤。UPlot 可以独立于 AI Data 被使用；AI Data 的图形生成与特征切片可以共享观察节点，但不要求图页面先完成才允许取数。实际绘图和切片还可能在指定上下文中重新运行 Feature，不能假定所有产物来自同一次已经物化的结果。

## 二、特征计算环境：对象及关系

### 2.1 主要对象

| 对象 | 性质 | 不应混同 |
|---|---|---|
| **特征运行工作区** | 能够加载相关代码、运行环境、配置与数据访问能力的实际执行场所 | 不是一个 Feature、一个 Sof 或一轮特征运行 |
| **Sof 数据源** | 数据源命名、配置与运行时访问能力，可关联行情目录、品种集合及日历等 | 配置不等于实际数据集的全部文件 |
| **实际数据集** | Sof 可以定位和读取的实际行情、盘口等数据资源 | 不等于数据源名称或特征计算结果 |
| **特征运行上下文** | 本次所用 Sof、品种／板块、日历和时间范围等执行条件 | 不等于 Feature 自身的业务计算参数 |
| **特征实例** | 一个具体 Feature 的类型、参数及上游依赖的实例化表达 | 不等于已经运行完成的结果 |
| **特征运行结果** | Feature 在确定的上下文中计算后返回的数据 | 不等于图层显示数据，也不等于全部计算中间状态 |

### 2.2 关系

工作区承载执行环境；Sof 规定怎样使用某一数据源并访问实际数据集；运行上下文选择本次执行所使用的 Sof、对象、日历与时间；特征实例规定计算什么及其参数和依赖。

因此应当区分“构造／取得特征实例”和“在某个 Sof 上下文中运行它”。一个 Feature 对象可以先构造，然后在指定的运行上下文中执行；同一工作区也可以运行不同特征和使用不同数据源。不能把“工作区—Sof—特征实例”固定为逐级一对一所属关系。

## 三、UPlot：图形定义及其内部关系

| 对象 | 性质及主要关系 |
|---|---|
| **CAEGraph** | 组织完整图形表达及参数的上层对象，可以包含多组 PlotSet |
| **PlotSet** | 在特定对象范围、日历和时间段下组织一组图表布局 |
| **图表布局对象** | 安排单图、主副图、多品种共同图、每品种独立图等结构 |
| **绘图类（Plotter）** | 决定怎样绘制 K 线、价格线、事件点、线段、交易等具体图形内容 |
| **PlotCtx／绘图数据对象** | 运行时处理时间窗、对象、特征数据、坐标及用于显示的数据 |
| **实际展示的图** | 根据上述图形表达在特定数据和显示环境下得到的可视内容 |

主要包含／使用关系：

    CAEGraph
       └─ 包含一个或多个 PlotSet
             └─ 组织图表布局
                   └─ 使用具体绘图类
                         └─ 在相应上下文中取得并转换数据显示

CAEGraph 不等于一张静态图片。一个 CAEGraph 可以组织多个 PlotSet 和多个图，某个 PlotSet 又可以包含多个品种或图层。UPlot 的图形定义还可以通过其他业务代码直接使用，不以 AI Data 为必经入口。

## 四、平台 CAE：与 UPlot 的关系

主要区分三个对象：

| 对象 | 性质 |
|---|---|
| **CAE 业务／图形对象** | 可被平台引用的 CAE Fao 或由它组织／返回的 CAEGraph 等图形表达 |
| **平台 CAE 节点** | 平台登记相关 CAE 对象后形成的可定位对象，有平台侧节点身份 |
| **图页面** | 根据平台节点打开、由 Trier／Bokeh 等展示环境呈现的图形页面 |

关系可表达为：

    CAE 业务／图形对象
             │
         注册到平台
             ▼
        平台 CAE 节点
             │
          打开／展示
             ▼
          CAE 图页面

因此，**CAEGraph、平台 CAE 节点、图页面不是同一个对象**；也不能推定一个平台节点只能包含一个 PlotSet 或一张图。

目前从相关调用可以确认 AI Data 能使用 CAE 节点创建接口取得图页面引用。本轮仅记录这层使用关系，不进一步调查平台节点的全部持久化字段、Trier 内部页面类或数据库结构。

## 五、AI Data：观察运行侧的主要对象

AI Data 内部应先分清**观察运行与数据组织**，再认识其平台网页操作服务。此前 observe-iterate 总结的三个 Python 调用属于观察运行主链，但不是 AI Data 内部全部对象。

| 对象 | 性质 | 主要关系 |
|---|---|---|
| **Run Brief** | 一次观察运行的完整配置，描述数据上下文、对象、时间窗来源、定位特征、Evidence及输出条件 | 被程序直接构造，或由网页操作通过 Profile 生成 |
| **AI Data Run** | 按 Run Brief 开展一次观察组织工作的运行，具有独立 run_id | 生成或复用观察节点，形成相关图、切片和交付 |
| **定位特征／Anchor** | 用于识别观察位置或区间的 Feature 与定位声明，也可以使用人工时间窗 | 用来生成观察时间节点 |
| **观察时间节点（Timespan Node）** | 某个有身份的观察时间窗，可组织为 big／mid／small／tick 等层级 | 为图和切片提供共同的时间范围 |
| **观察 Evidence** | 本次要展示或切片的 Feature 信息，包括定位特征、额外观察特征及行情背景等不同角色 | 根据本次 Run 的配置进入图层或正式切片 |
| **图页面／图引用** | 关联某次 Run、具体观察节点和图形配置的平台 CAE 页面入口 | 使用 UPlot 及平台 CAE 能力 |
| **正式特征切片** | 在观察节点范围内从实际 Feature 取得的结果记录 | 是图所对应的观察证据，不从截图倒推 |
| **定位来源记录** | 说明某个节点由哪些真实 Feature occurrence 定位出来 | 与节点及正式切片共同帮助追溯来源 |
| **共享显示视图** | 从绘图层导出的可见数据视图 | 供人和 AI 对齐图上内容，不代替正式切片 |
| **交付包** | 组织节点、特征切片、定位来源、行情背景、字段说明及图引用 | 是数据交付，不自动完成专业分析 |

### 5.1 Run 与观察节点不是一个对象

一次 AI Data Run 可以形成多个观察时间节点。节点之间存在包含、父子与时间窗关系；同一组已确定的时间窗可以供图和正式特征切片使用。

**big／mid／small／tick 表达观察窗口层级**，不必然等同于 1d／30m／1m／5s 的行情频率，也不是平台 CAE 节点编号。一个 big 节点可以关联一张或多张图，而一张平台图页面也可能包含多个 PlotSet。

### 5.2 Core 与 Full 是运行能力阶段，不是两种不同业务数据源

- **Chart/Core**：获得 Run Brief 解析信息、观察时间节点、定位来源及图形关联所需的基础资料。它本身不表示正式 Feature 切片已全部产生。
- **Board/Full**：在新建或复用 Core 的基础上取得正式 Feature 切片，并形成相应交付包。

因此“Core 已生成”“平台图页面已创建”“正式切片已取得”“交付包已生成”是不同的完成事实。实际查看页面时也可能才发生图形取数和构图，不能把返回图 URL 等同于已完成全部页面计算。

## 六、AI Data：平台用户操作侧的主要对象

| 对象 | 性质 | 与观察运行侧的关系 |
|---|---|---|
| **User Operation Service** | 将平台用户操作映射成具体 AI Data 运行与结果的服务 | 使用相同的底层绘图及取数能力 |
| **User Operation** | 一次用户操作，拥有 operation_id、操作类型、执行状态和尝试记录 | 可关联一个或多个 AI Data Run 及结果，不等于 run_id |
| **标准 Profile** | 将网页有限输入绑定为 Sof、Feature、定位规则、时间范围和其他运行参数 | 形成 Run Brief |
| **Evidence Registry** | 网页允许选择的 Evidence／变体目录 | 提供可选范围，不代表全部可运行 Feature |
| **Evidence Revision** | 在已有观察时间窗基础上生成的一版证据集合与数据 | 可以复用冻结的 Core，保留旧版；不是 FeatureVersion |
| **图状态** | 图是否已按当前 Evidence 刷新，例如 stale／current | Evidence 更新并不自动意味着图已刷新 |
| **Operation Result／Artifact** | 执行状态、Run 引用、图链接、可下载数据和错误等返回信息 | 供网页、CLI 或程序读取 |
| **Operation Store 与后台执行** | 保存请求、结果、历史、幂等及实际执行状态 | 不替代特征运行引擎或 AI Data 的核心取数逻辑 |

### 6.1 平台网页的四类操作

| 操作类型 | 作用于哪些对象 |
|---|---|
| **Overview** | 根据标准 Profile 建立长期概览的 Run、观察窗口与图引用 |
| **Focused Search** | 在所选范围内创建新的 focused Core，重新定位下层节点；不会直接继承来源概览的全部节点身份 |
| **Build Evidence** | 基于现有 focused 冻结窗口创建新的 Evidence Revision、正式切片和交付 |
| **Refresh Chart** | 使用当前 Evidence 更新图显示；不重新定位节点，也不重新切片 |

四项是**用户操作类型**，不是四种 Feature，也不是四套独立业务计算引擎。

### 6.2 程序调用和网页操作为何不是两套绘图系统

此前 observe-iterate 总结的典型程序调用关系为：

    调用者提供 Run Brief
             │
       build_chart_run
             │
       生成／复用 Core
             │
        ┌────┴─────────────┐
        ▼                  ▼
    图页面生成          build_board_run
    （使用平台／UPlot）   （正式切片与交付）

其中 build_big_world_chart_pages 是一种图页面生成入口；只生成概览时也可以使用独立概览入口。图页面和正式切片共享 Core，但不是必须先生成平台图才能切片。build_board_run 在没有现成 Core 时也可以创建所需的基础部分。

网页操作则多了一层：

    用户在 Trier 提交少量选项
             │
       User Operation
             │
    Profile／Evidence Registry
             │
          Run Brief
             │
     同一套 AI Data 核心能力
             │
    Operation Result／Artifact
             │
      网页展示／打开／下载

因此，**网页不是 AI Data 三个 Python 调用以外的另一套绘图系统**。它在同一套核心能力外增加用户请求解析、标准配置、操作记录、后台执行、证据修订、状态与交付管理。当前网页只开放固定 Profile 的一部分操作，不能用网页选项反向限制 AI Data 程序接口支持的所有用法。

## 七、观察图数据与完整特征运行数据是什么关系

这里有三种不能混同的数据对象：

| 数据 | 主要用途 | 与图的关系 |
|---|---|---|
| **观察图对应的正式特征切片** | 在观察时间窗内理解行情、Feature occurrence 和相关业务事实 | 与图共享 AI Data 的节点、上下文和证据配置 |
| **图层共享显示视图** | 对齐用户实际看到的图层数值、坐标和展示变换 | 是图形显示层数据，不是正式主证据 |
| **特征全链路运行结果** | 追查从输入特征、责任块中间计算到目标输出实际发生了什么 | 可能与图对应切片包含重复结果，但具有另一种运行范围和信息层次 |

完整特征运行结果可沿既有特征运行实例取得输入 Feature、责任块中间事件和目标 Feature 输出。它不属于“每张图自动附带的全部数据”。当观察进入具体问题研判时，可以按需同时使用两类数据，但必须保留它们各自的运行身份和时间范围。

此外，AI Data 的图为了显示上下文可以比正式节点切片的时间范围更宽；这属于展示与数据切片的不同范围定义，不应被直接认作二者不一致。

## 八、总体关系列表

| 编号 | 对象间关系 | 关键边界 |
|---|---|---|
| R01 | 工作区**承载**特征、数据及绘图所需执行环境 | 工作区不是 Feature 或 Run |
| R02 | Sof**定位／提供**数据源访问与配置 | Sof 不等于物理数据集 |
| R03 | 运行上下文**选择** Sof、对象、日历和时间条件 | 构造特征实例不等于执行 |
| R04 | Feature 实例**在上下文中执行并产生**结果 | 结果身份与参数、数据条件有关 |
| R05 | CAEGraph**包含** PlotSet，并借布局、绘图类**显示**数据 | CAEGraph 不是一张静态图 |
| R06 | 平台**登记** CAE 对象为节点，并**提供**页面 | 图形定义、平台注册对象、页面不同 |
| R07 | AI Data Run Brief**绑定**上下文、定位特征和 Evidence | 不等于用户操作的状态记录 |
| R08 | AI Data Run**生成／复用**观察时间节点 | 观察节点不等于平台 CAE 节点 |
| R09 | AI Data**依据**时间节点**关联**图与对应正式切片 | 显示范围可以包含额外上下文 |
| R10 | AI Data**使用** UPlot 和平台 CAE**形成**图引用 | UPlot 不依赖 AI Data 才能绘图 |
| R11 | AI Data**组合**正式切片、定位来源、行情与图引用为交付包 | 图层共享视图不取代正式切片 |
| R12 | User Operation**通过** Profile／Registry**形成** Run Brief 并调用核心能力 | operation_id 不是 run_id |
| R13 | Build Evidence**生成** Evidence Revision，Refresh Chart**更新**图状态 | Revision 不是特征业务版本修订 |
| R14 | 全链路取数**依据**特征运行实例**取得**输入、中间、输出 | 不等于 AI Data 图对应切片 |
| R15 | 观察工作**消费**图及对应数据，必要时**追溯**完整计算结果 | 两种取数用途不同，可以交叉引用 |

## 九、需要保持区分的身份

| 常见说法 | 实际上可能指不同对象 |
|---|---|
| “运行” | 特征执行、AI Data Run、User Operation、生产团队 Run |
| “节点” | 观察时间节点、平台 CAE 节点、Feature 自身的业务节点 |
| “图” | CAEGraph 定义、PlotSet、平台节点、实际打开的图页面 |
| “图的数据” | 正式特征切片、行情上下文、图层共享视图 |
| “完整运行数据” | 特征输入、中间责任块结果与最终输出 |
| “版本” | FeatureVersion、Evidence Revision、Profile 版本或运行身份 |
| “工作区” | 可执行工程现场，不是 Sof、数据集或某次 Run 的产物目录 |

## 十、当前模型的事实程度与后续边界

已直接由现有源码与说明支持的关系：Sof 和特征运行上下文的分工；UPlot 的 CAEGraph／PlotSet／绘图类结构；AI Data 的 Run Brief、Core、观察节点、正式切片和交付；AI Data 创建平台 CAE 节点的调用；用户操作服务的四类 Operation、Profile、Evidence Revision 与 Result；既有完整特征运行结果的输入—中间—输出组织。

“特征运行工作区”“实际数据集”“整个绘图与观察数据体系”等名称是为认识系统所作的概念归纳，不表示已确认存在同名数据库实体或统一技术类。

**本轮不优先核实平台侧内部对象细节。** 只保留已证实的“CAE 对象—平台 CAE 节点—图页面”使用关系，不把平台节点存储字段和 Trier 页面内部结构写成既定结论。

对象及上述关系确认后，再单独更新它们与现有仓库、代码类、文件夹、真实运行产物的对应关系。这里不再用文件夹反过来定义对象。
