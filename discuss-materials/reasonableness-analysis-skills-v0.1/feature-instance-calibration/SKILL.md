# 特征实例参数可调性分析与标定

## 1. 何时使用

- `business-discrepancy-diagnosis` 已将问题初步定位为参数可能修复（`POSSIBLY_ADJUSTABLE`），或参数对上游对象的影响尚需深入判断（`COUPLED_UNRESOLVED`）；
- 已有清楚的业务意图，需要为特征首次选择合理的实例参数；
- 需要判断不同业务位置能否使用共同的实例参数，或验证调整后的完整实例是否合理。

不负责从头重复偏差定位，不因某个输出不合理就直接试值，也不自行改变已确定的业务定义或业务逻辑。

## 2. 与现有三个 Skill 的边界

- `business-expectation-derivation`：形成有来源、可检验的业务预期；本 Skill 不重新发明验收标准。
- `business-evidence-comparison`：寻找、对照业务正反例和新旧实例的实际效果；本 Skill 复用其证据判断与效果对照能力。
- `business-discrepancy-diagnosis`：追到最早业务分歧，做低成本的参数可修复性初筛；本 Skill 承接其结论，负责深入求解参数并验证实例。

参数求解期间如果发现原定位有误，或出现新的上游数据、特征或业务逻辑问题，返回偏差诊断，不把它们当作参数问题强行处理。

## 3. 输入

对已有实例的修复，优先直接使用：

```text
FrozenExpectation / ExpectationRegister
EvidenceComparisonPackage
DiagnosisReport
  └─ parameter_repairability
当前特征实例及参数
相关代码、配置、时间与数据绑定
业务正反例及其原始行情窗口
```

已经完成的偏差定位和证据对照不得无理由重新做一轮。

首次实例化时，可以由明确的业务意图、最小可检验预期、现有配置能力和真实数据直接进入，不强制先产生一次偏差诊断。

## 4. 执行步骤

### 步骤 1：参数可行域求解

以当前已有的业务预期和关键位置为依据，检查各可疑参数的业务含义、定义与消费位置，以及它们和上游输入、状态、其他参数的关系。

先明确完整特征实例原本希望表达的物理意义；对本轮涉及的局部对象或判断单元，按具体情况识别哪些参数与规则共同形成其局部物理意义、现有实例实际上表达了什么。区分已有业务定义与 AI 根据证据形成的候选解释，不重新定义原业务目标。参数间存在技术依赖或共同消费，不等于它们共同定义同一物理意义；也不要求为每个辅助参数强行赋予独立物理意义。

求解之前，识别参数的派生关系、共同消费、前后级联与相互制约，区分当前合法的独立自由参数和必须随之派生的参数。对于确实存在交互的参数，应在合法自由度内反求联合可行域，而不是分别求出区间后随意组合。

利用已有公式、隶属函数、规则和后置门，尽可能从目标业务结果反求参数的允许范围：

- 固定当前中间输入时，参数怎样改变才能使目标中间判断满足预期；
- 是否有不受当前参数影响的前件、门或状态，使期望结果始终不可达；
- 参数是否同时影响上游切段、候选身份或其他消费位置；
- 当前证明只适用于固定中间数据，还是已经覆盖完整特征实例。

有充分证据表明现有可配置能力无法解决的问题，不再盲目试值；保留不可调依据，返回偏差诊断并按其路由移交。

### 步骤 2：跨位置共同求解

对多个业务上清晰的正反例，分别反求允许的参数范围或参数组合，检查是否存在共同可行范围。存在参数交互时，应保留各位置对参数组合的联合约束，再求这些联合可行域的交集；不能仅将每个参数单独求出的区间机械组合。共同可行的参数组合还应在各位置保持预期的局部物理意义，不能只看输出类别是否相同。

- 存在交集：从共同范围内研究少量候选，而不是平均各位置的单独最优值。
- 没有交集：先分析冲突是否因为可解释的品种、时段或市场环境差异。
- 差异有明确业务依据，且现有实例机制支持分别配置：考虑按适用条件形成不同实例。
- 差异没有合理解释，或现有输入无法区分应产生不同结果的位置：返回偏差诊断，核实预期与输入；涉及新业务前件或新参数生成逻辑时移交叙事迭代。

不因不同位置要求不同数值就自动增加动态参数或新的业务规则。

### 步骤 3：少量候选试验

仅选择经过前两步分析、具有业务依据的少量参数候选。有证据表明多个参数存在实质性交互时，允许对关联的小参数组联合试验，不默认必须逐参数单独调整；也不因逐参数调整无效就直接否定联合调整：

1. 先利用已存中间数据进行低成本复算，检查参数是否真正生效及目标判断是否改变；
2. 区分用于排除原因的诊断性干预与用于获得实例的正式标定；
3. 若参数会改变上游输入、分段或状态，再进行必要的完整上游重跑；
4. 记录目标改善及可能影响的其他消费处；联合改变参数时检查其全部上游、下游影响，不只看最终输出条数。

对会改变上游对象的参数，不得只按原对象 ID 比较新旧结果；应回到固定的原始业务窗口和原始证据，判断新对象与新输出是否更合理。试验还需检查相关局部业务对象实际表达的物理意义怎样变化，是否丢失目标现象、混入不属于该意义的活动或破坏原本合理的局部过程。

### 步骤 4：完整实例验收或移交

调用 `business-evidence-comparison`，依据冻结的业务预期，比较新旧实例。验收重点是完整实例是否真正表达原本预期的业务物理意义，而不只是参数数值或输出类别达到某些条件：

- 本轮正反例是否得到合理处理；
- 未参与调参的场景是否仍然合理；
- 上游对象、其他下游输出和状态是否出现不合理副作用；
- 参数依据、适用范围与未决问题是否清楚；
- 整体和关键局部物理意义是否与原预期一致，有哪些真实案例支持或反证。

若证据足以支持当前业务目的和预期物理意义，固定候选实例及其参数和适用范围。若调整后形成了证据较充分、可能有价值但不同于原预期的物理意义，不得据此宣布原实例合理，应将其作为候选解释反馈给 Owner 或叙事迭代。若仍有偏差，返回 `business-discrepancy-diagnosis` 继续查因；若已有不可调证据，移交相应叙事／实现问题，不继续无依据试值。

## 5. 输出

### `CalibrationResult`

包含并引用以下结果：

```text
ParameterEffectMap
    参数定义、消费位置；派生、共同消费、级联、相互制约关系；哪些参数和规则共同形成局部物理意义
CalibrationEvidence
    少量单参或联合候选的依据及实际生效证据
InstanceComparison
    新旧实例在业务正反例、其他场景和上下游的效果对照，以及局部物理意义的变化
InstanceReasonablenessVerdict
    优先说明完整实例的预期物理意义、实际表达的物理意义及差异；
    关键局部物理意义、支持与反证案例、适用范围和剩余问题；
    再说明参数值及其依据，判断是否达到本轮业务目的
EscalationPacket
    超出参数可配置能力的问题及已有证明（如适用）
```

复用现有预期版本、证据来源与 `DiagnosisReport`，不再另立一套业务合理性判据。

## 6. EAW 用例中的边界示例

`t_gap_attack_ticks` 既用于上游攻击段切分，又参与下游接着打的间隔归一化。

在固定既有攻击段的中间数据下，可以由间隔得分、隶属区间、规则与门反推参数条件；但改变 `t_gap_attack_ticks` 后，攻击段本身可能合并、分裂或消失，原相邻对也可能不存在。

因此：

```text
固定中间输入下可调
≠
完整实例重跑后仍可得到合理业务结果
```

诊断 Skill 应先识别这种耦合和明显不可调的约束；本 Skill 才负责进一步分析不同真实位置的可行范围、少量有依据的候选与完整重跑后的业务效果。

## 7. 强制约束

1. 不先枚举参数再用输出数量选择看起来最好的值。
2. 不重复现有偏差诊断已经完成的调查。
3. 对已证明无法由参数解决的场景，不继续试值。
4. 不把局部中间数据复算视为完整实例有效性的证明。
5. 不把对象重分段、合并或消失直接计作业务改善。
6. 不在多个位置要求不同数值时，未经证据自行引入新的参数生成函数或业务逻辑。
7. 不把实现符合性当作业务合理性；不无痕修改被冻结预期。
8. 不替 Owner 决定真正的业务取舍，叙事或实现问题按诊断路由移交。
9. 不得默认多个参数彼此独立，也不得仅凭逐参数单独调整无效就判定联合调整无效；应先识别明确的参数关系及合法自由度，再分析联合可行性。
10. 不得仅因数值或输出类别符合预期就宣称实现了原预期物理意义；不得将调参后形成的其他物理意义冒充原特征目标。
