## 2. 要解决的不是“任何情况都允许强行发送”

目标：在 Owner 已授权的真实运行中，**不因 UI 文案变化或历史入口失效而无意义停跑**；确实配置不可用时优先处理/有界恢复，若 Owner 预先明确允许降级则在边界内继续，同时保留真实配置和专业质量影响；对未获准降级、身份/权限冲突和未知发送状态，仍须守住合法门禁。

需要明确区分以下情况：

| 场景 | 待设计的预期处理（尚非现行规则） |
| --- | --- |
| UI 文案/入口变化，但可以由新鲜证据证明配置满足 Owner 本 Run 目标 | 不要求字面显示历史标签；记录实际控件/配置证据，按原调用继续 |
| 目标配置确实不支持，且 Owner **在 GO 中预授权了具体降级边界** | 尝试合法档位、保存请求值与实际值/原因/可能专业影响；由管理 Pro 判断哪些结果需后续复验 |
| 目标配置不能证明已满足、且没有 Owner 降级授权 | 不擅自换档或假报等价；只阻断受影响发送，继续其他合法独立工作并说明最小解除条件 |
| C/发送状态 UNKNOWN、目标聊天/权限不明 | 保留原发送身份并实际对账；禁止因“不能停”而盲目重发、改号或绕过授权 |

**不能静默把较低档位称为 Pro**，也不能把任何已完成的低档调用无条件当作高档业务结果。

## 5. 将来落地时的最低验收用例

- **UI 文案变化**：不出现 `Pro` 文本但操作证据满足该 Run Owner 定义时，不产生虚假阻断，能按原 C 安全发送。
- **不能满足首选、有显式备选许可**：记录实际档位、原因及专业影响，合法继续；不假报 Pro 等价。
- **不能满足首选、无备选许可**：只阻断受影响动作，不擅自降级、不重复发送；其它合法工作可继续。
- **在途/UNKNOWN**：即使需要快速恢复，也不能重发原 C 或创建第二个竞争调用。
- **兼容性回归**：对通用发送、附件发送、单 Run 与多 Run 的各自责任验证通过；使用受控测试/合法真实回执，不拿尚未发生的动作冒充联调成功。
