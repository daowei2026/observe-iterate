你对第一点的纠正是对的。我之前把这项工作又往「设计验收」的方向带了一点。

**你这边工作的主要目的不是证明现有设计基本合理，而是尽可能从真实数据中发现具有较高业务价值的迭代点。** 证明某些设计够用，只是帮助缩小进一步分析的范围，不应该成为主要任务或主要产出。

这也意味着，给 AI 安排分析任务时，不能只是让它检验几个已有的假设，然后根据结果判断是否通过。还需要让它主动寻找原有设计没有表达好的业务差异，并进一步定位到具体的设计选择。

# **一、先进一步明确这项工作的意图**

我认为可以将你现在的工作定位进一步收敛为：

**通过真实数据，发现当前业务叙事中值得增加、改变或者重新组织的业务信息，并明确这些变化具体涉及当前设计中的什么内容。**

例如，期望发现的迭代点可以具有以下性质：

| 迭代点的性质        | EAW 中可能的例子                      |
| ------------- | ------------------------------- |
| 缺少一种业务现象的表达   | 没有异常大挂单，但持续补充形成的防守过程            |
| 缺少重要的业务属性     | 墙存在期间的挂单强度及其变化速度                |
| 对象的组织方式不够合理   | 不同性质的流动性过程被组织成了同一堵墙             |

这些都不是单纯的 Bug，而是有可能使业务叙事本身得到改善的方向。

而且我认为，你不一定要负责把每个迭代点的最终解决方案设计出来。你需要达到的程度可以是：

> 通过什么真实数据现象，发现当前哪项设计有局限；这个局限为什么值得处理；下一轮设计需要解决什么业务问题。

这样的成果已经可以交给常远方那边进一步细化。

# **二、EAW 当前最值得开展的一个具体任务**

## **任务：研究挂单与成交的不同演化过程，寻找当前 P1 设计中有价值的信息遗漏**

这个任务并不是检查 WALL、Build、AttackSegment、Absorb 的每个设计分支。

它的出发点是：原有高频特征已经能够表达一部分主动成交信息，而 EAW 希望进一步利用挂单信息，获得更加丰富的业务叙事能力。

那么我们就应该主动研究：

**在成交表现比较相似的情况下，挂单的不同演化过程，能否帮助我们更好地区分市场中发生的事情？而目前 P1 的特征能否保留这些差异？**

我认为这里可以形成一条相对完整、能够实际执行的分析路线。

**第一步：从原始数据中提取挂单与成交的演化信息**

不以当前 P1 的事件类型作为唯一分类依据

**第二步：寻找真实市场中存在明显差异的过程**

通过统计和案例观察，发现有代表性的不同表现形态

**第三步：研究这些差异有没有业务价值**

比较价格推进、后续攻防、反向运动等方面的区别

**第四步：对照现有 P1 的表达**

判断这些有价值的差异是否已经被保留

**第五步：定位值得迭代的具体设计**

明确应该增加什么信息、改变什么识别方式或重新组织什么对象

# **三、第一步：从原始数据中提取什么信息？**

这里先不急着研究小尺度拐点，也不急着判断哪种 Wall 合理。

先围绕比较明显的盘口挂单过程，取得一组相对基础的业务信息。

## **3.1 选取观察区域**

第一轮可以从以下三种入口寻找候选观察位置。

| 选取入口      | 具体寻找什么               | 为什么要选               |
| --------- | -------------------- | ------------------- |
| 异常大挂单     | 出现大挂单之后的一段盘口演化过程     | 研究当前 Wall 主要覆盖的业务对象 |
| 同价位挂单显著变化 | 短时间内挂单增加或减少较多的位置     | 研究当前设计可能忽略的挂单变化     |
| 同价位持续成交   | 累计成交比较大，但可见挂单始终维持的位置 | 研究不一定表现为异常大挂单的防守结构  |

这三个入口可以有重合，不需要强制将它们分成互斥类型。

特别是后两个入口，不应该要求当前已经存在 Wall。否则，就很难找到现有 Wall 识别方式之外的业务现象。

## **3.2 对每个候选观察区域提取以下信息**

| 信息类别  | 具体需要的信息                                    |
| ----- | ------------------------------------------ |
| 价格    | 最新成交价、买一卖一价、价格推进与回退情况                      |
| 挂单量   | 初始量、当前量、最大量、最小量、逐 Tick 变化                  |
| 成交    | 同价位方向成交量、累计成交量、成交发生的节奏                     |
| 补充与撤减 | 根据同价位挂单变化和成交量估计净新增挂单                       |
| 可见性   | 原来关注的价位是否仍在最优档、何时离开、何时重新出现                 |
| 现有特征  | Wall、Build、AttackSegment、Absorb 的实际输出及携带属性 |

其中需要重点提取的是挂单量与成交量之间的关系。

假设在同价位、可合理估计成交归属的情况下：

\\[ N_t=Q_t-Q\_{t-1}+C_t \\]

其中 \\(N_t\\) 是估计的净新增挂单量，\\(Q_t\\) 是可见挂单量，\\(C_t\\) 是对应价位的成交消耗量。

这能够帮助我们初步区分挂单减少到底主要能由成交解释，还是存在较大的净撤减，以及挂单在持续受到消耗时是否得到了补充。

由于只有半秒聚合及一档盘口，价位切换时不能直接延续这种量变计算，也不能将估计的净撤减当作精确的撤单量。

我建议先给 AI 一些具有明确业务意义的候选差异，作为寻找迭代点的起点。

但这些不是固定的分类体系，AI 需要结合真实数据进一步发现其他形态。

**维持一段时间后突然消退**

**多次减弱、恢复后再次减弱**

这些过程可能具有相同的起点和终点，但内部结构明显不同。

这一组直接对应你最开始提出的疑问：挂单连续几拍没有变化，随后迅速减少到正常水平，目前 Wall 的生命周期是否关注到了这种变化？

因此这不是无缘无故找一个新的分析角度，而是在研究**当初被主动舍弃的信息是否值得重新纳入叙事**。

# **五、第三步：怎样判断发现的差异有没有业务价值？**

这是整个任务最关键的一步。

如果只是找到很多不同形状的挂单曲线，最后可能又陷入大量细枝末节。

因此，对于前面找到的不同过程，要进一步研究它们在其他业务信息相近的情况下，是否表现出重要差异。

## **5.1 先研究价格推进与成交之间的关系**

例如，对于初始挂单量和累计主动买入成交量相近的卖方流动性区域，比较：

| 观察内容         | 想认识什么                 |
| ------------ | --------------------- |
| 成交过程中价格的净位移  | 相似的进攻力量是否带来了不同程度的价格推进 |
| 价格最大推进距离     | 是否一度接近或穿越原流动性区域       |
| 价格回退幅度       | 是否出现明显的反向运动           |
| 成交结束后的价格变化   | 挂单演化差异是否对应不同的后续表现     |
| 后续是否再次发生明显交互 | 流动性对象是否仍然具有业务相关性      |

这里我建议先采用连续的价格变化信息，而不是立即引入一个复杂的小尺度转折分类。

例如，可以在某个已经发生的挂单变化过程结束之后，观察后续不同时间长度内，价格向原攻击方向推进和反方向退离的程度。

这样能够暂时绕开前面关于贴近转折方向、区域型反转以及尺度定义的争论。

如果后面发现确实需要判断是否形成了某类小尺度反转，再引入相应的转折特征。

### **挂单演化与后续价格表现**

当然，需要控制品种、时段、前期运动方向、市场活跃度、初始挂单量和攻击强度等背景，避免把其他因素造成的差异错误归因于挂单演化。

# **六、第四步：拿现有特征的结果回答一个具体问题——重要差异丢在哪里了？**

假设第三步已经找到某种具有业务价值的差异，那么再去对照 P1 的输出。

我认为应该要求 AI 分别检查三个层次。

| 检查层次      | 具体问题                                |
| --------- | ----------------------------------- |
| 单个特征      | 当前 Wall 或 Build 等特征有没有直接表达这种差异？     |
| 多个特征联合    | 即使单个特征没有表达，现有四个特征的结果合在一起，能不能恢复这种差异？ |
| 底层计算与正式输出 | 是根本没有计算这种信息，还是内部计算过，但正式输出没有保留？      |

例如，假设发现快速净撤减与持续补充具有明显不同的业务意义。

那么就要分别追究：

Wall 有没有记录流动性强度的减弱？Build 有没有保留净撤减的信息？Absorb 有没有携带足够的可见量与成交消耗信息？这些信息在当前输出中能不能被联合使用？

最终可能得到以下几类结果。

**情况 A：已有信息足够，但还没有形成相应的业务组合**

例如，Build 和 Absorb 的已有属性联合起来就能够表达某种差异。

迭代方向：研究上层叙事的组合关系，而不是修改底层识别。

**情况 B：底层计算了相关信息，但没有对外保留**

例如，内部已有可见剩余量，但正式稀疏事件不能表达重要的变化过程。

迭代方向：重新考虑属性和关键点的信息取舍。

**情况 C：当前识别方法本身遗漏了某类现象**

例如，没有异常大挂单的持续补充型防守根本没有进入 Wall 的识别范围。

迭代方向：改变识别入口，或者增加一种业务对象。

这三类结果都能够比较具体地指向后续的叙事或特征设计工作。

应该要求 AI 尽可能形成有真实数据证据支撑的**候选设计迭代点**。

例如下面这种交付结构：

### **候选设计迭代点示例**

这是产出格式示例，并非已经发现的真实问题。

**迭代点：重新审视 WALL 对流动性减弱过程的表达**

1\. 新发现的业务认识

# **九、我建议当前先安排这一项任务，而不是同时研究所有特征**

| 研究方向                   | 当前安排                  |
| ---------------------- | --------------------- |
| 挂单与成交演化过程中的重要业务差异及信息遗漏 | **优先实际开展**            |

这样安排的原因是，第一项研究不需要完整 EAW 或 P2 已经实现好，也不需要先把转折定义研究清楚，就有机会发现 Wall、Build、Absorb 等现有设计中值得重新审视的信息取舍。

更重要的是，它能够为以后沉淀 Agent 提供一条实际走过的业务分析路径：

**寻找真实市场中的重要差异 → 判断差异的业务价值 → 检查现有表达是否保留了差异 → 定位具体设计的迭代点。**

我认为这条路径比之前的「给预期、看数据、找不合理问题」更具有主动发现新业务知识的能力，也更符合你现在希望开展的工作。
