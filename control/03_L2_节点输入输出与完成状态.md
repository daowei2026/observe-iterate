# L2｜节点输入输出与最小完成状态

## 1. 节点表

| 节点 | 必需输入 | 主要输出 | 正常后继 |
|---|---|---|---|
| U 复用并核对理解 | 名称、代码版本、实例、旧 Package／Chat、源码与读取接口 | 当前最小 `FeatureUnderstandingPackage` 或受影响部分 delta | X |
| X 实例运行 | 精确代码、参数、数据、日历、执行入口 | `FeatureRunResultBinding` | G |
| G 全量统计与高置信发现 | U、X、ReviewTarget、必要分层 | `GlobalBehaviorProfile`、`FindingDiscoverySummary`、当前结果绑定的 `CandidateFindingQueue`、`GlobalProfileGate` | Q |
| Q finding 队列判断 | 当前 finding 状态、队列快照、Owner 指定候选状态 | 下一待处理 finding，或“无待处理 finding” | D 或 Release |
| D 偏差诊断 | 单个 finding、处理链、证据、业务意图 | `LogicLocalization`、`DiagnosisReport`、责任阶段、确认事实、竞争解释、后续处理类型 | M、B 或 Q |
| M Feature 行为修改 | 已定位的 Feature 行为问题、`LogicLocalization`、反例和修改范围 | 修改结果、必要回归与新旧比较 | X |
| B 运行前提／结果绑定修正 | 错误版本、参数装配、范围、入口、结果身份或读回证据 | 修正后的运行绑定 | X |
| Release | 最新 U/X/G、`FindingDiscoverySummary`、finding 状态、已知限制 | `FeatureReleaseGate`、`UpstreamReleasePackage` | 下游或等待汇合 |

X 是实际运行，不是新 Skill；M、B 是 D 的两类后续处理，也不是所有 Run 必经的新阶段。`FindingDiscoverySummary` 是 G 的结果，`LogicLocalization` 是 D 内部必须形成的诊断结果；二者都不新增主干节点。

## 3. Finding 状态

```text
CANDIDATE
DIAGNOSIS_IN_PROGRESS
CONFIRMED
FIX_IN_PROGRESS
FIXED_PENDING_RERUN
CLOSED_ON_LATEST_PROFILE
DEFERRED_BY_SCOPE
REJECTED_AS_NON_ISSUE
SUPERSEDED
```

`candidate_origin` 另行记录：

```text
EXECUTOR_DISCOVERY
OWNER_RAISED
REGRESSION
```

Owner 提出的候选可以先登记为 `CANDIDATE + OWNER_RAISED`。这意味着必须在释放前完成判断，不表示预先确认代码缺陷或业务规则错误。

`FIXED_PENDING_RERUN` 不能算关闭；只有最新实例和最新全量统计确认后，才进入 `CLOSED_ON_LATEST_PROFILE`。

finding 从 `DIAGNOSIS_IN_PROGRESS` 进入 `CONFIRMED` 或 M 前，应已有 `logic_localization_ref`。如果当前只能定位到处理阶段，记录最窄已定位范围与未决点，不用推测填补。

若 finding 的原因是运行绑定错误而不是 Feature 行为错误，可以在进度记录中注明 `binding_correction`，不需要为此再建立一套 finding 状态体系。

## 4. G 完成检查

G 进入 Q 前至少回答：

- 当前正式结果绑定是什么；
- 哪些业务面被检查，为什么适用于当前 Feature；
- 是否在发现第一个候选后仍完成其余适用业务面的高置信发现；
- 哪些现象被升级为高置信候选，为什么；
- 哪些观察未升级，为什么；
- Owner 指定候选当前是什么状态；
- 哪些业务面没有检查，是否影响当前 Gate；
- 当前队列快照精确引用在哪里。

参考类别不是固定检查表。执行者可以依据当前 Feature 的对象语义和结果提出清单外候选，也可以在证据不足时不升级某个参考现象。

## 5. Release 完成检查

本轮单 Feature 可以释放时，至少回答：

- 当前代码、参数和数据范围是什么；
- 最新运行结果在哪里、是否读回；
- 统计过哪些业务对象链和结构不变量；
- 当前 `FindingDiscoverySummary` 与队列快照在哪里；
- 原有已知问题在最新版本中的状态；
- Owner 指定候选是否已经完成判断；
- 是否仍有尚未处理的高置信 finding；
- 每个已确认 finding 的责任逻辑定位在哪里、为什么定位到这里；
- 哪些问题已关闭、暂缓或仍未决；
- 下游将消费哪一份 ReleasePackage；
- 什么变化会使该结论失效。

## 6. 不要求的工程记录

以下内容除非影响结论，否则不要求进入正式状态：

- 每条 shell 命令；
- 每次中间导出；
- 每个临时脚本版本；
- 每项无业务影响的性能数字；
- 为了填模板而产生的空字段。
