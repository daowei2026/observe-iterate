# 跨层业务完成全景与更新协议（候选控制设计 V0.2）

> **位置**：`control/`。本文件规定共享 Feature 理解、Feature 运行、全量行为统计、观察材料、场景合理性、诊断／标定和外部接口的持续完成视图。它不是新的专业 Skill，也不是已经实现的数据库或程序。
>
> **关联**：[L0 总任务](01_L0_完整业务任务与双向衔接.md)｜[L1-M B～E](02_L1_观察材料准备流程.md)｜[L1-R](03_L1_合理性分析流程.md)｜[L2 I/O](04_L2_节点输入输出登记表.md)｜[Gate](05_三级Gate及后继路由.md)。

## 1. 为什么必须维护全景

任何一次正式进度查询都应能从已核实事实回答：

- 当前 Feature 名称、代码版本、参数实例和数据范围；
- `FeatureUnderstandingPackage` 是否有效，哪些对象、状态、事件或字段仍未确认；
- 当前 Feature 是否已真实运行，artifacts 和实际范围是什么；
- 全量行为统计做到哪里，当前 `GlobalProfileGate` 是什么；
- 哪些结构疑点等待 Skill 3，哪些参数问题等待 Skill 4，哪些实现／设计问题在外部接口；
- 最新修正是否使旧运行、旧统计、旧图和旧场景结论失效；
- 观察材料 B～E 做到哪里，是否达到 `DATA_READY`；
- Skill 1 选择了哪些真实案例，哪些预期已冻结；
- Skill 2 哪些案例已完成三条过程链和第一次业务分歧分析；
- 当前版本在哪些范围被支持、有哪些反例、哪些属于覆盖外或证据不足；
- 父任务可以结束、受阻，还是仍有合法工作可做。

全景由原生 Skill 产物、运行 artifacts、Worker 记录、Gate 和外部处理返回投影生成。写了一份全景文档不会改变真实完成状态。

## 2. 聚合层级

| 层 | 记录／汇总对象 | 完成或未完成的含义 | 聚合到 |
|---|---|---|---|
| **实际工作实例** | U/X/G、B～E、S1/S2、Skill 3/4、外部修正和一次复用 | 输入真实可用，原生输出被核实，版本与返修关系明确 | 对应阶段实例 |
| **L1 阶段实例** | 共享理解、运行、全量统计、材料准备、场景分析、问题处理 | 本阶段必需产物满足消费者，或形成合法限域／阻断结果 | 本轮业务问题 |
| **业务问题** | `question_id + analysis_round_id` | 是否回答到本轮约定深度；支持、反证、覆盖外、未决和不可调都可成为结果 | 父业务任务 |
| **父业务任务** | `business_task_id` 和当前有效完成要求 | 必答问题是否满足，是否还有合法必做工作 | `TaskProgressOverview` |

不使用未经定义的“完成百分比”；先记录已完成、在途、受阻、待验、失效和不适用的真实范围。

## 3. 阶段完成判据

### 3.1 U｜共享 Feature 理解

至少有：

- 当前 Feature、代码版本和实例引用；
- 业务对象及身份作用域；
- 状态和已实现转换；
- 输入／输出 occurrence；
- 业务主输出和关键中间判断；
- 处理关系；
- 参数定义、派生和消费位置；
- 运行结果字段映射；
- 未确认项及对下游影响。

只有“读过代码”或列出函数名，不等于 U 完成。

### 3.2 X｜Feature 执行

至少有：

- 代码版本；
- 参数实例／版本；
- 数据范围、日历和 Session；
- 执行入口与环境；
- artifacts、日志和实际加载范围；
- 核心输出可读取状态。

文件存在但版本、参数或范围无法绑定，不等于 X 完成。

### 3.3 G｜全量行为统计

至少有：

- `StatisticsInputReadiness`；
- 每项统计的对象单位、对象键、时间基础、分母、去重和同刻规则；
- 对可用对象、状态、事件、生命周期和分层形成的 `GlobalBehaviorProfile`；
- 结构疑点与场景解释问题分开；
- 代表位置和证据引用；
- `GlobalProfileGate`。

统计出若干数字但没有明确“数的是什么”，不等于 G 完成。

### 3.4 D／P／外部接口｜问题处理

#### Skill 3 完成

- 偏差陈述具体；
- 事实与竞争解释分开；
- 处理链和最小责任阶段清楚；
- 需要的区分检查已做或缺口具名；
- 参数可修复性状态和路由有证据。

提出“可能原因列表”不等于完成诊断。

#### Skill 4 完成

- 参数定义、消费和耦合关系清楚；
- 可行域与跨位置共同范围有依据；
- 候选试验真实生效；
- 完整实例的物理意义和副作用已评估；
- 形成新实例或有界不可调结论。

局部中间复算改善不等于新实例完成。

#### 外部实现／设计返回完成

- 返回物与原 diagnosis 绑定；
- 实现返回含 commit、改动、测试和新版本；
- 设计返回含业务定义、实现要求、验收条件和版本；
- 需要的实现已经完成；
- 后继 U 或 X 已明确。

只有口头答复或只有 commit、未说明行为变化，不能解除等待。

### 3.5 M｜观察材料准备

共享 Feature 理解不再记为 M-A；M 只记录 B～E。

#### B 完成

- 任务指定位置、普通经验默认或高频多尺度路径已形成；
- 位置属于当前实例并可被 D 绑定；
- 来源和限制清楚。

#### C 完成

- C1 根据共享 Package 列出输入、主输出、状态和必要中间判断；
- C2 已读原手册、形成第一版 HTML，并在复杂点循环中同步更新同一份预期与 HTML；
- C3 整理出位置、实例和字段可注入代码；
- 预览实例没有被固化；
- 能力缺口和语义损失清楚。

#### D 完成

- 理解本次实际使用的 CAEGraph 调用链；
- 真实实例、B 位置和共享字段已绑定；
- C2 展示语义未被无痕改写；
- 形成可直接交 E 运行的完整定义；
- 确定性纠正有记录，拿不准的问题已返回来源。

#### E 完成

- W1 提供真实运行事实；
- E 完成问题分类和专业核图；
- 图通过 D 与 C2 双重核对；
- E4 形成正式取数准入；
- W2 导出绑定该运行的正式图数据；
- 图与数据一致性核对通过；
- 形成 `ObservationMaterialPackage`。

只有 HTML、只有 W1 成功或只有未核对数据，不等于 `DATA_READY`。

### 3.6 S1｜场景选择与预期冻结

至少有：

- 当前 `CurrentReviewTarget`；
- 案例来自同版本 `ObservationMaterialPackage`；
- 具体品种、开始和结束时间；
- 明确案例类型；
- 不只从已有输出选择，已考虑潜在漏报；
- 每个案例的原始过程描述和预期 Feature 过程；
- 支持、反证、未决和 non-goal；
- `CaseReviewSet` 与 `FrozenExpectationSet` 已冻结。

看到图、记下几个位置，不等于 S1 完成。

### 3.7 S2｜场景过程对照

至少有：

- `RawMarketProcess`；
- `ExpectedFeatureProcess`；
- `ObservedFeatureProcess`；
- 对象身份、时间和中间判断对齐；
- `EarliestBusinessDivergence` 或无法定位的具体限制；
- `EvidenceComparisonPackage`；
- 材料缺口、覆盖外、新预期候选和诊断疑点已分流。

只看最终输出、没有中间过程，不等于 S2 完成。

### 3.8 R｜本轮综合交付

至少说明：

- 当前有效版本和参数实例；
- 全量 Gate；
- 当前支持范围；
- 当前反例和失败场景；
- 覆盖外；
- 证据不足与未决；
- 已处理参数／实现／设计问题；
- 下游是否达到软 Gate；
- 下一轮工作。

## 4. 状态词

每个工作实例和阶段至少使用：

```text
NOT_STARTED
IN_PROGRESS
WAITING_INPUT
WAITING_EXTERNAL
READY_FOR_REVIEW
ACCEPTED
PARTIAL_WITH_LIMITS
BLOCKED
INVALIDATED
NOT_APPLICABLE
```

专业原生状态另外保留，例如 `PASS_TO_SCENARIO_REVIEW`、`SUPPORTS`、`COUNTERS`、`POSSIBLY_ADJUSTABLE`，不得全部压成管理状态。

## 5. 失效传播

| 变化 | 必须失效或重验的范围 |
|---|---|
| Feature 代码版本变化 | U 核对；X/G/M/S1/S2 旧结果失效 |
| 参数实例变化 | X/G/M/S1/S2 旧结果失效；U 更新实例绑定 |
| 对象／状态／事件／处理中间结构变化 | U 及所有下游失效 |
| 数据版本或时间对齐变化 | X/G/M/S1/S2 失效 |
| 只补运行结果字段、不改行为 | U 字段映射和依赖该字段的 G/M/S1/S2 重验 |
| 只改图形展示 | M-C～E 与依赖该图的 S1/S2 重验 |
| 只改案例或场景预期 | S1/S2 重验；U/X/G/M 不失效 |
| 新证据只影响某个案例解释 | 该 S2 结果和相关诊断重验；但若据此改 Feature，仍回 X→G |

当前 V0.2 不做复杂的局部依赖自动计算；若不能确定失效范围，采用保守重跑规则。

## 7. 更新时机

以下任一事实发生时必须更新全景：

- U Package 被接受、修订或失效；
- Feature 运行成功、失败、范围变化或版本变化；
- G 形成新剖面、疑点或 Gate；
- Skill 3／4 或外部接口有新结果；
- 参数／实现／设计修正触发重跑；
- B～E 任一阶段被接受、退回或阻塞；
- `ObservationMaterialPackage` 状态变化；
- S1 案例或预期被冻结、修订或退休；
- S2 完成案例分析或形成新疑点；
- 某产物因版本变化失效；
- 父任务完成条件被满足、改变或无法满足。

更新必须引用真实产物、Gate 或返回记录，不用口头推测覆盖现有状态。

## 8. 当前不维护的复杂指标

V0.2 不维护：

- 完成百分比；
- 自动问题优先级；
- 自动跨问题影响图；
- 局部重跑成本最优化；
- 将问题数量当作 Feature 质量分数。

先用 EAW Wall 和一个 FQA Feature 验证这份全景是否足以支持真实运行，再决定下一版控制项。
