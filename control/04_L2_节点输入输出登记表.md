## 2. 共享理解、运行和全量统计

## 7. 全量 Gate 消费规则

| Gate | 下游资格 |
|---|---|
| `BLOCKED` | 不得进入正式场景线；先修正版本、数据、对象键或核心字段 |
| `DIAGNOSIS_REQUIRED` | 进入 D；未经诊断不得把疑点当成已解决或直接调参 |
| `RERUN_REQUIRED` | 旧 G、M、S1、S2 结果失效；先 X→G |
| `PASS_TO_SCENARIO_REVIEW` | 可进入 M；不代表 Feature 已合理 |

## 8. 不把“输出存在”误认为“输入就绪”

| 错误理解 | 准确资格 |
|---|---|
| U 有一份文档 → 可统计 | 对象键、事件、状态和运行结果字段必须与当前实例一致 |
| X 有文件 → G 可用 | 代码、参数、数据范围和实际 artifacts 必须绑定且可读取 |
| G 有统计 → 已合理 | G 只完成结构剖面；需按 Gate 诊断或进入场景线 |
| M 有 HTML → `DATA_READY` | 必须核图、正式取数并核对图数据一致性 |
| S1 看到案例 → 可正式判断 | 必须冻结案例和场景预期 |
| S2 有反例 → 立即调参 | 先 D 定位根因与可调性 |
| P 局部复算改善 → 新实例合理 | 必须 X→G；通过 Gate 后重做 M／S1／S2 |
| 外部修正有 commit → 闭环 | 必须判断是否更新 U，并重跑 X→G |

## 9. 当前不建设的节点

V0.2 不新增：

- 问题影响范围与依赖分级 Skill；
- 多问题并行调度节点；
- 局部统计替代全量重跑的 Gate；
- 场景反向驱动画图的自动节点。

这些只在 EAW Wall 与一个 FQA Feature 实跑后，根据真实成本决定。
