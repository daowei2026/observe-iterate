# L2｜工作节点输入输出登记表：细到可以发现缺环，但不把 Skill 拆成固定调用

> **材料准备按 [control/02](02_L1_观察材料准备流程.md) 的 A～E 外层 Workflow 推进；阶段的专业判断和字段级 I/O 以对应 Skill 文件为准。** A／C／E 有内部 Workflow；B 只记录当前经验性用法；D 是单一集成动作，没有 `WORKFLOW.md`。不强制每个内部步骤独立调用 Pro，也不允许因合并委派而略过上游产物。旧“0～7 步”及历史 `Mxx` 只用于读取既有报告，不作为新工作的现行节点。

## 1. 一次节点工作需要的最小交接封面（【N】）

```yaml
node_id: <M 使用 A/B/C/D/E 或阶段内部步骤；R 使用 R07 等；仅作现有成果定位>
question_id: <当前业务问题>
stage_view: <M-A～M-E 或 R0～R5>
stage_instance_id: <本问题/材料批次/分析轮次的阶段实例>
work_item_id: <具名工作>
input_refs: [<已取得且可复查的上游产物>]
input_versions: {code: ..., data: ..., feature_instance: ..., expectation: ...}
required_input_scope: <对象、时间、用途、就绪等级>
expected_outputs: [<阶段原生产物或最小可核查结果>]
completion_condition: <本工作何时可以被消费者使用>
possible_outcomes: [<成功、限定、缺证、不可得、返修等>]
continuation_target: <各结果的具体后继阶段/条件>
progress_evidence_refs: [<可用于汇总完成、返修、阻断的结果或 Gate 引用>]
```

这不是要求每个字段或内部步骤单独填写一份表。一个完整阶段产物可承担多数内容；封面只补精确身份、依赖和接续信息。

## 2. 观察材料准备：A～E 阶段 I/O 与后继

| 阶段 | 最小输入 | 可核查专业成果 | 后继所需条件／异常返回 |
|---|---|---|---|
| **A 特征事件级 occurrence 理解** | 外层输入：特征名称、特征代码版本、特征实例；可定位的源码、类型和接口 | `特征事件级 occurrence 与发生位置说明`、`特征处理关系说明`、未确认项；区分输入、业务主输出和中间处理结果 | 事件、位置和主处理链足以被 B/C/D 消费→B、C；缺核心代码事实留在 A 定向核查，不用需求猜代码 |
| **B 观察位置准备** | A 产物、外层特征实例、任务明确位置（如有） | 普通场景的经验默认位置，或高频 1d→30m→1m→5s→tick 多尺度位置路径 | 真实位置可由 D 绑定→D；位置无数据／不成立留在 B 修订；不因 C 展示方便改变位置 |
| **C 展示方式准备** | A 产物、只读按需使用外层特征实例、CAEGraph 专业知识和能力资料 | 待展示信息、展示预期、复杂点处理、位置与实例可注入代码、实例注入合同、预期 HTML 和能力缺口 | 展示结构、实例注入接口和 HTML 可被 D/E 消费→D；能力或展示语义问题留在 C；C 不固化外层真实实例或 B 最终位置 |
| **D CAEGraph 定义集成** | 外层输入、A/B/C 产物、锁定 CAEGraph 仓库 | 仓库理解记录；已绑定真实实例、字段、品种和时间的完整 Python CAEGraph 定义／脚本初稿；集成差异与定义级检查 | 可直接交 E 尝试运行→E；位置问题回 B，展示问题回 C，字段／集成问题留 D；D 是单一动作且不派 Worker |
| **E CAEGraph 执行／运行** | D 完整定义、C 展示预期／HTML、外层实例、环境和授权 | E 专业基准与判断；W1 运行／patch／日志；最终图核对；W2 正式图数据；图数据一致性核对 | W1 后由 E 用 D/C 专业核图；图接受后才形成准入并签 W2；位置／展示／集成问题分别回 B/C/D；最终按 `DATA_READY/PARTIAL_WITH_LIMITS/BLOCKED` 交接 |

阶段内部文件不另复制到本表；管理使用时直接引用对应文件和产物版本。尤其：D 没有内部 Workflow；E 的专业 `WORKFLOW.md` 与 `WORKER_DELEGATION.md`、W1／W2 模板是不同性质的文件。

**字段关系说明**：阶段产物是专业工作成果；`WorkItem` 是对专业工作的组织；Worker `ExecutionAction` 是 E 内的真实工具动作。一个阶段可以一次委派贯通多个内部步骤，也可以因真实缺口定向返修；不以字段数、图层数或内部步骤数机械决定调用次数。

## 3. 合理性分析：节点级 I/O

| ID / R 视图 | 节点目的（专业源） | 最小输入 | 原生或最小可核查输出 | 下一节点及可消费条件 | 缺口/失败处理 |
|---|---|---|---|---|---|
| **R01 / R0** 分析接管/事实准备 | 【S-R】README 双轨；预期推导输入三层 | 业务问题、已有材料/版本、已有预期（若有） | `AnalysisInputAssessment`【N】封面：哪些事实已确认、缺口和可开展范围 | 未具备预期→R02；已有清晰最小预期→R04；仅有部分数据→R03 有界探索 | 事实问题可局部查；需要独立新材料时走 L0 补证；尚未冻结预期的请求须标注探索上下文，不虚构 FrozenExpectation 或 DataBinding |
| **R02 / R1** 推导最小预期与场景 | 【S-R】`business-expectation-derivation` 步骤 1～8 | BusinessIntent、JudgmentTarget、来源/事实、候选样本 | `ExpectationRegister`（SEED/WORKING）、`InputSuitabilityAssessment`、`ScenarioExpectationSet`、`OpenQuestions` | R03 可探索；具备可检验命题→R04 请求冻结 | 分歧事实未确定→R01/局部查证；真实目标取舍只形成问题；不从实现自动证明业务合理 |
| **R03 / R1/R2** 小样本探索 | 【S-R】README + 对照 Skill 探索路径 | WORKING 预期、有来源且记录限制的真实小样本 | `ExploratoryFindings`【N】封面：已看样本/问题、新预期、未知字段 | 返回 R02 完善预期，或送 R04 | 不得作为正式 `SUPPORTS/COUNTERS`；样本不足则补小样本或注明无法探索 |
| **R04 / R1** 冻结对照预期 | 【S-R】预期推导第 9 步 | R02 候选、探索证据、来源/适用/反例、当前轮次 | `FrozenExpectationSet` 及版本 | `G-EXPECTATION-FREEZE` 合格→R05 | 不可检验/来源不明→R02；新命题形成新版本，旧版不覆盖 |
| **R05 / R2** 正式对照资格与证据映射 | 【S-R】证据对照步骤 1～2 | R04 冻结版、真实材料、DataBinding、TimeBasis、参数/代码版本 | `EvidencePreflight`、证据映射、缺口和质量问题 | 资格满足→R06 | 跨边界缺材料→L0 补证；材料存在不自动等于目的适用 |
| **R06 / R2** 场景与正式证据对照 | 【S-R】对照步骤 3～8 | R05、冻结预期、样本/场景/时间与版本 | `EvidenceComparisonPackage`、`ScenarioEffectTable`、新候选、`DiscrepancyQueue` | `G-COMPARISON`；值得诊断→R07；已达到要求→R13；新预期→R02 新版本 | `MISSING/AMBIGUOUS/PENDING` 是领域现象；有反证不叫工作失败 |
| **R07 / R3** 建立诊断与竞争解释 | 【S-R】诊断步骤 1～4 | R06 偏差、冻结预期、处理链和证据 | `DiagnosisReport` 候选、竞争解释和最早分歧候选 | 证据足够→R09；需最小检查→R08 | 没有具体偏差不强制诊断 |
| **R08 / R3** 低成本区分性事实检查 | 【S-R】诊断步骤 4～5 | R07 竞争解释、最小新证据和授权范围 | `MinimalDiscriminatingExperiment` 或 `AdditionalEvidenceRequest` | 返回 R07/R09；跨任务请求回原轮次 | 证据不可得形成有界未决，不重复无进展 |
| **R09 / R3** 定位、可修复性初筛与路由 | 【S-R】诊断步骤 6～8 | R07/R08 证据、业务目的和参数依赖 | 完整 `DiagnosisReport` 及可调性状态 | `G-DIAGNOSIS`；可调→R10；原预期问题→R02；能结案→R13；缺证→R08 | 已证明不可调不得盲试；实现/叙事问题形成外部候选移交 |
| **R10 / R4** 反求参数联合可行域 | 【S-R】标定步骤 1～2 | R09 定位或首次实例化入口；冻结预期、原始窗口和参数/公式 | `ParameterEffectMap`、联合可行域与冲突原因 | 可行且有试验资格→R11；无交集／不可调→R09/R13 | 不假设参数独立；不可实现时不枚举试值 |
| **R11 / R4** 少量有界候选试验 | 【S-R】标定步骤 3 | R10、预算/动作资格、真实数据和当前实例 | `CalibrationEvidence`、候选依据、实际效果与副作用 | 有必要候选→R12；不可行／成本不许可→R09/R13 | 局部复算不等于完整实例；上游对象改变须按原始窗口对齐 |
| **R12 / R4↔R2** 完整实例新旧复验 | 【S-R】标定步骤 4 调用证据对照 | R11、R04、原始窗口、新旧实例和对照口径 | 同一项 `INSTANCE_REVALIDATION` 的比较包，供 `CalibrationResult` 使用 | `G-CALIBRATION`：达标→R13；仍偏差→R07/R09 | 不重复执行同一次比较；旧对象 ID 变化不可直接一一对比 |
| **R13 / R5** 问题级分析交付 | 【S-R】各 Skill 结果 | 本次实际适用结果、限制和完成条件 | `AnalysisDelivery` + 原生结果 + `QuestionCompletionRecord` | `G-ANALYSIS-DELIVERY` 合格→L0 收束 | 不要求所有问题都经过诊断或标定；是否可结束按原完成定义 |

## 4. 不把“输出存在”误认为“输入就绪”

| 典型错误 | 准确的消费资格 |
|---|---|
| C 用真实实例生成预期 HTML → 实例已正式绑定 | C 只能作预览；D 必须按实例注入合同完成正式绑定 |
| D 有完整脚本 → E 已完成 | D 只提供可运行定义；E 仍须 W1 运行、专业核图、W2 正式取数据和一致性检查 |
| W1 有 HTML → `DATA_READY` | E 必须先与 D/C 核对图并形成取数准入，再签 W2 正式取得图数据 |
| R02 有 `WORKING` 预期 → R06 正式结论 | 先 R04 冻结；R03 可继续探索 |
| R06 `COUNTERS` → 立即 R10 | 只有 R09 有可修复性依据才走 R10（首次实例化除外） |
| R11 局部改善 → 完整实例合理 | 需要 R12 复验整实例及副作用 |
| R09 `PROVEN_NOT_ADJUSTABLE` → Gate 失败 | 若定位与证据达标，可合法交付不可调结论 |

## 5. 后续管理使用本表的方式

每个阶段或节点被执行／复用时，至少检查：输入真实可得、版本与用途一致、输出达到消费者需求、异常有合法后继、是否存在可推进但被误挡的并行工作。已有合格产物可以复用，仍须保留消费资格证明。

## 6. 完成与全景更新

M 的 A～E 阶段工作实例或 Rxx 节点完成、部分有效、返修、不可得或被版本替代时，应将具名结果、版本和影响范围交给 [跨层业务完成全景](06_业务完成全景与更新协议.md)：

```text
工作实例结果／Gate 变化
→ 更新当前工作完成或阻断事实（保留历史）
→ 重算 M 的 A～E 阶段实例及 R 阶段实例
→ 重算 M/R Workflow 和 question_id
→ 重算 ParentTask 当前完成状态、剩余工作与下一合法动作
```

不强制每个内部步骤独立写进度报告；可从阶段产物、W1／W2 Worker 记录和 Gate 回执生成投影。只提交候选、W1 运行成功但未核图、实际效果未知或缺必要核对时，不得标记当前有效完成。
