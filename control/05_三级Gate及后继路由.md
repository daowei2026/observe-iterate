# 三层 Gate：验收对象、输入、输出与失败后继

> 材料准备专业执行以 [control/02](02_L1_观察材料准备流程.md) 的 A～E 外层 Workflow 和五个阶段 Skill 为准。本表只规定跨工作消费和必要管理判断；不为每个阶段或内部步骤强制增加一次独立 Gate。旧结构只用于追溯既有记录，不是新工作的现行链路。R 侧原 Gate 语义不变。

## 1. Gate 首先判断什么

| 判定对象 | 示例 | 容易犯的错误 |
|---|---|---|
| `WorkQuality` | A 是否准确还原 occurrence；D 是否理解仓库并形成完整定义；E 是否取得一致的图和数据 | 将业务反证判成专业工作失败 |
| `UseEligibility` | A 是否足以供 B/C/D 使用；E 数据是否可供 R03/R05 消费 | 文件存在就默认下游可用 |
| `ActionEligibility` | W1 运行／修复、W2 正式取数、昂贵重跑是否有权限和成本资格 | 一次获准等于以后所有动作获准 |
| `TaskCompletion` | 本轮材料或分析问题是否达到约定交付 | 强制“全部修到合理”才算完成 |

硬检查可记录 `PASS/FAIL/UNKNOWN/NOT_RUN`；必需硬检查未知或未运行不能算 PASS。专业领域状态仍使用各 Skill 的原生状态，不能改写成 Gate 成败。

## 2. L0｜完整业务任务 Gate

| Gate / 触发 | 输入与验收对象 | 通过后继 | 未通过／缺信息后继 |
|---|---|---|---|
| **H0 TASK-ENTRY** | `BusinessTaskInput` 及已知范围；M 外层至少需要特征名称、代码版本、特征实例 | 启动 M-A；已有同版本 A～E 产物可先核复用资格 | 目标或对象不明→具名补充；不凭猜测扩范围 |
| **H1 MATERIAL-HANDOFF** | E 最终脚本、HTML、W2 正式图数据、核对结果、限制；或真实 `PARTIAL_WITH_LIMITS/BLOCKED` | 交 R；R03/R05 按用途检查 | `PLAN_READY`、W1 运行成功或只有 HTML 不能当实际证据；缺项形成定向补证 |
| **H2 EVIDENCE-RETURN** | 原请求身份、返回材料或不可得结果、版本和限制 | 回原问题／轮次，按结果解锁受影响节点 | 版本不匹配不自动解锁；迟到结果保留历史 |
| **H3 PARENT-CLOSE** | `QuestionCompletionRecord[]`、材料与分析引用、未决项 | 按本轮完成合同结束 | 可继续则回准确阶段；不可继续形成具名停止 |

## 3. L1-M｜A～E 的实际检查与后继

以下检查可以由同一专业委派贯通，不要求每项单独 Gate；但下游消费前必须确认所需上游产物已经有效。

| 阶段／条件 | 应检查的业务事实 | 后继与返修 |
|---|---|---|
| **A occurrence 理解** | 输入事件、业务主输出、中间处理、各事件发生位置和处理关系是否有代码依据 | 合格→B/C；核心事件或位置不明→A 定向核查 |
| **B 观察位置** | 当前普通默认或高频多尺度位置是否属于当前实例并可被 D 绑定 | 合格→D；位置无数据／不成立→B；不因 C 展示方便改变位置 |
| **C1 待展示信息** | 输入、业务主输出和必要中间结果是否明确；A 已确认的位置／身份／引用关系是否正确带入 | 合格→C2；缺信息回 C1 或 A |
| **C2 展示预期与 HTML** | 是否直接读原 CAEGraph 使用手册；第一版预期是否已有 HTML；复杂点循环是否同步更新预期和同一份 HTML | 合格→C3；展示／能力问题留在 C2；没有第二份独立“最终 HTML” |
| **C3 可注入代码** | 是否从 C2 当前实现整理；是否保留实例、位置和字段注入接口；是否保持 C2 当前展示语义 | 合格→D；需要改变展示预期时返回 C2 |
| **D 定义集成** | 是否理解锁定 CAEGraph 仓库调用链；是否把外层真实实例、A 字段和 B 位置一次性绑定进 C3 代码 | 合格→E；拿得准的 B／C 确定性缺项可直接纠正并留痕；需要新位置选择或改变 C2 预期则返回 B／C；A 事实不清返回 A |
| **E1 专业基准** | D／C2／实例／位置／环境是否冻结；W1 修改权限和候选交付是否明确 | 合格→按派单合同签 W1；基准不完整则回对应阶段 |
| **W1 运行与有限修复** | Worker 是否使用 D 的真实实例和位置；patch 是否只处理授权机械问题；运行结果是否可核对 | 回 E2 消费；机械问题可新 revision；位置／展示／集成问题由 E2 路由 B/C/D；W1 成功不等于图通过 |
| **E2／E3 专业评价与核图** | E 是否亲自判断问题性质；最终脚本是否符合 D；最终 HTML 是否符合 C2 当前展示预期和业务语义 | 两类核对通过→E4 正式取数准入；未过→回受影响阶段 |
| **E4 正式取数准入** | 是否冻结被接受的脚本、HTML、运行、实例、位置、数据阶段和完整性要求 | 合格→按派单合同签 W2；没有准入不得派 W2 |
| **W2 正式取数** | 工单是否绑定 E4 准入；Worker 是否禁止修改图定义、脚本、位置和展示语义 | 回 E5 消费；需修改图／脚本时准入失效 |
| **E5 图数据一致性** | 正式数据是否来自被接受的运行；数据阶段、图层映射、品种、时间、身份和缺失语义是否正确 | 合格→E6／H1；部分／不可得按真实范围交接，不以预览冒充完整数据 |

**动作边界**：正常读取、短窗运行和可控新增观察产物不默认需要独立隔离工程或统一 G-RUN。只有具体动作存在显著资源、权限或写面风险时，才针对该动作作 ActionEligibility 判断。

## 4. L1-R｜合理性分析关键 Gate

| Gate | 必要输入 | 应核对什么 | 通过后继 | 不通过／条件不同的后继 |
|---|---|---|---|---|
| **G-EXPECTATION-FREEZE** | 来源明确、可检验的最小预期，适用/反例、轮次和已看探索证据 | 版本和来源清楚，不无痕改写 | R04→R05 | 含糊→R02；新证据产生新版本 |
| **G-COMPARISON** | 冻结预期、EvidencePreflight、DataBinding、时间/版本、真实场景、对照包 | 数据、业务含义和目的适用分开；证据状态与场景对应；同源不重复计票 | 足够回答→R13；值得诊断→R07 | 缺证→R05/补证；新预期→R02；`COUNTERS` 不造成 Gate FAIL |
| **G-DIAGNOSIS** | 冻结预期、偏差、DiagnosisReport、竞争解释／排除证据 | 找到最早可追踪分歧或有据说明无法定位；区分参数、实现、输入和业务取舍 | 可调→R10；已定位／不可调／有界未决→R13 | 需最小试验→R08；缺材料→H2→M |
| **G-CALIBRATION** | 可调入口、参数约束、候选成本、原窗口、新旧实例和完整比较 | 试验资格、实验真实性、完整实例业务含义分开 | R11/R12 后→R13 或返回 R07/R09 | 无交集／不可调形成合格结论；无资格不强行试验 |
| **G-ANALYSIS-DELIVERY** | 本轮问题、实际专业成果、证据／版本和限制 | 是否回答到约定深度；支持、反证、不适用、未决真实 | `QuestionCompletionRecord`→H3 | 可补查回具体 R 节点；不可得／超范围形成具名结果 |

## 5. L2｜局部事实与管理边界

| 位置／性质 | 最低要求 | 是否另建管理 Gate |
|---|---|---|
| A～C 的专业分析与展示准备 | 依各阶段 Skill 保留来源、字段级产物和完成条件 | 不另建固定 Gate；可合并专业委派，但不跳过消费资格 |
| D 单一集成动作 | CAEGraph 仓库理解、真实实例／位置／字段绑定、上游纠正记录、完整定义和检查 | 不拆内部 Workflow；不派 Worker |
| E 专业 Workflow | executor 自己完成问题分类、核图、正式取数准入和一致性判断 | 不能委派给 Worker；派单映射另见 Worker 合同 |
| W1 运行／修复 | D 完整定义、明确 patch 权限、真实环境、候选 HTML／日志／patch | 一般不另建 Gate；高影响动作单独判断 |
| W2 正式取数 | E4 准入、最终脚本／HTML／运行绑定 | 是 E 的内部必经条件，不能与 W1 合并提前授权 |
| R03→R04 | 探索样本和候选预期有版本；正式对照前冻结 | 正式冻结是必需 Gate |
| R05→R06 | 冻结版、DataBinding、时间／参数和材料资格 | 必须做正式输入检查 |
| R10→R11 | 参数约束、成本和动作资格 | 在 G-CALIBRATION 中检查 |
| R12→R4 判断 | 原始窗口、新旧完整实例和同次比较 | 完整对照必须真实验证 |

## 6. Gate 未通过的结果分流

1. **输入缺失或格式错**：回对应上游阶段补具体字段，不默认重跑整个 M/R。
2. **D 可确定性纠正的 B／C 小缺项**：只有唯一修法、不改变位置／展示语义且完整留痕时可继续；否则返回原阶段。
3. **执行事实不成立**：返回真实错误、日志和影响；效果未知先对账。
4. **专业充分性不明**：形成具名判断请求，写明事实、缺什么判断、合法选项和后继。
5. **新事实影响既有结果**：只修订受影响的 A/B/C/D/E 或预期版本，保留未受影响成果。
6. **超范围或无资格**：阻断对应动作，不授权 Worker 自行扩大任务。
7. **合法限域结果**：保留可用子集，明确用途和剩余必需项；不能借局部通过降低原目标。

Gate 不通过不必使全任务归零；只阻断依赖该结果的范围。

## 7. Gate 结果更新业务完成全景

每项生效决定至少留下：`target_stage_instance_id / affected_work_item_refs / accepted_scope / retained_results / missing_requirements / repair_target / decision_ref`。M 侧阶段使用 A～E，不再使用旧步骤作为当前完成单位。

- 资格满足不自动等于父任务完成；
- UNKNOWN／NOT_RUN 保留具体阻断范围；
- 限域接受、不适用和等价复用写清依据；
- 代码、数据、实例或定义版本变化后，只重验受影响范围；
- 历史合法结果、D 上游纠正和 Worker patch 不无痕覆盖。
