# BI-01-RESTART-01 长程推进地图

<a id="goal"></a>
## 1. 完整目标

建立由 AI 持续开展、Owner 在必要环节进行业务判断的长程业务观察与设计迭代过程。成功标准不是完成若干文件、图或计算，而是持续取得可检验的业务认识，并据此形成有依据的继续、修订、补 Case、停止或等待行动。

本 run 不继承旧 I4 试跑的业务输出、Gate、聊天或在途状态；旧材料只保留历史追溯资格。当前采用关系由 R0001 首次管理、R0002 接线修复、R0004 Case-01 接收和 R0006 I4/G4 阶段接收共同构成。

<a id="business-system"></a>
## 2. 正常系统的业务关系图

```text
Owner 总意图
  ↓
I1 选择值得观察的真实业务问题
  ↓ G1
I2 固定合法 Source / Method / Case / As-Of / Missingness
  ↓ G2
I3 取得并限定可信结果范围
  ↓ G3
I4 真实业务观察与挑战
  ├─ 事实过程
  ├─ 单品种 → 静态集合 → U2 → U2+U3
  ├─ 增量或有据无增量
  ├─ 支持、反证、缺失、证据依赖
  └─ 下一项最能缩小不确定性的观察
  ↓ G4
I5 Owner Pack
  ├─ Owner 可直接看懂的市场过程
  ├─ 已解决/未解决的业务问题
  ├─ 增量/无增量、支持、反证、争议
  ├─ 行动选项、前置、风险和停止条件
  └─ 真正需要 Owner 回答的问题
  ↓ G5
Owner 判断（仅正式方向、投入和重要取舍）
  ↓
I6 将反馈转成下一轮实际行动
  ↓ G6
下一轮 / 合法停止 / 等待
```

局部证据问题只限制受影响的 claim；不清零已成立的事实和业务认识。管理 Gate、独立审查、Owner 接受和生产资格保持分开。

## 4. 当前阶段与业务问题

### 4.1 I4 已回答的问题

原 Q-01：

> HC、RB、I 在共同转折后的成员差异是什么；单品种、静态板块、U2 和 U2+U3 各自增加了什么认识？

当前答案：

1. Working/Completed、actual/knowledge 和观察范围决定结论能否成立；混用会制造伪排序。
2. U2 有同轮身份、可知时间、资格和证据定位价值。
3. exact-same-actual 名单没有证明稳定机会边界或经济过程边界。
4. Case-01 当前 U3 没有证明独立 Quality 增量；Case-02 没有对应 U3 输出。
5. 有据无增量是合法结果，不能用字段、图或 schema 数量替代业务增量。
6. 这些结论不等于完整 U2/U3 无用；formal Formation/Separation/Quality 尚未被实际验证。

### 4.2 当前 I5 问题

> Owner 是否应当采用“保留 U2 的身份/时间/可追溯性组织价值，暂停把 exact 成员组织和当前 U3 当作机会选择/Quality 既成能力”的方向；若不采用，是否授权一个具名 consumer 驱动的正式验证？

I5 的工作不是增加新 Case，而是把上述市场事实、设计价值、无增量边界、风险和选项组织成可直接判断的 Owner Pack。
