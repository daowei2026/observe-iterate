## 5. as-of T 重建结果

### 5.1 合法 T

选择合法 T 至少需要沿逐对象确认／发布时间排序，并在每个候选 T 只保留当时已知、未被未来修订覆盖的对象。本轮没有取得任何一个品种的确认时间序列，也没有实际对象 id／revision，因此无法建立已知集：

\[
K(T)=\{o \mid confirm\_time(o)\le T,\; version(o)\text{ 在 }T\text{ 时可用}\}.
\]

若直接从最终历史图挑一个看起来“分化明显”的日期，会同时引入三类泄漏：

1. 用实际转折位置代替确认可知位置；
2. 用最终完整对象序列倒填 T 时状态；
3. 用事后行情决定目标过程和样本窗口。

本轮因此没有选 T、没有形成候选组、没有使用后续结果。

<a id="natural-challenge"></a>
## 7. 最近自然挑战、反证与替代解释

### 7.1 能够诚实检查的挑战

本轮能检查的最近挑战不是市场反例，而是对“有一张三尺度多品种图就足以开始 as-of 判断”的挑战。结果是否定：

- 页面和 run locator 只能证明曾有一项工具实践被记录；
- 没有逐对象确认时间和正式切片，就不能重建当时已知集；
- 图点放在实际转折位置，会使视觉上最有吸引力的差异恰好最容易含未来信息；
- 因此，“图可定位”不等于“业务输入合格”。

这对工具使用方式形成了真实反证，但没有反证市场假设本身。

### 7.2 尚不能检查的市场挑战

以下内容均保持未知：

- 后来是否出现反向大／中尺度对象；
- 被选品种是否比未选品种更早失败；
- 同一逻辑在相邻窗口是否给出相反结果；
- 是否存在计算故障伪装成“无信号”；
- 成员更换、时序错位或小尺度负担是否推翻中尺度差异。

### 7.3 合法替代解释

1. 正式数据包可能真实存在于原工作站，只是没有挂载或随本轮派发；当前结论不否认其存在。
2. 局域网页面可能仍能正常显示完整图，但页面视觉仍不能替代结构化 as-of 数据。
3. 文档所述参数可能与实际 run 完全一致，但在读取实际 JSON 和 manifest 前只能记为待核。
4. 当前 GitHub 工作面没有这些实物，可能是运输遗漏而非生成失败。
5. 某些对象可能没有方向字段或没有确认字段；在字段字典与逐行数据到达前，不能把空值解释为无信号。

<a id="method-feedback"></a>
## 8. 对当前设想的反馈

### 8.1 保留

- 保留“大尺度用于可比背景、中尺度用于选择差异”的低成本首层设想；
- 保留小尺度只在解释局部负担或时序时条件性加入；
- 保留允许合法无候选，而不是强制选品种；
- 保留沿同一材料追到最近自然挑战，而非只挑成功窗口。

### 8.2 修订

在任何图面观察前增加一个最小但硬性的**实例资格检查**：

1. run 与 manifest 一致；
2. 参数文件字节与 run 消费关系可核；
3. 每个对象同时有实际时间和确认／发布时间，或明确说明为何没有；
4. 能按 T 截断并保留 revision 语义；
5. K 线与对象使用同一日历／时区映射；
6. 缺失、计算故障与真实无信号可区分。

这是防未来信息的必要条件，不是把当前探索固化为新业务 Gate。

### 8.3 暂不使用

- 不用最终全历史图选择最漂亮窗口；
- 不用单一参数名推断方向语义；
- 不用图上颜色、形状或实际位置代替字段；
- 不用小尺度点数或密度当成固定评分；
- 不进行全市场重算或额外大规模拉取。
