## B1. 初始参数：为什么这样起步，哪些真能改

### B1.1 本特征到底接收什么

正常外层接收三份具名 NativeEpisodeSource 配置。每份把对象/Calendar/数据、原 ScaleTurnCalendar 方法、Episode 邻接政策、度量方法、market 口径和 N 方法连起来；并不是直接接收一张已经算好的“六项指标表”。

```text
同一真实来源的 5m close + open_uti + calendar_position + calendar_time
→ 原 ScaleTurnCalendar 来源及其实际/确认转折

→ 已完成过程的度量，或当前未完成过程的前缀/节律
→ N 选择最近6个与此前6个已完成过程，逐指标总结
  同时独立保留当前 working
→ 正常 core.v2 薄保存
→ 修后 TIS 具名读者
→ 本轮图用投影、对应数据和解释
```

正常有界生产实际经 `BoundedExecution.advanceFiniteQuoteMode` 更新有限累计、`BoundedEpisode.measureRecentEpisode` 形成过程度量，再经 `advanceNodeBehaviorCurrent` 调用原 `NodeBehavior` 方法。端点描述并不冒充完整路径；路径长度/效率/逆向量来自实际累计，只有完整可用时才出数。这个调用核对避免了只读一个旧 helper 就宣称掌握当前算法。

## B2. 输入到输出：已经核实的方法及普通语言

### B2.1 两个完成窗怎样形成

在明确对象、Scale、Context、方法及知识切点下，选当前可用的完成过程；实际结束时间定义先后，同实际时刻冲突只能用有依据的来源顺序处理，不能按 UUID、价格或列表位置猜。当前 Open working 另外选择，不能入已完成样本。

从合法完成序列取最后十二个，保留原时间顺序，前六个为 previous、后六个为 recent。启动阶段不足十二个就是 InsufficientHistory；例如6+5到6+6是样本成熟变化，不是市场突然变好。两个窗口的每个过程长度不同，六段可能覆盖很久，不能称固定“最近六天”。某个过程确认较晚时，其实际端点和进入可知窗口的时刻也不相同。

每项指标按成员原 MetricSpec 核定义、单位和 normalization。一个固定成员的该项数值不可用，会形成该指标缺件；不能把它扔掉后从窗外补一个好过程。完成成员数量充分、某项指标可用、working可用，是不同层次的判断。

### B2.2 六项指标怎样解释

以下价格为当前方法实际使用的 close 采样路径，方向来自起始转折映射；公式只描述其适用范围，缺件状态另保留。

|指标|本轮采用的含义|不能写成|
|---|---|---|
|DirectionalProgress|沿该过程既定方向的端点净推进；方向向上看末价减起价，向下看起价减末价，故可以负|绝对涨幅、必然正的盈利、单纯买入方向收益|
|RawAmplitude|起止端点价格的绝对差|整段 high-low、最大曾经涨幅|
|BusinessDuration|起止位置的真实 Calendar Clock 差，单位 CalendarUTITick|未经映射核实的秒数、bar根数或自然日|
|CanonicalPathLength|完整原采样路径上相邻 close 变化绝对值累计；缺口不补连|转折端点直线长度、K线实体累计或高低价振幅|
|PathEfficiency|完整、非零路径的端点绝对位移／上述行程|胜率、收益率、方向是否判断正确；零路径没有合法比值|
|RawCounterMove|按原方向累计得到的过程内最大逆向回撤负担|最后一拍距极值的差、总逆向成交量或保证止损额|

正常 `BoundedEpisode` 用端点基线和有限完整累计组合输出。即便端点和 Calendar 可得，跨过缺价的完整行程、效率和逆向量仍可缺失；不是整条记录只能“全有或全无”。效率可高而方向推进为负，因此单独把高效率标成“沿预期方向走得好”不成立。

对某一可用指标，近期六值记为 x、此前六值记为 y：

```text
current = median(x)
previous = median(y)
change = current - previous
 dispersion = median(|x_i - current|)
```

最后一项是**近期未缩放 MAD**，不是标准差，也没有除以价格或中位数。上述变化是原单位绝对差，不是百分比。各段效率先算再取中位数；`median(端点位移)/median(行程)` 通常不能替代 `median(各段效率)`。

### B2.3 LOO能告诉什么，不能告诉什么

本实现逐一剔除近期窗口成员，计算剩余五值的中位数及相对基准中位数的绝对移位，并保留全部并列。源码使用实际 Double 的精确有理数值比较，以免浮点舍入制造假的唯一最大值。

六值排序为 x1≤…≤x6 时，基准是(x3+x4)/2；剔除一个后中位数为 x3 或 x4，绝对移位均为(x4−x3)/2。因此在这个完整六值方法下，六个绝对影响并列并不说明实现没运行；它反而说明该 LOO 输出**不能用来排六个成员谁最重要**。移位零也不能推出没有极端成员，更不能推出六个过程相似。LOO适合作为该统计量的单点剔除敏感幅度，与原成员分布一起看。

### B2.4 working与节律是独立语义

working 描述尚未结束的那个真实过程：起点、方向、观察 through、截至目前的duration/progress/efficiency/counter等。它未完成，但当时前缀中的某些数值可以合法可用；“completion=Pending”不是“全部方法没实现”。它不进入十二个完成样本，也不能直接作为同成熟度的第七个完成过程比较。

正常局部节律另留最近六个真正极值更新间隔，按**此前3个与近期3个间隔**计算中位数、差；这与 N 的“此前6段/近期6段”是两个对象和两个窗口。初始点不是一次极值更新；只有严格改善才计数。若不足六个间隔，两个节律中位数及比值不能假称样本充分。

waiting 从最近一次局部极值更新起算；没有更新而有合法局部起点时从该局部起点起算。waiting_ratio=waiting/近期三个间隔的中位数，故可以远大于1；分母为0是 NotApplicable，不应硬写0或无穷。字段可用性、局部次数、全程次数和局部起点共同决定解释。

缺价/不连续会中断局部邻域：恢复首条可以成为局部起点，waiting可能为0、local_count仍为0；它不因此是全程新纪录。全程精确计数可继续未知，已完成窗和宏观 working Life 可继续保持。图层若把所有零等待点画成“创新高/低”，会把数据恢复误写成行情事件。

### B2.5 薄输出不是一张可随意拼接的宽表

正常生产输出为 `Thin.U2ThinNodeRecord/core.v2`，修后 TIS 提供24张具名表。对观察有用的关系如下：

|表组|包含的业务信息|消费要点|
|---|---|---|
|rows、origins、revisions、failure_targets、corrections|发生、原时点、确认/known_from/as_of、修订/状态与失败|成功、失败、未变化和缺件分别看；不能只留有数的成功行|
|bindings、specs、normalizations|对象、Context、Scale、方法、N/LOO和指标定义|specCode的kind与definition_kind分开；不能按列表排序配名称|
|windows、recent_members、previous_members|窗口地址/状态、两侧有序成员、实际/确认/可知时点、方向及身份|用 rows.window 与 binding 关联；成员不是每拍都重新保存|

`to_df()` 拒绝这一产品；正常 `to_dfs/read_session` 可以按产品取表。exact使用book/kind/Life/revision，As-Of还必须指定Life和原整数知识时间。当前读者解析地址、禁止引用未来/别的对象基础，并检查相关必要正文；不能自行按当前列表顺序代替它。

历史正常示例 `read_context.py` 明确用了 `feature.rerun(CalType.OnlyRead)`。本轮技术单采用其正常只读语义，而不是把所有 rerun 名称一律禁掉；无参数强制重算仍不允许。示例又从另一旧配置文件取 sources、从 Calendar候选首项取值，不能不核对就照搬。本单改为以完整R30实例原件和实际binding为准。

## B3. 展示首版及其业务理由

### B3.1 先单品种看清，不以单品种作为永久范围

先用 rb 一个真实观察点把价格过程、两窗成员、六指标和working接起来。初始取原末段 `2024-02-29 14:55` 附近，是因为R33已经给出可追查线索且适合检查“历史窗改善与当前反向负担并存”；不是按未来收益选一个好看的点。其exact、当次As-Of和全部成员仍须重新正常读取。

首次图数可消费后，再增加同一对象前后位置、普通/相反情况及hc/i并列。多品种并列显示各自原单位和各自窗口跨度，不做未归一化price排名；即使效率是ratio，也不能忽略不同窗口范围、分段和成熟度而把它直接等同于投资强弱。

### B3.2 图、表、文字怎样分工

**价格与过程图**保留真实5m close路径；OHLC作为背景时明确区别。完成过程端点连线/范围带只表达分段边界，不能让人以为行程只由那条直线形成。标出previous/recent各成员顺序、working起点到through、实际端点及确认/known_from。图页可见对象、Scale、历史口径和As-Of；长身份放同页表或悬浮，不能为了简洁删掉来源。

**完成窗统计面板**分别显示六项 current/previous/change/MAD 与状态。原价格、时间和ratio不共用一个无法解释的纵轴。不把“近期”缩写成固定日数，不把MAD0写成所有过程一致。LOO细节放表或展开区，禁止六人贡献排行榜；成员原值需要观察参考复算时另标身份。

**working面板**与完成统计分开，保留duration/progress/efficiency/counter及等待/节律。让读者能同时说“已完成过程最近如何”和“当前这个过程截至此刻如何”，而不是用一个绿/红总标签盖掉分化。缺件断线并显示原因；completion Pending不遮掉合法数值，reading error也不伪装成Pending。

**解释文字**直接回答图中看到什么、哪些输出支持、哪些反对、还有什么替代解释。首版必需的提醒是：完成窗可能滞后于当前长working；价格位移不是high-low；效率不是收益/胜率；端点恢复不代表缺口路径恢复；历史bar的open标签不等于close开盘已知。

这些不是要求每张图堆满所有字段。以实际问题决定图/表/文字组合，保留可定位关系即可。

### B3.3 长期概览与大—中—小的判断

长期概览适合导航覆盖、窗口更新和异常区间，不适合单凭压缩后的线形解释十二个长短不同的过程。中等视图的跨度应从所选真实成员起止和working through推出；若太长，就分段或联动，不能把窗外边界截掉后仍称看完整窗口。局部视图用于核确认、过程切换、回撤、缺价或恢复。

这里的大中小主要是**观察范围缩放**，不是将5m原输入换成30m/日线再假称同一个N。概览可为显示降采样，但路径计算和关键局部仍用原5mclose；降采样造成的平滑不得用来证明效率高。若aidata默认图式掩盖过程边界，就返回本项改画法，再改实际绘图配置。

本轮没有图样实物。因此这些是明确可执行、仍待真实渲染与人读检查的展示设计，不标成展示已验证。
