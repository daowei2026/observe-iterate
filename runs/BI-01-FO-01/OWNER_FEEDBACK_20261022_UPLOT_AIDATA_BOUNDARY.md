## 三、明确工作 3 的真实调用与工作 4 的数据来源

**工作 3 正常要实际使用 aidata 的三个公开入口，而不是仅在 aidata 仓库写适配器或直接调用 Uplot 就视为完成：**

1. `build_chart_run(run_brief_input)`：按当前业务问题及所选定位特征建立观察节点、冻结时间范围和 run 身份；不强制生成全部 big/mid/small/tick 层级。
2. `build_big_world_chart_pages(run, run_brief_input=..., save=True)`：以同一 run 真实注册现有 Trier/CAE 平台图节点，取得 `report_url` 并实际打开核验图层，而非只生成本地 HTML。
3. `build_board_run({...原 run_brief_input, "run_id": run.run_id}, reuse_core=True)`：复用同一定位结果，取得 `feature_slices/`、来源索引和 `delivery/` 等正式特征数据交付；按观察问题选择所需范围，不无意义重复生成或导出全部数据。

三者是**要核实真实调用、结果和衔接的标准路径**，不是要求每次机械重跑三遍：`build_board_run` 本身也可创建或复用 chart core，已有有效 run 可复用。具体 N 画法如与标准入口不兼容，先核实际差异、最小衔接与权限，不能绕过后直接把独立 HTML 当作工作 3 完成。

**工作 4 主要基于工作 3 使用 `build_board_run` 取得的同节点正式特征切片/交付包进行业务分析**，关联相同范围的行情与必要上游，保留 run/node、品种、时间、来源和数据身份。N 的多表及 as-known 若不能仅靠通用切片完整表达，须再核正常 `OnlyRead/read_session/read_at_knowledge` 正式结果；已经可靠、可直接消费的正式数据仍允许工作 4 先行分析，不为等待整包而停工。图用 `plot_view_data` 只用于核对画面，不能替代正式结果。
