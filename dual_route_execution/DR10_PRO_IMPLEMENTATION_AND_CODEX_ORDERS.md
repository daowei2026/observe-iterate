# Pro 完整主体实施与 Codex 明确指令交接

execution_revision: '2026-10-13-normal-feature-positive-methods'
status: `candidate_not_behaviorally_validated`

适用：当前 A/B 依据已形成后的正常实施、实际问题后的修正，以及向 Codex 指派工作。Owner 给整体目标与授权；业务源码主体与结果分析主要由 Pro 承担，Codex 承担合法工作区工程修通、编译、测试执行、真实运行及现场调查。当前任务已授的工程自主权就是相关工作的委派依据，不逐项要求证明 Pro 为何不写；未委派的其他业务仍由原责任者承担，Owner 不逐轮编提示。

## 1. 从已经明确的主体直接开始写

**沿完整业务地图连续实现所有已明确的主体。具名方法的内部算法与分支、参数真实作用、事件触发、状态更新、正常Feature包装、保存读取和直接消费者一起落实。内部函数存在不代表正常使用已经接通。**

同一次计算形成的业务结果直接复用。实际输入边界和存读边界作必要检查，业务过程处理真正的市场分支；不将完整算法重算、全文比较或逐事件磁盘往返嵌入正常计算用于自证。

相连实现具备条件就进行必要构建与正常调用，尽早取得真实数据结果；其余明确主体继续。检查新增业务的对象、过程、关系和参数作用，不能停在来源记录、schema或合法空表。

已授权工程师可连贯完成普通表示、相关依赖、包装、生成、存读与接线。只有真正未定业务、受保护工作或数据风险、共享平台公共行为变化才交对应责任者；文件较大或涉及多个模块不单独构成退回理由。

管理已完成的来源采用和旧要求处置不由 Pro 每轮重新调查；Pro 仍须从实际业务与代码确定完整修改影响。新增内部函数不能代替正常入口和消费者切换，已否身份、证明、发布职责不能以局部兼容名义复制到新路径。

**每次实质业务推进都以完整做完所属用例当前阶段全部约定工作为目标。禁止把单个Feature、一组局部Feature、一个接口、文件或最近修复清单设为本轮目标和停点。当前重点只决定顺序，不缩完整责任。Owner先看小特征只改变反馈先后，不授权逐Feature等待批准。**

Pro 先把当前工程任务与实际代码放在一起，找出自己负责但尚未实现的业务方法、结果分支、事件过程、状态及重要调用。依据完整特征依赖地图连续施工，尽量完成所有已经明确的剩余工作；实际容量不足时交已成实物，接续仍承担全部。函数树、当前方法、可换步骤、参数进入计算及其结果消费必须落实到代码；不能用类型、接口、外部预先给出的判断、no-op 或一个代表性锚点代替主体。

承重方法从公共参数继续展开到内部方法、业务动作、真实调用和结果消费；可独立理解、做错或调整的步骤具名，不以复用或独立状态作为拆分前提。有独立输入、状态与采样责任的子过程拆清，上层组合不重新包办业务。按既有规范落实业务类型、具名配置字段及输入输出说明，不以Text／任意数字承担有限业务判法。普通Reflex与CEPS分别沿原路线实施，不要求每个纯函数升级为CEPS；内部图或专用命令不代替正常公共Feature、注册和包装，方法未形成不改称仅待校准。

代码交付可按实际完成情况分批保存，但禁止预先选择局部完成停点。没有具体反证时，管理者不反复重开需求、比较研究方向或用审查材料替代施工。主体欠账仍由原实施责任方完成；B 的方法调用、状态或接线设计没做完，组织 B 做完，不改称消费者的启动条件。

**禁止为尚未观察到的故障、自证正确、审查安心或填满模板新建辅助系统。**不新增输入准入/journal、私有publisher、逐事件磁盘ACK、祖先证明、默认恢复、专用测试启动或设想场景矩阵；不得换名建设。实际故障先用已有错误/日志/输入输出/源码直接定位，确缺具体观察且现有手段不足时才做最小临时诊断，取得答案即回业务。真实反例可留已有测试，不由一个bug扩成框架。已有测试按当前需要使用，不删失败业务断言、不把未执行写成通过。

完整实现不要求首次零 bug，也不表示尚无环境的 Pro 已经编译通过。交给 Codex 时准确说明已写到哪里、哪些尚未编译或运行。诚实正式路径具备的部分尽早运行，同时继续其余主体；不等全量测试或最终验收才接真实数据，不因一条小路径成功而停止完整实现。必要进度、内存保护、正式保存/读回和结果解释继续做，不能归入后移的测试周边。

## 2. 源码编写与现场执行的分工

Pro 持续负责完整业务主体、必要承重工程选择和结果分析。工程师在当前已授的完整工程自主修通权及合法写面内处理依赖、类型和普通状态表示、正常构造包装、导出注册、声明生成、存读与实际兼容；授权本身已构成委派依据。生成产物仍由原工具产生；已明确业务含义下的生成输入、手写接线和说明可由有权工程师改，不因其为手写源码自动退回。真正未定业务、保护面或共享平台公共行为变化仍归原责任者。特征自身的全文哈希、摘要身份与自证校验已否，不作为工程师的“摘要编码”任务；真实业务统计、必要状态和正常保存读取保留。

业务源码主体尽量由 Pro 直接编写，不限核心；真正未定的方法和业务含义由 Pro 持续形成。已明确合同下的普通类型、事件／状态实现、注册、手写包装、存读和相关修复可由已获授权的工程师连贯完成，不因代码是手写的或接口重要就退回，也不逐项增委派理由表。缺现场信息由工程师查，缺环境由其执行；一轮未完 Pro 继续主体。不能推送时交真实补丁，由有权限者应用发布，编写／应用／提交分账。

Codex承担现场调查、应用已给代码、执行生成、编译、测试执行、真实运行和回交。生成产物由现有工具产生；已明确业务含义下，生成输入与手写接线可由已获授权的工程师修改。当前不默认同时补测试程序；真实反馈后确需编写时按源码和现场条件分工，已写不等于实际执行通过。

Owner 授权当前完整任务自主修通时，工程师依据专业经验完成必要依赖补齐、源码合用、实现修复、正常Feature构造与包装、生成、正常存读表示及实际兼容处理；权限包含工程判断，不限机械小修。初始文件和提交清单说明起点，不是禁止补齐相关依赖的封闭白名单；相关生产者、校验、读取、生成和直接消费者随同因问题集中处理。已有正确修法直接复用，实际选择和差分随正常回交说明，不增逐文件批准或修前证明。 只有需要新增或改变尚未决定的业务判法、破坏受保护工作或数据、改变共享平台公共行为时，才停受影响操作并交原责任者，其他已授权工作继续。既有合同已明确而代码写错的，可由工程师修正；文件大小、模块数量、重要接口、正式存储、身份、版本、兼容或需要工程选择，均不单独触发停工。保留完整业务字段、时间、身份、历史和真实检查；不调阈值求结果、不伪造上游、不缩业务、不建预防性辅助系统。只读任务与Owner明确暂停仍保持，其他用例和未授权平台不扩权。 细则见DR11§2和C自主修复边界。

两路均采用上述执笔与执行分工。同事滤波器／普通Reflex完整Feature按DR03/DR07保持完整方法和父组合，不改成我方Core加同事外壳。确有理由委派Codex完整基础Feature时，任务可覆盖完整连贯工作，但完整B包本身不替代委派理由。

## 3. 一份交接写清修改、完整目的与正常后继

工作单交清完整目标、当前顺序、已成与全部未完、管理已裁定事项、当前代码起点、保护面、已有工程自主权、真实运行依赖、正常入口和回交。文件清单是起点，相关直接依赖与消费者可在授权内补齐。新正常 C 任务由消息生成器携带已采用任务全文；合法同工作续作沿其自身正文，不再只截任务中的 CURRENT_C_WORK 小段。

先写完整业务工作、当前顺序和实际交回结果，再给必要定位。已有B任务直接引用完整正确正文，不复制第二包；任务存在、目录可写和方法能力不单独构成指派。正确正文禁止压缩或摘要替换，不能仅留历史引用。只准定点删除已被Owner否定的非实质任务及相关前置。

本次源码指令说明既定业务、完整未完范围、源码起点、任务相关仓库与保护面、预期行为及回交成果。正常完整工程工作单带入Owner已授自主修通权，列出的文件是起始交付，不将漏列依赖变成停工白名单；依赖合用、技术表示、生成与实际兼容由工程师连贯完成。

运行任务说明执行源码、新增业务问题、正常正式入口、数据／对象／频率／预热／配置、结果及已授权后继。工程师取得完整可用历史、成员覆盖及必要数量与时间分布；Pro按新增业务的过程尺度、回看、形成与变化条件，判断上游频率及参数是否合适，给有依据、可修改的首版及必要对照。不能只接受默认时间段、旧示例或参数已生效的说明；本次输入不足以检验新增方法时，实际调整安排。具体板块、日期和数值留本任务；TIS／FRP的K线完整历史与正常入口按平台执行补充。编译严格在edh-universe目录执行stack install，禁止添加其他参数。

当前任务全文或原 continuation 正文交清完整目标、地图位置、真实成果、全部已明确未完、本轮顺序、交回结果、正常接续和真实依赖阻塞。新正常 C 任务全文进入“本轮当前工作”，不因 CURRENT_C_WORK 标记缺失而省略，也不只截任务中的引文；合法同工作续作按实际采用关系优先。重点不缩 scope／权限，主控只搬原文，旧局部 focus 不能覆盖当前完整任务。普通已给清的应用、生成、编译、运行和读回连续做，不逐段重派。

地图的输入输出必须是可理解的业务内容：实际生产者、对象/范围/方向/时间/基数，怎样传到消费者、哪些字段必要或条件性、缺哪项影响哪个判断。业务依赖、源码施工和测试顺序分开；来源的全部诊断、参数比较、测试或最终接收不自动成为下游施工/实跑的前置。真实必须的上游缺件与直接消费者成组完成，不受影响主体继续。

方法仓/ref/角色模式、实现仓/分支/base/允许写面、实际执行版本与结果位置分别明确。共享面按当前既有安排保持单写，不默认新建worktree。纯执行单可无源码修改，codex_commit可空、execution_commit如实填；临时诊断限授权位置，不改变正式Feature、生产配置、共享依赖、正式预期或平台。

交接包含真实方法及内部算法、必要状态和时间、正常构造与包装、输入的实际生产者、结果与直接消费者。按已采用版本提供 B 的 11 实现映射正本、C 实施判断正本 §6—§9 及命中的平台代码例子；这些是正常实施方法，不新增清理阶段或阅读证明。已授权普通工程选择不反复回管理审批，实际选择随原正常回交说明。

## 4. 实际反馈、小修与业务分析的往返

Pro发布真实源码和明确任务，Codex在合法现场应用／生成、执行受派代码和标准构建。先读完本次错误，按共同原因查直接相关位置，当前授权范围内的工程修通集中做后复编；一次失败不自动结束单或归还现场。编译中不改同一源码，后继Pro保留工程师有效修订。

真正尚未决定的业务含义、破坏受保护工作或数据、共享平台公共行为变化，集中交原责任者，带错误、输入输出、相关位置、已处理与未执行。其他工程选择和已明确业务的实现错误由已获自主修通权的工程师集中修复及复验；Pro继续主体源码与业务分析。

编译通过且路径和安排已具备就实跑；生产者／调用未写继续主体，不用fixture冒充上游。正式结果按方便理解的形式回交后，Pro结合真实输入分析对象／过程／关系的形成演化、关键参数作用、必要对照和合法空，不只看表／行数。核心对象未实际形成不签生命周期验证。

按本次问题分清上游展示行、接纳过程、完成过程、有效评估、新发生和当前对象，检查实际数量、跨度与变化是否由业务规则解释。长期初始化、材料过少或核心判断未被触及时，区分输入尺度不合、数据不足、缺绑定、方法未实现与真实业务稀少，并继续具体修订／对照；不靠Pending说明结束。现有方法允许范围内的普通参数选择由Pro承担，不逐值交Owner，也不为增加结果改掉下游原业务。

实际异常分类为实现、接线、输入／预热、方法／配置、业务空、合同或平台。受权方法范围内的参数对照保留基线并解释，不静默调阈值追非空。真正改变未定业务含义、受保护工作或共享平台公共行为时按原责任返回；既定业务下的普通工程变化由已获授权工程师处理。当前能查清的问题不留给后续图审。

工程师可以质疑并给反证，Pro消费调查和修后结果，独立审查按实际范围复核。技术问题解决后还要返回原业务问题；reader修好不等于对象检查结束。长运行不追latest，原失败保持原版本，纯结果上传失败只补上传。

## 5. 工作组合与再判断

连续出现内部函数、局部 source 修改或缺件说明而重要方法和正常消费者没有推进，管理须改变实际安排。Pro 不以反复列完整 remaining 代替继续施工。旧错误工程治理只在当前确有该问题时适用：正确方法复用，多余职责退出，不重启全部 A／B 或默认新增迁移、恢复工程。

正常施工来自完整目标的全部实际未完，按C正常主线与DR13 §5连续推进。禁止预设单Feature、一组Feature、一个入口或几项修复的本轮完成停点。一条链可实跑就取反馈，其他主体继续；不等所有代码完才编译，也不让一条小链无限打磨吞掉其余任务。

业务理解／平台复用／有效经验从编码开始适用；主要探索由真实结果或具体反证推动。测试、proof、抽象、文档和控制材料增长而主体不动时，管理删除非必要工作，回未写业务或真正接通问题。已否旧技术任务必须从正文、工作单、前置、验收、后继和只服务它的代码/检查删除；不得改称暂缓或未来必做，不以原包已接受掩护继续建设。

管理根据完整剩余、实际信息增益和目标规模判断继续调查、修复、转向或接收。普通清楚工作不每轮重选研究方向；重要前提被推翻定向回A/B/平台，内部欠设计／欠上游继续本任务处理。仅真实不可取来源／权限及超授权高影响取舍才问Owner，只暂停受影响路径。

## 6. 已有业务特征、平台参考与CEPS方法

涉及已有Feature，Pro先读业务含义、参数、输入输出和相关实现，明确调用已有方法、订阅正式Feature、读取物化产品或仅参考解释。原运行值、存储读回和展示投影分别核本次所需内容；import或配置存在不证明正式复用。沿接受工程接好，具体缺项交原责任者，不在消费者猜来源或重算上游。细则见C平台复用方法§2.4。

既有平台按真实接口使用，保存／读回要求不推导为新建DTO、codec、serializer、sidecar或第二平台。真正公共平台问题先证明宿主内不能完成并窄回压。本方法不授权外仓开发。

Python/Numba、跨语言和Haskell/FRP共同使用 `agent_evolution/platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/00_REFERENCE_ROUTER.md`。按B的platform_reference_lock读package/reference/SHA同一完整正文，API和caller在目标exact ref核实；工作区私有配置由工程师查证，远端不可见不等于不存在。真实运行读取平台执行补充，不改原八份导入及锁。

CEPS从 `agent_evolution/skill_candidates/market-process-ceps-skill-pack-candidate-v0.2.0/skill/SKILL.md` 的implement_accepted_ceps_contract进入完整方法，实际实现端口、方法数据、子过程、Reflex余量和状态关系。Skill不授新写权，普通函数充分时保持直接，代表性检查不替代完整主体。有效EAW经验按索引命中读取，不每轮翻全部历史，不将用例名／阈值写入通用core。

## 7. 交回可直接继续的实物
