# L2｜节点输入输出与最小完成状态

## 1. 节点表

| 节点 | 必需输入 | 主要输出 | 正常后继 |
|---|---|---|---|
| U 复用并核对理解 | 名称、代码版本、实例、旧 Package／Chat、源码与读取接口 | 当前最小 `FeatureUnderstandingPackage` 或受影响部分 delta | X |
| X 实例运行 | 精确代码、参数、数据、日历、执行入口 | `FeatureRunResultBinding` | G |
| G 全量统计 | U、X、ReviewTarget、必要分层 | `GlobalBehaviorProfile`、finding 队列、`GlobalProfileGate` | Q |
| Q finding 队列判断 | 当前 finding 状态 | 下一待处理 finding，或“无待处理 finding” | D 或 Release |
| D 偏差诊断 | 单个 finding、处理链、证据、业务意图 | `DiagnosisReport`、责任阶段、事实、竞争解释、后续处理类型 | M、B 或 Q |
| M Feature 行为修改 | 已定位的 Feature 行为问题、反例和修改范围 | 修改结果、必要回归与新旧比较 | X |
| B 运行前提／结果绑定修正 | 错误版本、参数装配、范围、入口、结果身份或读回证据 | 修正后的运行绑定 | X |
| Release | 最新 U/X/G、finding 状态、已知限制 | `FeatureReleaseGate`、`UpstreamReleasePackage` | 下游或等待汇合 |

X 是实际运行，不是新 Skill；M、B 是 D 的两类后续处理，也不是所有 Run 必经的新阶段。

|---|---|---|
| CurrentReviewTarget | | |
| Feature 代码与参数 | | |
| U | | |
| X | | |
| G | | |
| Open findings | | |
| Closed findings | | |
| Accepted limitations | | |
| FeatureReleaseGate | | |
| UpstreamReleasePackage | | |

不需要为每次命令、每张临时表或每个内部检查建立独立工作项。只有会影响专业结论、版本绑定、恢复入口或下游使用的内容进入状态视图。

## 3. Finding 状态

```text
CANDIDATE
DIAGNOSIS_IN_PROGRESS
CONFIRMED
FIX_IN_PROGRESS
FIXED_PENDING_RERUN
CLOSED_ON_LATEST_PROFILE
DEFERRED_BY_OWNER_SCOPE
REJECTED_AS_NON_ISSUE
SUPERSEDED
```

`FIXED_PENDING_RERUN` 不能算关闭；只有最新实例和最新全量统计确认后，才进入 `CLOSED_ON_LATEST_PROFILE`。

若 finding 的原因是运行绑定错误而不是 Feature 行为错误，可以在进度记录中注明 `binding_correction`，不需要为此再建立一套 finding 状态体系。

## 4. 完成检查

本轮单 Feature 可以释放时，至少回答：

- 当前代码、参数和数据范围是什么；
- 最新运行结果在哪里、是否读回；
- 统计过哪些业务对象链和结构不变量；
- 原有已知问题在最新版本中的状态；
- 是否产生新的 finding；
- 哪些问题已关闭、暂缓或仍未决；
- 下游将消费哪一份 ReleasePackage；
- 什么变化会使该结论失效。

## 5. 不要求的工程记录

以下内容除非影响结论，否则不要求进入正式状态：

- 每条 shell 命令；
- 每次中间导出；
- 每个临时脚本版本；
- 每项无业务影响的性能数字；
- 为了填模板而产生的空字段。
