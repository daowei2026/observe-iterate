# L1｜本特征释放、已知限制与下游依赖

## 1. 两类 Gate 不混用

`GlobalProfileGate` 是统计 Skill 的专业输出；`FeatureReleaseGate` 是本轮任务在既定深度下是否可以把当前 Feature 交给下游的结论。

`PASS_TO_SCENARIO_REVIEW` 不自动等于可以释放下游。释放还要检查当前任务要求、已知 finding 和版本绑定。

## 2. FeatureReleaseGate

```text
BLOCKED
OPEN_CONFIRMED_DEFECT
RERUN_REQUIRED
PASS_WITH_ACCEPTED_LIMITATIONS
PASS
```

### `BLOCKED`

代码、参数、数据、对象键或运行结果不可靠。

### `OPEN_CONFIRMED_DEFECT`

存在本轮要求关闭、但尚未处理完成的已确认问题。

### `RERUN_REQUIRED`

行为已经改变，但最新完整实例和全量统计尚未完成。

### `PASS_WITH_ACCEPTED_LIMITATIONS`

当前 ReviewTarget 已完成；仍有 Owner 明确允许暂缓的已知限制，并已记录影响和返回条件。

### `PASS`

当前 ReviewTarget 下，所有确认问题已关闭，最新全量统计未产生新的待处理 finding，且没有待传递的已知限制。

`PASS` 只说明本轮声明的深度完成，不证明 Feature 在所有市场场景中完全合理。

## 3. 已知限制

暂缓问题必须记录：

```yaml
limitation_id:
source_finding:
status: DEFERRED_BY_OWNER_SCOPE
reason:
observed_scope:
business_impact:
downstream_impact:
why_not_blocking_this_release:
revisit_condition:
owner_source_ref:
```

不能把“暂时不改”“发生比例低”写成“问题不存在”。下游必须能看到这些限制。

## 4. UpstreamReleasePackage

每个可供下游消费的 Feature 输出：

```yaml
release_id:
feature_name:
code_ref:
constructor_ref:
parameter_instance_ref:
data_scope:
feature_understanding_ref:
latest_run_ref:
global_profile_ref:
feature_release_gate:
accepted_limitations: []
known_output_contract:
invalidation_conditions: []
```

下游不得只引用分支 HEAD、某次 Chat 的“已修好”声明或未绑定参数的结果目录。

## 5. 多线并行

不同业务线没有依赖时，可以使用现有多 Run 控制器并行。每个 Run 独立拥有：

- run_id；
- Codex manager/executor；
- Linux 工作区；
- Feature 版本、参数、运行结果和 Gate；
- TASK_PROGRESS。

一条线等待或返修，不占住另一条线。不同 Run 不共享工作区或未声明写面。

## 6. 显式汇合，不新建专业上级

具体任务可以声明：

```yaml
release_policy: JOINT_BASE_BARRIER
requires:
  - wall_base.release_gate in [PASS, PASS_WITH_ACCEPTED_LIMITATIONS]
  - f_base.release_gate in [PASS, PASS_WITH_ACCEPTED_LIMITATIONS]
```

主控只核对两个 Run 已经形成的真实 Gate 和 ReleasePackage；不替两个 manager 决定问题是否合理，也不复制专业报告形成第三套事实。

## 7. 下游依赖

下游启动前必须具名：

```yaml
downstream_feature:
required_upstream_releases: []
constructor_or_wiring_ref:
required_output_contract:
known_limitations_consumed: []
```

串行依赖必须按实际构造关系执行。例如 `F → Q → V` 中，Q 必须锁定 F 的 ReleasePackage；V 必须锁定 Q 以及其真实构造所需的 F 版本。共用一个构造入口不等于三个 Feature 可以同时独立放行。

## 8. 失效传播

上游代码、参数、数据范围或输出合同变化时：

1. 当前 ReleasePackage 标记失效；
2. 尚未启动的下游不得启动；
3. 已启动或已完成的下游标记 `STALE_UPSTREAM`；
4. 根据真实影响决定回到下游的 U、X 或 G，不无条件全部重做；
5. 历史结果保留，不无痕改写。
