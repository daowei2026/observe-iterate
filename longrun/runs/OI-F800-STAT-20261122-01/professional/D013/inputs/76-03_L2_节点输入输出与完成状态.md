# L2｜节点输入输出与最小完成状态

## 1. 节点表

| 节点 | 必需输入 | 主要输出 | 正常后继 |
|---|---|---|---|
| U 共享理解 | 名称、代码版本、实例、源码与读取接口 | `FeatureUnderstandingPackage` | X |
| X 实例运行 | 精确代码、参数、数据、日历、执行入口 | `FeatureRunResultBinding` | G |
| G 全量统计 | U、X、ReviewTarget、分层计划 | `GlobalBehaviorProfile`、finding、问题队列、`GlobalProfileGate` | D 或 Release |
| D 偏差诊断 | 单个 finding、处理链、证据、业务意图 | `DiagnosisReport`、路由、必要的 Owner 问题 | 修实现／参数／数据／场景 |
| FI 工程修正 | 已定位实现问题、反例、授权写面 | 新代码 commit、测试和完整比较 | U 或 X |
| P 参数处理 | 诊断结论或 Owner 给定新实例 | 新参数实例；正式标定时另有 `CalibrationResult` | X |
| Release | 最新 U/X/G、finding 状态、已知限制 | `FeatureReleaseGate`、`UpstreamReleasePackage` | 下游或等待汇合 |

FI 是工程动作，不是新 Skill；X 是实际运行，不是新 Skill。

每个 Run 的 `TASK_PROGRESS` 至少维护：

| 项目 | 当前有效版本／状态 | 精确引用或恢复条件 |
|---|---|---|
| CurrentReviewTarget | | |
| Feature 代码与参数 | | |
| U | | |
| X | | |
| G | | |
| Open findings | | |
| Closed findings | | |
| Accepted limitations | | |
| FeatureReleaseGate | | |
| UpstreamReleasePackage | | |
| 下一合法动作 | | |

不需要为每次命令、每张临时表或每个内部检查建立独立工作项。只有会影响专业结论、版本绑定、恢复入口或下游使用的内容进入状态视图。

## 3. Finding 状态

```text
CANDIDATE
DIAGNOSIS_IN_PROGRESS
CONFIRMED
FIX_IN_PROGRESS
FIXED_PENDING_RERUN
CLOSED_ON_LATEST_PROFILE
DEFERRED_BY_OWNER_SCOPE
REJECTED_AS_NON_ISSUE
SUPERSEDED
```

`FIXED_PENDING_RERUN` 不能算关闭；只有最新实例和最新全量统计确认后，才进入 `CLOSED_ON_LATEST_PROFILE`。

## 4. 完成检查

本轮单 Feature 可以释放时，至少回答：

- 当前代码、参数和数据范围是什么；
- 最新运行结果在哪里、是否读回；
- 统计过哪些业务对象链和结构不变量；
- 原有已知问题在最新版本中的状态；
- 是否产生新的 finding；
- 哪些问题已关闭、暂缓或转场景线；
- 下游将消费哪一份 ReleasePackage；
- 什么变化会使该结论失效。

## 5. 不要求的工程记录

以下内容除非影响结论，否则不要求进入正式状态：

- 每条 shell 命令；
- 每次中间导出；
- 每个临时脚本版本；
- 每项无业务影响的性能数字；
- 为了填模板而产生的空字段。
