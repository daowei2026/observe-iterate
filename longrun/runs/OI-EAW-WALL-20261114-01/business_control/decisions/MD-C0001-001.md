## 3. 本 Run 必须回答的三个业务问题

### Q-WALL-IDENTITY-LIFECYCLE

在一个可核实的真实运行范围内，同一 Wall 的 run-local 身份是否能从 Start 经 band 更新、Present↔Dormant 到 End 保持一致；重复、冲突、非法、迟到或状态不允许的变化实际怎样出现和处理；哪些是合法无输出、诊断、Pending、缺失或真正的业务反例。

### Q-WALL-PUBLICATION-STATE

`wall_occurrences`、`wall_current_view`、`wall_diagnostics` 与 DSU 完整 active map 之间是否可以在真实样本上形成一致、无误读的解释；尤其核实 current update 不是全量快照、End 的 update 与 active-map 删除并存、同一 firing 整批拒绝的实际影响和读取口径。

### Q-WALL-BUSINESS-SUITABILITY

上述身份、状态转移、发布和诊断语义，是否足以服务“在本次运行内维护由上游认出的同一 Wall 生命周期”这一业务目的及准确下游引用；对代表性场景分别形成 `SUPPORTS / COUNTERS / MISSING / AMBIGUOUS / NOT_APPLICABLE / PENDING`，而不是用实现行为循环证明业务设计正确。

实际工作区 tuple、数据/参数/时间、读取入口和现成材料核实是支撑这三个问题的事实工作，不另伪装成第四个已完成业务结论。
