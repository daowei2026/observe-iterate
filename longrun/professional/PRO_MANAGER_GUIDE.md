# 专业负责人 Pro 工作指南：观察材料准备 ↔ 合理性分析（角色适配候选 V0.1）

> **定位与成熟度**：本文件把仓库已有的 L0/L1/L2 业务控制面候选流程、观察材料准备 Skill 和合理性分析 Skills 映射为专业负责人 Pro 可实际执行的管理工作。它是**本次新增的角色适配建议**，不是对源 Skill 的修改，也不是已经获 Owner 确认的 Gate/授权策略或已通过真实长程试跑的角色合同。
>
> 本文件只约束**专业负责人应该如何认识、安排、接收和接续专业工作**；机器身份、C/D/W 工单、物理通信、Owner grant 和持久状态按 [V2 长程协议](../contracts/LONGRUN_PROTOCOL_V2.md)。专业执行方法仍由对应 Skill 决定。

## 2. 管理对象：一项业务问题、必要工作及其消费关系

专业负责人持有完整 `BusinessTaskInput` 和逐问题的目标、约束、已知/未知、已取得的材料、预期和分析结果、尚需的专业工作及完成边界；读取真实已采用的来源/结果，不凭聊天记忆写第二套“最新事实”。

初次接管应按顺序处理：

1. 还原 Owner 已明确的业务目的、对象、已有范围、禁止事项和本轮重要问题；**不要求 Owner 在开工前额外填写一份完整 TaskBoundary**。对未知深度/结束条件显式列出待明确项，在明确授权范围内允许有界事实调查；不得自行扩为无限任务，更不得因边界未知宣布完成。
2. 对齐仓库现有图/数据、需求和实现线索，以及 `question_id`、已知 `analysis_round_id`、材料和预期版本。存在可信历史产物时先检查复用资格，不默认重做。
3. 建立本轮**管理视图**：哪些问题可以并行，哪些依赖材料 M，哪些需要合理性分析 R，谁需要向谁交付；`MaterialRequirement`（要交什么）、`WorkItem`（怎么组织工作）、`ExecutionAction`（真实执行）分开，不按材料项生成同样数量的委派。
4. 给出能够被接收的专业子任务 D；每项 D 必须有具体目的、已核实输入、原业务工作身份、结果消费者、完成/停止标准及允许进一步签发 W 的边界。没有必要时一个 D 可以覆盖多个相邻 M/R 节点，一个业务节点也可以分批调查。
5. 把实际专业交付、限制、未决、可复用部分和下一步条件写入正式专业报告；根据 V2 协议正式签 D，不让主控从散文推导工作单。

### 一张 D 的最低专业信息（放在已有 `DELEGATION.md` 正文，不新增机器 Schema）

```text
当前业务问题 question_id / 需要回答什么
所属业务 Workflow（M 或 R）及当前 stage_view/control_nodes（仅作导航）
本次为何要做：具体专业目的及它的下游消费者
已核实的输入、代码/数据/参数/时间/预期版本、能否复用
本次可采用的 Skill 及适用步骤；不适用的步骤为什么可跳过
要求形成的原生业务成果与最低证据、验证和交接条件
允许的局部查证、Worker 操作、预算、工作区与硬停止点
成功、部分、缺证、不可得、失败时各自返回什么和谁消费
哪些内容需要再提交专业/Owner 判断；下一次检查的触发事实
```

`DELEGATION.json` 只承载 V2 已有身份、输入引用、预期交付和受权范围；上述专业语义放正文/业务原生材料，不擅自加必填机器字段。

## 3. 观察材料准备 M：负责人要组织和接收什么

按现有 [观察材料准备 Skill](../../skills/observation-material-preparation/SKILL.md) 与 [L1-M](../../control/02_L1_观察材料准备流程.md) 组织，不把 S0～S5 机械拆成六轮 Pro：

| 业务工作 | 专业执行人需要交的实物 | 负责人需要核的关系 |
|---|---|---|
| S0/S1 调查和计划 | 既有 CAEGraph/纯数据来源、业务处理骨架、`MaterialPlan` 及必需/条件/建议材料 | 是否足以回答原问题、已知事实与推断是否分开、既有完整图有没有被优先复用 |
| S2/S3 准备和实际取得 | 具体运行入口、版本/预算/授权条件、真实数据/图、源到图层映射、运行日志 | **只在实际动作合法时**启动；`source/postprocessed/construction_snapshot/viewport_final` 是否真实存在并标明 |
| S4/S5 核验与交接 | `MaterialReview`、实际数据与缺口、`PLAN_READY/DATA_READY/PARTIAL_WITH_LIMITS/BLOCKED`、材料包引用 | 必需材料有无真实取得；限定范围及不能回答的问题是否明确，`PLAN_READY` 不冒充实际材料 |

负责人**不替合理性分析选择“探索还是正式对照”的分叉**。M 向 L0 的交接只说明真实材料、代码/数据/参数/时间绑定、用途限制；由 R 的 R03（小样本探索）或 R05（正式对照证据准备）分别检查当前需要的输入。某项材料失败但其他问题能使用现有结果时，保留合格子集，不能机械重跑所有 CAEGraph。

## 4. 合理性分析 R：负责人要组织和接收什么

按 [合理性分析 README](../../skills/reasonableness-analysis/README.md) 允许快速路径、循环路径、首次实例化和提前 R5，不强制 R0→R5 各发一轮：

| 工作及来源 | 应取得的专业成果 | 接收时不可省略的检查 |
|---|---|---|
| R0/R1：预期推导 | `ExpectationRegister`、`InputSuitabilityAssessment`、`ScenarioExpectationSet` | `OWNER_EXPLICIT/BUSINESS_INFERRED/IMPLEMENTATION_DERIVED` 分开，探索可 `WORKING`；正式对照前 `FROZEN_FOR_COMPARISON` |
| R2：证据对照 | `EvidenceComparisonPackage`、`ScenarioEffectTable`、缺失及新候选 | 是否绑定冻结预期、实际场景、数据/时间/代码/参数版本；`COUNTERS` 不等于工作失败 |
| R3：偏差诊断 | `DiagnosisReport`、竞争解释、可修复性和真正需要 Owner 的取舍 | 是否沿处理链定位到最小分歧；未定位不跳到正式调参 |
| R4：条件标定 | `CalibrationResult`、联合可行域、少量有依据试验、完整新旧实例比较 | 仅在已具备入口/动作资格时开展；一次 `INSTANCE_REVALIDATION` 只产一次对照，原始业务窗口和上游重分段保留 |
| R5：问题交付 | `AnalysisDelivery`（候选封面）引用原生结果，逐问题状态与限制 | 是否回答到本轮已明确深度；有据反证、不可调、限定结论允许成为成果，结束需另外判定 |

发现新业务预期不能改写旧冻结版；需返回 R1 创建新候选。涉及新的跨 Workflow 证据需求，应优先判断能否在当前授权内做低成本局部事实检查，不能就发**具名** `AdditionalEvidenceRequest`，记录原问题/轮次/预期版本（冻结前明确 `not_frozen`），给材料执行人定向补证后返还原消费者。请求返回 `PARTIAL/PROVEN_UNAVAILABLE/NOT_APPLICABLE/CANCELLED/SUPERSEDED` 时都要关闭或限制**原请求**，不能无限等待或自动污染新轮次。

## 5. 专业工作接收、Gate 和正式决定不可混为一件事

对每个返回结果分别回答：

1. **WorkQuality**：这次专业工作是否按 D 的输入、方法、证据和交付标准完成？
2. **UseEligibility**：该实物能否按确切对象、窗口、版本、用途被下一项工作使用（尤其 M→R、R03/R05）？
3. **ActionEligibility**：新动作是否得到当前任务和实际 Worker/Git/预算/工作区许可？专业建议本身不等于授权。
4. **BusinessFinding / TaskCompletion**：业务发现到底是什么，当前问题是否达到本轮已明确的结束定义？`COUNTERS`、`PROVEN_NOT_ADJUSTABLE` 不应机械判 FAIL，`UNKNOWN` 的硬检查不能当 PASS。

这些检查可以形成**专业验收建议、具名待决问题或计划修订提议**，但本分支还没有确认统一的 Gate 正式接受者、可执行规则和受保护状态写入。负责人不得把自己写在聊天中的 `ACCEPT` 当作正式受保护 Gate；如果需要独立复核，必须由实际有权主体承担，不通过同一聊天自称两个角色实现。

管理决定若会改变已安排工作，说明 `被影响的具体 WorkItem/依赖/原因/保留产物/返修节点/新输入与输出/重新检查范围`。需要 Owner 的是**确有不同业务目标取舍、授权或本轮范围变更**；代码字段、时间语义和可由少量数据排除的技术问题应先交有能力的专业执行人查实。

## 6. 接到执行 Pro 回交后如何产生后继

- **已经满足 D**：记录专业成果和适用范围，解除本 D 的等待；相关业务节点是否达到消费资格另按已确认规则核对。一次 D 完成不等于完整 L0 完成。
- **部分有用**：保留可用材料/分析结果，按原问题分开处理未满足的依赖；新委派只覆盖受影响缺项。
- **缺具体事实**：给出最小区分性调查或补证需求；同一事实无变化不再反复要求“继续分析”。
- **预期/方案变化**：写候选版本和差异依据，不无痕覆盖旧冻结预期、旧执行单或已接受结果。
- **无法合法继续**：精确说明阻断来自权限、数据不可得、业务取舍或完成条件未知；保存可恢复入口，其他独立工作继续。
- **拟完成父任务**：逐项汇总真实材料和分析成果，缺口、结论与完成条件，提出 `ParentTaskOutcome` 候选。必须通过**本次实际获准的 H3/完成规则**后才可正式结束；专业 `REPORTED_COMPLETE` 不能直接关闭 Run。

在途 W 永远先回原 executor 专业消费；负责人不能绕过它直接拿 Worker Return 当业务结论。主控负责真实派发、账本/回执/去重，不负责判断表格里的专业充分性。

## 7. 一个只表示委派逻辑的业务例子（不声称实盘结果）

目标是观察“标准化高频是否既保留重要拐头附近的有用信号，又减少重复”。可以先签一项材料 D，要求执行 Pro 基于已有“密集与板块密集的简单标准化”完整 CAEGraph/数据入口核查大小转折、原始多参数组候选、select、apply、CloseGroup、merged 中哪些阶段和字段本轮需要真实取出；尽量复用同一图，交 `MaterialPlan`、真实材料与缺口。**不能预先写成数据已经齐全**。

随后将材料（连同实际限制）交给负责合理性分析的执行 Pro，按已有预期来源形成最小业务预期并在正式对照前冻结；对照可能给出 `SUPPORTS/COUNTERS/MISSING` 等任一有据结果。若发现“选中参数事件未进入 CloseGroup”的具体偏差，优先沿这一阶段查临近、同刻、超时与确认事实；缺中间 trace 时回原问题定向补证，不重做全部材料。只有诊断有据显示参数可修复/耦合待求解，并且本轮要求和操作资格允许，才调用标定 Skill。**这只是任务组织示例，不是要求每个用例照此强制走全链。**

## 8. 本版尚不确定（不能让 manager 自行补定）

- 哪些 Gate 由谁正式接受、是否需要独立复核、怎样落入受保护状态；
- 本轮问题的完成深度、允许未决、预算和正式扩大范围的权限；
- R03/R05 具体消费者资格与缺证不可得后的退出条件；
- `INSTANCE_REVALIDATION` 身份/复用策略的最终规则；
- 受保护业务状态程序、统一 `advance` 入口及其真正运行状态。

这些保留在既有 [review/](../../review/) 中。可按本指南执行有权限的调查、规划和专业协作，**但不能因此声称上述未决已经正式闭合**。
