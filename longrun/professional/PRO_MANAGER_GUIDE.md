# 专业负责人 Pro 工作指南：观察材料准备 ↔ 合理性分析（角色适配候选 V0.1）

> 本文件把当前 L0/L1/L2 控制面、观察材料准备 A～E Skills 和合理性分析 Skills 映射为 manager 的专业管理工作。机器身份、C/D/W、物理通信、Owner grant 和持久状态仍按 [V2 长程协议](../contracts/LONGRUN_PROTOCOL_V2.md)。

## 1. 权威来源与不能擅自补的内容

| 来源 | 作用 | 边界 |
|---|---|---|
| [L0 完整任务](../../control/01_L0_完整业务任务与双向衔接.md) | M→R、R→M 补证、逐问题收束 | 候选控制设计 |
| [L1-M A～E](../../control/02_L1_观察材料准备流程.md) | 材料准备外层阶段、阶段 I/O 和回流 | 外层 Workflow 权威来源 |
| [M 五个阶段 Skill](../../skills/observation-material-preparation/SKILL.md) | A／B／C／E 的内部专业工作、D 的单一集成动作、各阶段字段 I/O 和 E Worker 派单合同 | manager 不得改写专业方法 |
| [L1-R](../../control/03_L1_合理性分析流程.md)及 [R Skills](../../skills/reasonableness-analysis/README.md) | 预期、对照、诊断、标定和交付 | 不改写原生状态 |
| [L2 I/O](../../control/04_L2_节点输入输出登记表.md) | 阶段／节点的消费资格 | 不等于每项独立调用 |
| [Gate](../../control/05_三级Gate及后继路由.md) | WorkQuality、UseEligibility、ActionEligibility、TaskCompletion | 不是生产级自动服务 |
| [完成全景](../../control/06_业务完成全景与更新协议.md) | 阶段→M/R→问题→父任务的当前视图 | 只投影真实事实 |

manager 可以把已有专业合同具体化到当前任务，但不能在没有新增专业信息和授权的情况下，自行增加新的业务目标、专业预期或验收标准。

## 2. 管理对象

manager 持有：

- 完整 `BusinessTaskInput` 和逐问题范围；
- M 外层输入：特征名称、特征代码版本、特征实例；
- A～E 和 R 当前有效产物、版本、缺口与消费关系；
- Owner 已明确的约束、权限、成本和禁止事项；
- 当前完成全景及合法后继。

manager 不从聊天记忆写第二套“最新事实”，也不把历史旧流程继续作为新任务流程。

## 3. 初次接管

1. 还原 Owner 已明确的业务目的、对象、范围和禁止事项；未知完成边界显式保留。
2. 核对 M 的三个外层输入是否存在，并固定当前代码／实例版本。
3. 检查是否已有同版本 A～E 或 R 产物可复用；复用前核对输入、范围和版本。
4. 根据 [L2 I/O](../../control/04_L2_节点输入输出登记表.md) 建立当前管理视图：哪些上游已被接受、哪些后继真正具备输入、哪些仅是候选或待验。
5. 只签当前具备前置条件的专业 D；一份 D 可以覆盖相邻内部步骤，但不得把尚未形成的上游产物写成既定事实。

## 4. 一张 D 的最低专业信息

以下内容写入既有 `DELEGATION.md` 正文，不另造机器 Schema：

```text
当前 question_id、业务目标和本次范围
所属 M-A～E 或 R 节点／阶段
已经接受的上游产物及其版本
本次为何要做、由哪个下游消费
外层特征名称、代码版本、特征实例（M 任务）
应读取的具体专业文件：通常是 SKILL / WORKFLOW / IO_SPEC；D 为 SKILL + IO_SPEC；E 另含 Worker 派单合同与两份模板
要求形成的阶段原生产物与最低核对
允许的局部查证、Worker 操作、预算和停止条件
成功、部分、缺口、不可得、失败时分别返回什么
哪些问题必须回 manager 或 Owner 判断
```

不得把 manager 自己编写的业务说明升级成专业 Skill 新要求。

## 5. 观察材料准备 M 的安排与接收

| 阶段 | manager 应确认的输入 | executor 必须形成的成果 | manager 接收／后继 |
|---|---|---|---|
| **A occurrence 理解** | 三项外层输入和真实代码来源 | 事件级 occurrence、各事件发生位置、业务主输出／中间结果、处理关系 | 能供 B/C/D 消费则接受；核心事实不明返回 A |
| **B 观察位置** | A 产物、特征实例和任务明确位置（如有） | 当前经验性普通位置或高频多尺度位置路径 | 合格进入 D；位置问题返回 B |
| **C 展示方式** | A 产物、只读按需使用实例、锁定 CAEGraph 使用手册 | C1 清单；C2 当前展示预期、复杂点循环和唯一预期 HTML；C3 可注入代码与注入合同 | 合格进入 D；展示／能力问题返回 C |
| **D 定义集成** | 外层输入、A/B/C、锁定 CAEGraph 仓库 | 仓库理解、上游问题处理和绑定真实实例／字段／位置的完整 Python 定义 | 合格进入 E；D 是单一动作且不派 Worker |
| **E 执行／运行** | D 完整定义、C2 当前预期／HTML、实例、环境和授权 | E 专业判断；W1 运行／patch；最终图核对；W2 正式图数据；一致性核对 | `DATA_READY` 才可完整交 R；部分／阻塞按真实范围交接 |

### C 的接收边界

manager 接收 C 时应确认：

- C1 已明确待展示信息；
- C2B 第一版展示预期已经直接生成 HTML；
- C2D 复杂点循环每轮同步更新预期和同一份 HTML；
- 循环结束时的当前 HTML 是唯一预期 HTML，没有另造一份 C3 HTML；
- C3 代码保留实例、位置和字段注入接口，未固化 B 最终位置或外层真实实例。

### D 的接收边界

D 发现 B／C 缺项或错误时：

- 修法唯一、证据清楚、不改变 B 位置选择或 C2 展示预期时，可直接纠正并留下完整记录；
- 需要重新选择位置、改变展示预期、存在多个合理方案或拿不准时，必须返回 B／C；
- A 的事件、字段、位置或关系事实不清时返回 A；
- manager 不因 D “脚本能生成”就接受无痕上游修改。

### E 的管理边界

- E 的专业 Workflow 与 Worker 操作委派必须分开：executor 自己判断，Worker 按工单运行和导出。
- 专业 Workflow 不把派单写成业务判断节点；E1 产物映射到 W1，E4 产物映射到 W2。
- **W1** 只负责运行 D 定义、权限内机械修复及候选脚本／HTML／日志／patch；
- manager 不把 W1 成功直接当成图已接受，也不批准提前正式取数；
- executor 用 D／C2 完成专业核图并形成正式取数准入后，才可签发独立 **W2**；
- **W2** 只导出已接受图的正式数据，不得修改脚本、位置、字段或展示语义；
- E 发现品种／时间问题回 B，展示问题回 C，字段／绑定问题回 D；manager 接收专业判断后组织准确后继；
- manager 核对 E 是否完成专业合同，但不亲自重新设计图、修改脚本或替 executor 判断 Worker patch。

## 6. 合理性分析 R 的安排与接收

| 工作 | 应取得的原生产物 | manager 接收重点 |
|---|---|---|
| 预期推导／冻结 | `ExpectationRegister`、适用／反例、`FrozenExpectationSet` | Owner/业务推导/实现来源分开；正式对照前冻结 |
| 证据对照 | `EvidenceComparisonPackage`、场景效果、缺失和新候选 | 绑定冻结版本、真实材料、对象/时间/代码/参数；`COUNTERS` 不等于工作失败 |
| 偏差诊断 | `DiagnosisReport`、竞争解释和可修复性 | 沿处理链定位最早分歧；未定位不盲调 |
| 条件标定 | `CalibrationResult`、联合可行域、少量试验和完整新旧比较 | 动作资格、原始窗口、完整实例意义和副作用 |
| 问题交付 | `AnalysisDelivery`、`QuestionCompletionRecord` | 回答到约定深度；反证、不可调和有界未决可成为合格成果 |

新预期不能覆盖旧冻结版；跨 M 的真实补证需绑定原问题／轮次和用途。

## 7. manager 的 Gate 与后继

manager 每次接收结果至少区分：

- **工作质量**：产物是否符合 Skill；
- **使用资格**：下游是否能消费；
- **动作资格**：新的 Worker／重跑是否可启动；
- **任务完成**：本轮问题是否达到完成合同。

返回必须精确到 A/B/C/D/E 或 R 节点，不能泛化为“重新做材料准备”。未受影响结果继续有效。

## 8. 完成全景

每次有效提交、接受、返修、阻断、补证、版本失效和 Gate 结论后，更新：

```text
实际工作实例
→ M-A～E / R 阶段实例
→ M/R Workflow
→ question_id
→ ParentTask
```

特别记录：

- A/B/C/D 是否只是候选还是已接受；
- C2 当前展示预期／HTML 和 C3 代码版本；
- D 是否完成仓库理解、正式实例绑定和上游确定性纠正记录；
- E 的 W1 是否已运行、图是否已由 E 接受、W2 是否已签发、正式数据是否通过一致性核对；
- `PLAN_READY` 与 `DATA_READY` 的差别；
- Worker patch 是否改变业务语义；
- 哪些版本变化使下游失效。

主控可以持久化 manager 的决定，但不能从散文自行推断新的专业结论。

## 9. 禁止事项

- 不把 manager 写的任务说明当作新的专业 Skill；
- 不自行决定特征应该表现成什么样；
- 不让 executor／Worker 在一份 D 中把未接受的上游判断当作通过；
- 不因 W1 运行成功就接受 E；
- 不在最终图接受前批准 W2；
- 不以部分交付缩小其他必需范围；
- 不重复派发没有新事实的同一复核。

## 10. 当前状态

本指南和 A～E 新 Workflow 仍需真实 Run 验证。manager 的试运行决定不等于已有生产级受保护 Gate、自动依赖引擎或正式权限服务。
