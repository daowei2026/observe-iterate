# 通用接入回归核查（设计与执行清单，非真实 Run 记录）

同一版运行机制应接入以下不同专业来源；不得改公共文件来切换。

| 场景 | 输入来源 | 期望 |
|---|---|---|
| 已有统计闭环 | 原 task-inputs + control/01 + Skill | 继续原专业依赖、专业模板和完成条件 |
| 无 Skill 研究 | 一份具有步骤和完成条件的任务书 + 实例/GO | task_ref 指任务书，D 正文定位步骤，无伪 Skill |
| 混合 | 同一任务部分工作采用 Skill、部分直接按任务书 | 同一 D/C/Return 协议；真实依赖、无额外审批 |
| 自主结果驱动 | 已定目标/边界、executor 实际成果和下一工作建议 | manager 合法续接，不改变授权 |
| 多 Run/恢复 | 各自精确来源、绑定、独立工作区 | 无公共配置切换，UNKNOWN 先对账 |
| 只读研究 | 研究读/写面，不含生产修改 | 不要求生产写权，越权局部阻断 |
| 历史记录 | 原采用 commit、旧 Binding/D/Return | 可读，不改变历史授权和专业事实 |

机械协议验证运行 `python -m unittest discover -s longrun/tests -v`。真实 App Server 新建/发消息/回收、跨 Run Git 写面和恢复只有在真实 GO 后才能核实；不能由文档或测试替代。旧专业方法与模板不重写；统计闭环专业入口仅显式引用既有专用模板，以保持原阅读要求。新增离线 fixture 检查任务书/Skill 共用委派、任意 executor ID 和只读权限，另仓 mocked 建聊测试检查 manager/executor 及旧入口兼容。
