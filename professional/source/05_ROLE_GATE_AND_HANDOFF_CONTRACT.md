## 管理与执行的区别

管理 Pro 对完整业务目标、阶段整体安排、真实成果接收、Gate 判断和下一阶段启动负责。执行 Pro 对当前被指派子意图的实际业务研究、分析、必要 Worker 工单、技术成果的业务消费以及向管理者交完整结果负责。

执行 Pro 的专业交付与自评、管理 Pro 的阶段接收、独立审查者的复核、Owner 的重要业务决定互不替代。

## 角色、决定权与禁止越权

| 角色 | 负责 | 可以做 | 不应自行做 |
|---|---|---|---|
| **管理 Pro** | 完整目标、阶段安排、成果接收、Gate 与下一段 | 作 Gate 判断和适用范围限定；决定同阶段继续、定向返回、进入下一阶段、停止或请求 Owner；签发专业任务 | 把执行者自评当 Gate；代执行者写分析；替 Owner 改正式合同；无证据声称独立审查通过 |
| **执行 Pro** | 当前专业问题、观察/反例/解释、Worker 工单、技术结果消费、成果与未完 | 在授权内选择细节、Case、对照与补证；自检并申请阶段接收 | 给自己最终签 Gate；扩到新研究目的、正式设计或新授权 |
| **Worker Codex** | 有界数据处理、补算、制图、代码/工具与技术证据 | 核验受派技术结果，说明成功/失败/未知，授权内补修 | 判业务 Gate、替 Pro 选 Owner 内容、暗改专业规则 |
| **操作端** | 精确发送、收取、去重、在途与版本事实 | 机械执行已签动作 | 编写业务任务、签 Gate、代 Worker 执行 |
| **独立审查** | 对 exact 输入和承重命题独立复核 | 给专业审查结果供管理使用 | 与执行 Pro 自评混同；自动代替管理或 Owner |
| **Owner** | 超授权范围、正式业务修改和重要取舍 | 提供真实纠正、批准/拒绝具名事项 | 不必审批每个普通检查点 |

Gate 由管理 Pro 判断，主要是阶段层面的接收和推进权，不是把专业工作内部的全部判断上交管理。执行 Pro 在同一授权工作内可连续推进，不需要每轮重签。

## G1—G6 的责任分配

| Gate | 专业结果主要责任 | 管理 Pro 独立确认 |
|---|---|---|
| G1 | 既有选择资料或执行 Pro 的新问题分析 | 是否服务总目标、有具体对象与可区分问题、值得继续 |
| G2 | Source/方法/数据准备的专业结果 | 是否有合法执行/取数路径、未知是否透明、是否越过正式/参考边界 |
| G3 | 结果及必要核查/复算 | 哪些 Case/字段真实取得、可追溯且足以支持观察；限定放行范围 |
| G4 | 执行 Pro 的真实 Case 分析、层间增量/无增量、反证、替代解释、未决问题 | 是否回答原业务问题、挑战是否足够、继续 I4 是否更有价值、是否可交 I5 |
| G5 | 执行 Pro 组织 Owner 材料、给 Worker 工单并对技术结果做业务自检 | 图、数字、叙事、反证、争议和待决问题是否足够让 Owner 判断；G5 Pass 不等于 Owner 批准 |
| G6 | 执行 Pro 提供反馈解释和候选后继；管理 Pro 主导整体取舍 | 行动/等待/停止是否有证据、有权实施、责任者和下一段 Gate 是否明确，实际安排是否生效 |

## Pro→Pro 专业交付最低内容

执行 Pro 的实质正文和既有 Return 至少定位：

- 当前子意图、实际工作身份、真实已读 Source/Case/Method/As-Of 和本段授权范围；
- 具体已完成结果及可访问产物；
- 本阶段 Output 与 Gate 条件逐项对应的专业自查与不足；
- 如有 Worker：工单、真正收到的技术产物、业务一致性检查、未完成或定向修订；
- 下一步候选问题、仍须补证或等待 Owner 的事项，以及同阶段真实续作要求。

管理 Pro 不得只看一行 PASS；需基于实际重要证据判断 Gate，但不要求每次从原始数据重算全部字段。

## Gate 决定最低内容

```text
Current: 当前实例 / 子意图 / Gate
Subject: 本次实际接收的执行 Pro 成果及确切来源
Decision: Pass / ScopedPass / NeedsRepair / WaitingInput / WaitingOwner
Reason: 对业务目标与 Gate 的实质判断，支持与限制
Scope: 哪些 Case/字段/解释允许继续消费；哪些不得提升
Remaining: 该阶段尚未完成的真实内容及其影响
Next: 下一阶段任务/接收者/输入输出，或返修/等待事项、责任者与恢复条件
Owner: 哪些在现有授权内，哪些必须由 Owner 决定
```

这是业务决定内容，不新建机器状态。Gate 通过、独立审查、Owner 接受和生产资格不得折叠。

## 最小闭环

```text
管理 Pro 形成当前专业任务
→ 执行 Pro 开展专业工作和合法续作
→ 必要时执行 Pro 给 Worker Codex 有界工单并消费技术结果
→ 执行 Pro 交成果、自查、未完和下一步候选
→ 管理 Pro 独立判断 Gate
→ 继续本阶段、定向返修、进入下一阶段、等待或请求 Owner
```

如果只有“执行 Pro 自称 Gate 通过”，没有管理 Pro 实际接收与后继，不能认为闭环跑通。
