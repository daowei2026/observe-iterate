## 角色责任

| 角色 | 负责 | 不负责 |
|---|---|---|
| **执行 Pro（发单前）** | 决定图/数据处理要回答的专业问题、Case、证据版本、时间窗、合法比较域和不可作的推论 | 把“画图”本身当业务发现或让 Worker 自选投资结论 |
| **Worker Codex** | 按明确工单读取/加工冻结输入、生成图形和可复跑构建器、实际渲染核查、交数据与图对应的来源和问题 | 自动改正式 Method、候选资格、BusinessFinding/投资判断或未授权平台代码 |
| **执行 Pro（收到结果）** | 核查图是否支持专业发现、是否无未来信息/错轴/虚假因果，决定修图或形成阶段申请 | 以“已生成 HTML”自动签署 Gate |
| **管理 Pro** | 检查完整材料、确切图/证据和阶段 Output/Gate，决定通过、返修或请求 Owner 判断 | 把技术产物验收冒充 Owner 正式接受，也不替执行 Pro 编具体制图内容 |
| **操作端** | 只机械提交已被执行 Pro 正式批准的工单，核真实回执和唯一结果返回 | 不批准 READY、不重派 Worker、不判断业务 Gate |

执行 Pro 的 Worker 工单可以在 I4 发出，为观察补充中性图或数据证据；面向 Owner 的解释性图组，其业务主题应以 I4 实际发现为依据。一次工单只应有一个清楚的业务用途和有界写面。

## Worker 工单最低字段

| 字段 | 应填写的真实信息 |
|---|---|
| WorkOrderId / Parent | 对应子意图/Gate、当前具体业务问题 |
| Why / ObservationClaim | 本图或数据处理要区分哪项事实/候选解释，以及不应推出哪些结论 |
| Inputs | 精确文件、成员路径、Case/尺度/日历/As-Of、Source/Method 版本及必需字段；不得把不可访问位置当输入 |
| Context | 适用专业合同和必要原程序/源码的真实可访问版本 |
| Outputs | 图清单、每图所服务的问题、页面/PNG/数据表、源代码、可复跑说明和客观阅读顺序 |
| Visual Law | 总览/细节、actual/confirm、Working/Completed、单位/归一化、缺失/空组、证据/方法来源 |
| Execution | 目标环境、工具、允许读写面、受保护来源和验证办法 |
| Completion | 每张图能追到输入和参数，实际渲染可读，标题/图例/时间正确，关键点可核；未做浏览器/平台验收时如实说明 |
| Return | 文件相对路径/commit/清单、实际命令、关键截图或查看链接、校验、失败/未完、需 Pro 裁决的问题 |

不得只写“把图画出来”，也不得把一份历史画图材料交给 Worker 自行猜目标。

## Worker 回交与执行 Pro 专业接收

Worker 技术输出至少应提供：

- 图形工件、必要预览、可复跑代码及实际数据/参数来源；
- 输入与产物版本、Case、时间窗和日历；
- 图层/Legend 与字段对应关系，说明显示转换/归一化；
- 实际执行/渲染验证和未验证项；
- missing、空流、时间错位、来源身份及其影响；
- 技术问题与业务问题分开，业务争议返回执行 Pro。

执行 Pro 将图与真实结果和专业发现/反证逐项比对；不通过则交清定向修订。合格后纳入本阶段专业交付，再由管理 Pro 判断 Gate。技术完成、执行 Pro 专业接收、管理 Pro Gate 通过和 Owner 正式决定不得合并成一个“已验收”。
