## 阶段关系

```text
I1 --G1--> I2 --G2--> I3 --G3--> I4 --G4--> I5 --G5--> I6 --G6--> 下一轮/结案
```

外层阶段顺序推进；每一阶段内部不规定固定计算路线、Agent 数量、Case 数量或聊天轮数。一个阶段可以跨多轮运行，在满足 Gate 以前继续同一子意图。

管理 Pro 根据完整目标、既有结果和实际剩余安排工作并独立判断 Gate；执行 Pro 在已签发的当前阶段内负责专业工作和连续合法续作。不得将 I4— I6 混成没有独立结果与 Gate 的任务，也不得让执行 Pro 自签阶段 Gate。

## 每次进入下一阶段前必须交清

| 项目 | 最低内容 |
|---|---|
| 当前子意图和工作范围 | 具名身份；当前工作是否仍在同一子意图 |
| Input | 上游实际产物和来源、适用方法/Case/As-Of、缺项 |
| Output | 已形成的实质成果、证据、不足与限制 |
| Gate | 执行 Pro 交结果、自查与证据；管理 Pro 判断下游使用资格并给出范围、返修、等待或下一阶段安排 |
| OwnerAdditions | 本阶段有无新的、可追溯的 Owner 纠正/补充；不得由 AI 代写 |
| Handoff | 通过时交下一子意图的实际工作依据；未通过时定向补修或等待输入/决定 |

## 定向返回而不是清零

- 文件、Trace 或数值问题：返回 I3/G3 补受影响结果。
- 方法输入/兼容规则来源不明确：返回 I2/G2 定向澄清。
- 计算可信但业务解释、增量和反例未完成：继续 I4/G4。
- 改变正式合同或超出授权：交有权 Owner/原合同责任者。

一部分结果可信、另一部分未决时，可以在管理 Pro 核准的限定范围继续 I4；未决部分不得被提升为强结论。

## I4/G4 的最低专业要求

I4 要基于真实业务结果发现事实、差异、增量或无增量、反例和替代解释，直到能够把有价值的认识与未决问题交给 I5。

G4 不能机械写成“输出报告或三张图即可通过”。至少应有可追溯的业务发现，或经证据支持的无增量/当前不足结论；同时交本轮适用解释、不确定性、反向挑战和下一步值得研究的问题。
