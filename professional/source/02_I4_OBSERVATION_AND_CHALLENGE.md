## Input / Output / G4

| 字段 | I4 具体内容 |
|---|---|
| **Input** | G1 业务问题；G3 确认可消费的结果与路径/As-Of 事实；对应 MethodProfile/临时规则限制；单品种、静态分组、既有组织结果、组织结果加后续质量的比较基线 |
| **Output** | 对真实 Case 的现象与差异描述，业务增量或无增量的证据，支持/反证/缺失/替代解释，必要方法敏感性与反例挑战，明确可继续检验的候选问题 |
| **Gate G4** | 至少对主要观察问题形成有证据、有适用范围、经必要反向挑战的实质业务认识，或有据说明目前无法形成/没有增量及其原因；仅重新罗列公式、数字、题目或漂亮图均不通过 |
| **交付到 I5** | BusinessFinding / NarrativeHypothesis / Challenge / OpenQuestion 及其确切证据和限制；明确哪些确需 Owner 判断 |

## 执行分工

I4 由执行 Pro 承担实质业务观察。执行 Pro 从实际结果提出重要现象、业务解释和挑战，自查哪些认识有增量、有哪些反证或不足。管理 Pro 根据 I4/G4 证据判断是否达到阶段交付、是否继续 I4 或交到 I5。

只有数值表无法看清真实过程时，执行 Pro 可以在 G4 前提出目的明确的 Worker Codex 工单，要求中性事实图、数据切片或定向复算。Worker Codex 负责技术形成与实际渲染/检验；执行 Pro 消费结果后继续业务观察。

不得让 Worker Codex 自行判断图要证明什么。执行 Pro 必须先说明当前 BusinessFinding/待辨问题、Case、证据版本、时间窗和合法比较域。

## I4 真正要回答的四类问题

1. **现实中发生了什么**：哪个时点、哪些对象、哪些发生项/段/组候选、哪些推进—摩擦—保持事实及生命周期变化？
2. **业务上多知道了什么**：只用单对象、只用静态分组、再用组织结果、再加后续质量，认识在哪一层实际改变？哪层没有新增信息？
3. **是否经得住挑战**：结论是否由个别段、观察截止点、不同单位、临时方法、共享证据、未完成段或缺失数据造成？
4. **下一步怎样缩小不确定性**：找什么 Case、补哪个结果、核查哪条规则，或是否进入更深关系/跨尺度？

## 业务结论的身份

- **事实**：冻结 Case / 方法 / As-Of 下，运行产生或原行情直接支持的陈述。
- **CaseFinding**：这一 Case 内经过对照得到的业务发现。
- **NarrativeHypothesis**：需要其他 Case/后续事实检验的解释。
- **DesignFinding / MethodFinding**：定位到表达缺失、合同不清、方法敏感或证据重复的具体问题。
- **NextObservationQuestion**：下一轮可执行的验证问题。

一次 Case 的结论不能跳跃为已验证的市场普遍规律。

## 初始挑战清单

- 事实过程：实际点、确认点、Working/Completed 分界和不同 As-Of 的变化。
- Movement 区分：推进、路径效率、反向负担、保留/恢复是否存在可观察差异。
- 层间增量：单对象、静态分组、组织结果、组织结果加后续质量分别改变了什么认识。
- 解释挑战：Episode 成熟度、评价截止点、参数、单位、归一化、极端段或证据重叠是否造成表象。
- 下一步决策：最值得再检验的重复性、组内外边界或方法未封闭问题。
