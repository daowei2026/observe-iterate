# 四项专业工作的初始输出表达（可扩展）

## 1. 定位

目标是让执行 Agent、管理及 Owner 知道**当前产生了什么成果、依据是什么、后续怎样继续**。这是人可读的基本组织方式，**不是硬性机读 Schema、四阶段验收单或限制其他发现的格式**。可在实际运行中补充、变更。

同一轮专业工作不要求四项同时都完成；只描述当轮真实开展的内容以及与其他内容的关系，不因某一项尚未开展而虚构结果。

## 2. 建议的基本结构

**A. 本次观察对象与所用依据**

具体特征名称/实例；实际所用的实现或结果来源及版本；特征含义、输入、输出与参数中本次相关的部分。未知项写未知，不靠原 U2/U3 文档推断已经实现。

**B. 四项专业工作的进展、结果及其关系**

| 工作 | 需要交代的实质 |
| --- | --- |
| 1. 参数 | 实际采用或拟采用什么参数；为什么初步这样考虑；仍未明确的部分 |
| 2. 展示方式 | 实际展示配置文件及版本；选择哪些信息及理由；K 线叠加、附图或其他图形的具体画法、轴/时间/状态及变化含义；与 uplot 能力的对应、尚未验证处和修订依据 |
| 3. aidata 制图 | 工作 2 配置接入 aidata/feature_configs 的实际位置及调用版本；定位方式、观察范围、正式 Feature/已有结果入口和必要适配；真实取得的图、对应数据及尚无的部分 |
| 4. 检查分析 | 正式输出、对应行情及必要上游支持的真实现象与有边界认识；正确性、正常业务解读、展示易误读分别判断；哪些结论需要且已经实际视觉看图，哪些只基于数据 |

上表帮助组织内容，**不能因为用了表格就把有价值的图解、具体用例或因果追查删除或压短**。

工作 2 的说明不能替代实际配置文件，也不要求该首版永久定稿。按需说明随时间产生、保持、变化与修订如何表达，以及多品种颜色与其他性质的区分；不另设单/多品种选择栏、固定曲线数或逐拍机制。工作 3 的配置适配不代做工作 2 的重要业务画法。

**C. 重要发现及后续处理**

说明重要发现依据的具体结果/行情位置（若已取得）、目前认识、仍需处理的问题，以及下一步要继续哪项工作或返回修改哪项工作。一次专业循环可以形成多个发现，也可以如实交代尚无判断。

**D. 格式之外的额外分析**

执行中发现不在上述结构中的有价值分析，应原样保留并适当关联，不能为了满足既有格式而忽略。

## 3. 两种“完成”不要混同

- 某项配置、某张图、某个检查已经真实完成，可以记录为对应成果。
- 整体专业观察是否结束，应由具体特征当前值得研究的问题、已得认识和接续方向决定；不因为四个栏目都填了字就宣称专业任务全部完成。

不设置预定 Case 数、图数、得分、格式覆盖率或逐步签收条件。

## 4. 文字表达边界

优先使用正式特征结果、对应行情和必要上游分析；`plot_view_data` 只用来核对图实际显示了什么，不冒充正式特征结果。数据足够时可以形成有边界认识，不要求每个 Case 都视觉看图；正式图未打开，不写成“已看到图”，AI 只取得图对应数据，不写成“AI 已视觉看图”。参考计算与正式 Feature、Working 与 Completed、实际发生与确认可知时间等区别，仅在**本次具体特征涉及这些语义时**说明；不机械把旧 U2/U3 的完整字段清单列为本轮固定输出。
