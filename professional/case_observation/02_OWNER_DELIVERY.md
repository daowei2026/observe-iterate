# Owner 阅读交付：一个入口、一批用例、一个平台页面

## 1. 交付形态

在实际 run 的 artifacts 下组织本批成果，例如：

```text
artifacts/<batch>/
  OWNER_REVIEW.md
  cases/C-001.md ... C-005.md
  aidata/INPUT_AND_CALLS.md
  aidata/<实际入参文件与调用脚本>
```

这是组织示例，不是新增运行协议或强制文件数量。短小的逐例正文可以放在入口下的独立章节，内容只维护一份。大数据保留在既有交付位置，Git 保存准确索引，不上传凭据或整份工作区。

## 2. OWNER_REVIEW.md 必须直接给人什么

开头说明实际研究的品种、共同研究范围、已研究用例数及本批关键认识；只报告已做事实，准备阶段不填写虚假结果。本批 rb/hc/i 的概览从 **2021-01-01** 开始，不把报告里从 2013 年起的测试范围称为本批“全历史”；请求的结束边界和实际数据最后时间分开写。

**一个主要平台图链接**：打开同一平台页面能看到完整研究范围的 1d 概览及本批每个用例的 30min 大尺度图，后者叠加 **mid 参数贴近转折**。不是把多个 report_url 放进一个 Markdown 索引就算一个平台链接。允许利用现有平台增加图，也允许新建一个包含全批图的完整页面；不额外要求 URL 永久不变。页面更新后入口必须准确指向当前交付，原证据版本仍可追溯。

每例在入口中可快速看到：

| 内容 | 人应当立即明白什么 |
| --- | --- |
| 用例 ID、品种、核心时间 | 对应统一平台页面内的哪张图/PlotSet、哪个位置 |
| 为什么选这里 | 具体多品种分化和业务价值，不只一个类型名 |
| 回看后的认识 | AI 怎样解释，哪些支持，哪些尚拿不准 |
| 最值得反馈处 | 具体哪项判断、回看选择或未解决问题需要检查 |
| 详细正文位置 | 无需读运行日志即可进入该例的依据 |

## 3. 每例详细正文

保留本例的位置、各品种实际表现、核心区间/展示窗口/回看范围、研究问题、实际查看的信息、解释链、支持与反证、候选解释及未知。结论引用到可核对的日期、品种、数据或图中位置。

结果标签、口头好坏与交易机会不能混为一谈。对“当时能辨别”的主张明确真正可知依据，对事后描述如实标明；不要求每例提交统一 T 或成功预测。自然产生的词汇/特征缺口可附在该例，不扩大为当前必须完成的开发任务。

## 4. aidata 输入和调用：在入口就能看清关系

Owner 不应只能看到“已使用 aidata”。入口给出实际关键入参和调用顺序摘要，并链接完整入参文件/可复现调用脚本；详细记录可以放在 `aidata/INPUT_AND_CALLS.md`。

关键输入包括实际 workspace、aidata 精确提交及依赖/配置版本和相关本地差异、Context/DataBinding、实际品种或板块成员、日历/时区、频率、big_source/manual 窗口、定位/贴近转折参数、evidence_features、generation_depth、output_root 与 run_id。明确列出实际 `startDay/endDay`、全范围窗口与各用例窗口；不能只抄可能为空的 `context_ref.start_day/end_day`。本批同时列明 **30m 频率、big 节点层级、ScaleTurnCalendar("mid") 参数**，不能用“大尺度”一词混指三者。仅展示实际使用字段；敏感值遮蔽但保留配置引用和非敏感语义，不伪造默认值。

逐次记录：

| 次序 | 接口/动作 | 实际关键输入及完整配置位置 | 输出和用途 |
| --- | --- | --- | --- |
| 按真实调用填写 | build_chart_run | 真实 run_brief_input | 冻结 core/节点/范围 |
| 按真实调用填写 | build_big_world_chart_pages 或实际独立 overview 入口 | 真实 run、参数 | 实际平台对象、URL、图组成 |
| 按真实调用填写 | build_board_run | 同一 core 身份、reuse_core 等实参 | AI 真正消费的数据文件、范围和来源 |
| 确有调用时填写 | 现有 CAEGraph/PlotSet 页面组合的实际代码入口 | 所组合的图、run/node/范围及参数 | 单一平台对象、统一 report_url 和图内名称 |

三个既有接口分别是建立 core、生成平台图、形成正式数据，不是每次必须全调。未调用的明确写未调用及原因；独立 overview 与页面组合写出实际名称及与三个接口的关系。若第二接口已内部生成 overview，说明该事实，不虚记一次额外显式调用。不能把计划调用、源码可行或只生成 URL 写成真实成功。

保留用于全范围选例的方式一 1d 数据出处，再分别列出方式二各例的 1d/30m/mid 切片；后者不能冒充完整概览对应的全部历史数据。记录每品种实际首末时间、有效行/缺项以及图实际打开核验的操作者与结果；将 Case 对应到 aidata run/node/feature_key 和统一页面内的图名。

图显示的前后余量（原测试为 extra_time="10h"）不自动等于正式切片范围。研究实际使用了窗口外信息时，指出补充的正式数据来源；不要求图与切片总行数机械相等。历史测试的行数、URL、TEST-C001 等标签只作工具依据，不列为本批业务成果。既有测试支持了什么、本次参数变化后实际核到了什么，分别简要说明，不复制全套环境日志到 Owner 首页。

## 5. 完整性和反馈

正文、图和调用记录不要求 Owner 逐项批准。整批完成后由原管理机制交给 Owner 一次性查看，反馈按原 CHANGE 路径回到有权责任者。Owner 可以直接说“C-002 的先强后弱解释不对”或指出图中位置，AI 负责关联并定向修订。

统一平台页尚未交付或实际打不开时，应保留研究成果并明确缺口，不用 PNG、standalone HTML、临时 localhost 或多个独立链接宣称满足要求。现有报告已补充单页组合成功，不应再把旧源码改造建议列成本批必做；具体适用性见 [03](03_AIDATA_USE.md)。技术验证通过、平台能打开、专业研究成立、Owner 已阅读/认可分别是不同事实。
