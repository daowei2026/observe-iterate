# 业务交付：当前用例、观察过程与图数对应

## 1. 一个持续更新的阅读入口

在真实Run的artifacts下提供一个 `OWNER_REVIEW.md`。找到可讨论的对象或形成实质判断就更新，不等凑齐案例或扫完历史。入口首先回答：当前采用什么设想，实际看到哪里，形成/修正了哪项品种判断，用例现在是什么版本，还缺什么。

一种可用的轻量组织如下，具体可合并，不强制文件数量，不在准备阶段填假结果：

```text
artifacts/
  OWNER_REVIEW.md
  CURRENT_SCENARIO.md          # 当前采用设想及必要变化
  cases/CASE-001.md            # 初始用例及配套观察，可同文分区
  inputs/INPUTS.md             # 实际交付、语义、图数定位及缺口
```

必要的数据和图面实物留在既有正式交付位置，准确引用即可，不复制整份数据或工作区。关键T的状态表、对象定位或快照可按需放在对应研究材料，不增加一套庞大证据库。

## 2. 当前用例与观察材料分用途阅读

**用例正文**正面讲清：具体特征背景、对象及属性关系、已观察现象、所利用的候选规律、对后续品种的条件性判断和适用范围。用语稳定，能定位到具体尺度、点和线段，不以原价流水账或抽象名词代替业务主体。不要预先写成完整算法或通用网络系统。

**配套观察**保留关键时刻的当时可知依据、候选背景及变化、原判断、新信息和实际后续、失败与修订。两类内容可在一份Case里分区，引用已存在原件，当前内容只维护一份。必要条件和已知反证影响正文，详细检验与运行说明不反复打断故事。

一条关键观察可以包括“观察T—当前对象—新取得的信息—背景/判断—后续反馈”。这是内容提示，不是逐根日志模板，也不强制每次填满固定列。只记录足以追溯重要业务认识的信息。

## 3. 人能在图上找到AI谈的对象

入口给当前实际图入口、图名/成员/尺度、查看位置，并关联正式数据或对象标识。图和结构化依据共同支持观察；AI未实际看过图时如实说明，不将数据核对写成图面核验。

优先复用已交付、可阅读的图与必要状态说明。多视图可按尺度/时点组织在同一阅读入口，当前不继承旧五图单页或四固定阴影的布局义务，也不因此新建平台。实际T、方向、确认对应与可知范围应符合 [03](03_FEATURE_DATA_AND_VIEWS.md)，不能只靠图页存在来宣称满足。

如果最终历史图与当时可知视图分开，标清用途；被未来信息影响的探索如实注明。输入/显示缺口只限制依赖它的主张；必要可知状态无法核实时，交具体缺口，不能用事后图充当提前判断证据。

## 4. 输入记录以消费实际交付为主

至少写清实际来源与版本、品种/时间覆盖、尺度及特征配置、字段与方向语义、实际/确认时间口径、图数对应、哪些能力可用和哪些仍缺。已交付输入直接引用生产者的正式记录，不要求执行者重跑原取数或重写全套调用日志。

确实新增调用时再记实际入口、入参、输出及用途；未调用的说明复用来源。大数据不上传凭据或整份工作区。新Run的研究时间、输入生产时间和历史市场时间分别表达。

## 5. 反馈与接收

Owner可直接指出图中位置、某个对象或判断的问题，不必重填问卷。原专业者消费后只改受影响部分，保留原判断及版本来历；无反馈不自动停止其他可做研究。

管理按 [00](00_PURPOSE_AND_OUTPUTS.md)核实际业务内容，不仅核格式、谨慎措辞、取数或图能打开。限定范围初版可交接，不要求穷尽验证；尚不能形成用例则明确实际尝试、发现及下一步。方法准备、数据已到、结构可研究、具体判断已形成、图面已核、Owner已认可分别是不同事实。

首轮不要求3—5例，不把每个历史片段都做成独立新特征。已经满足授权目标就收拢，未满足但仍有明确可做的业务问题则继续；无新增问题时不为填时长反复润色，也不自动启动其他业务或实现任务。
