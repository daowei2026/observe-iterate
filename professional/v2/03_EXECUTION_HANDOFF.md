# V2 执行接线与异常处理（沿用既有角色，不新建角色体系）

## 1. 继续沿用的责任

管理 Pro 以完整 S1–S3 业务目的安排任务、检查实物和决定管理接收/接续；执行 Pro 选择观察内容、定义图的业务问题、消费图与数据、反证并提交业务认识；Worker Codex 按授权配置 aidata、取数、渲染和做技术核查；操作端沿已发布协议处理消息运输/回交/去重，不能自行决定业务问题；Owner 审阅关键事实、重要业务取舍或权限外变更。

这只是沿用 V1 已有工作分工，不将“角色分工”增加为 V2 第四个业务步骤。

## 2. 一次制图工单的最低输入/输出

输入：本轮观察问题、rb/i/hc 等对象范围、设计/方法来源、数据身份与获取方式、要核查的合法时间窗、图层与比较用途、aidata 锁定版本、不能得出的结论。

输出：确实运行的命令和环境、aidata run/node 身份、可打开的实际图、同一冻结窗口的主证据与共享视图、核验结果、已知局限、技术待解问题和精确返回路径。**无图不可交“已画图”，只有图无可消费数据不可交“同源证据完成”。**

## 3. 工程问题不改变业务目标

缺少 CSV/ZIP 正式导入或画法、Feature 接口不兼容、环境缺失时：
- 工作主线仍是 S2 获取可核验图与数据；执行 Pro 将缺项定向拆成有边界的 Worker 任务；
- 通用工具修改只能在 aidata 实施；不得创建 observe-iterate 内的平行制图工具；
- 必须遵守 aidata 的 Owner 意图、当前 API 和 TODO；验证后返回原业务观察；
- Worker 不替执行 Pro 下“设计不合理”结论；
- 无法合法执行时准确标记 `WAITING_INPUT / BLOCKED` 及可恢复条件，不能默默跳到 S3 假装看过图。

## 4. 长程 Gate 与原始真实结果

保留通用 `ROLE_RETURN`、有权采用的 `QUESTION_WORK_RETURN`、管理地图/任务、Workmap Intake 和实际审阅；这些是运行与可消费资格，不再规定六个业务阶段。

只有真实 Owner GO 才能新建活动任务、Binding、聊天、轮次；准备版本不等于 GO。旧 `BI-01-RESTART-01` 的 Gate、聊天、token、Return、Owner 决策不作为 V2 派发或完成事实。

资料版本变化后做精确 Source/Method/Data 身份核对，不用旧结果给新成果冒名背书。
