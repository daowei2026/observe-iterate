# V2 执行交接：固定数据、aidata 和现有长程角色

## 1. 既有分工不需要重建

管理 Pro 依据三步完整业务目标安排和接收，执行 Pro 负责观察方案和业务分析，Worker Codex 根据明确技术工单使用 aidata 画图与取同源数据，操作端按有权任务运输消息与成果，Owner 审阅重要业务认识。此为原有长程职责，不另设角色分工阶段。

## 2. S2 工单必须写清楚的事情

输入：本轮固定两份 ZIP 的确切文件名、数据位置/校验状态、需要查看的 U2 机会簇与 U3 四方面、品种 rb/i/hc、已定义的观察时间/As-Of、哪些图层需要展示、应保持的 Reference/Shadow/Withheld 边界，以及当前 aidata 版本。

输出：使用现有 aidata 实际生成且能打开的真实图、与图一致的冻结数据视图、run/node/timespan 和读图说明、A/B 原件及结果来源、运行/测试事实和有界阻断。不得用重算另一批 Feature 代替本次 ZIP，不能以“有图链接但图打不开”报完成。

## 2.1 当前 Worker 工作区（与数据存放位置分开）

本次执行 Codex **可用工作区**：`/dwdhome/fy/BASE_E6_2`。S2 派工时以此作为 aidata 执行的工作区起点，在实际 Codex 机器上核对路径存在、必要权限、所用 aidata 版本、Python/Fao 依赖及本轮固定 ZIP 的真实读取路径，再记录执行命令与产物位置。

这个工作区**并非**本轮两份 ZIP 的新增数据来源，也不表示 aidata 仓库必定检出在该目录；固定数据来源以 [05](05_BI01_FIXED_INPUT_DATA.md) 为准。不能因为工作区可进入就声称数据已到达、图已画出，不能为打通接口偷偷重新计算预先验算好的 U2/U3 数据。若实际 Codex 环境不具备某项条件，只反馈具体阻断和受影响的任务，不预先扩成环境建设项目。

## 3. 两种特殊情况

- **发现固定预计算数据有具体疑问**：指出文件、字段、行、时间、方法及影响，允许有界核对并向管理/Owner 反馈；无新的有权决定，不自改固定原件、不扩为整套重新验算。
- **发现 aidata 确实没有现成能力**：先调查现有入口与 TODO；除非实际业务推进不可避免，否则不修改工具。确需改动时**仅在新建的 aidata 独立分支上**提交，不能改现有 aidata 分支，也不能另造 observe-iterate 画图实现。相关权限/回交仍按正常 Worker 合同处理。

## 4. 当前不给 AI 图片

交付给执行 Pro 的是图对应的真实结构化数据、标记和图上对象定位信息；图/链接供 Owner 审阅。当前不要求图片像素进入模型，不为此制定视觉验收，不把“AI 没看到图”列为阻断。无法取得同源数据时才是当前输入缺件。

Pro 无法通过 GitHub 提交本轮成果时，应先保留原实质回答/Return，再按 [V2 轮次备用 ZIP 交付合同](../../runtime/operations/V2_ROUND_RECORD_CONTRACT.md) 将对应文件打包。MCP server 可写的 `H:\fy\observe-iterate-share` 与操作 Codex 可读的 `/dwdhome/fy/observe-iterate-share` 是**同一共享传输通道的两侧路径**，不是 aidata 工作区或数据源。由操作 Codex 核对包身份、内容、GitHub 是否已有同轮提交，合法时再发布回仓；共享盘存在 ZIP 不等于已获业务接收或 GitHub 提交成功。

## 5. 运行与业务分开

正常 `ROLE_RETURN`、`QUESTION_WORK_RETURN`、管理 Workmap、合法续作及有权接收继续使用；这些是长程机制，不替代业务目标或多造三个 Owner 审批阶段。新 `BI-01-V2-01` 不继承旧 run 的专业结果和 Gate；**原 I1–I3 的业务背景作为 Source 阅读，和旧执行状态不是一回事**。
