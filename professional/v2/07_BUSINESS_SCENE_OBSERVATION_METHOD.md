# BI-01 V2：叙事业务问题驱动的真实行情观察方法

> **历史参考资料（非现行执行合同）**：本文件原属于 V2 S1–S3 方法；当前仅按具体特征需要参考其中的业务知识。旧固定数据、阶段目标、操作方式及 GO/Gate 不能直接适用于 BI-01-FO-01；现行任务以已采用的 `professional/feature_observation/` 与 FO-01 Binding 为准。

## 1. 方法定位：不替实际执行预设场景分类

**这份方法不定义固定的 A/B/C 场景类别、用例清单、优质阈值、强弱计算公式或样本配额。** 要观察什么类型的场景，是专业 Agent 在真实阅读 U2/U3 人读 Narrative、Use Case、Owner Decision 并初步查看基础行情后，解释性地决定和必要时修订的。既不能只挑事后强者，也不能让初始化、Pending、缺项、工程测试或某个单字段反例替代中心目标。

核心问题：在 `DirectionalReleaseIntent` 的市场过程中，多个品种表达共同一轮方向机会时，是否出现值得研究的较强运动、组内是否真的存在强弱差异；U2 能否识别共同机会的恰当位置与成员；U3 四个 Movement Evidence Bundles 能否在当时提供辨别成员后续方向运动质量的有效信息，并且比已经有的 C0/N、原价或简单共同事件关联更有实际增量？若组内都不值得做，也应可以拒绝硬选；具体怎么观察由市场事实决定。

## 2. 阅读真实设计以理解其场景，不从字段倒推任务

先取得锁定 Source 的实际正文，不只凭 [06 导航](06_U2_U3_DESIGN_SOURCE_MAP.md) 的标题：
- Owner Decision / U2 Narrative：U2 的机会身份、转折后相容方向组织、不同成员和重复暴露边界是什么；U2 不负责最终好坏排名。
- U3 Narrative / Use Case：为什么需要 Progress、Friction、Retention、ObservabilityAndConstraint；为什么“方向明确、有运动、低摩擦、保持好、当时可知且有必要约束”不能压成单一效率或原方向字符串；U3 Current、Outcome、Feedback 以及组内比较/质量下限的职责是什么。
- 原 I1–I3 的 OP-01/Q-01 和实际方法/数据资格：旧结果作为问题和可追溯历史，不预先代替本次判断。

写出简明的业务问题及预期观察关系：**市场中希望识别何种共同方向过程 → U2 应提供什么机会/成员身份 → U3 应提供什么当时强弱依据 → 哪一种真实后续运动会支持或反证 → 对已有基线新增什么。** 当确有数据或语义限制时明确影响，不以逐字段“已有/没有”表取代业务问题。

## 3. 先观察只有基础行情/转折的图，独立发现位置

优先看固定 rb/i/hc K 线、small Zig、mid 贴近转折的 actual/confirm/known、原 Segment/Episode 等在 [05](https://github.com/daowei2026/observe-iterate/blob/c7971cc616e09db47681abc868e77acdc272f84a/professional/v2/05_BI01_FIXED_INPUT_DATA.md) 有来源的事实，使用已有 aidata 的基础可见图和同源结构化数据；Owner 实际看图，AI 仍不视觉看像素，不能声称 Pro 亲眼见到了图。基础图本身可用于理解转折与运动，**先不以 U2 的现成 raw 集合或 U3 数值决定哪些行情值得观察**。

专业 Agent 自行从真实市场过程提出候选观察位置与研究理由：谁在何时出现相近转折、是否沿共同方向运动、是否值得比较、成员之间在什么已知范围表现强弱差异、有哪些基础事实使“机会”或“强弱”仍模糊。不得把“同actual”“正进展”“单一效率高”直接等同于有效机会或较强品种。基于未来路径得到的候选须注明是**回顾性发现**，且不能用这些发现反证“当时已预知”。

若从基础行情得出的有意义场景不能落入现有 U2 raw 索引，也要保存确切时间和定位，用于检查识别入口的边界，不自动宣称正式 U2 漏检；若一直找不到适合的主要场景，要先说明固定输入内实际搜过什么、为何没有以及对本次任务影响，让管理决定下一步，而不是无限扩大工程。

## 4. 再核 U2 在这些地方的实际结果

对于每个有价值的位置，比较基础行情所体现的真实共同过程，与 U2 已给出的 raw C1、参考 C1/S/C2、起点、成员/组外、known/confirm、生命周期：
- U2 找到的位置/共同方向和成员为何合理、可疑或不合理？其识别时机会是否仍存在？
- 有没有实际看似相关的错时组外对象？是不同 actual/知识时点，还是需要反证的遗漏？不要用结果事后合组。
- 分清 U2 只组织机会身份，U3 才评价组内强弱；单纯 raw 同组不是正式簇、不是已可用的优质机会。

当前固定数据广域没有正式 C2 Commit/H1 或逐例完整 Qualification/Separation，因而**可以核场景与 raw 观察关系，不能据 raw 例子断言正式算法的准确率/召回率或资金机会数量**。

## 5. U3 四方面的当时辨别与后续事实检查

先明确比较哪一轮机会/哪个 Episode、合法 As-Of、成员及可以比较的观察范围。根据固定预计算 U3/N 原行逐项说出：
- Progress：当前方向推进是否足够清楚，与哪个原预期和尺度有关；
- Friction：当时路径顺不顺、逆向/折返负担是什么，哪些是原段/跨段的区别；
- Retention：运动是否保持、历史 Completed 和当前状态是否混用；
- ObservabilityAndConstraint：数据、可知延迟和成本/流动性等约束是否允许形成判断。

**比较的主体是成员后续运动质量，而不是单纯把四组已有字段列完。** 至少辨明哪几项让成员间发生可解释差异、哪几项只是同源重复、哪些缺失/Withheld，是否存在真正值得继续研究的较强成员、是否全体都不合格或尚不能判断。不预设总分、固定强弱阈值或必须给出排名。

对未来结果，需要严格分开：
- **发现性观察**：可利用已经发生的走势找出业务典型位置，明确是回顾性现象，不产生“提前识别”资格。
- **验证性观察**：只有当时四方面输入合法且事先说明检验问题/比较窗口/Outcome End 口径、没有用本次后续结果挑赢家或补全 Current，才比较后来实际推进、摩擦、保持、恢复等，明确 Supports/Weakens/Contradicts/Unknown 及替代解释。
- 如果仍是原 S1 后 24 根的**显示上下文**而无统一 Outcome 合同，不准悄悄把显示末端当正式质量标签；可以做探索性路径对照，但不能宣称已验证四方面预测力。

尤其在本次两包中，**U3 R02 只有一个 Case 的五个 As-Of×三成员=15 行；R03 Quality 全 WITHHELD；其他广域主要是 C0/N/C1 raw，完整四方面及非空组外质量链缺失**。可以使用 N/C0 作为某项已经具有的运动描述/基线，必须显式标为“原有 N 事实、非正式 U3 Current”，不得把 N 代充正式四束或临时重算新质量特征。若实际数据不能验证充分性，要以所选场景说明具体欠哪些字段/Output、影响什么判断，不能以表面“完成四束分账”代替辨别力检验。

## 6. 真实证据、Owner 读图与业务决策

每个重要观察应构成可直接阅读的关系：
1. **选中位置与理由**：哪种业务过程为何正好检验原叙事？回顾发现/验证地位、选样规则及原基础行情图位置。
2. **基础行情**：真实转折、共同方向、成员可知时点与关键后续路径；图链接和同图结构化行。
3. **U2 对照**：原位置、成员、组外与身份是否真的能组织此轮机会；raw/reference/正式资格及其他解释。
4. **U3 当时四方面**：有哪些可用指标，怎样区分成员，强弱/整组弱/无法判断为何，哪些原本就来自 N。
5. **后续检验**：未来实际市场运动/路径及合法 Outcome/显示范围区分；支持、反证、未知以及不能直接推出交易收益。
6. **对设计的价值**：现有 U2/U3 解决了哪个问题、什么不足以支持“好做”、什么新的方法或字段才值得考虑；如已有更直接低成本的 C0/N/简单共同事件关联，必须比较。

图的版本、run/node/window/As-Of、真实浏览器页面与数据包共同定位。不能凭 320 图、33,944 CSV 或一组字段穷举声称场景研究完成。选择—核图—判断—反证可连续迭代；重要发现及时保存实质正文，既不以单 Case 为停点，也不无限清空重复 CSV。

## 7. 方法到运行的边界

管理 Pro 应检查 S1 选样是否真的围绕这种场景和质量辨别目标，而不是仅证明覆盖年份/成员/原字段；执行 Pro 决定真实场景、取数、图和专业判断；Worker 只落实已有图与同源数据及浏览器显示，操作端不擅自挑 Case 或新增业务规则。尚未取得 Owner 新 GO 时，本文件只属于下一新 run 的专业候选方法准备，不能改变已暂停旧 run 或自动启动。
