# V2 观察迭代：完整业务目的与三步流程

## 1. 为什么重写

原 I1–I6 把业务步骤、可信数据准备的特殊措施、Owner 审阅、管理接收和后继安排混在同一条阶段轴。V2 将**业务工作**与**执行角色和运行管理**分开。人以审阅、重要取舍为主；可授权的操作、取数、制图、观察和问题分析由 AI 实际完成。

本专业流程**替代** V1 的六个子意图，不从六个旧 Gate 逐个映射为新 Gate，也不继承先前 run 的业务结论为本轮完成事实。

## 2. 本轮观察意图与边界

围绕 U2+U3 的四个业务方面开展真实数据观察，先回答：
- **U2：共同机会簇出现在哪里？** 找出的形成位置、成员和关联范围是否符合当时可见的实际市场过程？是否合理、有遗漏、错组或者无价值的分组？
- **U3：在这些位置，四个方面是否真的能够区分品种好不好做？** 观察产生了哪些有意义的差异、没有差异、反例和无法确定的部分？

四个方面的**具体字段、定义、适用方向与方法资格**由本轮有效业务 Source 提供；不可根据名字猜测，也不从上一轮找到的例子倒推出此次必然结论。本轮品种暂固定为 `rb/i/hc`；该边界限制验证的外推，不使个别 Case 成为主动收工点。

## 3. 业务步骤（S1–S3）

### S1：确定观察对象 / Scope
- 说明为什么看该对象、共同机会簇和 U3 四方面分别需要核对什么。
- 确定真实品种、观察尺度、可用的业务设计/结果与合理的首批窗口；无法合法确定的内容明确缺项。
- 输出：可执行的观察问题及所需图/数据的初步范围。不要预定所有 Case 数、固定图数或以后必然发生的结论。

### S2：画图与对应数据
a. **确定要怎么看、怎么画。** 先想清楚要显示哪些行情、现有特征结果、共同机会簇位置、组内外成员、时间关系和后续反馈，定义合法对照和图层。
b. **取得必要数据、实际生成图与同源数据。** 正常情况使用已经实现的可信业务特征结果；只有缺正式结果且具备明确来源/方法/观察资格时，才可采用 AI 小范围验算（Reference/Diagnostic）。**临时验算是例外手段，不是一个正常业务阶段，也不能冒充正式运行结果。**
- 图和数据统一经 `daowei2026/aidata`；具体要求见 `01_AIDATA_CHART_AND_DATA.md`。
- 输出：实际可打开的观察图、同一 run/窗口的相关数据、来源和时点资格、每张图怎么读；不能只交给 Owner 数字表或制图计划。

### S3：给观察想法 / Ideas
- 从真实过程出发，回答哪些地方合理、不合理、为什么；同类位置有没有反例；U3 四方面哪些区分有效、重复、或目前未证。
- 与已有单品种事实或简单基线比较，不能因图形漂亮、字段多、数值有差异就自动宣称投资增量。
- 每项重要判断返回 S2 图上可以核对的位置和原始数据范围，并说明支持、反证、替代解释与未知。
- 输出：人可以审阅的实际市场过程、图/数与对应的业务认识；必要时提出具体设计修订或继续观察的问题。

## 4. S2 ↔ S3 允许迭代

首批图是探索入口，不是最终完整图单。S3 发现缺少某个比较、时间上下文或可疑形态时，可以明确目的回到 S2 补图/补数，再继续形成想法。不得以第一张图、单个 Case、一次调用、画图任务完成等作为整项当前业务目标的自动停止条件。

## 5. 基本证据纪律

- 保留原始时间、确认时间、系统当时可知时间（As-Of）、Working/Completed 与 Reference/Formal 区别；不可使用事后信息装作当时可知。
- 图形展示范围、正式切片窗口和解释所依赖范围明确分账；图上的上下文行情并非自动获得可消费证据资格。
- 相同价格轨迹计算出的多个指标不能冒充独立证据；发现形态后仍需回到原始事实核验。
- 当前没有数据或明确方法时，应标记 `unavailable / pending / withheld`，而不是制造图、排名或投资建议。
- Owner 审阅与反馈是外部业务判断和真实修订输入，不作为第四个业务步骤。管理接收与 Pro 回交仍使用现有长程机制。

## 6. 完成/继续的实质标准

单次工作完成需要：提出了有根据且有适用范围的业务认识（包括有据无增量）或准确说明阻断；相关图、真实数据和分析可由 Owner 直接定位；下一工作（继续 S2、继续 S3、问题修订、待输入或候选停止）具体可执行并由有权角色接收。

禁止以“已生成图 / 运行脚本通过 / Pro 返回 / 有一份长报告”代替实质完成。
