# 工具、数据与首次观察图面准备

本文件把当前探索需要的工具使用知识直接放在新工作区，供 Management Pro 理解任务准备、Professional Pro 按本轮任务实际使用。它是操作参考，不是固定研究方法，也不预先指定每轮必须调用哪些接口、使用哪些品种/日期/频率/尺度参数。

**工具使用原则：**沿既有 aidata 正式入口取得特征数据和图；已存在且适用的正式交付优先复用；只补本轮业务问题真正缺少的输入或图。不另建直连 KLine/数据库的平行取数通道，不把图层导出当正式数据，不因新 Run 机械重算全部内容。当前现场的 README/API、代码版本、参数和权限优先于历史试用记录。

## 1. aidata 接口职责与典型调用关系

项目现有 aidata 使用涉及三个主要接口。它们职责不同，**不是每次都必须全部重新调用**：

| 接口 | 主要职责 | 产物/用途 | 不能据此声称 |
|---|---|---|---|
| **build_chart_run(run_brief_input, dry_run=False)** | 根据 brief 建立本次 run/core，确定图和正式数据共同使用的节点、时间范围及输入身份 | 返回 run 对象及 run_id，供后续图页和数据交付复用 | 仅建立 run 就代表平台图或正式 feature_slices 已生成 |
| **build_big_world_chart_pages(run, run_brief_input=..., save=True)** | 消费已建立的 run/core，生成 big-world 平台图页并返回图定位 | 查看特征对象与行情图层 | 多个页面自动等于一个组合页面；图页存在就代表正式数据切片已取得 |
| **build_board_run({...run_brief_input, "run_id": run.run_id}, reuse_core=True, dry_run=False)** | 复用同一 run/core，生成正式结构化特征切片、来源索引和交付清单 | AI 对已交付特征做读取、定位和程序辅助分析 | 数据切片等于图页；也不代表专业业务解释已成立 |

典型的“同一批既要看图又要读取正式特征数据”的调用关系是：

1. 准备并核对本次 run_brief_input。
2. 调用 build_chart_run 建立 run/core，保存实际返回的 run_id。
3. 调用 build_big_world_chart_pages 生成需要的特征图页。
4. 如本轮还需要结构化特征数据，调用 build_board_run，传入同一 run_id 并按现场 API 支持情况复用 core。
5. 按实际输出的 manifest、页面定位和文件索引核对交付，不凭计划调用或返回 URL 宣称成功。

如果已有适用的 run/core、图页或正式切片，应先检查其对象、时间范围、特征配置和版本是否覆盖当前工作；适用就复用，缺什么才补什么。不要为了“流程完整”重复建立昂贵的 run 或重复导出。

### 什么时候需要哪些调用

- **只需要先看特征图**：确认是否已有可用 run/core；缺少时建立 run，再生成对应 big-world 图页。若不需要结构化数据分析，不因形式要求强行执行 board。
- **需要AI读取、比较和分析正式特征对象**：除图页外，还需要正式 board 切片及 manifest；优先复用同一 run/core，确保图和数据对应同一输入身份。
- **只需要独立概览**：才考虑独立 overview 入口。当前Owner已说明1d概览不适合添加特征、不是首次主要观察图，不应为了调用接口而生成或反复调整它。
- **需要一个完整时间范围的首次观察图**：本轮设想是以一个相对完整的时间窗口建立可观察的大尺度图，并在其上叠加大、中尺度贴近转折。若采用 manual big_source，需确认该窗口实际生成的节点及正式切片范围覆盖预期观察区间。不能把若干局部窗口拼起来后称为完整历史。
- **后续需要局部放大**：局部窗口可以在原完整背景之外另行生成，但要保留其与完整背景的对应关系；局部窗口的正式切片只支持该窗口，不自动覆盖窗口外的完整历史。

具体哪一种调用组合最合适，由本轮业务观察所需图数和数据决定，不预设每次都走完整三接口链。

### 概览图的独立入口

项目已有独立的 build_run_overview_chart_page(run, run_brief_input=..., save=True) 概览页入口。它与 build_big_world_chart_pages 的职责不同：后者在既有使用方式中可自行建立概览并生成各 big 节点图页；若已由后者生成同一概览，不应再无理由重复调用独立入口。

Owner 对首次观察的当前设想是：1d 概览可能是静态、不可自由调整且不能添加特征，因此**不把1d概览当作第一次业务观察的主图，也不在其上反复尝试叠加特征**。是否另需概览只由本轮实际用途决定。

### 页面组合

页面组合是现有平台图形组织能力，不是第四个行情/特征数据获取接口。项目已有通过 CAEGraph/PlotSet 组织多个图表到一个平台页面的成功使用记录；但这不等于任意图表、任意图层和任意时间范围都已验证可以组合。

本轮设想的第一张观察图是“相对完整时间范围的大尺度图，同时显示大尺度和中尺度贴近转折”。需要在实际 aidata 版本和页面能力上核对这一具体组合，不能拿旧的“1d概览+若干局部30m图”成功记录替代验证。如果当前接口无法直接生成所需图，先定位具体缺口和现有可复用组合方式，再决定是否需要技术补充；不要擅自改成不符合Owner观察目的的页面方案，也不要先改共享服务源码。

## 2. brief、特征输入与几个容易混淆的维度

aidata brief 通常需要明确本次实际采用的工作区/运行标识、Context、成员选择、日历、节点/窗口配置、特征输入及输出位置。常见字段/对象包括：

- **context**：实际数据集、成员数据范围、起止边界等 Context 信息；
- **blk、extract_time_syms**：板块或成员选择表达；必须核实际展开后的品种，不能只记录别名；
- **calendar_override**：实际交易日历/夜盘边界配置；
- **generation_depth、big_source**：节点生成层级及其时间窗口/来源方式；
- **evidence_features**：用于图和/或正式切片的行情、贴近转折等特征锚点；
- **output_root、run_id**：本次实际输出位置和唯一运行标识。

具体字段、构造器、参数和类型必须对照当前 aidata README/API 与本次特征生产者的正式交付核实；上表是理解 brief 的导航，不是可直接复制的完整入参模板。

**以下概念必须分开记录：**

1. **K线频率**：例如日线或30分钟K线，说明行情采样频率。
2. **贴近转折特征尺度**：例如大、中、小尺度，说明使用哪一层贴近转折特征。
3. **节点/生成层级**：例如 generation_depth、slice_levels、图层 surfaces 中的 big，说明 aidata 按什么层级组织节点或显示。
4. **图表时间范围/显示余量**：说明图窗口和额外上下文，不等同正式切片范围。

不能因为图叫“大尺度图”，就推断 KLine 频率、平台节点层级和贴近转折参数都是 big；也不能因为在 big 页面显示某特征，就把该特征误称为 big 尺度。

### 特征锚点和图层绑定

既有使用方式中，行情可以通过 make_point_anchor(KLine(freq=...), uti_fields="closeUti", ...) 作为正式行情证据；点型特征可通过对应的 Feature/anchor 与图层绑定提供横纵坐标、feature key、label、显示 surface 等信息。贴近转折的具体构造器、方向字段、坐标字段和尺度参数，以本次实际特征交付为准，不预设所有贴近转折都使用同一个构造器。

plot_binding、feature_key、正式数据字段与图例必须对应同一个实际特征对象。不能只改图例名称就声称已换成另一尺度特征，也不能把图上临时绘制的点当作正式特征输出。

## 3. 正式数据交付怎样消费

build_board_run 的正式交付通常包含 manifest、切片统计、时间范围索引和按节点/成员/feature key 组织的数据文件。常见定位入口包括：

- board.delivery_manifest_path 或交付中的 DELIVERY_MANIFEST.json；
- board.feature_slice_stats_path 或对应 feature_slice_stats.csv；
- run 下的 manifest/timespan_index.csv、chart_manifest.csv、run_summary.json；
- feature_slices/<node>/symbol/<symbol>/<feature_key>/<df_key>.csv 一类文件路径。

以上是常见结构示意，**实际路径、节点名、feature key、df key、文件数和字段以本次 manifest 与 FILE_INDEX 为准**，不能写死旧测试中的节点编号或 __default__ 文件名。

**完整范围与局部窗口必须分开：**若本轮只为某个局部窗口生成 board，正式 feature_slices 只覆盖该窗口及其实际交付范围，不能因为同一 run 另有完整时间范围图，就声称 board 已取得完整历史数据。反过来，若本轮正式交付的是完整时间范围节点，也不能把图上自动显示的额外余量算进正式切片。每次按 manifest 的 node、timespan、symbol 和 feature_key 确认覆盖。

读取正式数据时：
- 保留原始字段、空值和时间；不要为了图形完整而填零、插值或拼接不同时间点。
- 用 manifest/FILE_INDEX 对应 run、node、symbol、feature key、DataBinding 和文件，不凭目录名猜。
- 程序扫描、统计和辅助计算可以消费正式交付；图层投影、浏览器内序列或截图只能用于显示/核对，不能反向冒充正式特征数据。
- 记录实际覆盖的首末有效时间、缺失行、共同时间范围和未覆盖范围。请求的 startDay/endDay 不保证与实际首末数据相等，尤其不能未经核对就称结束日全天已包含。
- 若日历或 UTI 用于时间映射，应使用当前 Context 对应的日历转换；不能把 UTI 猜成 Unix 秒/毫秒，也不能把无时区自然时间文本擅自转成 UTC。
- 图表的 extra_time、自动轴边距或显示余量不等于正式切片范围。需要分析窗口外信息时，应从正式数据交付取得或按授权补取，不能从图层倒算。
- 图可能使用 ratio、标准化或其他展示变换。核对图与 CSV 时先确认展示基准，不能把图轴坐标直接称作原始价格。

已适用的正式数据/core可以复用。若只缺某一尺度、某几个品种或某段时间，优先补足具体缺口，不重复取得无关的全量数据。

## 4. 首次观察的图面准备：Owner当前设想，待现场核对

这些是Owner提前提供的操作思路，目的是减少AI首次画图时的偏差；它们不是已验证的 aidata 能力或固定绘图规范。

### 4.1 首次主图

- 1d概览图可能不可自由调整，也不能添加特征。第一次观察不把它作为主要工作图，不在上面尝试叠加贴近转折。
- 优先尝试一张**相对完整时间范围的大尺度图**，在同一张图上同时显示大尺度和中尺度贴近转折点；如果已有相应的线段对象或能够由正式对象可靠表达的线段，也一并让人能辨认其连接关系。
- 这样做是为了沿时间从前往后定位大尺度背景，并在同一时间语境下查看其中的中尺度结构；不是先制作很多局部案例图。
- “相对完整”由本轮实际特征覆盖、可读性和观察目的确定，不预设固定起止日期。若完整范围过密，先保留全局定位图，再针对实际候选范围做局部放大；不能用局部图取代背景来源。

上述叠加方式需在实际 aidata 版本中核实。如果大尺度和中尺度特征不能直接在同一 big 图上显示，先报告具体限制、现有可用图层及最小替代方案；不要默默改用1d概览或只画其中一个尺度。

### 4.2 贴近转折方向、上游zig与额外贴近点

贴近转折输出不保证每个点都有方向。贴近转折点可能多于上游 zig 点，其中有些可能是没有方向的额外贴近点。因此第一次画图和读图时：

1. 先检查贴近转折正式输出有哪些字段、哪些记录有方向、方向覆盖率如何；不要假定方向字段一定存在或完整。
2. 若贴近转折缺少方向或方向覆盖不全，检查上游 zig 是否提供方向，以及贴近点与 zig 点能否通过正式 ID、来源、时间或其他可靠键对应。
3. 区分有正式方向的转折点与额外的无方向贴近点；不能把所有贴近点都当成有方向的 zig 点。
4. 左右两侧的价格运动方向可能提供视觉辨认线索，例如方向点两侧的运动表现不同；但这只能作为待核线索，必须与正式字段或上游对象对应后才能认定方向。
5. 如果无法可靠对应，保留“方向未知/尚未核实”，不要只凭图形给无方向点补造正式方向。

若方向点和额外贴近点在图上使用不同标记，图例必须说明标记依据；不能用颜色或形状制造一个数据中并不存在的方向分类。

### 4.3 实际转折时间与确认信息时间

图上应尽量让人分清：
- 贴近转折实际指向的历史位置和时间；
- 确认信息实际到达的时间；
- 确认事件涉及的一个或多个对象，以及它是否修订此前状态；
- 截至当前观察时点，哪些对象已确认、哪些只是当前发展部分、哪些仍未知。

实际转折点通常对应价格图上的位置；确认时间可能不对应一个价格坐标。若两者不同，应通过关联标记、辅助时间轴或配套表格表达确认时间，不要把确认点伪装成实际价格转折点。完整历史图用于发现和回看；重建某个T时，不能仅画T竖线却仍把T之后才确认的点显示为当时已知。

### 4.4 小尺度按需使用

首次不默认叠加小尺度。只有中尺度线段内部的反复、回突、推进中断或反向负担确实影响业务判断，而中尺度图不足以讲清时，才打开相应小尺度对象和图。不要为了“图层齐全”一次性叠加全部尺度。

### 4.5 人与AI如何共同核图

图面至少要能辨认品种、统一时间轴、图表用途、特征尺度、贴近转折点、已核实方向、线段连接、实际时间和确认信息时间。AI讨论时要给出品种、尺度、对象/点的时间或索引、所在图及当前T；人能在图上找到同一个对象。

要区分四种证据状态：正式字段直接提供、通过上游对象可靠对应、图形仅提供视觉线索、目前无法核实。AI没有实际打开或查看图时，不声称已经目视核验；结构化数据计算也不能冒称图面可读性已通过。

## 5. 运行环境、版本与权限

- 复用当前有权工作区和既有运行环境；开工时记录实际仓库 checkout、分支/commit、必要的本地差异、aidata及相关依赖版本。不能只记录一个 aidata SHA 就推断整个工作区一致。
- 使用现场正式 Python/运行入口和现有依赖。没有实际需要不重装、升级依赖、改 TLS/环境配置或重启共享服务。
- 本文不授予 aidata、uplot、tis/frp、平台服务或共享工作区写权限。注册、部署、服务重启、源码修改和全局配置变更须有相应授权及明确技术工单。
- 记录真实的输入 brief、关键非敏感参数、run_id、output_root、调用顺序、返回值、manifest 和实际图页 URL；敏感连接信息不得写入 Git。
- Owner提供的旧 probe 若包含顶层执行、取数或写文件副作用，不要直接 import 或重跑；先理解其输入构造，按本轮授权和现场 API 编制最小调用。
