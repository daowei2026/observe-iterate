# 图数准备工单约定 V0.1

本约定仅适用于 **Professional Pro 已决定要准备的图及其正式数据**。图主要供人看，正式数据供 Professional AI 读；两者应当能按本次 run/core、品种、窗口、特征对象及实际展示转换对应。本约定不定义观察目的、市场研究方法或新的 Agent/派发机制。

## 一、角色边界

**Professional Pro 签发前：**根据本次专业工作，确定需要准备的图和数据，并提交一份具体可执行的 aidata Python 脚本，或者准确指定现有可执行脚本及本次明确修改。需要使用的品种、时间窗口、特征、参数、图面配置及正式数据内容，由脚本和既定配置直接表达；不要要求 Worker 重新选择、设计。

**Codex Worker：**在当前既定执行环境执行签发脚本，进行必要的普通工程修通，核实际页面、正式数据及二者对应，交给原 Professional 使用。不决定观察题、场景/窗口、特征配置、业务关键 T、候选规律或数据的未定义语义。

执行环境由当前 Run 已明确的固定执行环境来源提供，Professional 不必每张工单重新选工作区或软件版本。CO-05 的具体工作区见 `runs/BI-01-CO-05/OWNER_CHANGE_20261102_CHART_DATA_PREPARATION.md`。Worker 在该环境中执行、核对，不得混淆 Worker 聊天工作区与 aidata 代码工作区，不擅自更换 checkout、升级依赖或修改共享平台。若现场的精确软件版本尚无可核验依据，就如实说明，不能编造 commit；不因此要求 Professional 每次重新选版本，也不默认进行全面差异审计。

本工单不负责新能力研究、平台改造、特征方法开发、事件发布/修订历史重建和额外数据审计。确有需要时另外给工单，不与本次图数准备混在一起。既有授权内的正常执行故障可由 Worker 自主修通；涉及改变本次内容、计算语义、业务参数或越权写面时，提交准确阻断给 Professional。

## 二、正常工单只需要这些内容

1. **现有工单身份**：沿用 `overlay/12_管理接收与地图校验.md` 的 `order_id/work_id/run_id/issuer_ref/issuer_invocation_id/issuer_assignment_token/return_to` 等字段、工单位置和机械检查；不另建身份体系。
2. **确定的执行脚本**：引用当前 Run 已明确的固定执行环境，提供可运行的脚本内容或准确的脚本位置、执行命令、本次输入与输出位置；遵守已有写面，不让 Professional 每单重新选环境版本。工单不另起参数清单重复 Python 代码；需要改动的脚本须由 Professional 事先写清楚。
3. **明确的图数交付**：应实际出现哪些图/页面、哪些正式数据，以及 Professional/人怎样取得和核对二者。图和数据不必物理上一图一 CSV，但其来源、品种、时间、特征和必要对象应相互可定位。
4. **执行回交与例外**：按原机制交 `FULL_RESPONSE.md`，记录实际调用/结果、run_id、图页和正式数据可访问位置、对应关系、是否实际打开图与读取数据、缺件及修正。图数不满足时如实报告已完成范围；不以仅返回 URL、脚本退出码 0 或本机路径存在冒充实际交付。

上述不是四张新表。能在脚本里完整确定的内容，不再单列重复字段；正常工单不要求 Worker 作业务论证、前置设计或大型技术报告。

## 三、完整 Python 示例（说明具体程度，不是本次默认配置）

下面的**单项示例**取自 Owner 提供的历史 `画图.md` 中“1d + 30m 大尺度图与正式数据”接口验证程序。历史数据源、窗口、`calendar_override`、`ScaleTurnCalendar("large")` 等都只是示例参数，不是 CO-05 本轮实际采用的输入；现场 API 仍以当前工作区有权版本为准。示例说明 Professional 应把具体 brief、特征构造、图数接口及调用顺序提前写成代码，而非让 Worker 再设计。

```python
from datetime import datetime
from pathlib import Path

from mquant.aidata.api import (
    build_chart_run, build_big_world_chart_pages,
    build_board_run, make_point_anchor,
)
from mquant.aidata.profiles import ensure_profile_runtime
from mquant.frame import KLine
from mquant.quant import OptContext
from mquant.tis import ScaleTurnCalendar

ROOT = Path(
    "/dwdhome/fy/BASE_E6_2/mquant/aidata/"
    "test_runs/fy_owner_1d_30m_20261027"
)
ROOT.mkdir(parents=True, exist_ok=True)
ensure_profile_runtime()

context = OptContext({
    "sof_name": "TA_updto20240229_DBA",
    "stk_tlist": "tick_test_all57_takeout_lcNsiNcy",
    "startDay": "2013-02-19",
    "endDay": "2024-02-29",
})

def kline_evidence(freq):
    return make_point_anchor(
        KLine(freq=freq),
        uti_fields="closeUti",
        label=f"{freq} KLine正式行情数据",
        feature_key=f"test_kline_{freq}",
        slice_levels=["big"],
        evidence_role="market_context_sidecar",
        is_raw_market_data=True,
    )

turn_evidence = make_point_anchor(
    ScaleTurnCalendar("large"),
    uti_fields="x",
    label="30m大尺度贴近转折",
    feature_key="test_scale_turn_large",
    slice_levels=["big"],
    plot_binding={
        "kind": "point",
        "x_field": "x",
        "y_field": "y",
        "label": "大尺度贴近转折（L）",
        "surfaces": ["big"],
        "style": {"marker": "diamond", "size": 20},
    },
)

brief = {
    "output_root": str(ROOT),
    "run_id": f"fy_test_1d_30m_{datetime.now():%Y%m%d_%H%M%S}",
    "run_note": "Owner aidata 1d/30m 接口验证示例",
    "context": context,
    "blk": "blk@steel",
    "calendar_override": "night_end_at_2300",
    "extract_time_syms": "blk@steel",
    "generation_depth": "big",
    "big_source": {
        "mode": "manual",
        "timespans": [
            ("2021-08-15", "2021-09-30", "TEST-C001"),
            ("2021-11-01", "2021-12-15", "TEST-C002"),
            ("2022-03-01", "2022-04-15", "TEST-C003"),
        ],
    },
    "evidence_features": [
        kline_evidence("1d"),
        kline_evidence("30m"),
        turn_evidence,
    ],
}

run = build_chart_run(brief, dry_run=False)
pages = build_big_world_chart_pages(
    run, run_brief_input=brief, save=True
)
board = build_board_run(
    {**brief, "run_id": run.run_id},
    reuse_core=True, dry_run=False
)

print("RUN_ID:", run.run_id)
print("PAGES:", pages.to_dict("records"))
print("STATS:", board.feature_slice_stats_path)
print("DELIVERY:", board.delivery_manifest_path)
```

这个示例是**调用方式示例**，不强制每单都用三个窗口、`large` 或 `build_big_world_chart_pages`；也不要求另行选择是否复用历史 run。Professional 依当前确定的方案提供实际脚本，Worker 运行它。`build_board_run(..., reuse_core=True)` 仅说明本次图/数据使用同一 run/core 的已知接口关系，不是要求研究是否复用历史运行。

## 四、交付与边界

正常只交：
- **可实际打开的图**：图页 URL 或本次明确需要的图文件，明确实际可见范围和图层；不能只声称返回了地址。
- **AI 可实际读取的正式数据**：沿 aidata 的 `build_board_run` 等正式交付获取，给出实际数据位置/必要索引及与图层的对应关系；不能用图面投影、截图或猜测字段代替正式数据。
- **简明技术回交**：真实 run_id、图数位置、是否满足本次工单、必要修正与局部缺件；保留原工单必须的身份与派发/回交证据。

**不默认交付** `KEY_T_EVENT_LEDGER`、`FIELD_QUALIFICATION`、`DIRECTION_MAPPING_RECEIPT`、全量正式切片审计、环境差异报告或额外统计/哈希清单。确实需要且有确定算法的局部提取，由 Professional 在本单脚本里定义；需要重新设计或研究语义的工作另签工单。

原有 `overlay/12` Worker 身份、签发、`worker-order`、`worker-result`、实际发送核验和返回原签发 Professional 的规则继续有效。本约定只有在 Owner 的本次纠正或现行任务明确引用时才成为具体工单要求；**不追溯改写已签或已发送的历史工单**。
