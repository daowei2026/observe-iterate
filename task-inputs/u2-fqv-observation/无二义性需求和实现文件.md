## 二、对象范围与真实输入依赖

```text
各品种真实 5m KLine（close、closeUti）＋实际交易 Calendar
    └─ 已有 ZigZag / RctZigWithStatus
          └─ 已有 ScaleTurnCalendar → actual/confirm 的真实贴近转折、selected P/T/C
                   └─ F：多品种共同转折候选与形成依据
                          │  已存 F + 当前 KLine／Turn／Calendar
                          └─ Q：同一候选的逐成员方向运动、整体方向组织
                                 │ 已存 F/Q
```

- **F、Q、V 是三个独立 FAO 和三个独立正式结果**。F 的正常 KLine 输入由 FRP 内部 `GroupCandidateKLineInput` 使用既有 KLine、转折处理器；Q 按准确配置读取已有 F 及必要行情和转折材料；V 从已存 F/Q 组合成自身判断。不能把上游被加载误称为独立 `NativeSourcePlan` 必做前置。
- 不在本项范围内：S 组外分离、Clusters 机会簇演化、U2 跨尺度、U3 运动质量、资金预算及最终策略收益；不能把 V=Accepted 当成它们已成立。
- F 自己不要求先运行近期行为 N 或重算全历史 Episode 统计。

## 四、F｜共同价格转折候选组

**业务问题：** 哪些不同品种的真实转折可以被当前方法看作一次共同转折的候选；哪些有明确相容依据、哪些仍缺材料或被否定、哪些互相重叠/包含？

**输入：** 不同品种的实际贴近转折，含对象、Turn Life/Revision、actual/confirm/known、方向、Peak/Trough 类型、selected P/T/C、Clock、来源有效性、声明 Universe 和 Profile。

**两两关系：**

1. `ActualNear`：在真实交易 Calendar 上两转折距离不超过 `2 × formationΔ`；缺当时合法 Clock 则 unresolved。
2. 方向相容与转折类型相容：按当前配置矩阵分别判断 `Compatible / IncompatibleVeto / Undetermined`。
3. selected P/T/C 的局部弯折：比较各自弯折方向是否相容；缺 P/Clock、共线等保留明确未决。
4. 有任何必需项 Veto，则 Pair 为 `PairVeto`；四项都支持才为 `PairPositive`；其余为 `PairUnresolved`。

**候选形成：** 在有限实际转折时间域内，用两两支持的完整连接寻找候选成员组合；只要 AB、BC 相容，不能自动推成 ABC 相容。既有确实支持的组合与仍可能成立的组合都可能保留；重叠、严格超集覆盖及成员被拒绝不是相同含义。不同成员集合可能拥有不同 Candidate Life；同一合法身份的修订保留 Revision 链。F 不依据 Q 后续运动重新选组。

**可读取结果：** F 发生主表 `occurrences`、候选成员子表 `occurrences_groupMembers`、Pair/Required、重叠、覆盖、依据及历史关联等其他正式明细（各表以本版本 `to_dfs()` 所得清单为准）。F 的 `Supported / Incomplete / Contradicted` 与 `Open / ClosedSupported / ClosedInsufficient / Withdrawn / Subsumed / EndedByScope` 不能压成单个“成立/不成立”。

**观察重点：** 对同一批实际转折，叠加 F 成员、Pair 理由、候选形成和关闭时点。能独立评价的是“转折在时间/形态上是否明显相近”；现有 F 分组不自动证明市场中存在一个独立的“共同机会”客观真值。

## 五、Q｜转折后成员组的方向组织

**业务问题：** 给定 F 的同一候选和显式 `DirectionUp/DirectionDown`，各成员转折后沿所问方向实际怎样运动？整体是否达到本方法的方向支持条件？

**输入：** 准确 F 候选（全部原序成员，包括尚未得到完整 F 正面依据的成员）、每个成员的 requested/used Turn、后续合法 KLine 路径、Clock、来源及真实后继 Turn。Q **不重选 F 成员**。

**每成员六量：** `ProgressP=方向符号×(端点价格−转折价格)`、`AmplitudeA=abs(端点价−转折价)`、`DurationD=Calendar 差`、`PathLengthL=相邻真实价差绝对值之和`、`EfficiencyE=A/L`（L>0）、`CounterC=相对历史最佳方向推进的最大逆向回落`。端点可知不等于全路径可知；缺价、缺 Clock、采样断裂影响相应量，不能填零。

**成员主要判断：** 已知 P<0 为 `ContradictsAskedDirection`；P=0 为零净推进未定；真实运动段已由合法后继 Turn 完成且 P>0 可支持；working 时 P>0 还需要路径/Clock/覆盖和 `D≥2×ΔQ` 等合法成熟条件。`MotionCompleted` 是实际后继 Turn 确定的，不是观察期限到达。

**组级判断：** 任一必需成员明确反向，组级可以 `QualificationRejected`；否则依次处理冲突和未成熟/缺材料；所有成员支持且都完成为 `QualifiedCompleted`，否则可为 `QualifiedWorking`。Q 六量不是六票加权的运动质量总评分：组级方向正面，**不证明成员路径相似、质量同等好或组成独立机会**。

**可读取结果：** Q `occurrences` 主表、`occurrences_organizationMembers` 成员明细及 `to_dfs()` 的量测/不可用/形成引用等表。要看成员真实路径，仍须将其 asked/used Turn、源 KLine 对齐；Q 不是完整 KLine 历史存档。

## 六、V｜共同转折组的局部成立判断

**业务问题：** 对同一准确 F 候选，形成依据到什么阶段了？Q 是否给出相应方向组织？在当时知识下能否作一个局部成立观点？

现行方法：`ClosedFormationLocalValidity`。V **不重算 F 两两相容、也不重算 Q 六量**。主要判断关系（按源码实际优先级还需考虑撤回、冲突、形成原依据更正等）：

| F 状态 | Q 状态 | V 主结果 |
|---|---|---|
| F 支持但还没正式关闭形成观察 | Q 即使支持 | `Pending`，可有 `FormationObservationOpen` 原因 |
| F 支持且形成观察关闭 | Q `QualifiedWorking` | `AcceptedWorking` |
| F 支持且形成观察关闭 | Q `QualifiedCompleted` | `AcceptedCompleted` |
| Q 明确 `QualificationRejected` | — | `Invalid`，保留方向反证 |
| F 的有效形成依据被反证 | — | `Invalid`，保留形成反证 |
| 必需材料不足/原形成依据发生未吸收修订 | — | `Pending`（具体原因不同） |
| 已确认的必需运动冲突 | — | `ValidityConflict` |
| 原 Turn 被撤回且题目已不适用 | — | `SubjectNotApplicable` |

V 发行的是**局部 F/Q 组合结论**，不是 S 的组外分离结果，不创造最终 OpportunityCluster 身份，不评策略盈利或资金配置。V 的 `AcceptedWorking` 还不是 completed，也不保证未来持续成立。V 对未变化的正式业务观点可以不重复发行；“没有新 V 记录”不能绘成 Invalid。

**可读取结果：** `occurrences`、`occurrences_validityMembers`、`occurrences_validityReasons`、`occurrences_validityRecordPrevious`、`occurrences_validityDutyEnd`，以及相应配置与引用。逐状态看图必须用准确 Life/Revision、F/Q 当次引用、known/actual 与原因子表，不能随意把各自 latest 结果拼在一起。

## 八、观察合理性时需要保留的边界

| 可观察并检查的问题 | 单看已有结果还无法证明的事 |
|---|---|
| F：真实转折与候选归组、分开、覆盖或重叠是否可从图上解释 | “归成同一组”就是同一轮真正市场机会 |
| Q：各成员支持/反向/零推进是否对应当时合法路径 | 两个成员都向上就必然有共同、协调、持续的方向组织 |
| V：F 关闭和 Q 方向组合的时间与原因是否合理 | `AcceptedWorking` 说明组外独立、以后成功或值得分配资金 |
| actual/confirm/known 的时间关系是否准确 | 可把事后确认无痕贴回确认以前的回放画面 |
| 正式发生表、已存引用、可读子表是否匹配 | 没有新发行的一段空白就表示 `Invalid` |

**观察前最好先不显示 F/Q/V 标签**，只看真实价格转折、方向及其先后，再依次打开 F、Q、V。独立预期若无法提出，可以如实记录“现阶段只有方法输出预期，尚未形成独立的市场现象预期”；不反向编一个正确故事替现有设计作证明。

## 九、正常 Python 入口、用法与运行限制

现役原示例仅负责构造三个 FAO，不会因为 `make_features()` 被调用就启动计算：

```python
from mquant.frame import CurrSof, CurrCalendar
from mquant.tis.frp.fqv_kline_example import make_features

with CurrSof(sof_name='TA_updto20240229_DBA', stk_tlist='steel'), \
        CurrCalendar('night_end_at_2300'):
    f, q, v = make_features(freq='5m', symbols=('rb', 'hc', 'i'),
                             delta=600, direction='DirectionUp',
                             retrace_pct=0.5, check_retrace_pct=0.5,
                             membership_line=0.5, spec_term='M',
                             distance_times=100, x_step_times=0.1,
                             overlap=0.2, source_core_multiples=30)
    # 本批已存在正式结果时，可以使用三个对象各自的公开读口。
    f_df = f.to_df()
    q_df = q.to_df()
    v_df = v.to_df()
    # 只有明确获得运行授权且准备在正常环境重算时，才调用：
    # f.rerun(2).to_df(); q.rerun(2).to_df(); v.rerun(2).to_df()
```

`to_df()` 默认主表 `occurrences`，`to_dfs()` 返回全部具名明细，也可以通过 `read_exact(...)`、`read_at_knowledge(...)` 读取准确历史观点。必须用原来的配置及正式结果物理根，不能拿此 JSON 另外造一种 Runner，亦不能把原 `NativeSourcePlan` 或专用 `u2-integration-production` 当成本次正常输入。

脚本在新机器运行前，核实同一指定 FRP/TIS 版本、生成的 Python ADT、SOF/Calendar 数据和正式产物目录是否存在；没有这些环境，本整理文件本身不保证运行。`--mode rerun` 覆盖的是原定**全时段**实例，可能较重，应明确授权才执行。FY 当前 EAW Wall 正式 Run 与这个 U2 取材任务分开，不因本文件出现自动扩大其 Run 范围。
