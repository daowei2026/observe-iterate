# Source Activation, GitHub Use and Maintenance

## 1. 四层材料

```text
GitHub canonical Agent release；
generated Project runtime bundle；
per-task current authority packet；
dynamic external/repo evidence。
```

## 2. Required source 三层证明

### Availability

```text
exact source可打开；
identity/hash明确。
```

### Activation

```text
实际读了哪些heading/anchor；
提取了哪些本任务义务；
哪些部分未读。
```

### Use

```text
本轮artifact哪个section消费；
支撑哪项claim；
是否与其他source冲突。
```

三层不全，不能把“source已用”写成完成事实。

## 3. GitHub链接

URL只作 locator。required source 状态必须是：

```text
FETCHED_AND_USED
FETCHED_NOT_NEEDED_AFTER_REVIEW
BLOCKED
NOT_APPLICABLE
```

`repo accessible` 不等于正文已读。

## 4. Loading levels

```text
FULLY_LOADED_RUNTIME_CORE
MANDATORY_SELECTED_SECTIONS
COLD_COMPLETE_REFERENCE
```

新聊天重新激活方法；业务结果通过完整artifact继承。

## 5. Task packet

必须直接提供：

```text
task/mode/scope；
Owner delta；
accepted current parent；
consumer；
unresolved clause；
Delegation Envelope；
P0 Owner surface；
required external sources；
output/non-goals。
```

高权力 current artifact 不只给 branch URL。

## 6. Agent维护

每项 candidate delta 说明：

```text
正向能力；
canonical owner；
Profile激活；
完成门；
Harness；
runtime bundle rebuild；
旧成果影响。
```

旧成果影响：

```text
FUTURE_ONLY
REAUDIT_EXISTING
RETROFIT_EXISTING
INVALIDATE_AND_REBASE_DOWNSTREAM
```

Maintenance只产生Agent delta，不自行修业务artifact。
