# P0 正向业务骨架

## 1. Mission A 真正要形成什么

```text
自然语言市场过程／粗需求
→ small-but-complete市场问题
→ Source和客观事实
→ 关键Feature及其层级
→ Feature组合和竞争解释
→ 状态、时间、方法与正式产品
→ 实现者不再裁业务的合同。
```

## 2. Feature Narrative Stack

按当前用例实际需要裁剪：

```text
Source／measurement
→ objective local facts
→ atomic/local Feature
→ single-subject behavior Feature
→ relation Feature
→ organization/group Feature
→ higher market interpretation
→ investment/capital evidence。
```

省略中间层时必须解释语义如何直接连接。

## 3. 每项承重 Feature 的三句话

```text
正面含义：
  它表达什么市场结构。

向上作用：
  为什么下一层或consumer需要。

NonClaim：
  它明确不意味着什么。
```

例如“不能说它等于高质量”不能替代“它正面究竟表达什么”。

## 4. 不属于 Feature 的东西

```text
Pending／Missing／Conflict等knownness；
LifeId／key／writer；
Book／receipt；
方法内部候选和缓存；
审计计数；
文件或回调。
```

这些可以保护 Feature，但不能冒充业务特征。

## 5. Owner 真正校准什么

Owner P0 主要看：

```text
观察问题和scope；
Feature是否存在及正面含义；
Feature怎样层层组合；
独立business life；
关键method回答什么问题；
时间、回看和历史；
正式product／consumer claim；
跨仓和平台职责。
```

局部阈值初值、tie-break、等价容器和测试组织默认不是 P0。

## 6. 任务级放权

每任务声明：

```text
PRO_MAY_DECIDE
PRO_MAY_SET_PROVISIONAL
HUMAN_CALIBRATION
OWNER_DECISION_REQUIRED
```

Provisional 选择必须有：

```text
current v0；
method version；
理由；
最强反对；
不变量；
reopen trigger。
```

## 7. Owner 人读顺序

先展示：

```text
市场过程与Feature世界；
当前方法／controller；
时间、state、lookback、复杂度；
正式产品、consumer、Case；
真正P0变化。
```

最后才展示 receipt、Harness和package metadata。
