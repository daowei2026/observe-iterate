# Pro 完整主体实施与 Codex 明确指令交接

execution_revision: '2026-09-30-continuous-implementation'
status: `candidate_not_behaviorally_validated`

适用：当前 A/B 依据已形成后的正常实施、实际问题后的修正，以及向 Codex 指派工作。Owner 给整体目标与授权；源码尽量由 Pro 编写，工作区编译、测试执行、真实数据运行及现场调查由 Codex 承担。确实做不了或有具体理由不适合 Pro 做的编码，再明确委派；不让 Owner 逐轮编提示，也不让 Codex 自行接管剩余工程。

## 1. 从已经明确的主体直接开始写

Pro 先把当前工程任务与实际代码放在一起，找出自己负责但尚未实现的业务方法、结果分支、事件过程、状态及重要调用。按依赖顺序和本轮上下文容量组织施工批，直接完成实际程序。函数树、当前方法、可换步骤、参数进入计算及其结果消费必须落实到代码；不能用类型、接口、外部预先给出的判断、no-op 或一个代表性锚点代替主体。

分批回答的是怎样做完全量主体，不重新挑一小块探索是否值得做其他部分。每批保留实际完成的代码，下一批接着完成明确未完项。没有具体反证时，管理者不反复重开需求、比较研究方向或用审查材料替代施工。主体欠账仍由原实施责任方完成；B 的方法调用、状态或接线设计没做完，组织 B 做完，不改称消费者的启动条件。

当前先尽快完整实现约定业务逻辑和正式连接，接通真实数据并查看结果。不要为覆盖自己设想的全部场景，提前大量编写测试用例、fixture、测试矩阵、proof 或工业化设施；这类工作放到真实反馈后按实际需要安排。对直接妨碍当前编译、接通和运行的具体问题，完成所需检查，不顺势扩成整类场景测试。已有测试按当前需要使用，不删失败断言、不把未执行写成通过。

完整实现不要求首次零 bug，也不表示尚无环境的 Pro 已经编译通过。交给 Codex 时准确说明已写到哪里、哪些尚未编译或运行。诚实正式路径具备的部分尽早运行，同时继续其余主体；不等全量测试或最终验收才接真实数据，不因一条小路径成功而停止完整实现。必要进度、内存保护、正式保存/读回和结果解释继续做，不能归入后移的测试周边。

## 2. 源码编写与现场执行的分工

源码尽量由Pro直接编写，不限核心。合同和实际代码已足够时，类型、方法、事件／状态、调用、注册、手写包装和修复一起完成；简单、普通路线或已有B设计不自动成为下放理由。确实做不了或有具体理由不适合的编码才委派，可覆盖连贯范围，不新增逐项理由表。缺现场信息让Codex查，缺环境让它执行，一轮未完Pro继续。不能推送时交真实补丁，由有权限者应用发布，编写／应用／提交分账。

Codex承担现场调查、应用已给代码、执行生成、编译、测试执行、真实运行和回交。生成输入／手写接线由Pro写，生成产物由现有工具产生。当前不默认同时补测试程序；真实反馈后确需编写时按源码和现场条件分工，已写不等于实际执行通过。

正常构建工作单预先给出编译小修源码范围，可含本次直接相关既有模块。能够根据现有声明／函数体／调用确定，且无需新增业务或重要工程选择的小修，由工程师集中处理、检查同类位置并复编。需要事件状态、重要接口、存读／结构或业务判断的，集中回Pro。只读单保持只读，其他用例／共享平台／明确保护面不因报错扩权。细则见C的AUTONOMOUS_FIX_ZONE_AND_STOP_GATES.md。

两路均采用上述执笔与执行分工。同事滤波器／普通Reflex完整Feature按DR03/DR07保持完整方法和父组合，不改成我方Core加同事外壳。确有理由委派Codex完整基础Feature时，任务可覆盖完整连贯工作，但完整B包本身不替代委派理由。

## 3. 一份交接写清修改、当前目的与正常后继

先写实际业务工作和本批结果，再给必要定位。已有B任务直接引用，不复制第二包；任务存在、目录可写和方法能力不单独构成指派。

本次源码指令说明既定业务／工程、要修或实现的范围、允许写面和保护面、预期行为及回交成果。正常构建单同时明确可连续处理的编译小修范围，不限本轮新文件，也不逐行派发；有理由的其他编码委派说明本批理由。

运行任务说明执行哪份源码、当前要回答的实际问题、正式路径、数据／对象／频率／预热／配置、结果回交与已授权后继。工程师从现有配置取得板块、完整成员、日历和数据，给Pro实际必要内容；Pro检查默认参数有效性并给初始安排。具体板块、日期和参数只在本任务。标准构建遵循平台规定，TIS／FRP严格在edh-universe目录执行stack install，禁止添加其他参数。

任务或原continuation正文给一小段CURRENT_C_WORK说明：已有真实成果、本轮实际工作、交回结果、正常下一步及需其他责任者处理的情况。它不取代完整scope／权限，主控只搬原文，已有合法续作不被初始focus覆盖。普通已给清的应用、生成、编译、运行和读回可以一单连续做，不为每个工作段重新派发。

方法仓/ref/角色模式、实现仓/分支/base/允许写面、实际执行版本与结果位置分别明确。共享面按当前既有安排保持单写，不默认新建worktree。纯执行单可无源码修改，codex_commit可空、execution_commit如实填；诊断程序限授权输出位置，不改变正式Feature、生产配置、共享依赖、正式预期或平台。

## 4. 实际反馈、小修与业务分析的往返

Pro发布真实源码和明确任务，Codex在合法现场应用／生成、执行受派代码和标准构建。先读完本次错误，按共同原因查直接相关位置，授权小修集中做后复编；一次失败不自动结束单或归还现场。编译中不改同一源码，后继Pro保留工程师有效修订。

超小修的业务／重要工程问题集中交Pro，带错误、输入输出、相关位置、已排除原因和未执行部分。Pro须实际处理并尽量写修订；信息不足给定向调查，不能只登记回压、建议修改或让工程师猜。修后工程师在确切新版本复验，同根问题查相关实现；无关合法工作继续。

编译通过且路径和安排已具备就实跑；生产者／调用未写继续主体，不用fixture冒充上游。正式结果按方便理解的形式回交后，Pro结合真实输入分析对象／过程／关系的形成演化、关键参数作用、必要对照和合法空，不只看表／行数。核心对象未实际形成不签生命周期验证。

实际异常分类为实现、接线、输入／预热、方法／配置、业务空、合同或平台。受权方法范围内的参数对照保留基线并解释，不静默调阈值追非空。重要语义／工程变化按原责任返回；当前能查清的问题不留给后续图审。

工程师可以质疑并给反证，Pro消费调查和修后结果，独立审查按实际范围复核。技术问题解决后还要返回原业务问题；reader修好不等于对象检查结束。长运行不追latest，原失败保持原版本，纯结果上传失败只补上传。

## 5. 工作组合与再判断

正常施工来自完整目标的实际未完，按C正常主线与DR13 §5组织相连业务批。一条链可实跑就取反馈，其他主体继续；不等所有代码完才编译，也不让一条小链无限打磨吞掉其余任务。

业务理解／平台复用／有效经验从编码开始适用；主要探索由真实结果或具体反证推动。测试、proof、抽象、文档和控制材料增长而主体不动时，管理停止非必要深化，回未写业务或具体接通；必要工程内部也采用合理首版，不以必要之名加厚。

管理根据完整剩余、实际信息增益和目标规模判断继续调查、修复、转向或接收。普通清楚工作不每轮重选研究方向；重要前提被推翻定向回A/B/平台，内部欠设计／欠上游继续本任务处理。仅真实不可取来源／权限及超授权高影响取舍才问Owner，只暂停受影响路径。

## 6. 已有业务特征、平台参考与CEPS方法

涉及已有Feature，Pro先读业务含义、参数、输入输出和相关实现，明确调用已有方法、订阅正式Feature、读取物化产品或仅参考解释。原运行值、存储读回和展示投影分别核本次所需内容；import或配置存在不证明正式复用。沿接受工程接好，具体缺项交原责任者，不在消费者猜来源或重算上游。细则见C平台复用方法§2.4。

既有平台按真实接口使用，保存／读回要求不推导为新建DTO、codec、serializer、sidecar或第二平台。真正公共平台问题先证明宿主内不能完成并窄回压。本方法不授权外仓开发。

Python/Numba、跨语言和Haskell/FRP共同使用 `agent_evolution/platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/00_REFERENCE_ROUTER.md`。按B的platform_reference_lock读package/reference/SHA同一完整正文，API和caller在目标exact ref核实；工作区私有配置由工程师查证，远端不可见不等于不存在。真实运行读取平台执行补充，不改原八份导入及锁。

CEPS从 `agent_evolution/skill_candidates/market-process-ceps-skill-pack-candidate-v0.2.0/skill/SKILL.md` 的implement_accepted_ceps_contract进入完整方法，实际实现端口、方法数据、子过程、Reflex余量和状态关系。Skill不授新写权，普通函数充分时保持直接，代表性检查不替代完整主体。有效EAW经验按索引命中读取，不每轮翻全部历史，不将用例名／阈值写入通用core。

## 7. 交回可直接继续的实物

Pro交确切源码、构造／调用和参数路径、本批已写／完整未完、工程师指令及实际结果分析；工程师交应用／生成／受派差分、命令、版本、数据／配置、日志、必要业务样本、可复现问题和未执行。双方明确下一方要消费什么，不能以报告替代程序或实际结果。

业务解释对应输入和正式输出，说明适用生命周期／关系、参数作用、异常处置、修后复验及限制。源码提交、编译、writer/readback、局部解释和完整接收分账，后续图审／成熟化不遮盖当前核心未知。

正常长程回合按Overlay09/11保存真实提示、完整可见回答和必要实物，失败／调查／分析也回交；已保存内容不重复抓取，不追补隐藏思考或旧历史。执行者交准确地图事实，不直接改公共README、全局图／预算／资格，原任务内合法continuation继续由承办者负责。
