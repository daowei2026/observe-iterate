# 两类实现怎样连接，并交回真实可用结果

执行修订：`2026-09-29-pro-code-real-data-first`。使用 A 的完整业务合同、B 的确切工程设计与实际任务授权。滤波器／普通 Reflex 路线和 CEPS等复杂表达路线按 DR01/DR03选择，不以有无状态分路，也不强制两路数量相同。

## 1. B 先选真实连接形态

明确上游结果通过直接函数、正式Feature订阅、确切物化产品或平台已有接口怎样进入下游。选法依据业务时间、状态、消费者、replay与实际宿主能力；不能只因为任务分给两种Agent，就强制增加一次存储、搬运或公共接口。

设计包括谁构造实例、谁调用、触发来自哪里、参数／方法版本怎样进入、输出如何被实际使用、失败怎样归类。完整设计确定后再发施工任务，不能把主要接线欠账交给实现者首次决定。

当设计涉及 Python／Numba、DBA／Fao 跨语言交接或 Haskell／FRP 时，B 从 `agent_evolution/platform_engineering_references/feature-platform-engineering-reference-pack-candidate-v0.1.0/00_REFERENCE_ROUTER.md` 选择 reference，并把同一 `platform_reference_lock` 交给两路实现者。两路不得分别抄写或改写平台约束。

## 2. 五类实质关系必须连起来

**材料。**采用真实来源、对象、范围、版本和cut；缺资料、合法空、冲突分别表达。真实上游未实现时标明计划新增和生产责任，不把fixture或外部预算结果当正式source。

**方法。**具名参数、方法／RulePack版本实际进入构造与调用；结果被下游唯一writer消费。允许合法测试seam，不允许用外部传入已判定结果替代尚未实现的方法。资料不足的校准分支保持明确不可执行，不胡填阈值；结构方法足够时实际完成。

**事件。**业务触发、采样、read-old、same-firing、proposal／commit和revision保持合同含义；不把回调顺序、技术延后或轮询变成新业务时间。真实中间事件来自被消费的计算链，不另算诊断副本。

**状态。**明确拥有者、active identities、必要常驻状态、结束／清退、正式历史、恢复和合法迟到修订；不可把全部history常驻或默认丢掉。去重／tombstone等物理计划由B决定，不新建总WholeState掩盖多个业务过程。

**正式输出及消费。**writer、产品类型、物化、正式readback和真实消费者逐段落实；发布层不再作第二次业务判定。Git merge不是运行集成，schema存在不是writer运行，源码存在不是编译或真实输出。

## 3. 交付者和整体责任

A保业务语义，B保完整工程设计。普通Reflex完整Feature的接收者按原版或明确接入版交付；Mission C承担分派的复杂过程和连接；父工程集成任务具名承担两路汇合和整体验证。单个Feature实现者不默认负责全用例，Owner不替日常补设计。

不把整个用例包装成总Fao或总DSU，不把内部helper晋升公共Feature凑分路。已有平台优先复用，修改平台前先证明宿主内不能完成并形成窄backpressure。两路适配和组合欠账由当前campaign处理，不互相当成外部启动条件。

共享 reference 只约束宿主工程，不证明 live API。实现者在任务 exact ref 上核真实 Feature／Fao／Frame／DBA／CEPS／CFIS、caller、writer 和 consumer；发现 drift 时返回 B 更新 RepoFact／设计，只暂停依赖冲突的路径。

## 4. 首次实施完成约定主体，不持续探索代表性内核

任务已明确时，Pro按[DR10](DR10_PRO_IMPLEMENTATION_AND_CODEX_ORDERS.md)尽量完成相关全部源码，包括方法、类型、事件/状态、调用、注册、手写包装及修复；简单不自动下放。分批为上下文和可检查成果服务，不把完整责任改成反复挑小内核。普通函数保持最低充分形态，两路业务边界不因执笔者改变。

Codex按[DR11](DR11_CODEX_TWO_ROUTE_EXECUTION_AND_FEEDBACK.md)调查现场、应用Pro代码、执行生成、编译、实际测试及真实运行。只有Pro做不了或有具体理由不适合的编码才明确委派，可直接引用已签B任务，不逐函数重问；纯执行单不要求源码提交。报错不自动授予新修改权，不能换表达路线或扩展未指派的存储/平台工作。结果交Pro实际分析和尽量亲修，合理小修按指令，重要合同外取舍才召回Owner。

当前优先完整业务逻辑和正式接通，不默认同时扩写测试程序、全场景矩阵、罕见组合、proof或工业化设施。对妨碍当前构建/接通的具体问题作定向检查；真实反馈后按需要补回归。有获授权的诚实“真实输入→业务主体→正式输出→readback”后尽早运行，同时继续其他主体。不等全量测试或全部主体齐备，也不因小路径可跑取消完整责任；初次反馈不等于成熟效果或production接受。

正常顺序沿C实施判断§3—§4的五段主线，按业务链交错。构建单预授可确定的编译小修，工程师按原因集中修复复编；重要修法回Pro。小修实际差分仍审，普通步骤不逐次事前放行。

## 5. 各类证据分别交回

代码：exact repo/commit/path/symbol和实际调用位置。构建：实际命令、环境、退出码、日志与未执行项。真实数据：代码／配置／输入范围、原始结果、合法空或失败、未触达区域和限制。读取失败不能吞成业务空，不为非空输出改阈值、窗口、频率或品种范围。

旧版测试只证明旧版；当前源码变化后明确尚未复验，或给真实的适用性证据，不自动继承绿色。运行失败可能增加知识，也可能增加剩余工作；它不是未写主体完成的证明。Pro判断、源码写入、编译、writer、readback、消费者与整体完成分别报告。

普通执行者把完整分析和实物提交到授权工作面；不维护全局推进图或自行更换下一任务。管理／审查端从这些提交及原始结果核实际增量，更新工作线和后续责任；两种实施方法均采用同一外层交付规则。

## 6. 回流直到被实际消费

Pro实际源码→Codex应用/生成/编译/运行→结果回仓→Pro判断并尽量写修正，或确有理由委派编码/定向调查→Codex复验→管理接收并继续完整主体。不能只登记反馈。A含义不闭合回A，RepoFact变化先补事实，B主要设计未完继续B，代码偏离合同由实施修复，真正平台问题走窄证据。

只对受影响分支停线，保留正确成果、完整scope和历史投入。环境不可用就安排可执行端，不反复原样空转，也不把Pro缺环境当自动下放剩余代码的理由。缺写权限、缺源或机器准确说明，未发布不当远端current。测试/proof/抽象/文档持续增长而主链不动时，管理停止非必要部分，回到实际未完或具体接通，不以提交数、自测数解释进度。

正式结果取得后，Pro还须分析对象／关系演化和关键参数作用，必要对照与异常修复复验后进入独立接收；技术排障不能取代原业务目的。局部工作单结束与完整Goal另核。
