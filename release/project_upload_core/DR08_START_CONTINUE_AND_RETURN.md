# 启动、管理调用与实际接续

执行修订：`2026-09-18-question-work-v1`。管理完整职责以DR06为准，专业方法按DR00与CURRENT_EXECUTION取得。固定题与源索引见仓库根 `agent_evolution/agent_candidates/dual_route_execution/DR12_PROFESSIONAL_QUESTION_CATALOG.md`，工作组合/上下文/管理题见DR13，具体字段和主控处理见DR14。它们约束委派及交付，不规定统一内部思考步骤。

共同回交仍使用 `agent_evolution/agent_candidates/runtime_overlay_candidates/agent_owned_long_horizon_overlay_v0_3/13_角色回交与主控接续协议.md`。新题组绑定增加question_work_ref指向本轮RETURN，旧回交不追造。自动接收/转换/派发本次未部署，旧工具不会因正文新增而获得新能力。

## 1. 管理角色的实际调用

开始任务、重大要求变化、现有安排需要有据重判、阶段交付、实际进度/质量与预期偏离、反复失败/长期无主体进展等，交管理Pro完成相应判断。已有仍有效计划可以继续，不因新聊天或采用题库自动重做启动管理。

每批预先绑定DR14的三类触发：具名实质成果、重要变化、本段投入复看位置。专业者报告达成的业务事实与证据，主控读取已规定条件和实际运行事实，不能临场判重要性。一个小检查点不自动问全部管理题；同一信号已处理/在途去重，相关多信号可合并。

全局管理必须收到Owner完整目标、完成要求、直接纠正和各重要工作真实位置；地图/候选/推进者待办只是待核材料。不得预锁成认可旧路线、修完当前包、只处理推进者问题。关键前提可疑时扩展到相关上游；当前整体认识和已读未变方法可引用，不每次搬全部历史。

发现方向错误或主体遗漏立即处理，不以先审完当前包、完成当前循环为由拖延。持续提交/测试通过而没有有效接近完整目标，同样需管理。局部审查不得登记为全局判断；仅记录信号、收取或发布不等于管理发生。

管理判断不预限为下一项必须最小、出现返修全线停、所有剩余本轮做完。遵守Owner明确约束，允许有权Pro按完整目标调整。一次不足时继续同一管理work，保留实际认识与未完；局部审完不能仓促签发依赖未完判断的新方向。未受影响的已授权专业工作可继续。

## 2. 管理调用采用具名问题及明确输入

按DR13 §7选择M-START（启动/重大变化）、M-REASSESS（具体投入取舍）、M-CLOSE（批次/阶段收拢）；管理与审查可同轮，但权限、独立性和新增判断负担须相容，不把重型审查和重型全局重判硬塞一起。

每次管理消息必须包含：完整目标的直接来源、当前整体位置、这次究竟需要哪项判断、相应专业题的完整结果与原文、已有管理/审查的实际范围、新输入与尚欠责任。题面与这些引用由有权Pro提供，主控不再只发“你是管理者，请继续”。

共同立场如下，结合具名委派使用：

> 你负责以最快、最有效的方式达成Owner完整目标。必须预期旧工作可能局部、不完整甚至整体方向错误，独立核全部必要工作及当前任务的价值。已有投入、文件、阶段和你自己的旧安排不自动取得续行地位。发现方向错误、遗漏主体或低效投入，明确纠正并落到实际任务。
>
> 当前深入问题、相应专业结果、原文和接续位置见绑定。使用已有固定专业题/组合组织工作，保留必要现场判断和完整目标视野。形成需要的总体安排/取舍/收拢、条件性预算、地图、Owner事项和具体后继；只审一个局部或只给下一题不算全部管理完成。
>
> 按实际委派交ROLE_RETURN及新绑定的QUESTION_WORK_RETURN；兼任职责分别交清。未完继续同一事项，已经成立内容引用复用。主控不补业务范围、重点、验收或限制。

纯机械发布/补交保持窄职责，不冒称重新管理；发布后接回原事项尚欠的实质责任。管理者需要重型专业判断而尚无输入时，具名交原专业角色并接回，不自己装入所有领域形成超载上下文。

## 3. 给后续角色的具体工作要求

后续要求由有权Pro提供或确认，清楚到可执行。按DR14在现有任务写QUESTION_WORK_BINDING：完整目标/范围、当前批结果与重点、所选固定题及合法mode、全义务覆盖、原文exact路径/章节、实际输入/已做/已审/未完、交付/完成要求、预算、四类返回与具名触发。每项定位必须有实质正文，不能几个状态或方向留主控解释。

已明确任务可直接作为提示，不再造缩水摘要。当前业务答案仍由专业者分析，不强制多个解释、方案数或评分。题目不适用要依据业务；暂未做的适用义务继续留在整体覆盖。

A按原方法完成业务地图、方法程序、时间/状态及完整合同；A-2/A-3联动同一局部合同，A-4整合/探针按原权力。B分事实/设计/接收，先完整目标工程再代表性接收往返。C按获指派结果完成完整主体并尽早真实反馈。两路/Pro/Codex权限沿DR01–05/07/10/11，不由题号扩大。

一项工作可以跨多调用；承办者交具体未完和下一重点，在原范围继续。A next_handoff、B施工任务、C实施指令直接接入，但正式mode/阶段/跨角色授权另核。新证据影响Owner要求时具名返回，不能默改全局地图、范围或资格。

## 4. 审查、接收和正常返修

独立审查取得完整专业方法、exact候选、真实证据，不信Builder自评；参与候选形成不能自称fresh。探针暴露下游残留但无最终verdict；审查复做承重判断，管理仍独立裁整体投入。

回交明确对象/范围/依据/未审，旧结果在相同版本范围依据下复用，有新证据可具名重审。原计划已授权的同范围修订直接回承办者集中修改并复验，不每条finding新开管理。真正目标/结构/范围/权限变化交有权判断，不能主控自由分类。只承担审查者按既定路线交结论；兼任管理者另交完整管理，局部审完不关闭总体未完。

管理接收先确认当前工作对完整目标的必要性，再判保留/返修/停止/重排。通过/返修/待证都更新实际影响、共同说明/子图/工作量/资格和后继。只保留正确适用且有助目标的成果；不得使用已知错误输入，不因任意局部finding全线停止。

方法漏用、题目带偏或Skill/Harness明确缺项按原角色修实物/授权维护，不加回执冒充修订，不默认全历史审计。反馈跟到正文修改及新输入被消费，已有正确部分不重做。

## 5. 主续作与到期管理同时接续

采用新题组时，主控在解析ROLE_RETURN主动作后，必须逐项检查绑定trigger及本轮观察。主CONTINUE不表示无管理责任。RESULT/CHANGE依专业事实和证据，EFFORT依实际计数；UNKNOWN回原责任者补判定，不能默认为NOT_YET。到期非阻塞管理与原专业工作分别派发、记录、去重并跟到决定被消费。

一份回交同时达到多个相同决定条件时合并一次管理，已有管理在途则追加证据而不重新起一轮。管理只完成部分时在同一管理work继续。管理返回后，只有实际改入任务/地图/预算/后继或明确保留理由，才算信号被处理，收到一篇报告不够。

当前工具不自动完成这些动作；受控试跑须记录实际下一消息和两项责任状态。没有异步执行能力时按实际循环顺序发送，不能承诺后台已经开展。任务被新合法决定替换，保留旧历史和未处理义务，旧结果不能覆盖新安排。

## 6. 投递、发布与返回

主控只能使用已确定任务/固定操作文字和确切来源位置，不重新概括改义，不添加业务限制，不把AI推荐升为Owner唯一决定。缺结构定向补交，缺实质分析继续原事项，缺文件只补交付，等待和裁定各有具名责任。相同补交错误有限恢复后交既定接收者窄处理，不无限重启。

发送前核实际任务版本/授权/在途。已发送、已完成、状态未知不盲发；明确失败恢复真实缺失动作。回答结束、实物存在、commit产生、远端ref更新分别有证据。原业务已做不因管理接收缺失重做。

必要地图读取和版本检查沿Overlay09–12，不新设读图/绑定固定流水线。旧workmap_gate与计划内新成果待审的关系仍未改造；旧工具误挡续作如实报告，不能静默绕过，也不能把新指纹说成专业PASS。准备消息、实际发送和下游消费分开。

新题组和读取周期必须进入实际入口，旧上传/会话记忆不自动更新。保持旧work、scope、来源/已审资格、预算和在途，按真实管理接收迁移；方法发布、结构校验、本机采用、真实角色效果和生产结果分账，不因此开放代码/数据/新阶段。
