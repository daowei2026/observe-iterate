# 本轮问答与实质材料入库

执行修订：`2026-09-08`。适用于各用例的正常长程与中途材料补齐；与 [09](O09_GITHUB_WORKSPACE.md)、[10](O10_REVIEW_AND_ROUTE.md) 配合，不改 A/B/C 专业方法。

## 1. 当前默认：Pro 自己保存本轮，不等待历史聊天整理

每次向获授权的 GitHub 工作面交付时，负责本轮的 Pro 同时保存：**本轮实际收到的用户提示全文、本轮给用户的完整回答正文、本轮新形成或修订的必要实质文件**。问答不是摘要，也不只是结论和 NEXT_ACTION；分析、依据、候选、否定、限制等可见正文都保留。

采用该规则之前的历史提示和回答，**不由该 Pro 补录，不作为继续或材料补齐的前置条件**。已有历史记录继续保留，不删除；不得为了“完整上下文”重新导出全部聊天、逐轮追补旧回答或凭记忆重造原文。确实决定当前合同的旧 Owner 指令只需保留已经可得的准确依据；若其缺失影响本次选择，具名报告该一项，不能扩张成全历史工程。

不回填历史问答，**不等于可以不补旧任务包、必要上游正文或有效修订**。凡正在作为当前业务／工程依据使用的实质文件，仍须按下文补齐。

本规则不要求先建设自动聊天导出器、GitHub Actions 或新管理 Agent。Pro 本轮自行入库是正常路径，已有 Codex／routine 可机械核查、补推送及投递；不能因为没有外部抓取器就推迟保存。

## 2. 一轮一条可读记录，重试不复制

优先复用现有 provenance／chat 位置。没有时可使用：

```text
<任务目录>/provenance/turns/<聊天标识>/<本轮标识>.md
```

聊天标识可用任务内稳定代号，取不到平台聊天 ID 不猜。轮标识从现有记录或投递任务取得；开始重试前先查同一轮是否已经保存。并行聊天使用不同代号，不同时覆盖同一文件。

一份文件即可，包含简短来源说明、本轮提示全文、本轮回答正文和实质文件定位。记录来源为 `pro_current_turn_self_record`，不是账号级导出，也不声称已保存整个聊天。文件头可写已存在的输入提交；不写尚未产生的自身输出提交。时间可取得才写准确值，未知不补猜。

保存用户本轮实际消息，不用 `01_当前任务.md` 或发送模板冒充实际提示。附件由定位关系连接，不把全文又粘入提示段。只保存获授权的用户可见内容，不写系统／开发者指令、隐藏思考、凭据或未授权敏感资料；确需删减敏感信息时明确标注，不能仍称逐字无删节。

### 回答与提交回执的先后

Pro 先完成准备给用户的回答正文，写入本轮记录，与材料一起提交；远端读取后，聊天发送相同正文，可在末尾附简短的提交号、路径和核验结果。**这段提交后产生的发布回执允许不反写本轮文件**，并在记录头注明该范围，避免“把自身提交号写进文件→又产生新提交号”的无限循环。

除上述机械回执外，不得把核心分析只留在聊天。最终如有实质增补或纠正，更新同一本轮记录后再交付；保留 Git 历史，不生成重复“最终版2”。不要求证明网页最终渲染与文件逐字节相同，但不得声称保存了实际不可见的内容。中断只保存到半截时，标明不完整和恢复点，不能造完整记录。

## 3. 必要实质文件：补正文，不补一个看起来齐全的清单

围绕完整任务目标、当前成果和近期交接，主动沿依赖检查：当前任务包／工程包、必要父包、仍有效的后继修订、承重审查、方法正文和上游接口，以及用于当前判断的实际证据。

- 当前仅有名字、版本、hash、段落偏移、摘要或临时 sandbox 链接：均不能代替可读取的正文。已有附件／本地文件就实际导入，不长期只登记欠账。
- 另一正式仓库已有原文：使用经过读取核验的 `(repo, commit, path)`，不整仓复制；跨仓引用冻结确切版本，不依赖 latest。
- 导入前对账被保留的有效修订：不能只上传最早完整父包，再把后来已使用的修订标成“未改变”。不按版本号大小盲选；旧候选被保留、吸收、替代或拒绝的依据要明确。
- 若当前合同由多份有效文件共同组成，完整保留各部分并建立明确入口，不强迫一轮合成巨型文件。原位合并必须有完整移动和对照，不能借清理路径重写业务。
- 不再使用的中间稿，不要求全部导入活动目录；但不可删掉仍被审查、修订或下游依赖的内容。

同名不同文、两个候选的取舍不清、已知后继缺席，都属于**当前选择待核实**，不能预设“只差拷贝字节”。先保留证据，按既有授权定向裁定或返回对应专业任务；不偷偷改语义，也不为所有机械搬运重开 Owner Gate。

## 4. 同一实质文件只上传一次

先打开总包／成员目录，看回答中的多个下载项实际指向什么，再形成来源到仓库正文的对应关系。

**总包中的 A、B 被回答分别讲解、分别链接时：A、B 各保留一个正文落点即可；多个讲解位置和别名都指向它，不再复制“总包版A”“单文件版A”。** 已在仓库的同一内容直接引用。

去重以实际内容和来源身份核对，不凭同名或“意思相近”。同名不同字节须查明，近似文件不能为了省空间丢掉差异；必须分别保留的不同版本用 Git 历史或明确冻结引用，不伪称同一文件。

日常活动文件按主题稳定路径原位维护，不复制一套套版本目录。完整 ZIP 如只承担运输且成员已完整落库，可只保留包身份和成员对应，不重复提交二进制；原包字节本身是必要证据、无法无损拆出或 Owner 明确要求时，可留一份原件。不可为了“去重”破坏已有 accepted parent 或删除历史证据。

原始问答与规范正文职责不同：回答解释了某份任务包，不代表可以只存回答而不存任务包；同一正文被解释多次，也不需要多份物理拷贝。特别大的原始行情、重复截图及环境文件不在本入库要求中，按已有数据权限和持久证据位置处理，禁止塞 base64 到正文凑“完整”。

## 5. 一次交付的实际顺序与检查

1. 读取目标分支最新 head，核写权、当前任务、已保存轮次和必要依赖；以确切版本组织本次修改。
2. 保存／修订完整实质正文，建立一次来源对应；已存在的同内容不重复上传。保存本轮提示与完整回答。
3. 从实际文件构造链接，核对本轮新增、修改及受影响的必要引用。若正文有内容完整性疑点，先处理，不以文件数和 hash 代替语义。
4. 将本轮正文、问答和地图事实尽量原子提交。使用明确文件列表纳入新文件；不能只用会漏掉未跟踪文件的提交方式。不得夹带其他人的改动、强推或改写历史。
5. **实际发布到接收者读取的获授权远端分支，并在提交成功后的确切 commit 上逐条读取交付入口、本轮问答及全部本轮必要文件／引用。** 至少检查存在、非空、完整读取、身份匹配；搬运不改正文的文件还须核对字节／hash。404、只读标题、截断、错误版本都不算可读。可用 connector 或已有本地 Git 工具，不以固定工具为前提。
6. 远端核对后才在聊天报告已提交；区分“实质材料已入库”“本轮问答已保存”“业务／工程已通过”。三者不能互相替代。

相对链接按该提交解析；引用另一仓或旧审查对象用确切 commit。若 API 返回截断或空内容，按实际格式分段读取、读 blob 或用已有解包方式，不能盲信 manifest。不能访问的具体项及影响范围在原地图留一条，不另造长篇验收台账。

推送失败只补推送；路径错误先检索实际文件再修引用；内容缺失补正文；不要重新发送整个业务任务。写入前 head 漂移时，比较受影响路径后正常重基线或暂停冲突写面，禁止 force。失败时留实际状态，不报已发布；不依赖该缺项的工作可继续。

## 6. 小几轮补齐既有材料：默认 2–3 轮，可提前结束

这是 `MATERIAL_CATCHUP` 工作，不是重做用例，也不恢复历史问答。完整范围始终是当前任务需要的实质材料；轮次是控制上下文的安排，不是限时删范围。

**第一批：核当前依据，直接导入最承重的部分。** 读既有地图、当前包、有效修订及必要附件成员，确定正确当前集合与最高影响缺项。同轮开始提交完整文件，不能只交盘点／hash表。先修已存在文件的错误路径；新发现的版本冲突单独标明。

**第二批：补余下依赖和有效后继。** 按第一批留下的实际剩余内容分主题读取并提交，核对源成员→仓库正文，保留有效方法、状态、参数、上下游接口与审查细节；不因目录整理降低细度。

**第三批（确需时）：从远端入口作仓库独立可读检查。** 不借未入库的聊天记忆，沿当前入口读完必要正文和引用；修错链、漏件、重复落点或错误版本选择；更新地图，给出剩余真缺项或明确材料已齐。

上一批已完成即不要重跑。同一已授权补齐任务内可按剩余项继续机械批次，不为每批拷贝额外发起一轮独立业务审查；这不授权自行进入新业务里程碑。需要再开一轮时说明剩余实质内容及原因，不能为了凑三轮制造回执，也不能为了三轮内结束把材料缺失宣称成“以后再说”。

结束标准：当前完整依据、有效修订与必要输出能从仓库直接取得或沿核准外仓引用取得；来源对应不丢独有内容；必要引用实际核验；本次采用规则以来的各轮提示回答均已保存。旧问答未补录不影响此项完成。**材料齐全不自动解除业务缺陷、独立审查要求或 A→B→C Gate**；下一项业务问题仍按 [10](O10_REVIEW_AND_ROUTE.md) 和最新任务授权判断。

## 7. routine 可直接学习的有限职责

Pro 是本轮问答与实质产物入库的默认责任者。已有 Codex／routine 只做：定期发现未发布成果、核必要文件和实际远端版本、补机械缺项、同步当前进度、按已签发问题渲染和投递；不重复抓取或另存已有完整的本轮记录，不要求 Pro 补历史聊天。

任务正文、所需材料与状态必须在投递端实际读取的同一快照可见；只落本地或只翻状态不算可投递。已完成／已发且未确认状态的同一任务不盲目重发：先核实际发送和新成果；只重试失败动作。没有新材料／绑定不足／需要业务决定时，不凭 Builder 的 NEXT_ACTION 编下一任务。

地图保存当前实质进展、待补项和下一项理由；问答记录保存过程。区分最新发出、最新完整交付、最新核验，取不到的状态写未知；不能只因最近有 commit 就称聊天正在工作。规则文件更新不等于已部署 routine：采用时核实实际加载版本，未运行不声称自动化已经接通。初版可人工继续发起各轮，无需等待调度设施。
