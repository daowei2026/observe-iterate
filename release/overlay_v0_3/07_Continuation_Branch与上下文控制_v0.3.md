# Continuation、Branch 与上下文控制

执行修订：`2026-09-07`。

采用 GitHub 持续工作面时，`00_长程推进地图.md`（或已有等价地图）、`01_当前任务.md` 和完整正文是持续入口；不再每轮手工维护一份平行 Continuation 真源。建图／接续见 `09_GitHub持续工作面与版本管理.md`，审查与选路见 `10_独立审查与下一轮问题选择.md`。

换聊天只提供：任务目录与输入 commit、当前里程碑、任务卡路径、必读正文／审查／Owner 决定路径、未关闭问题和相关 Agent 执行修订。其余内容从这些正本读取。Builder 的下一步仅为未签发建议，不能随换聊天获得运行权。

没有 GitHub 写权或仍按明确离线合同运行时，可提供薄 Continuation：任务与版本、本轮实质产物、变化、未决问题、审查状态、Owner 状态、受影响下游、候选下一问题及必读材料。必须明确实际未发布状态，不能伪称已同步工作面。

上下文压力依靠“全图导航＋本轮完整承重正文＋必要相邻依赖”控制。不要缩写方法，不把全部历史重灌，也不能因不在清单就拒绝必要的关联读取。原始问答按需回查，最新代码事实使用 live head 比较后的 exact commit。

多个独立写面可并行；共享地图和共同接口保持一个写者。聊天分支的决定不自动写回父线或兄弟线，合流时明确正文与路线变化。分析分支不等于 Git 工作分支：前者隔离上下文，后者隔离仓库修改，不能互相替代。
